# Claude 커맨드의 Codex 실행 규칙

이 저장소 내부용 연결 규칙이다. 작업 절차와 출력 형식의 정본은 `.claude/commands/`에 두고, Codex 진입점은 해당 원본을 실행 시점에 읽는다. `.claude/skills/`도 복제하지 않고 상대 심볼릭 링크로 공유한다.

- 저장소 루트의 `AGENTS.md`와 작업 경로의 하위 지침을 먼저 따른다. 원본의 프로젝트 상대 경로는 저장소 루트 기준이다. 테스트를 작성·수정·리뷰하기 전에는 `.claude/rules/Agents.md`를 읽는다. 스킬 원본 내부의 상대 링크는 실제 `.claude/skills/` 원본 위치 기준으로 해석한다.
- Codex 호출은 `$이름 입력` 형식이다. 원본의 `$ARGUMENTS`·`ARGUMENTS`는 호출 뒤의 사용자 입력 전체(여러 줄 포함)를 뜻하며 셸 변수가 아니다. `init-worktree`의 브랜치명도 이 입력에서 받는다.
- 원본의 `/이름`, `/sc:이름`, `Skill` 호출은 실제 `.claude/commands/` 파일이 있으면 그 파일을 읽어 수행한다. `/Issue-Branch`는 `$issue-branch`에 대응한다. 그 외 스킬·플러그인은 현재 제공된 목록에서 존재를 확인하고 사용한다. 같은 이름의 전역 스킬이 있어도 이 진입점에서는 연결된 프로젝트 원본을 사용한다.
- `Read`·`Grep`·`Glob`·`Bash`·`Edit`·`Write`·`TodoWrite`는 현재 Codex의 파일 읽기·검색·명령 실행·편집·계획 기능으로 수행한다. 도구 이름이나 예제 경로가 실제로 존재한다고 가정하지 않는다. `init-worktree` 예제의 `.cursor/scripts` 대신 이 저장소의 `.claude/scripts/worktree_manager.py`를 확인한다.
- 원본이 병렬 작업을 명시하면 현재 제공된 Codex 서브에이전트 도구와 동시 실행 한도 안에서 나눠 실행한다. Claude의 `Agent`·`Task`·`Workflow`나 `subagent_type` 이름을 그대로 호출하지 않는다. 위임이 제공·허용되지 않으면 순차 수행하고 그 사실을 보고한다. 의존 단계는 선행 결과를 기다리며, 병렬 작업에는 공통 입력과 파일 소유 범위를 전달한다.
- `thinking` 켜기·끄기, `/config set --thinking true`, 모델·권한 모드 변경 지시는 적용하지 않는다. 실제 변경하지 않은 설정의 복원 안내도 출력하지 않는다. 외부 도구가 필요하면 현재 제공된 동등 기능을 확인하고, 없으면 필요한 입력이나 미수행 범위를 알린다.
- 커맨드 파일을 읽거나 추천받는 것만으로 커밋·GitHub 게시를 실행하지 않는다. 사용자가 `$commit`·`$cr` 실행을 요청하면 그 커밋 범위, `$issue-branch` 실행을 요청하면 이슈 등록과 브랜치 생성 범위에 대한 요청으로 해석한다. 사용자가 지정한 파일·기능 범위를 우선하며, 원본의 후속 작업 제안을 자동 실행하지 않는다. push 금지·Co-Authored-By 금지·파일 삭제 확인 규칙은 `AGENTS.md`를 따른다.
- GitHub에 이슈·PR·댓글 본문을 게시할 때는 생성한 본문이 비어 있지 않고 필요한 내용을 포함하는지 직접 읽어 확인한다. 여러 줄 본문은 구조화된 도구 인자 또는 `gh`의 `--body-file`로 전달한다.

완료 전 원본의 필수 산출물과 검증을 확인한다. 수행하지 않은 도구 호출·테스트·외부 게시를 성공으로 보고하지 않는다.
