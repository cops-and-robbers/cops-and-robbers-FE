## 🔥 구현 기능

닉네임 확인 결과를 서버의 `code`로 나눠, **금칙어 닉네임에는 "중복"이 아닌 전용 문구**를 띄운다.

| 서버 `code` | 지금 화면 | 바꾼 뒤 화면 |
|---|---|---|
| `AVAILABLE` | 사용 가능한 닉네임이에요 | 그대로 |
| `DUPLICATED_NICKNAME` | 중복된 닉네임이에요. 다른 닉네임을 입력하세요 | 그대로 |
| `BANNED_WORD_NICKNAME` | 중복된 닉네임이에요. 다른 닉네임을 입력하세요 | **새 문구 (아래 초안)** |

> [!IMPORTANT]
> BE [#248](https://github.com/cops-and-robbers/cops-and-robbers-BE/issues/248)이 `code` 필드를 추가한다는 가정으로 쓴 이슈다. 서버에 반영된 뒤 연동한다.

<br>

## 📝 현재 문제점

- BE #247(v4.2.0, dev)부터 `GET /api/user/check-nickname`이 금칙어가 든 닉네임에 `isAvailable: false`를 준다. 중복일 때와 응답 모양이 같다.
- 앱은 `isAvailable`만 본다. `UserRepositoryImpl.checkNickname`(`user_repository_impl.dart:25`)이 `bool`만 돌려주고, `nickname_setup_page.dart:128`이 `false`를 모두 `NicknameValidationState.duplicate`로 바꾼다.
- 그래서 금칙어 닉네임에도 "중복된 닉네임이에요"가 뜨고, 사용자는 왜 안 되는지 모른 채 다른 표기로 계속 시도한다.
- 서버 `message`는 한국어 한 문장이라 그대로 띄우면 en·ja가 깨진다. 문구는 앱이 언어별로 갖는다.

<br>

## 🛠️ 해결 방안 / 제안 기능

BE #248 이후 응답 (200)

```json
{ "isAvailable": true,  "code": "AVAILABLE",            "message": "사용 가능한 닉네임 입니다!" }
{ "isAvailable": false, "code": "DUPLICATED_NICKNAME",  "message": "이미 사용 중인 닉네임입니다." }
{ "isAvailable": false, "code": "BANNED_WORD_NICKNAME", "message": "닉네임에 부적절한 표현이 포함되어 있습니다." }
```

- `NicknameCheckResponseModel`에 `code`를 받고, 확인 결과를 "사용 가능 / 중복 / 금칙어" 셋으로 돌려준다.
- 화면 상태에 금칙어 경우를 더하고, 아래 문구를 빨간 안내(지금 중복 안내와 같은 모양)로 띄운다.
- `message`는 화면에 쓰지 않는다.

> [!WARNING]
> `code`가 없거나 모르는 값이면 지금처럼 `isAvailable`만 보고 `false`는 중복으로 처리한다. #248이 배포되기 전 서버와도 그대로 동작해야 한다.

새 문구 초안 (세 언어 모두 확정 전)

| 언어 | 문구 |
|---|---|
| ko | 사용할 수 없는 표현이 들어 있어요. 다른 닉네임을 입력하세요 |
| en | This nickname contains words that aren't allowed. Please enter a different nickname |
| ja | 使用できない表現が含まれています。別のニックネームを入力してください |

## 📌 참고

- 버튼 이름 "중복 확인"은 그대로 둔다. 결과 문구로 이유를 알린다.
- `PATCH /api/user/me/nickname`의 400 `INVALID_INPUT_VALUE`는 범위 밖이다. 확인 결과가 사용 가능일 때만 확인 버튼이 켜져(`nickname_setup_page.dart:305`) 이 응답에는 거의 닿지 않는다.
- 금칙어 필터 자체: BE #247 (게시글·댓글·채팅은 서버가 `*`로 가려 저장, 앱 작업 없음)
