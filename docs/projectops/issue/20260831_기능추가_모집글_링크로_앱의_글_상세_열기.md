⚙️ [기능추가][Flutter][딥링크] 모집글 링크로 앱의 글 상세 열기

🔥 구현 기능
---

모집글 링크를 누르면 앱이 열리면서 그 글의 상세로 바로 이동합니다. 상세의 공유 버튼도 이 링크를 만들어 공유합니다.

| 표면 | 내용 |
|---|---|
| 링크 수신 | `https://copsandrobbers.app/g/{id}` 를 누르면 앱이 열리고 해당 모집글 상세로 이동. 일본어(`/ja/g/{id}`)·영어(`/en/g/{id}`) 경로도 같은 글로 이어진다 |
| 폴백 스킴 | `copsandrobbers://open/community/{id}` 수신. 웹 상세의 "앱에서 열기" 버튼이 인앱 브라우저 등에서 앱을 깨울 때 쓴다 |
| 공유 버튼 | 모집글 상세의 공유 버튼이 글 제목 + 링크를 OS 공유 시트로 보낸다 |
| 전 상태 대응 | 앱 종료(콜드)·실행 중(웜)·미로그인, 어느 상태에서 눌러도 결국 그 글에 도착한다 |

📝 현재 문제점
---

> [!WARNING]
> 모집글 상세의 공유 버튼이 "준비 중" 안내만 띄운다. 링크 경로가 정해지지 않아 미뤄둔 자리다.

- 앱이 해석할 수 있는 링크는 방 초대(`/join/{code}`)뿐이다. 모집글 웹 페이지가 열리면 글 링크가 돌기 시작하는데, 그 링크에서 앱으로 이어지는 길이 없다
- 도메인의 앱 링크 인증 파일에는 모집글 경로가 이미 등록되어 있다. 경로 해석 없는 앱이 새 도메인 선언과 함께 출시되면 링크가 앱만 열고 글로 이어지지 않는 상태가 되므로, 이 작업은 반드시 새 도메인 선언과 같은 릴리스로 나가야 한다

🛠️ 해결 방안 / 제안 기능
---

새로 짜지 않고 이미 검증된 두 구조를 그대로 따른다.

- **이동은 푸시 알림과 같은 구조**: 댓글 푸시가 이미 "커뮤니티 상세로 이동"을 구현했다. 웜은 리스너가 상세를 push 하고, 콜드는 스플래시가 인증·활성 게임 확인을 마친 뒤 목적지로 go 한다(go(home) 경합 방지). 딥링크도 같은 자리에 같은 방식으로 얹는다
- **미로그인은 초대 코드와 같은 구조**: 로그인 전에 들어온 글 id 를 보존했다가, 약관·닉네임까지 진입 절차가 모두 끝난 시점에 소비해 상세로 보낸다. 링크를 타고 온 신규 가입자도 가입을 마치면 그 글에 도착한다
- **공유 링크는 `/g/{id}` 하나만 만든다**: 글의 언어별 정본 경로 판단은 웹이 한다. 앱은 언어를 몰라도 되고, 규칙이 바뀌어도 앱 업데이트가 필요 없다

⚙️ 작업 내용 (구현하며 확정)
---

- `DeeplinkEvent` 에 `communityPost(postId)` 추가. `/g`·`/ja/g`·`/en/g` 3경로와 커스텀 스킴 파싱, 숫자가 아닌 id 는 unknown 처리
- **딥링크 경로를 라우터 별칭 라우트로도 등록**: 엔진이 실행 중 들어온 인텐트의 원시 URI 경로를 라우터로 전달하는 것을 실측으로 확인했다(`flutter_deeplinking_enabled=false` 로 막히지 않음). 딥링크 경로가 실제 라우트로 존재하지 않으면 404 가 목적지 위를 덮으므로, `/g/:postId` 등 3경로를 `/community/:postId` 로 넘기는 별칭을 둔다 (`/join` 과 같은 원리)
- **커스텀 스킴은 `copsandrobbers://open/{라우터 경로}` 규약으로 확정**: host 뒤에 라우터 경로를 그대로 실어야 엔진이 전달한 경로가 실제 라우트에 안착한다
- **initial link 의 스트림 재전달(echo) 필터**: app_links 가 콜드 스타트를 일으킨 링크를 스트림에도 한 번 더 흘리는 것을 실측으로 확인했다. 안 거르면 같은 링크가 콜드·웜 양쪽에서 이중 처리된다
- 콜드 스타트 emit 에서 모집글 이벤트 제외. 콜드는 스플래시가 단독 처리한다 (푸시와 같은 이유)
- 스플래시: 활성 게임이 없을 때의 목적지에 딥링크 상세를 반영(푸시 목적지와 같은 자리), 미로그인이면 글 id 를 보존하고 로그인으로
- 앱 루트 리스너: 웜 이벤트는 상세 push, 진입 절차가 안 끝났으면 보존. 보존된 초대 코드와 글 id 가 동시에 있으면 초대가 우선이고 글은 버린다 (게임 참여가 글 열람보다 앞선다)
- `pending_community_post_provider` 신규 (초대 코드 보존과 같은 방식)
- 상세 공유 버튼 연결: 글 제목 + 링크. 링크 빌더는 초대 링크와 같은 자리(share_util)에 둔다
- 상세 안내 화면(삭제된 글·불러오기 실패)을 커뮤니티 톤으로 정리: 돋보기 든 캐릭터를 넣고 버튼을 커뮤니티 파랑으로 맞춘다. 딥링크로 이 화면에 도착하는 경우가 생기는 만큼 첫인상을 맞춘다
- `AndroidManifest.xml`: 기존 App Links 필터에 `pathPrefix` `/g/`·`/ja/g/`·`/en/g/` 추가, 커스텀 스킴 필터에 `host="open"` 추가
- 분석 이벤트 2종: 공유 버튼 탭, 딥링크 유입(cold·warm·pending 구분)
- `deeplink_event_test` 확장, 파서 전 케이스 실행 검증
- `docs/DEEPLINK.md` 갱신: 모집글 시나리오, 스킴 규약, "딥링크 경로는 라우터 실제 라우트 필수" 원칙, 언어 추가 시 세 곳(인증 파일·매니페스트·파서) 동기화 체크리스트

📌 참고
---

> [!IMPORTANT]
> PR base 는 `20260812_#470_v3_앱_전면_개편` 이고, **이 작업은 반드시 v3 와 같은 릴리스로 나가야 한다.** 도메인 인증 파일에 모집글 경로가 이미 등록되어 있어, 경로 해석 없이 나가면 링크가 앱만 열고 끝난다. 부득이 빠지게 되면 웹 인증 파일에서 `/g` 경로를 임시로 빼두어야 한다.

- 활성 게임 참여 중의 콜드 스타트는 게임 복귀가 우선이고 링크는 버린다 (푸시와 동일한 정책)
- 삭제됐거나 잘못된 글 id 는 상세의 안내 화면이 받는다 (라우터의 기존 정책 그대로)
- recents 재실행의 중복 처리는 기존 dedup 이 그대로 막는다
- 구버전 앱 사용자가 링크를 누르면 브라우저로 열린다. 웹 상세 페이지가 받으므로 잃는 것이 없다
- `/g/abc` 처럼 잘못된 링크를 브라우저로 되던지는 폴백은 넣지 않는다. 자기 도메인 링크를 앱에서 다시 열면 OS 가 또 앱으로 가로채는 순환 위험이 있고, 웹은 숫자 id 만 만들어 실익이 없다
- 기존 `copsandrobbers://join/{code}` 스킴은 open 규약 이전의 형태다. 웹 브릿지가 이미 쓰고 있어 정비는 별도 작업으로 남긴다 (docs/DEEPLINK.md 참조)
