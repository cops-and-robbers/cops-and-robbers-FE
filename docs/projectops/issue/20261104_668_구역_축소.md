📝 현재 문제점
---

- QA에서 플레이 구역이 너무 크니 줄었으면 좋겠다는 의견이 있었고, 구역 축소를 경찰과 도둑, 술래잡기 공통 옵션으로 넣기로 했습니다 (DEC-0120의 자기장).
- 옵션의 규칙, 잠금 조건, 서버 저장 범위가 정해지지 않았습니다.
- 지금은 구역을 벗어나면 배너와 반복 진동으로 경고하고 일부 메뉴를 막습니다. 계속 밖에 있어도 그 이상의 불이익이 없어, 축소가 들어오면 밖에 머무는 쪽이 유리해질 수 있습니다.

🛠️ 해결 방안 / 제안 기능
---

아래 내용은 모두 팀 확인 전 제안입니다. 숫자는 QA에서 조정합니다.

### 표기

- 이름: 구역 축소
- 설명: 시간이 지나면 플레이 구역이 점점 줄어들어요
- 켰을 때: 반경 500m → 200m까지 줄어들어요 (실제 값으로 표시)

### 최종 반경

- 최종 반경 = max(감옥 반경 + 100m, min(시작 반경 × 40%, 200m)). 앱이 계산하고 사용자는 켜고 끄기만 합니다.
- 술래잡기는 감옥 반경을 0으로 계산합니다.

| 시작 반경 | 감옥 반경 | 최종 반경 |
|---|---|---|
| 500m | 100m | 200m |
| 350m | 10m | 140m |
| 1km | 10m | 200m |

### 줄어드는 방식

- 게임 시간과 구역 크기에 상관없이 항상 4번 줄어듭니다.
- 축소 간격 = (게임 시간 − 경찰 시작 시간) ÷ 5. 경찰 출발 뒤 한 간격이 지나면 1차 축소가 일어납니다.
- 1회 축소량 = (시작 반경 − 최종 반경) ÷ 4. 4차에 최종 반경이 되고, 마지막 한 간격은 그대로 유지합니다.
- 다음 구역 경계는 지도에 항상 미리 보여 주고 남은 시간을 표시합니다. 별도 축소 예고 문구는 넣지 않습니다.
- 축소는 정해진 시각에 한 번에 일어납니다.
- 감옥이 중심에 없으면 최종 원이 감옥을 품도록 중심을 꼭 필요한 만큼만 옮깁니다.

예: 30분 게임, 경찰 시작 5분이면 10, 15, 20, 25분에 줄어듭니다.

| 시작 반경 | 1차 | 2차 | 3차 | 4차 |
|---|---|---|---|---|
| 350m | 약 298m | 245m | 약 193m | 140m |
| 1km | 800m | 600m | 400m | 200m |

### 토글 잠금

- 시작 반경이 "감옥 반경 + 100m" 이하일 때만 잠급니다. 예: 감옥 10m면 110m 이하, 감옥 100m면 200m 이하, 술래잡기면 100m 이하
- 게임 시간이 짧아도 잠그지 않습니다.
- 폴리곤 구역은 이번에 지원하지 않으므로 잠급니다.
- 구역을 먼저 정하므로 처음 방을 만들 때는 토글이 나올 때 잠금 여부를 이미 알 수 있습니다.
- 확인 화면이나 대기방 게임 설정에서 구역을 바꾸면 조건을 다시 확인합니다. 안 맞으면 자동으로 끄고 잠급니다. 다시 가능해져도 켜는 것은 사용자에게 맡깁니다.

| 상황 | 문구 |
|---|---|
| 구역이 작을 때 | 구역이 작아서 쓸 수 없어요. 플레이그라운드를 넓히거나 감옥을 줄여 보세요. |
| 구역이 작을 때 (술래잡기, 감옥 없음) | 구역이 작아서 쓸 수 없어요. 플레이그라운드를 넓혀 보세요. |
| 폴리곤 구역 | 구역 축소는 원형 구역에서만 쓸 수 있어요. |

### 구역 이탈

- 1단계: 구역 밖으로 나가면 지금처럼 앱을 막습니다.
- 2단계: 구역 밖에 n초 있으면 경고가 1번 쌓입니다.
- 3단계: 경고가 m번 쌓이면 강제 체포합니다.
- 경고 횟수와 다음 경고까지 남은 시간을 화면에 띄웁니다.
- 구역으로 돌아와도 경고 횟수는 유지합니다.
- 앱을 다시 켜도 같은 라운드면 경고 횟수를 유지합니다. 방장이 재시작하면 0부터 다시 셉니다.
- 게임 id, 라운드 시작 시각, 경고 횟수를 함께 `SharedPreferences`에 저장합니다. 같은 방의 다음 라운드는 게임 id가 같아 게임 id만으로는 구분되지 않습니다.
- 같은 라운드 판단: 게임 id가 같고 시작 시각 차이가 2초 이내입니다. 시작 이벤트와 게임 정보 API의 시각은 소수점 자리가 다를 수 있습니다 (#641의 게임 기록 복원과 같은 기준).
- 시작 시각을 받지 못하면 저장값을 복원하지 않고 0부터 시작합니다.
- 강제 체포되면 경고 횟수를 0으로 되돌립니다.
- 술래잡기에서 강제 체포되면 탈락합니다.
- 이벤트 게임에서는 강제 체포를 호출하지 않습니다.
- 강제 체포되면 모든 참가자에게 알립니다. 서버가 기존 `ARREST` 이벤트를 `police: null`로 보내고, 앱은 `police`가 없으면 전용 문구를 띄웁니다. 경찰 체포처럼 배너, 진동, 시스템 채팅을 함께 처리합니다.

| 언어 | 문구 (초안) |
|---|---|
| 한국어 | [닉네임]님이 구역 밖에 오래 있어서 잡혔어요! |
| English | [Nickname] was caught for staying outside the game area too long! |
| 日本語 | [ニックネーム]さんはエリアの外に長くいたため捕まりました! |

- 위치를 계속 공개하는 패널티는 쓰지 않습니다.
- 경찰은 잡히지 않으므로 지금 동작을 유지합니다.

### 서버 계약

- settings에 `shrinkFinalRadiusMeters` 하나만 추가합니다. null이면 꺼짐입니다.
- 서버는 저장하고 내려주기만 합니다. 게임 로직과 게임 중 수정 금지는 그대로 둡니다.
- 서버의 새 로직은 저장할 때 검증뿐입니다: 원형 구역, 감옥 반경 < 최종 반경 < 시작 반경
- 현재 반경은 앱이 시작 시각과 설정으로 계산합니다. 게임 중 API 호출은 없습니다.
- 서버 핑 판정은 원래 구역 기준이므로, 줄어든 구역 밖 핑은 앱에서 막습니다.
- 강제 체포는 지금 체포 API가 경찰 전용이라 새 API를 요청합니다: https://github.com/cops-and-robbers/cops-and-robbers-BE/issues/226

### 앱 버전

- 축소는 각 앱이 같은 공식으로 계산하므로, 구역 축소를 배포할 때 Remote Config 강제 업데이트로 버전을 맞춥니다.

❓ 미정
---

- n초, m번 값
- GPS 오차, 연결 끊김, 앱이 백그라운드에 있을 때의 이탈 시간 계산
- 축소 직후 밖으로 밀려난 사람에게 시간을 더 줄지
- 서서히 줄이는 방식과 짧은 게임의 체감: QA 뒤 판단
- 구역을 줄일 때 저장 순서: 앱이 먼저 축소를 끄고 구역을 저장하는 안
- 폴리곤 지원 시점
- 구역을 바꿀 때 최종 반경을 다시 계산하는 시점. 넓혀도 저장된 값은 서버 검증을 통과합니다 (500m를 1km로 넓혀도 200m가 남음).
- 중간 단계의 중심 이동: 선형으로 옮기는 안
- 최종 반경 저장 단위: 정수로 반올림할지

QA에서 함께 볼 것:

- 축소량이 아주 작은 구역. 210m, 감옥 100m면 1회 축소가 2.5m입니다.
- 축소 간격이 아주 짧은 게임. 게임 시간과 경찰 시작 시간이 1분 차이면 12초입니다.
- 기기 시계가 다른 폰끼리 축소 시점 차이
