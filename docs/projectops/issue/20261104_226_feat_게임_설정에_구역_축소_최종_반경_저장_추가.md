## 🔥 구현 기능

구역 축소에 필요한 서버 작업 두 가지입니다. 최종 반경을 게임 설정에 저장하고 내려주는 것과, 구역 밖에 오래 머문 도둑을 체포하는 API입니다.

- 팀 확인 전 제안이고, 숫자는 QA에서 조정합니다.
- 규칙과 시안: https://github.com/cops-and-robbers/cops-and-robbers-FE/issues/668

**역할 나누기**

| 서버 | 앱 |
|---|---|
| 값 저장 | 최종 반경 계산 |
| 저장할 때 범위 검증 | 축소 시점과 현재 반경 계산 |
| 값 내려주기 | 줄어든 구역 표시, 구역 밖 핑 막기 |
| 강제 체포 처리 | 구역 이탈 판정, 경고 횟수 관리 |

게임 로직과 게임 중 수정 금지는 그대로이고, 게임 중 API 호출도 늘지 않습니다.

## 📡 API

`settings`에 필드 하나만 추가합니다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `shrinkFinalRadiusMeters` | Integer, nullable | 구역 축소의 최종 반경(m). `null`이면 꺼짐 |

**요청**: `POST /api/games`의 `settings`, `PUT /api/games/{gameId}/settings`

```json
{
  "roundDurationMinutes": 30,
  "locationRevealIntervalMinutes": 5,
  "policeWaitMinutes": 5,
  "maxParticipants": 10,
  "shrinkFinalRadiusMeters": 200
}
```

**응답**: 아래 네 곳에 같은 이름으로 내려줍니다.

- `POST /api/games`
- `GET /api/games/{gameId}`
- `PUT /api/games/{gameId}/settings`
- 대기실 `SETTINGS_UPDATED` 이벤트

## ✅ 저장 시 검증

값이 있을 때만 두 가지를 확인합니다. `null`이면 검증하지 않습니다.

1. 구역 타입이 `CIRCLE`입니다.
2. 최종 반경이 감옥 반경보다 크고 플레이그라운드 반경보다 작습니다.

예: 감옥 100m, 플레이그라운드 500m

| 최종 반경 | 결과 | 이유 |
|---|---|---|
| 200m | 저장 | 100m보다 크고 500m보다 작음 |
| 50m | 거절 | 감옥보다 작아서 감옥이 구역 밖으로 나감 |
| 100m | 거절 | 감옥과 같음 |
| 500m | 거절 | 시작 구역과 같아서 줄어들지 않음 |
| 700m | 거절 | 시작 구역보다 큼 |

최종 반경을 만드는 공식은 앱에만 있습니다. 서버는 값이 범위 안에 있는지만 봅니다. QA에서 공식의 숫자를 바꿔도 서버는 고치지 않아도 됩니다.

## 🚨 강제 체포 API

구역 밖에 오래 머문 도둑을 앱이 체포 처리할 수 있도록 API를 하나 추가합니다. 지금 `/system/arrest`는 경찰만 호출할 수 있어 도둑 앱에서 쓸 수 없습니다.

구역 이탈 판정과 경고 횟수는 앱이 GPS로 처리합니다. 서버는 위치를 검증하지 않고, 체포 처리만 합니다.

`POST /api/games/{gameId}/system/force-arrest` (이름은 조정 가능)

- 요청 본문: 없음. 로그인한 도둑 본인이 대상입니다.
- 응답: `/system/arrest`와 같습니다.

```json
{
  "robberNickname": "도둑1",
  "remainingThieves": 3
}
```

기존 체포와 다른 점:

| 항목 | 경찰 체포 | 강제 체포 |
|---|---|---|
| 호출하는 사람 | 경찰 | 도둑 본인 |
| 도둑 상태 `JAILED` 변경 | 함 | 함 |
| 도둑의 잡힌 횟수 | 올림 | 올림 |
| 경찰의 체포 수 | 올림 | 올리지 않음 |
| `ARREST` 이벤트 | 경찰 정보 포함 | `police`를 `null`로 전송 |
| 남은 도둑 0명이면 게임 종료 | 함 | 함 |
| 경찰 대기 시간 중 호출 | 거절 | 허용 |

강제 체포도 모든 참가자가 알 수 있어야 합니다. 경찰 체포처럼 `/subscribe/game/{gameId}/system`으로 `ARREST` 이벤트를 보내고, 앱은 `police`가 `null`이면 "구역 밖에 오래 있어서 잡혔다"는 문구를 띄웁니다.

```json
{
  "police": null,
  "robber": { "participantId": 12, "nickname": "도둑1", "status": "JAILED" },
  "remainingThieves": 3
}
```

지금 `ArrestData.of`는 경찰 정보가 있다고 보고 만들기 때문에 `null` 처리가 필요합니다.

거절하는 경우:

- 게임이 진행 중이 아닐 때
- 호출한 사람이 도둑이 아닐 때
- 이미 수감된 상태일 때

이벤트 게임에서는 앱이 이 API를 호출하지 않습니다.

## ❓ 같이 정할 것

**1. 구역을 바꿀 때 저장 순서**

`PUT /area`와 `PUT /settings`가 따로라서, 구역을 줄이거나 폴리곤으로 바꾸면 저장된 최종 반경이 조건에 안 맞을 수 있습니다.

- 제안: 앱이 먼저 축소를 끄고 구역을 저장합니다.
- 정할 것: `PUT /area`에서도 검증할지

**2. 감옥이 없는 술래잡기**

지금 dev에는 모드 값이 없습니다. 술래잡기 서버 작업에서 감옥 없는 구역이 생기면 감옥 반경을 0으로 보고 검증합니다.

- **핑 판정:** 서버는 원래 구역 기준을 유지하고, 줄어든 구역 밖 핑은 앱에서 먼저 막습니다.
