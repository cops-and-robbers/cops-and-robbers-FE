## 제목

⚙️ [기능추가][튜토리얼][Flutter] 별도 튜토리얼 페이지 신설 및 기존 코치마크 시스템 대체

## 본문

## 📝 현재 문제점

- 인게임 코치마크 튜토리얼이 있지만, 게임이 시작된 시점(시간 압박 상황)에 떠서 사용자가 그냥 스킵함
- QA 피드백 — "어떻게 잡는지(체포 방법)", "다른 참가자 위치를 어떻게 보는지" 등 핵심 메커닉을 모르는 채로 본 게임 진입
- 코치마크는 화면별로 1회만 노출되며, 다시 보려면 설정에서 전체 일괄 초기화만 가능 (개별 항목 다시 보기 불가)
- 페이지마다 흩어진 GlobalKey 관리로 유지보수 부담

## 🛠️ 해결 방안 / 제안 기능

- 별도 튜토리얼 페이지(`/tutorial`)를 신설하고, **실 게임/세션 화면에서 떠오르던 코치마크 호출은 모두 제거**한다.
- `tutorial_coach_mark` 패키지 자체는 **유지**한다. 패키지 호출 위치를 *튜토리얼 페이지 내부*로만 한정하면 시간 압박 상황 스킵 문제가 사라지고, ①②③⑤ 디테일 페이지 구현 시 재사용 가능하다.
- 카탈로그 + 디테일 패턴 — 카탈로그 화면에서 5개 항목을 자유롭게 선택 진입
  - ① 방 만들기 — 구역 설정(운동장·감옥, 위치 잡기 + InfoRadiusChip 탭하면 키보드로 반경 입력) + AppSlider 사용법(드래그 + 값 영역 탭하면 키보드 입력)
  - ② 방 참여하기 — 초대 코드 6자리 입력 + 카메라 아이콘으로 QR 스캔 입장
  - ③ 대기방 — 팀 변경, 게임 설정 보기, 준비 완료
  - ④ 인게임 — 타이머·지도·내 마커, 참가자 보기, 채팅, 도둑 위치 공개, 구역 이탈 경고, 경찰 대기 카운트다운
  - ⑤ QR 체포·탈옥 — 경찰: QR 스캐너 사용, 도둑: QR 보여주기 + 감옥/탈옥 (둘 다 의무)
- 카탈로그는 **5개 카드 모두 노출**, 활성 항목만 탭 가능하고 미구현 항목은 비활성 + "준비 중" 배지로 표시한다. 항목이 늘어나는 대로 활성으로 전환.
- 실제 UI 위젯 코드를 그대로 재사용 (정적 스크린샷 X), 실제 API 호출과 지도 SDK는 mock으로 처리해서 클릭 가능한 인터랙티브 형태로 진행한다.
  - 인게임(④)은 hand-built 뷰 + `AppSnackbar` 안내로 이미 1차 구현됨. 시간 압박 없는 환경이라 코치마크 대신 자유 탐색형이 더 잘 맞음.
  - ①②③⑤은 항목 특성에 따라 *코치마크* 또는 *하단 고정 가이드 바* 중 적절한 패턴을 선택해 구현 (디테일 페이지 작업 시 결정).
- 모든 항목은 [건너뛰기] 가능, 다만 ③·④·⑤ (대기방·인게임·QR)은 건너뛰기 시 한 번 더 AppDialog로 확인 ("정말로 건너뛰시겠어요? 이거 안 보면 게임 진행 어려우실 텐데 ㅠㅠ" 톤). ④ hand-built 뷰는 자유 탐색형이라 [건너뛰기] 자체가 없음 — 가드는 ①②③⑤ 디테일 페이지에서만 적용.
- 신규 유저 진입 — 백엔드의 `isNewUser` 응답을 기반으로 첫 진입 시 자동으로 `/tutorial` 1회 강제, 기존 API 변경 없음. **별도 작업으로 분리** (이번 작업 범위 외).
- 재진입 — 설정 페이지의 "튜토리얼 초기화" 메뉴를 "튜토리얼 다시 보기"로 변경하고 카탈로그로 라우팅.
- 디자인은 기존 디자인 시스템(AppColors, AppTextStyles, AppSpacing/AppPadding/AppRadius, AppDialog) 강제 사용.
