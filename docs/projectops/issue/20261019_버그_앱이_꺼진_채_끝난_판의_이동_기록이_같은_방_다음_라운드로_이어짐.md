# ❗ [버그][Flutter][게임기록] 앱이 꺼진 채 끝난 판의 이동 기록이 같은 방 다음 라운드로 이어짐

## 🗒️ 설명

게임 중 앱이 꺼진 상태로 그 판이 끝나면, 같은 방에서 다음 라운드를 할 때 이전 라운드의 이동 경로·거리가 새 라운드 기록으로 복원된다. 기기 기록 파일을 게임(방) id만으로 구분하기 때문이다. 같은 방의 라운드는 game id가 같다. 기록 파일을 **라운드 단위로** 구분해야 한다.

> [!WARNING]
> 복원된 거리는 30초마다 서버로 전송되어 팀 MVP 동점 판정(BE #212, 서버 v2.39.0)에 쓰인다. 서버는 라운드의 첫 거리 값에는 시속 상한 검사를 하지 않으므로, 이전 라운드 거리가 그대로 판정에 들어간다. 결과 카드의 거리·경로도 부푼다.

<br>

## 🔄 재현 방법

1. 방에서 게임을 시작하고 조금 움직인다 — 기기 파일 `game_record.txt`에 `g {gameId}` 머리줄과 경로가 쌓인다.
2. 게임 중 앱을 강제 종료하고, 앱이 꺼진 채 그 판이 끝나게 둔다 — 파일을 지우는 `markEnd`가 실행되지 않는다.
3. 앱을 다시 켜고 같은 방에서 다음 라운드를 시작한다.
4. 게임 화면 진입 시 `begin(gameId)`가 같은 머리줄의 파일을 찾아 이전 라운드 경로·거리를 복원한다.

<br>

## 📸 참고 자료

| 위치 | 역할 |
|---|---|
| `game_record_local_datasource.dart` `openForGame` | 머리줄 `g {gameId}`가 같으면 저장 기록을 돌려준다 |
| `player_game_record_provider.dart` `begin` | 게임 화면 진입마다 파일을 열어 복원 |
| `player_game_record_provider.dart` `markEnd` | 파일을 지우는 유일한 곳 — 앱이 살아 있을 때 게임이 끝나야만 실행 |
| `game_page.dart` `_maybePublishDistance` | 복원된 누적 거리를 `/publish/game/{gameId}/distance`로 전송 |

라운드를 가를 값은 서버 게임 시작 시각(`gameStartTime`)이다. 대기실 진입은 GAME_START의 `startTime`, 앱 재실행은 `GET /api/games/{gameId}` 설정 응답에서 채워진다. 두 경로의 시각 정밀도가 다를 수 있어 문자열이 아니라 시각 차이로 비교해야 한다.

<br>

## ✅ 예상 동작

- 같은 라운드에 다시 들어오면(앱 재실행) 지금처럼 경로·거리가 복원된다.
- 다른 라운드면 이전 기록을 버리고 0부터 새로 쌓는다.
- 시작 시각을 알 수 없으면 복원하지 않고 새로 시작한다.
