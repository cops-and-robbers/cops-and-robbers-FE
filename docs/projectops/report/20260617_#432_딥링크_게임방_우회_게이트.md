### 📌 작업 개요

딥링크(`/join/:inviteCode`)로 게임방에 진입할 때 위치 권한·배터리 최적화 게이트를 우회하던 버그(#432)를 수정한 작업. 정상 경로(홈)에만 존재하던 진입 게이트 로직을 공용 헬퍼 `GameEntryGate`로 추출하고, 홈 화면을 이 헬퍼에 위임하도록 리팩터한 뒤, 딥링크 진입 경로에 인증 분기와 함께 게이트를 적용했다.

### 🎯 구현 목표

- 딥링크 진입 시 홈과 동일한 위치 권한·배터리 최적화 진입 조건 보장
- 게이트 로직을 두 진입 화면(`home_page`, `deeplink_join_page`)이 공유하도록 중복 제거
- 미로그인 사용자의 pending invite 유실 없이 게이트 적용
- 게이트 분기 흐름의 회귀를 위젯 테스트로 보호

### ✅ 구현 내용

#### 1. 문제와 원인

정상 경로(홈의 방 만들기 / 방 참여하기)는 게임 진입 전에 ① 위치 권한 ② (Android) 배터리 최적화 무시를 순차 확인한다. 그러나 딥링크 진입(`DeepLinkJoinPage`)은 빌드 직후 곧장 `handle()` → join API → 대기실로 들어가 이 게이트를 전혀 거치지 않았다.

- 게이트 로직이 `home_page`의 **private 메서드**(`_ensureLocationPermission`, `_ensureBatteryOptimization`)로만 존재해 재사용 불가
- `DeepLinkJoinPage._run()`이 게이트 없이 `handle()`을 호출

결과적으로 Android에서 배터리 최적화 미해제 상태나 위치 권한 미허용 상태에서도 딥링크로 게임 입장이 가능했다.

#### 2. 공용 게이트 헬퍼 신규 — `GameEntryGate`

- **파일**: `lib/core/services/permission/game_entry_gate.dart` (신규)
- 두 진입 화면이 공유하는 게임 진입 게이트.
  - `abstract interface class GameEntryGate` — `Future<bool> ensure({context, locationContext})` 단일 메서드 노출
  - `GameEntryGateImpl` — 실제 위치 권한 + (Android) 배터리 최적화 판정 구현. `home_page`의 기존 게이트 로직을 그대로 이전하되 `State.mounted`를 `context.mounted`로 치환
  - `@Riverpod(keepAlive: true) GameEntryGate gameEntryGate(Ref ref)` — provider로 노출하여 테스트에서 override 가능
- **설계 핵심**:
  - **콜백(onGranted) 대신 `Future<bool>` 반환** — 콜백 안 async 추적 곤란을 피하고 호출자가 `await ensure(...)` 후 동기적으로 분기
  - **차단 시 안내 다이얼로그를 await** — 다이얼로그가 닫힌 뒤 `false`를 반환하므로, 호출자(딥링크)가 라우팅 등 후속 처리를 안전한 시점에 수행. "다이얼로그 띄운 직후 홈 이동 → 페이지 dispose 경합"을 방지
  - **네이티브 판정 예외 흡수** — 위치/배터리 판정이 throw하면 호출자가 무한 로딩에 갇힐 수 있어 본문을 try-catch로 감싸고, 예외 시 거부(`false`)로 취급
  - **`_ref` 무효화 방어** — 다이얼로그 await 중 ref 무효화 위험을 피하려 `backgroundService` 인스턴스를 미리 캡처
  - 동작/순서/디버그 빌드 스킵(`kDebugMode`)/iOS 배터리 스킵은 기존과 100% 동일

#### 3. `home_page.dart` 리팩터 (동작 불변)

- **파일**: `lib/features/session/presentation/pages/home_page.dart` (수정)
- 기존 private 게이트 메서드 2개(`_ensureLocationPermission`, `_ensureBatteryOptimization`, 약 107줄)를 제거하고 `GameEntryGate.ensure()` 위임으로 교체 (순증 24줄 / 삭제 107줄)
  - `_onCreateSession`: `gameEntryGateProvider.ensure(context, locationContext: home)` 통과 시에만 드래프트 초기화 후 세션 생성 플로우로 이동
  - `_showJoinRoomDialog`: 동일 게이트 통과 시에만 `_showJoinRoomDialogInternal()` 호출
  - 중첩 콜백(`onGranted` → `onGranted`) 패턴이 `await` 직선 흐름으로 단순화됨
- 외부 동작은 변하지 않음. `locationContext`는 기존대로 `home`.

#### 4. `deeplink_join_page.dart` — `_run()` 인증 분기 + 게이트

- **파일**: `lib/features/session/presentation/pages/deeplink_join_page.dart` (수정)
- `_run()`에서 **인증 상태를 먼저 분기**하는 것이 핵심:
  1. `_readUserSafely()`로 인증 상태 확인 (실패 시 null = 미로그인 취급으로 폴백)
  2. **미로그인** → 게이트 없이 곧장 `handle()` 실행. pending invite 저장 + 로그인 이동은 `handle()` 내부에서만 일어나므로, 게이트를 먼저 태우면 거부 시 invite가 저장되지 않은 채 흐름이 끊긴다. 따라서 게이트를 스킵해 invite 보존을 보장
  3. **로그인** → `gameEntryGateProvider.ensure(locationContext: waitingRoom)` 평가
     - 통과 → 기존 `handle()` + outcome 분기 로직 실행 (join API 호출)
     - 미통과 → 안내 다이얼로그가 닫힌 뒤 `context.go(home)`으로 복귀 (무한 로딩 방지)
- `locationContext`는 딥링크가 대기실로 진입하므로 **`waitingRoom`** 사용
- 로그인 후 재진입 경로(`main.dart`의 pending invite 소비 → `joinByInviteWithCode`)도 같은 `_run()`을 통과하며, 이때는 로그인 상태이므로 게이트 경로(3번)를 탄다
- `_readUserSafely()` 신규 — `authNotifierProvider.future`를 try-catch로 읽어 실패 시 null 폴백 (`handle()`도 동일 provider를 읽으므로 일관 재처리)

### 📌 리뷰 반영 핵심

- **invite 유실 방지**: 미로그인 사용자에게 게이트를 먼저 태우지 않고 `handle()`로 보내 pending invite 저장을 보존
- **라우팅 경합 제거**: 차단 다이얼로그를 await한 뒤 false를 반환하도록 하여, 다이얼로그 표시 직후 홈 이동으로 인한 페이지 dispose 경합을 차단
- **수명 안전**: `keepAlive` provider + 다이얼로그 await 중 `Ref` 무효화 위험을 서비스 인스턴스 사전 캡처로 회피, 네이티브 예외는 try-catch로 흡수해 무한 로딩 방지
