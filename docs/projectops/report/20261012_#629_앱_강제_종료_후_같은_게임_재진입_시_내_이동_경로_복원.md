### 📌 작업 개요
게임 중 앱 프로세스가 종료(크래시·OS 종료)된 뒤 같은 게임에 재진입하면, 종료 전까지의 내 이동 경로·거리·체포/잡힌 위치를 복원하도록 개선. 기록은 기기 파일에만 저장하고 서버로 보내지 않음. 함께 결과 카드에서 쓰이지 않던 `RoutePainter`와 투영 함수 정리.

**보고서 파일**: `docs/report/20261012_#629_앱_강제_종료_후_같은_게임_재진입_시_내_이동_경로_복원.md`

### 🔍 문제 분석
- 내 기록(`PlayerGameRecord`)은 `PlayerGameRecordNotifier` 메모리에만 존재 → 프로세스가 죽으면 소실
- 재실행 시 스플래시가 진행 중 게임으로 복귀시키지만, `GamePage` 진입 시 `reset()`이 기록을 초기화 → 결과 카드에 튕기기 전 경로가 빠짐
- 네트워크만 끊긴 경우는 앱이 살아 있어 기존에도 기록이 유지됨 (이번 범위 아님)

### ✅ 구현 내용

#### 기기 기록 파일 저장소 추가
- **파일**: `lib/features/game/data/datasources/game_record_local_datasource.dart`
- **변경 내용**: 앱 지원 디렉터리의 `game_record.txt` 하나에 기록 이벤트를 한 줄씩 덧붙여 저장. 첫 줄은 `g <gameId>`, 이후 `p|a|c <lat> <lng>`(점·체포·잡힘) 또는 `r`(복원 지점)
- **이유**: 매 틱 전체를 다시 쓰지 않고 덧붙이기만 해서 쓰기 비용을 줄이고, 쓰다 죽어 잘린 마지막 줄은 개행 유무로 판별해 버림

#### 게임 진입 시 복원 (`reset` → `begin`)
- **파일**: `player_game_record_provider.dart`, `game_page.dart`
- **변경 내용**: `GamePage` 진입 시 `await begin(gameId)` 호출. 파일의 `gameId`가 같으면 이벤트를 재생해 복원, 없거나 다르면 파일을 새로 쓰고 초기화. 복원이 끝난 뒤 위치 스트림을 시작
- **이유**: 복원된 경로 뒤에 새 점이 이어 붙도록 순서 보장

#### 게임 종료 시 파일 삭제
- **파일**: `player_game_record_provider.dart`
- **변경 내용**: `markEnd`에서 기록 파일 삭제. 결과 다이얼로그는 메모리 상태를 읽으므로 영향 없음
- **이유**: 종료된 게임은 재진입할 일이 없음. 중도 퇴장으로 남은 파일은 다음 게임 진입 시 덮어씀 → 기기에 남는 파일은 최대 1개

#### 꺼져 있던 구간 미기록
- **파일**: `player_game_record.dart`, `route_geometry.dart`, `record_route_map.dart`, `game_over_result_dialog.dart`
- **변경 내용**: 복원 직후 첫 점은 직전 점과의 거리를 더하지 않고 새 구간으로 시작. `PlayerGameRecord.segmentStarts`에 구간 시작 인덱스를 남기고, `splitRouteSegments`로 나눠 구간마다 Polyline을 따로 그림
- **이유**: 앱이 꺼져 있던 동안의 이동은 알 수 없으므로 직선으로 잇거나 거리에 넣지 않음

#### 미사용 코드 정리
- **파일**: `route_painter.dart`(삭제), `route_geometry.dart`
- **변경 내용**: 어디서도 쓰이지 않던 `RoutePainter`와, 그것만 쓰던 `projectRoute`·`RouteProjection`·`projectRouteToCanvas` 제거
- **이유**: 결과 카드는 경로가 없으면 안내 문구를 보여주는 방식으로 바뀌어 페인터 폴백이 남아 있지 않음

### 🔧 주요 변경사항 상세

#### 이벤트 재생 방식
실시간 누적과 파일 복원이 같은 `_apply` 로직을 거쳐 상태를 만든다. 거리는 저장하지 않고 재생하면서 다시 계산하므로 실시간 누적값과 동일. 복원 지점(`r`)도 파일에 남겨, 두 번 이상 튕겨도 구간 경계가 유지됨.

**특이사항**:
- 파일 열기·쓰기·삭제 실패는 로그만 남기고 메모리 누적은 그대로 동작 (게임 진행에 영향 없음)
- 저장 크기: 점 한 줄 약 31바이트, 2m 이상 이동 시에만 저장. 1시간 연속 이동 기준 iOS 약 110KB, Android(2초 주기) 약 55KB
- 더미 게임(`isDummy`)은 기존처럼 기록하지 않음
- 신규 의존성 없음 (`path_provider` 기존 사용)

### 🧪 테스트 및 검증
- 저장소 테스트(실제 임시 디렉터리): 같은 게임 재오픈 시 이벤트 복원 / 다른 게임이면 폐기 / 잘린 마지막 줄 무시 / 삭제 후 재오픈 시 빈 상태
- Notifier 테스트(재시작 = 컨테이너 재생성): 같은 게임 재진입 시 경로·거리·마커 복원 / 다른 게임 진입 시 메모리·파일 모두 초기화 / 복원 후 첫 점은 거리 미합산·새 구간 / 두 번째 재시작 후에도 구간 경계 유지 / 게임 종료 후 재진입 시 빈 상태
- `splitRouteSegments`: 경계 없음 / 경계에서 분할
- 기존 `GamePage` 위젯 테스트 하네스에 기록 디렉터리 override 추가 (테스트 환경에는 `path_provider` 채널이 없음)
- `flutter test` 전체 통과(1399), `flutter analyze lib test` 이슈 없음
- 실기기에서 게임 중 강제 종료 → 재진입 → 결과 카드 확인: **미확인**
