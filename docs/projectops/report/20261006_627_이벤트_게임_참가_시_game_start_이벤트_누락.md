# ❗ [버그][애널리틱스][게임] 이벤트 게임 참가 시 game_start 이벤트 누락

### 📌 작업 개요

대기실을 거치지 않고 게임에 들어가면 `game_start`가 기록되지 않던 문제를 고쳤습니다. 이벤트 게임 현장에서 시작 수가 낮게 나오던 원인입니다.

### ✅ 구현 내용

| 경로 | 위치 | 기록 값 |
|---|---|---|
| 코드로 이벤트 게임 참가 | `home_page.dart` | 팀 경찰, 인원 없음 |
| 딥링크로 이벤트 게임 참가 | `deeplink_join_page.dart` | 팀 경찰, 인원 없음 |
| 대기실에서 앱을 내려 둔 사이 게임 시작 | `waiting_room_page.dart` `_checkStatusOnResume` | 서버 응답의 팀, 대기실 인원 |

- `AnalyticsService.logGameStart`가 `gameId`를 받아 같은 게임을 30초 안에 다시 보내지 않습니다. 대기실 소켓 신호와 복귀 확인이 겹쳐도 두 번 세지 않습니다.
- 이슈는 gameId 단위로 한 번만 보내자고 했지만, 같은 방의 다음 라운드는 gameId가 같아 "한 번 더"를 누른 판의 시작이 빠집니다. 그래서 일반 게임은 시간으로 구분했습니다. 판은 기권으로 일찍 끝날 수 있어도 결과를 닫고 다시 모여 시작하는 데 30초보다 오래 걸립니다.
- 라운드가 없는 이벤트 게임은 나갔다가 다시 들어와도 한 번만 보냅니다.
- `participantCount`는 생략할 수 있게 바꿨습니다. 이벤트 게임은 대기실 인원을 알 수 없고, 이 값은 지표 계산에 쓰지 않습니다.
- 이미 진행 중인 게임에 다시 들어가는 경로(스플래시, 홈 복귀)는 이슈에서 정한 대로 건드리지 않았습니다.

### 🔍 참고할 점

- 중복 방지 기록은 메모리에만 있습니다. 앱을 끄고 같은 이벤트 게임에 다시 참가하면 다시 기록될 수 있습니다. 사람 수 지표에는 영향이 없고 횟수 지표만 조금 늘 수 있습니다.
- 배포한 날은 어드민 일정에 앱 업데이트로 남겨야 합니다. 이후 `game_start` 증가를 실제 증가로 오해하지 않기 위해서입니다.

### 🧪 테스트

- `analytics_service_test.dart`: 겹친 신호는 한 번만, 같은 방의 다음 라운드와 다음 게임은 다시 보내는지 확인
- `deeplink_join_page_test.dart`: 이벤트 게임 참가 시 `game_start`를 보내고 게임 화면으로 가는지 확인
- 코드 참가와 대기실 복귀 경로는 위젯 테스트를 더하지 않았습니다.
- GA4 DebugView와 실기기 확인은 아직 하지 않았습니다.
