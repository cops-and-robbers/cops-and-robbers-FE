### 📌 작업 개요

인앱 메시지를 전면 외부화하여 다국어(한국어/영어/일본어) 지원 인프라를 구축. 코드 내 한국어 하드코딩을 모두 ARB로 분리하고, Flutter 공식 `flutter_localizations` + `intl` + `gen-l10n` 파이프라인을 채택. 사용자가 설정에서 언어를 바꾸면 앱 재시작 없이 즉시 반영되는 핫 스위치까지 포함. 8개 커밋(인프라 → core → auth → game → session → settings/언어선택 페이지 → 기타 feature → 가이드 문서)으로 단계적 진행.

**후속 작업 (2026-05-18 추가 6개 커밋)**: CodeRabbit 리뷰 피드백을 근본 원인 관점에서 처리. 임시 자동 생성 키(hex suffix, prefix+파일명, `_Lnnn` 라인 번호 패턴) 전부 의미 기반으로 마이그레이션 완료 → **자동완성 패턴 0건 달성**. 백엔드 detail 다국어 미지원 + `Accept-Language` 헤더 미전송 이슈로 영어/일본어 사용자에게 한국어 detail이 노출되던 문제를 messageKey 기반으로 통일. `locale_provider`의 `isFollowingSystem` stale state 문제를 Record state로 reactive화.

### 🔧 주요 변경사항 상세

#### `AppLocale` Notifier (lib/core/i18n/locale_provider.dart)

지원 로케일: ko, en, ja. 기본은 ko (시스템 로케일이 지원 외이거나 첫 실행).

```
우선순위:
1. SharedPreferences 저장값 (사용자 명시 선택)
2. 시스템 로케일 (PlatformDispatcher.instance.locale)
3. kDefaultLocale (ko)
```

`build()`는 동기 흐름이라 SharedPreferences 비동기 로드를 직접 못 넣음 → 첫 프레임은 시스템 로캘 반환, `Future.microtask(_loadFromStorage)`로 다음 프레임에서 덮어쓰는 패턴. `followSystem()`은 저장값 삭제 후 시스템 로캘로 전환.

**Record state 마이그레이션 (2026-05-18, 커밋 dd5679b)**:

기존 `_followingSystem` 내부 bool 필드 방식은 두 가지 문제:
1. `ref.watch`로 받지 못해 UI에서 `setState` 강제 갱신 필요
2. 시스템 ko 상태에서 "한국어 명시 선택" ↔ "시스템 따름" 전환 시 `Locale` 값 동일 → Riverpod이 상태 변경 미감지 (stale)

해결: state 타입을 `({Locale locale, bool isFollowingSystem})` Record로 통합. 두 값을 atomic하게 갱신하면 `isFollowingSystem`만 바뀌어도 Record 동등성이 깨져 watcher가 재트리거됨. consumer는 `.locale` 추출, UI는 `ConsumerWidget`으로 단순화.

```dart
// Before
state = locale;  // _followingSystem은 별도 필드
// After
state = (locale: locale, isFollowingSystem: false);  // atomic
```

**특이사항**:
- 지원 외 언어 코드가 SharedPreferences에 남아있으면 silently 제거

#### `AppException.messageKey` 패턴

```dart
abstract class AppException implements Exception {
  final String message;        // 폴백 (한국어, 로깅용)
  final String? messageKey;    // ARB 키 (UI에서 변환)
  // ...
}

// Repository:
throw ServerException(
  message: '버그 제보 처리 중 오류가 발생했습니다.',
  messageKey: 'dialogBugRepositoryImplMessage',
);

// UI:
catch (e) {
  if (e is AppException) {
    final msg = AppLocalizations.of(context).errorByException(e);
    AppSnackbar.show(context, message: msg);
  }
}
```

`errorByException(e)`는 `error_message_mapper.dart`의 extension. 키가 비어있거나 미등록이면 `e.message` 폴백 — i18n 미적용 레거시 코드와 공존 가능.

**백엔드 detail 정책 (2026-05-18 변경, 커밋 775d3aa)**:

초기 구현은 백엔드 RFC 7807 `detail`이 있으면 서버 메시지를 사용자에게 그대로 표시했으나, 백엔드가 한국어 detail만 응답 + 클라가 `Accept-Language` 헤더 미전송 → 영어/일본어 사용자에게 한국어 detail이 노출되는 문제 발견. `DioExceptionHandler`에서 `hasServerMessage` 분기 전부 제거하고 messageKey 기반으로만 메시지 결정. 백엔드 detail은 `_logError`에서 `debugPrint`로만 출력 (개발자 디버깅용).

연관 변경:
- `AppException` fallback `message`를 한국어 → 영문 디버그 코드(`'auth_provider.signInWithGoogle.unknown'` 등)로 중립화 → fallback이 사용자에게 노출되더라도 한국어가 영어/일본어 사용자에게 보이는 일 차단
- UI 8곳에서 `e.message` 직접 접근을 `l10n.errorByException(e)` 매퍼 경유로 통일

```dart
    );
  }
}
```

`ScreenUtilInit` 내부에 두는 게 핵심 — 외부에 두면 라이브러리가 child를 캐싱해 locale 변경이 반영 안 됨. `ValueKey`로 트리 통째 강제 재구성해 Localizations widget도 새로 만들어 즉시 적용.

`onGenerateTitle`은 `MaterialApp.title`이 상수라 locale 변경 시 자동 갱신 안 되는 문제 회피.

#### 운영 주의사항

- **자동 생성 파일 편집 금지**: `lib/l10n/app_localizations*.dart`는 `flutter gen-l10n`이 덮어씀. ARB만 수정
- **3개 ARB 동시 추가 필수**: ko만 추가하면 en/ja는 `untranslated.txt` 기록 후 폴백 동작
- **ARB 수정 후 `flutter gen-l10n` 명시 실행 권장**: `generate: true`로 자동 실행되지만 IDE 자동완성/빌드 동기화를 위해 명시적 실행이 안전
- **Placeholder는 ASCII만**: `{이름}` ❌ → `{name}` ✅
- **`Cops` 영어 + `泥棒` 일본어 혼용 금지**: 일본어 ARB는 `警察` + `泥棒`으로 통일
- **`messageKey` 없는 Exception은 영어/일본어 사용자에게 한국어 노출됨** — Repository에서 throw할 때 반드시 동봉
- **`e.message` 직접 UI 노출 금지** — 반드시 `l10n.errorByException(e)` 매퍼 경유. fallback message는 영문 디버그 코드(언어 중립)로 작성
- **백엔드 detail은 사용자 노출 금지** — `DioExceptionHandler`가 detail을 debugPrint로만 출력. messageKey 기반 메시지로만 표시
- **임시 자동 생성 키 패턴 금지** — `_Lnnn` (라인 번호), hex suffix (`xxxXxxx5e0d`), prefix+파일명 (`dialogsettingsPageMessage`). PR 체크리스트 grep 검증 통과 필수
