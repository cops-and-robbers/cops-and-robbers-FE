### 📌 작업 개요

앱 빌드 트리거 워크플로(`PROJECT-FLUTTER-SUH-LAB-APP-BUILD-TRIGGER.yaml`)가 댓글 키워드만 보고 실행되던 것을 팀원 댓글에서만 실행되게 했다. 댓글에서 읽은 브랜치명을 스크립트 본문에 직접 끼워 넣던 다섯 곳은 스텝 `env`로 넘기게 바꿨다.

### 🎯 구현 목표

| # | 항목 | 수정 전 | 수정 후 |
|---|---|---|---|
| 1 | 실행 조건 | 댓글에 `@suh-lab` + 빌드 키워드만 있으면 실행 | 키워드 + 댓글 작성자가 `OWNER` / `MEMBER` / `COLLABORATOR` |
| 2 | 브랜치명 전달 | 스크립트 본문에 `${{ steps.source_info.outputs.branchName }}` | 스텝 `env: BRANCH_NAME`, 스크립트는 `process.env.BRANCH_NAME` / `$BRANCH_NAME` |

### ✅ 구현 내용

- `trigger-builds` 잡 `if`에 `contains(fromJSON('["OWNER","MEMBER","COLLABORATOR"]'), github.event.comment.author_association)` 추가.
- 브랜치명을 쓰는 스텝 다섯 곳: 브랜치 존재 확인, 브랜치 없음 에러 댓글, Android 트리거, iOS 트리거, 트리거 완료 로그.
- 브랜치명은 PR 머리 브랜치 이름이나 이슈의 "Guide by SUH-LAB" 댓글에서 읽는다. 둘 다 따옴표나 줄바꿈이 섞일 수 있는 입력이라, 스크립트 본문에 직접 들어가면 스크립트가 깨지거나 다른 코드가 실행될 수 있었다.

### 🧪 테스트 및 검증

- `actionlint`: 지적 0건.
- 스크립트 본문에 브랜치명을 직접 넣는 곳이 남지 않았는지 검색으로 확인했다(남은 5곳은 모두 `env` 값).
- 실제 댓글로 실행해 보지는 않았다. 머지 뒤 빌드 댓글을 한 번 달아 확인해야 한다.

### ⚠️ 주의사항

- 공개 저장소에서는 조직 소속을 비공개로 둔 사람이 `MEMBER`가 아니라 `CONTRIBUTOR`로 잡힐 수 있다. 그 사람의 빌드 댓글은 아무 안내 없이 무시된다. 최근 댓글 100건에서 이 저장소에 댓글을 단 팀원(EM-H20, INSANE-P)은 모두 `MEMBER`였다.
- 실패 안내 스텝 하나는 오류 메시지를 아직 스크립트 본문에 직접 넣는다. 고정 문구와 API 오류 문구라 사용자 입력은 아니어서 이번 범위에서 뺐다.
- 이 워크플로가 보내는 `repository_dispatch`(`build-android-app`, `build-ios-app`)를 받는 워크플로는 저장소에 없다(이슈 참고란). 이번에는 손대지 않았다.
