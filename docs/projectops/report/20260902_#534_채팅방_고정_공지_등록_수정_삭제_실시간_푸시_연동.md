### 📌 작업 개요
채팅방 상단에 방장이 고정해 두는 공지("고정 채팅") 기능을 신규 구현. 등록·수정·삭제 REST 4종 연동, 전용 STOMP 채널을 통한 실시간 반영, 대화창 시스템 메시지 노출까지 한 번에 붙였다. 기존 `community_chat_meeting_info_page.dart`(모임 정보 화면)는 삭제되고 `community_chat_notice_page.dart`(공지 화면)로 대체됐다.

### 🎯 구현 목표
- 서버 API v2.31.0에 추가된 채팅방 고정 공지 CRUD(`POST/PUT/GET/DELETE /api/community-posts/{postId}/chat/pin`) 연동
- 방마다 공지는 최대 1개, 재등록 시 이력 없이 교체되는 서버 정책(하드 삭제)에 맞춘 상태 모델링
- 전용 소켓 채널(`/subscribe/community/{postId}/chat/pin`)을 통한 실시간 갱신
- 방장 전용 등록/수정/삭제 UI, 멤버 전용 읽기 화면

- **이유**: 배너와 일반 메시지는 성격이 달라 서버가 채널을 분리했다(주석상 DEC-0055, BE #190). 실패해도 스트림은 유지(파싱 실패 시 로그만 남김).

#### 데이터 — Repository 구현
- **파일**: `lib/features/community/data/repositories/community_chat_repository_impl.dart`
- **변경 내용**:
  - `getNotice`/`registerNotice`/`updateNotice`/`deleteNotice` 구현, 각각 별도 `messageKey`로 에러 매핑(`errorCommunityChatNoticeLoadGeneric`, `errorCommunityChatNoticeSaveGeneric`, `errorCommunityChatNoticeDeleteGeneric`).
  - `_toNotice()`: 응답의 `id`가 없으면 `null` 반환(서버가 200 + 필드 null로 주는 "공지 없음"을 도메인 null로 접음).

  - `connect()` 스트림에 `_stomp.onPinChanged` 구독 추가 → `CommunityChatEvent.noticeChanged(postId)`로 변환해 전달.
- **이유**: 화면·Notifier는 REST/소켓 구분 없이 이 인터페이스만 본다.

#### Provider — 공지 상태 관리
- **파일**: `lib/features/community/presentation/providers/community_chat_notice_provider.dart` (신규)
- **변경 내용**: `@riverpod` `CommunityChatNotice`(family: `postId`, autoDispose). `build()`에서 소켓 이벤트 구독 시작 후 REST로 초기 조회. `register()`/`edit()`은 저장 응답을 그대로 상태로 반영(재조회 없음). `delete()`는 상태를 `null`로. `_onEvent()`에서 자기 방(`postId` 일치)의 `noticeChanged` 이벤트만 받아 `_refetch()` 수행. 재조회 실패는 예외를 삼키고 기존 상태를 유지(로그만 남김).
- **이유**: 다른 방의 공지 변경 이벤트까지 반응하면 화면과 무관한 요청이 늘어난다. 소켓 자체는 로그인 수명으로 별도 provider(`community_chat_socket_provider`)가 관리하며, 여기서는 이벤트만 청취.

### 🔧 주요 변경사항 상세

#### 공지 없음/있음 상태 표현
서버는 "공지 없음"을 404가 아닌 200 + 필드 전부 null로 응답한다. `CommunityChatRepositoryImpl._toNotice()`가 응답의 `id`가 없으면 도메인 `null`로 접어, 상위 계층(Provider·UI)은 HTTP 상태코드를 신경 쓰지 않고 `CommunityChatNoticeEntity?`만 다룬다.

#### 실시간 갱신 흐름
소켓의 `pinChannel` 프레임 → `CommunityChatStompDatasource._handlePin`이 `postId`만 파싱 → `Repository.connect()` 스트림에서 `CommunityChatEvent.noticeChanged(postId)`로 변환 → `CommunityChatNotice` provider가 자기 방 이벤트만 걸러 REST로 재조회. 방 목록/게임 상태를 관리하는 `community_chat_room_provider.dart`는 `CommunityChatNoticeChangedEvent`를 받아도 상태를 바꾸지 않는다(주석: "공지 변경은 공지 화면이 따로 듣는다").

**특이사항**:
- 공지 등록/수정 API 응답이 비정상적으로 빈 값(id null)이면 `_requireNotice()`가 예외를 던진다 — 방금 쓴 공지가 사라진 것처럼 보이는 상황을 막기 위한 방어 로직.
- `FORBIDDEN_NOT_CHAT_PIN_HOST`는 기존 멤버 강퇴의 `FORBIDDEN_NOT_CHAT_HOST`와 별도 코드다.

### 📌 참고사항
- `docs/api-docs.json` v2.31.0 변경 내역에 따르면 등록·수정·삭제는 항상 세 가지를 함께 트리거한다: (1) 실시간 웹소켓 반영, (2) 채팅 대화창 시스템 메시지, (3) 방 참여자 전원 FCM 푸시(입장·퇴장 안내와 달리 항상 발송). 이번 구현은 (1)과 (2)까지 확인했다.
- 본문 글자 수 제한(500자)은 UI(`maxLength`)에서 먼저 막고 있으나, 클라이언트-서버 값이 어긋나면 서버가 400을 반환한다(스키마 정본은 api-docs 기준).
