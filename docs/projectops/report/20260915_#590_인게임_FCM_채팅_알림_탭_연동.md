# 인게임 FCM 채팅 알림 탭 연동

### 📌 작업 개요
백엔드가 보내는 인게임 채팅 FCM의 `CHAT` payload를 앱 이동 이벤트로 변환하고, 알림을 탭하면
참가 중인 게임의 기존 채팅 패널을 전체 또는 팀 채널로 여는 흐름을 추가했다. 백그라운드 실행과 앱
종료 상태 모두 인증·활성 게임 복구를 거쳐 처리하며, 이미 열린 게임 화면은 재생성하지 않는다.

**보고서 파일**: `docs/report/20260915_#590_인게임_FCM_채팅_알림_탭_연동.md`

### 🎯 구현 목표
- `data{type: CHAT, gameId, scope}` payload 검증 및 이동 이벤트 변환
- 백그라운드 알림 탭과 앱 종료 상태의 알림 탭 모두 기존 게임 채팅으로 연결
- `ALL`은 전체 채팅, `TEAM`은 팀 채팅으로 정확히 전환
- 인증 절차와 활성 게임 복구 중에는 이동 의도를 보존
- 종료·퇴장·다른 게임 알림은 현재 화면을 유지하고 안내
- 연속 알림과 비동기 응답 경합에서도 최신 이동 의도만 적용

### ✅ 구현 내용

#### CHAT payload 모델링
- **파일**: `lib/core/services/fcm/push_navigation_event.dart`,
  `lib/core/services/fcm/push_navigation_event.freezed.dart`
- **변경 내용**: `GameChatPushEvent`를 추가하고 양수 `gameId`와 `ALL`·`TEAM` scope만 허용하도록
  `PushNavigationEvent.fromData`를 확장했다.
- **이유**: FCM 문자열 payload를 라우팅 전에 검증해 잘못된 알림이 게임 화면 이동으로 이어지지 않게 한다.

#### 앱 상태를 넘는 채팅 진입 의도 보관
- **파일**: `lib/core/services/fcm/push_navigation_service.dart`,
  `lib/main.dart`, `lib/features/auth/presentation/pages/splash_page.dart`
- **변경 내용**: `pendingGameChatPushProvider`가 인증·스플래시 처리 중인 채팅 진입 의도를 보관하고,
  참가 상태 검증을 마친 이벤트는 `openGameChatPushProvider`로 기존 채팅 패널에 전달한다. 살아 있는 앱의
  알림 탭 스트림은 `main.dart`에서 pending 상태로 넘기며, 콜드 스타트에서는 일반 게임 복구를 먼저
  마치도록 스플래시 목적지와 분리했다.
- **이유**: 스플래시 이동과 푸시 이동의 경합을 막고, 로그인·약관 동의·닉네임 설정이 끝나기 전에
  목적지가 소실되는 문제를 방지한다.

#### 참가 상태 검증 및 게임 화면 이동
- **파일**: `lib/features/game/presentation/widgets/game_chat_push_listener.dart`(신규)
- **변경 내용**: 인증 게이트를 통과한 뒤 내 활성 게임을 조회해 알림의 `gameId`와 진행 상태를 검증한다.
  유효하면 기존 `activeGameRoute`로 게임 화면을 열고 채팅 이벤트를 전달한다. 라우트·인증·새 알림이
  바뀌면 이전 HTTP 응답을 무효화해 늦게 끝난 요청이 최신 화면을 덮어쓰지 못하게 했다.
- **이유**: 종료되었거나 퇴장한 게임, 다른 게임의 오래된 알림으로 잘못 이동하는 것을 막는다.

#### 기존 채팅 패널 재사용
- **파일**: `lib/features/chat/presentation/widgets/chat_overlay.dart`
- **변경 내용**: 현재 게임과 일치하는 채팅 이벤트를 한 번 소비해 `ALL`은 전체 채팅, `TEAM`은 팀
  채팅을 선택하고 패널을 연다. 이미 게임 화면에 있으면 같은 `ChatOverlay` 상태를 유지한다.
- **이유**: 별도 채팅 화면이나 중복 게임 화면을 만들지 않고 기존 채팅 구독·입력 상태를 보존한다.

#### 오래된 알림 안내 및 다국어 처리
- **파일**: `lib/core/widgets/snackbars/app_snackbar.dart`, `lib/l10n/app_ko.arb`,
  `lib/l10n/app_en.arb`, `lib/l10n/app_ja.arb`, `lib/l10n/app_localizations.dart`,
  `lib/l10n/app_localizations_ko.dart`, `lib/l10n/app_localizations_en.dart`,
  `lib/l10n/app_localizations_ja.dart`
- **변경 내용**: 현재 게임에서 열 수 없는 채팅 알림 문구를 한국어·영어·일본어로 추가했다.
  앱 최상위 리스너에서도 기존 스낵바를 사용할 수 있도록 대상 `OverlayState`를 선택적으로 전달한다.
- **이유**: 유효하지 않은 알림을 조용히 버리지 않으면서 현재 화면과 공통 UI를 유지한다.

### 🔧 주요 변경사항 상세

#### warm·cold 공통 처리
- 앱이 살아 있을 때는 기존 `pushNavigationEventsProvider` 스트림을 재사용해 채팅 의도를 보관한다.
- 앱 종료 상태에서는 `getInitialMessage()`로 확보한 이벤트를 pending 상태의 초기값으로 사용한다.
- 스플래시와 인증 화면에서는 이벤트를 소비하지 않고, 정상 라우트에 도달한 뒤 활성 게임을 검증한다.

#### 중복 화면과 요청 경합 방지
- 같은 게임 화면에서는 라우팅하지 않고 기존 채팅 패널만 연다.
- 반복 알림도 소비 후 상태를 비워 다음 탭을 정상 처리한다.
- 요청 세대 값을 비교해 로그아웃·라우트 변경·후속 알림 뒤에 완료된 과거 응답을 무시한다.

**특이사항**:
- 서버 payload에 메시지 ID가 없으므로 앱에서 채팅 이력이나 미읽음 수를 별도로 생성하지 않는다.
  실제 채팅 상태는 기존 STOMP 흐름이 계속 담당한다.
- 서버의 발신자 제외, 게임 알림 허용 설정, 팀 범위 필터링 계약은 그대로 사용한다.
- 새 REST API나 외부 의존성은 추가하지 않았다.

### 🧪 테스트 및 검증
- `PushNavigationEvent.fromData` 테스트: `ALL`·`TEAM`, 잘못된 gameId·scope, 기존
  `COMMENT`·`REPLY` 회귀 포함
- `GameChatPushListener` 위젯 테스트: warm 진입, cold 인증 대기, 기존 패널 재사용, 오래된 게임 안내,
  연속 알림 응답 경합, 로그아웃·dispose 이후 응답 안전성 포함
- 관련 테스트 12건 통과
- `flutter analyze` 통과
- 전체 테스트 1,240건 통과, 커뮤니티 페이지의 기존 overflow 관련 6건 실패
- iOS 실기기에서 테스트 서버 연결 시 인게임 채팅 FCM 수신 확인

### 📌 참고사항
- 이전 iOS 미수신은 앱 알림 권한이나 이번 프론트 구현 문제가 아니라, 해당 백엔드 변경이 반영되지 않은
  프로덕션 서버에서 테스트한 환경 착오였다. 테스트 서버에서는 정상 수신한다.
- 프로덕션에서 같은 동작을 확인하려면 인게임 채팅 FCM 백엔드 변경이 배포된 뒤 다시 검증해야 한다.
