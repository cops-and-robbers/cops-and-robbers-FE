# App Store 심사 거부 대응 — 권한 요청 문구 현지화 불일치 해결 (#402)

### 📌 작업 개요
App Store 심사에서 Guideline 4 - Design 위반으로 거부됨. 거부 사유는 "권한 요청 문구가 앱 현지화 언어와 일치하지 않음"(영어 iPad 심사 환경에서 권한 다이얼로그가 한국어로 노출). iOS 권한 문구 현지화를 핵심으로 해결하고, 조사 과정에서 발견한 Android 포그라운드 서비스 알림 하드코딩과 소셜 로그인 버튼 비공식 문구도 함께 정리.

### 🔍 문제 분석

iOS는 개발자가 `Info.plist`에 작성한 권한 문구(`NS*UsageDescription`)를 시스템 권한 다이얼로그에 그대로 노출한다. 기존 구현은 이 4개 문구가 한국어로 하드코딩되어 있었고, `InfoPlist.strings`(Base/ko/ja)에는 앱 이름(`CFBundleDisplayName`)만 현지화되어 있을 뿐 권한 문구는 현지화 키가 없었다.

Xcode 설정상 `developmentRegion = en`, `knownRegions = (en, ko, ja, Base)`인데 root `Info.plist` 값이 한국어였기 때문에, 영어/일본어 기기에서 `Base → root Info.plist` 폴백 시 한국어 문구가 노출됐다. 이것이 심사 거부의 직접 원인이다.

### ✅ 구현 내용

#### iOS 권한 요청 문구 현지화
- **파일**: `ios/Runner/Info.plist`, `ios/Runner/Base.lproj/InfoPlist.strings`, `ios/Runner/ko.lproj/InfoPlist.strings`, `ios/Runner/ja.lproj/InfoPlist.strings`
- **변경 내용**: root `Info.plist`의 권한 문구 4종을 영어(개발 언어 base)로 변경하고, Base(영어)·ko(한국어)·ja(일본어) `InfoPlist.strings`에 동일 키를 현지화 추가
- **이유**: 기기 언어에 맞는 권한 문구가 노출되도록 locale별 override 구조 확립. 기존 `CFBundleDisplayName` 현지화 패턴(Base=영어 fallback)과 동일하게 통일

대상 키: `NSLocationWhenInUseUsageDescription`, `NSLocationAlwaysAndWhenInUseUsageDescription`, `NSCameraUsageDescription`, `NSUserNotificationsUsageDescription`

#### Android 포그라운드 서비스 알림 문구 현지화
- **파일**: `android/app/src/main/kotlin/com/elipair/copsandrobbers/GameSessionForegroundService.kt`, `android/app/src/main/res/values/strings.xml`, `values-ko/strings.xml`, `values-ja/strings.xml`
- **변경 내용**: 게임 진행 중 백그라운드 위치 추적 알림의 채널명·알림 제목/내용 하드코딩(한국어)을 제거하고 `fgs_*` string resource로 분리, `getString(R.string.fgs_*)` 참조로 변경
- **이유**: 영어/일본어 기기에서 상시 알림이 한국어로 노출되던 품질 이슈 해결. string resource화로 OS 언어 변경 시 자동 갱신

#### 소셜 로그인 버튼 문구 공식 가이드라인 준수
- **파일**: `lib/l10n/app_ko.arb`, `lib/l10n/app_ja.arb` (+ `gen-l10n` 재생성물 `app_localizations*.dart`)
- **변경 내용**: `buttonGoogleSignIn`·`buttonAppleSignIn`의 ko/ja 문구를 "시작하기/始める" → "계속하기/続ける"로 변경
- **이유**: Apple은 Sign in with Apple 버튼의 임의 번역을 금지하고 공식 현지화 어휘(로그인/계속하기/가입)만 허용. en이 이미 "Continue with..."이므로 Continue 계열로 통일

### 🔧 주요 변경사항 상세

#### iOS 권한 문구 현지화 구조
- root `Info.plist`: 권한 문구 한국어 → 영어 (개발 언어 base, 폴백 안전화)
- `Base.lproj/InfoPlist.strings`: 영어 권한 문구 4종 추가 (영어/미지원 로케일 fallback)
- `ko.lproj`/`ja.lproj/InfoPlist.strings`: 각 언어 권한 문구 4종 추가

로케일별 동작:
- 영어 기기 → Base.lproj(영어) + root Info.plist(영어) → 영어
- 한국어 기기 → ko.lproj → 한국어 (기존과 동일 문구)
- 일본어 기기 → ja.lproj → 일본어
- 기타 미지원 기기 → 영어 fallback (앱 UI 폴백과 일치)

**특이사항**:
- Android는 위치/카메라/알림 런타임 권한 다이얼로그 문구를 OS가 기기 언어로 자동 생성하므로, iOS와 같은 권한 문구 현지화 문제는 구조적으로 발생하지 않음. 매니페스트는 `<uses-permission>` 선언만 존재
- Android에서 발견된 한국어 하드코딩은 권한 요청이 아닌 "게임 진행 중" 포그라운드 서비스 알림으로, 심사 거부 항목과는 별개 범주

#### 소셜 로그인 버튼 가이드라인 검증
- **Apple**: 허용 동사는 Sign in / Sign up / Continue 3가지뿐이며 공식 현지화만 사용 가능. "시작하기"·"始める"는 비공식 어휘로 가이드라인 위반(잠재 심사 리스크)
- **Google**: "Google" 단어만 포함되면 자유 번역 허용·권장 → 기존 문구도 문제는 없었으나 일관성을 위해 함께 통일

최종 문구:
- en: `Continue with Google` / `Continue with Apple` (변경 없음, 공식)
- ko: `Google로 계속하기` / `Apple로 계속하기`
- ja: `Googleで続ける` / `Appleで続ける`

### 🧪 테스트 및 검증
- iOS: `plutil -lint`로 `Info.plist` 및 3개 `InfoPlist.strings` 문법 유효성 OK, 각 lproj 권한 키 4/4 존재, `project.pbxproj`의 `InfoPlist.strings` PBXVariantGroup(Base/ko/ja)이 Resources 빌드 단계에 포함됨 확인
- Android: `xmllint`로 3개 `strings.xml` 유효성 OK, 각 `fgs_*` 키 4/4, `.kt` 한국어 문자열 리터럴/`CHANNEL_NAME` 잔존 0
- 소셜 버튼: ARB 3종 JSON 유효, `flutter gen-l10n` 에러 없음, 생성물에 신규 문구 반영 및 구 문구(시작하기/始める) 완전 제거 확인
