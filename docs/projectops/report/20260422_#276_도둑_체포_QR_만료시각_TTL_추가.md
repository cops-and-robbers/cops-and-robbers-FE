### 📌 작업 개요

도둑 체포용 QR 페이로드에 만료시각(`exp`) 필드를 추가하여, 저장된 QR 스크린샷으로 체포 판정을 우회하는 리플레이 공격을 차단. 페이로드 생성·파싱·검증을 담당하는 공통 도메인 모델 `QrPayload`를 도입하여 도둑 측과 경찰 측이 동일한 포맷을 공유하도록 단일화. 백엔드 API 스펙은 변경하지 않고 프론트엔드 단독 구현. 코드 리뷰 피드백을 반영하여 파싱을 `int` 전용으로 엄격화하는 방어 강화도 포함.

### 🎯 구현 목표

- QR 페이로드에 Unix millisecond 기반 만료시각 포함 (TTL 30초)
- 경찰 스캔 시점에 만료 여부 판정 후 만료 QR 거부
- 인코딩/디코딩/만료 검증을 공통 유틸에 집중시켜 포맷 불일치 방지
- QR 스캐너 범용 위젯(`QrScannerPage<T>`)은 수정하지 않고 호출측에서 검증 처리
- 기존 "이미 체포된 도둑" 스낵바 처리와 동일한 패턴으로 UX 일관성 유지
- QR 입력값은 외부 입력이므로 타입 관대함을 제거하여 fractional 절삭을 방지

- **변경 내용**: `tryParse`에서 `pid is! num` / `exp is! num` 검증을 `is! int`로 변경. `pid.toInt()` / `exp.toInt()` 암묵적 변환 제거. 테스트에서 "num double 허용" 케이스를 삭제하고 fractional pid·exp 거부 케이스 2개 추가

### 🔧 주요 변경사항 상세

#### QrPayload 인터페이스

```dart
class QrPayload {
  final int participantId;
  final DateTime expiresAt;

  factory QrPayload.freshFor({
    required int participantId,
    required DateTime now,
    required Duration ttl,
  });
  static QrPayload? tryParse(String raw);
  String toRaw();
  bool isExpiredAt(DateTime now);
}
```

- `freshFor`: `now + ttl`을 `expiresAt`으로 설정. `now`를 파라미터로 받아 테스트에서 시각 주입 가능
- `tryParse`: JSON 디코드 실패, 최상위 Map 아님, `pid`/`exp` 누락, 타입 오류(문자열·fractional 포함) 모두 null 반환. **`int` 전용 엄격 검증**으로 fractional 절삭 공격 방지
- `isExpiredAt`: `!now.isBefore(expiresAt)` — `expiresAt`과 정확히 같은 시각도 만료로 판정 (경계 닫힘)
- `toRaw`: `{"pid": int, "exp": ms}` 포맷의 JSON 문자열 생성

**특이사항**:
- Freezed 대신 Plain Dart 클래스 선택. 필드 2개에 `copyWith`/JSON 직렬화 어노테이션이 불필요하여 오버엔지니어링 회피
- `now` 주입 설계 덕분에 테스트에서 `DateTime.now()` 모킹 불필요
- `tryParse`는 `int` 전용. `num`(double 포함) 허용하지 않음 — 외부 QR 입력의 방어적 검증

#### 경찰 스캔 플로우

```
카메라 스캔 → rawValue(String)
  → onParse = QrPayload.tryParse
     ├ 파싱 실패 → null → 스캐너가 계속 스캔
     └ 성공 → QrPayload → Navigator.pop(payload)

game_page 후처리
  ├ payload == null               → 취소로 간주, 종료
  ├ isExpiredAt(now) == true      → 만료 스낵바, 종료
  ├ 이미 체포된 pid                → 기존 스낵바, 종료
  └ 유효                           → arrestRobber(gameId, pid) 호출
```

**특이사항**:
- 만료 검증이 "이미 체포된 도둑" 체크보다 먼저 수행됨. 만료된 QR로는 어떤 상태 판단도 하지 않음 (스테일한 페이로드에 상태 정보를 드러내지 않기 위함)
- `QrScannerPage` 범용 스캐너는 무수정. `T? Function(String)` 콜백 시그니처에 `QrPayload.tryParse`가 그대로 대입됨

### 📌 참고사항

- **백엔드 무변경**: 체포 API는 기존대로 참가자 ID만 받음. `exp` 필드는 클라이언트 검증 전용이며 서버로 전송되지 않음
- **하위 호환 정책**: `exp` 없는 구버전 QR은 `tryParse`에서 null 반환되어 인식 불가. Remote Config 기반 최소 버전 강제 업데이트로 구버전 접근을 차단하는 전제로 설계됨
- **위협 모델 범위**: "저장된 QR 스크린샷 재사용" 차단이 주 목적. QR 위조(임의 `pid`로 가짜 QR 생성), 앱 디컴파일을 통한 검증 우회, 기기 시계 조작 등은 프론트 단독 구현으로 원천 차단 불가 (본 이슈 범위 외)
- **코드 리뷰 대응**: 자동 리뷰 도구가 지적한 "fractional pid/exp 암묵 절삭" 이슈는 `int` 전용 엄격화로 수용. 테스트 이름 규칙(`<subject>_<expected>_when_<condition>` 영문) 권고는 기존 한국어 서술형 관행과의 일관성을 우선하여 거부
- **향후 개선 여지**: 서버 측 QR freshness 직접 검증, 게임 세션별 공유 시크릿 기반 HMAC 서명 등은 별도 이슈로 분리 가능 (백엔드 지원 전제)
