### 📌 작업 개요
홈/커뮤니티/마이페이지 3탭 바텀 네비게이션을 `go_router`의 `StatefulShellRoute`로 추가. 이번 범위에서는 홈 탭만 실제 화면으로 연결하고, 커뮤니티·마이페이지는 준비중 placeholder로 처리.

### 🎯 구현 목표
- 하단 탭 네비게이션 골격 추가 (탭 4개 이상으로 늘어도 코드 구조 변경 없이 확장 가능하게)
- 각 탭이 독립적인 네비게이션 스택과 딥링크 진입점을 갖도록 구성
- i18n 적용 (ko/en/ja)

### ✅ 구현 내용

#### RoutePaths에 커뮤니티/마이페이지 경로 추가
- **파일**: `lib/router/route_paths.dart`
- **변경 내용**: `community`(`/community`), `mypage`(`/mypage`) 경로 상수와 `communityName`/`mypageName` 이름 상수 추가
- **이유**: 홈과 동일 레벨의 독립 탭 브랜치로 라우팅하기 위함

#### 바텀 네비게이션 i18n 문구 추가
- **파일**: `lib/l10n/app_ko.arb`, `app_en.arb`, `app_ja.arb`
- **변경 내용**: `bottomNavHome`, `bottomNavCommunity`, `bottomNavMyPage`, `comingSoonMessage` 키 추가
- **이유**: 탭 라벨과 준비중 안내 문구를 하드코딩하지 않고 다국어 지원

#### 확장 가능한 바텀 네비게이션 위젯
- **파일**: `lib/core/widgets/navigation/app_bottom_nav.dart`, `test/core/widgets/navigation/app_bottom_nav_test.dart`
- **변경 내용**: `BottomNavItem`(아이콘/라벨 데이터)과 `AppBottomNav`(리스트 기반 렌더링) 위젯 추가. 탭 개수는 `items` 리스트 길이에만 의존해 하드코딩된 분기가 없음
- **이유**: 향후 탭이 늘어나도 위젯 코드 변경 없이 항목만 추가하면 되도록 설계

#### 준비중 공용 화면
- **파일**: `lib/core/widgets/pages/placeholder_page.dart`, `lib/features/community/presentation/pages/community_page.dart`, `lib/features/mypage/presentation/pages/my_page.dart`
- **변경 내용**: 제목/메시지를 받는 공용 `PlaceholderPage`를 만들고, 커뮤니티·마이페이지가 이를 감싸는 얇은 래퍼로 구현
- **이유**: 두 탭 모두 현재 실제 기능이 없어 중복 없이 하나의 위젯을 재사용

#### 라우터 배선 (StatefulShellRoute)
- **파일**: `lib/router/main_scaffold.dart`, `lib/router/app_router.dart`
- **변경 내용**: 기존 `/home` GoRoute 트리(설정/공지사항/세션 생성 흐름 등)를 그대로 유지한 채 `StatefulShellRoute.indexedStack`으로 감싸고, 홈/커뮤니티/마이페이지 3개 브랜치로 구성. `MainScaffold`가 바텀 네비게이션 바와 함께 각 브랜치를 표시
- **이유**: 탭마다 독립적인 네비게이션 스택과 딥링크 진입점을 제공하기 위함

### 🔧 주요 변경사항 상세

#### 서브 라우트 풀스크린 처리
설정/공지사항/세션 생성 흐름 등 홈 브랜치 내부의 화면들은 `parentNavigatorKey: rootNavigatorKey`를 지정해 root navigator 위에서 풀스크린으로 뜨도록 처리. 지정하지 않으면 이 화면들도 `MainScaffold`의 body 안에서 렌더링되어 바텀 네비게이션 바가 계속 노출되는 문제가 있었음.

**특이사항**:
- `parentNavigatorKey`는 자식 라우트에 상속되지 않아, `settings`뿐 아니라 그 하위인 `credits`, `create-session`의 하위인 `playground`/`prison`까지 각각 개별적으로 지정해야 했음

#### 바텀 네비게이션 바 safe-area 처리
`AppBottomNav`를 `SafeArea(top: false, ...)`로 감싸 바의 고정 높이(92)는 그대로 유지하면서 시스템 하단 인셋(iPhone 홈 인디케이터, 안드로이드 제스처 네비게이션 영역)을 그 아래에 추가로 확보
