### 📌 작업 개요

커뮤니티 모집글 상세 화면 신규 구현. 목록(#475)에서 카드를 눌러 들어갈 화면이 생겼고, 게시글 단건 조회·수정·삭제·모집 상태 변경을 실서버에 연결했다.

작업 도중 백엔드 스웨거가 2.15.0 → 2.18.0으로 두 번 올라가 계약이 바뀌었다(커서 페이지네이션, 국가 조회 API 분리, 주소 3종). 노션 스펙 대신 갱신된 `api-docs.json`을 정본으로 삼아 맞췄다.

- 커밋 27개 / 파일 73개 / +11,584 −1,665
- 테스트 639개 통과, `flutter analyze` error·warning 0

---

### 🎯 구현 목표

- 모집글 상세 화면 구현 (지도·본문·액션·댓글)
- 작성자 본인 글의 수정·삭제·모집 상태 변경 연동
- 더보기 메뉴 3갈래 분기 — 내 글 / 남의 글 / 비로그인
- 목록·상세가 같은 메뉴 위젯을 쓰도록 공통화
- 화면 문구 다국어 처리 (ko/en/ja)

### ✅ 구현 내용

#### 상세 화면 신규

- **파일**: `lib/features/community/presentation/pages/community_detail_page.dart` (신규 688줄)
- **구성**: 상단 지도 미리보기 → 상태 배지·참여 인원·제목 → 장소·모임 일시 → 본문 → 좋아요·스크랩·공유 3분할 → 채팅 참여 버튼 → 댓글 목록·입력창
- **비로그인 열람 허용**(DEC-0014). 쓰기 동작만 로그인을 요구하고, 비로그인이 누르면 안내 후 로그인 화면으로 보낸다

#### 게시글 CRUD 실서버 연동

- **파일**: `community_remote_datasource.dart`, `community_repository_impl.dart`, `community_provider.dart`
- **연동**: `GET /{postId}`, `PUT /{postId}`, `DELETE /{postId}`, `PATCH /{postId}/status`
- 목데이터 스위치를 제거하고 게시글 CRUD는 전부 실서버로 전환. 좋아요·스크랩·댓글은 API가 없어 메모리 목을 유지하되, Repository 인터페이스 뒤에 두어 교체 시 화면 수정이 없도록 했다

#### 모집글 수정 화면

- **파일**: `community_create_page.dart` (작성/수정 겸용으로 확장)
- 서버 수정이 `PUT` **전체 교체**라 작성과 보낼 값이 완전히 같다. 화면을 따로 두면 한쪽만 고쳐지며 갈라지므로 작성 화면이 옵셔널 `post`를 받아 수정 모드로 열리게 했다
- 진입은 `/community/:postId/edit` 라우트. 목록 카드에서 고르면 상세를 먼저 깔고 그 위에 올려, 완료·취소 어느 쪽이든 닫았을 때 방금 보던 글이 나온다

#### 더보기 메뉴 공통화

- **파일**: `community_menu_button.dart`, `community_post_menu.dart` (신규)
- 목록 카드와 상세가 같은 표면을 쓰고, 보이는 항목만 호출부가 정한다. 판정 기준은 `writerId`와 로그인 사용자 id 비교 하나
- 목록 카드 메뉴도 실동작으로 연결. 제자리 동작(마감·삭제)은 그 카드만 갈아끼우거나 빼고, 화면을 떠나는 동작(수정)만 상세를 경유한다

#### 장소 표기·선택

- **파일**: `community_map_preview.dart`, `community_location_picker_page.dart` (신규)
- 좌표는 지도에서 찍고 "만나는 곳"은 작성자가 직접 입력(DEC-0015). 서버가 좌표를 역지오코딩해 동 단위 지역을 따로 저장한다
- 장소 행을 탭하면 **지번 주소**가 클립보드에 담긴다. 화면에 보이는 동 단위 라벨로는 지도 앱이 핀을 못 찍는다

#### 국가 조회 API 분리 대응

- 목록이 `countryCode`만 받도록 바뀌어(DEC-0021) `GET /country`를 진입당 1회 호출하도록 연결. 실패해도 예외를 던지지 않고 기기 로케일로 물러선다 — 국가 하나 못 알아냈다고 목록 전체가 에러 화면이 되면 안 된다

### 🔧 주요 변경사항 상세

#### 사라진 글 처리 (다른 사용자가 먼저 삭제한 경우)

상세를 보는 사이 작성자가 글을 지우면, 무엇을 눌러도 실패하는 유령 화면이 된다. 서버가 조회·수정·상태변경·삭제 **모든** 경로에 `404 POST_NOT_FOUND`를 주므로 이 신호 하나로 판정한다.

| 상황 | 동작 |
|---|---|
| 삭제된 글 상세 진입 | "다시 시도"(영원히 404) 대신 **목록으로 돌아가기** |
| 머무는 중 액션이 404 | 알리고 상세를 닫음. 딥링크로 돌아갈 곳이 없으면 재조회시켜 안내 화면으로 |
| 목록 카드 액션이 404 | 그 카드만 걷어냄 |

실시간 동기화는 하지 않는다. 커뮤니티에 STOMP 채널이 없고 모집글은 실시간 데이터가 아니다. **낡은 화면을 잠깐 보는 건 허용하되, 낡은 상태로 행동했을 때 갇히지 않는 것**을 보장하는 방향으로 잡았다.

#### 지도 플랫폼 뷰 크래시 수정

실기기에서 `hasSize` assert로 앱이 죽는 문제를 잡았다.

플랫폼 뷰(GoogleMap)는 전역 포인터 라우트를 걸어 두고 터치마다 자기 크기를 묻는다. 다른 화면이 이 화면을 완전히 덮으면 `Overlay`가 아래 화면을 레이아웃에서 빼는데, 그 상태에서 화면 아무 데나 누르면 터진다. iOS `RenderDarwinPlatformView` / Android `RenderAndroidView` 공통이다.

덮이는 동안 지도를 **트리에서 들어내는** 것으로 해결(offstage로는 조건이 그대로 남는다). 판정은 `isCurrent`가 아니라 `secondaryAnimation`을 본다 — 바텀시트·다이얼로그가 떠도 `isCurrent`는 false가 되지만 그때는 아래 화면이 그대로 레이아웃되므로 크래시 조건이 아니고, 거기서까지 들어내면 작성 화면에서 날짜·인원 시트를 여닫을 때마다 지도가 새로 뜬다.

**상세 화면에만 있던 문제가 아니다.** 작성 화면 위에 장소 선택, 상세 위에 전체화면 지도도 같은 조건이었다. 공용 위젯 한 곳에서 고쳤다.

#### 목록 API 호출 최적화

전체 → 우리동네 → 전체으로 토글할 때마다 목록을 다시 불렀다. 그때 딸려 나가는 건 목록 하나가 아니다 — 유일한 watcher가 사라지며 국가 조회 provider도 함께 폐기돼, 돌아올 때 **GPS 측정과 `/country`(Geoapify 일 3,000건 한도 공유)까지** 다시 탔다.

`CommunityFeedNotifier`를 스코프 family + `keepAlive`로 전환해 스코프마다 인스턴스가 따로 살고 각각 최초 1회만 조회하게 했다.

계량 Repository로 실제 화면에서 측정한 결과:

| 시나리오 | 목록 호출 | 국가 호출 |
|---|---|---|
| 진입 직후 | 1 | 1 |
| 토글 왕복 3회 후 | 1 | 1 |

캐시 규모도 함께 쟀다. 본문 1000자 상한 · 5페이지(100건) 최악 조건에서 **약 0.34 MB**로, 지도 SDK 인스턴스보다 훨씬 작다.

**특이사항**: `MINE` 스코프가 열리면 사용자별 목록이므로 로그인·로그아웃 시 무효화가 필요하다. 현재는 해당 스코프가 API를 타지 않아 주석으로만 남겼다.

#### 에러 문구 다국어 누락 수정

`errorCommunityPost{Create,Update,Delete,Status}Generic`·`errorCommunityAddressLoadGeneric` 5개 키가 ARB에는 있으나 `error_message_mapper`의 switch에 빠져 있었다. 그 경우 조용히 하드코딩 한국어로 폴백해 **en/ja 사용자에게 한국어가 그대로 노출**된다. 수정·마감·삭제가 정확히 이 경로라 함께 고치고, 같은 누락을 잡는 회귀 테스트를 넣었다.

#### 당겨서 새로고침

`CustomMaterialIndicator`로 Material 기본 동작(흰 원판이 위에서 내려왔다 올라가는 움직임)은 그대로 두고 안쪽 표시만 앱 색으로 교체. 당기는 동안 링이 진행도만큼 차고, 요청이 날아간 뒤에는 무한 회전한다.

응답이 즉시 와도 200ms는 돌린다. 캐시로 번쩍이고 사라지면 오히려 아무 일도 안 일어난 것처럼 보인다(`AppLoading.minVisibleDuration`과 같은 판단). 지연을 먼저 걸고 `finally`에서 기다려 **느린 요청에는 시간을 더 얹지 않는다.**

#### 댓글 입력 UX

답글 대상 안내 배너를 제거했다. 입력창 위 한 줄을 늘 차지해 정작 읽어야 할 댓글을 밀어냈고, 대상 강조는 목록 쪽 배경 하이라이트와 힌트 문구가 이미 보여 준다. 배너의 × 를 대신해 **본문 아무 곳이나 탭하면** 키보드가 내려가고 답글 모드가 풀린다.

### 🧪 테스트 및 검증

- 전체 **639개 통과**, `flutter analyze` error·warning 0, 문구 톤 검사 통과
- 신규 테스트 영역: 모집글 수정 모드, 사라진 글 처리, 목록 카드 메뉴, 지도 덮임 대응, 당겨서 새로고침, 무한 스크롤 회귀, 에러 키 매핑
- 목록 카드 메뉴 테스트는 실제 `GoRouter`를 세워 **목록 → 상세 → 수정** 스택 모양까지 확인한다

**검증 중 확인한 사실 두 가지** (문서와 코드가 어긋나 스파이크로 실측):

- GoRouter 17은 중첩 경로를 push해도 **부모 페이지를 스택에 만들지 않는다.** `/community/:id/edit`만 push하면 닫을 때 상세가 아니라 목록으로 튕긴다 → 목록에서 push를 두 번 명시적으로 한다
- 당겨서 새로고침 스피너는 최소 유지 없이 **320ms 언저리에 사라진다.** 처음 쓴 테스트가 하필 그 경계를 찍어 아무것도 고치지 않아도 통과했다

### 📌 참고사항

**백엔드 대기 중** — 열릴 때마다 하나씩 교체한다

- 좋아요·스크랩·댓글·참여 인원: 메모리 목 사용 중. Repository 인터페이스 뒤에 있어 구현체만 바꾸면 된다
- 게시글·댓글 신고 API: 현재 "준비 중" 안내
- 목록 `scope`·`sort`: `ALL`+`LATEST`만 동작. `NEARBY`·`MINE`·거리순·검색은 백엔드 로드맵 단계

**미확정**

- 채팅 참여하기: 게시글 단위 채팅인지 별도 채널인지 미확정. 와이어프레임 확정 후 연결
- 공유: 딥링크 경로 확정 후 연결

**운영 시 주의**

- 모임 장소가 정확 좌표로 저장·노출되며 흐리기 처리가 없다
- 운영자가 문제 글을 내릴 수단이 아직 없다 (어드민에 커뮤니티 API 미포함)
