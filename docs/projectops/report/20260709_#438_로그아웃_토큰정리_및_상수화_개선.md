### 📌 작업 개요

로그아웃 흐름의 잠재적 세션 부활 버그를 수정하고, Remote Config 파라미터 키·게임 팀 판정을 상수/공용 유틸로 통일했다. 세 갈래 개선 모두 "무증상으로 잠복하다 특정 조건에서 터지는" 신뢰성 결함을 겨냥한 정리 작업이다.

1. **로그아웃 토큰 정리 보장** — Firebase signOut이 실패해도 로컬 토큰이 항상 삭제되도록 수정 (세션 부활 방지)
2. **Remote Config 키 상수화** — 문자열 리터럴 산재를 상수 참조로 통일 (오타 시 무증상 버그 차단)
3. **게임 팀 판정 공용화** — raw `'POLICE'`/`'ROBBER'` 비교를 `GameTeam` 유틸로 교체 (대소문자 무관 처리)

---

### ✅ 구현 내용

#### 1. 로그아웃 토큰 정리 보장 — `AuthRepositoryImpl.signOut()` (수정)

- **파일**: `lib/features/auth/data/repositories/auth_repository_impl.dart`

**문제**: 기존 `signOut()`은 3단계(백엔드 로그아웃 → Firebase 로그아웃 → 로컬 토큰 삭제)를 순차 실행했다. 2단계 Firebase `signOut()`이 예외를 던지면 바깥 `try` 블록이 즉시 이탈해 **3단계 `clearTokens()`가 스킵**됐다. 결과적으로 로컬 SecureStorage에 access/refresh 토큰이 잔존하고, 앱 재시작 시 부팅 로직이 이 토큰으로 세션을 되살려 "로그아웃했는데 다시 로그인되어 있는" 상태가 발생할 수 있었다.

**수정**: Firebase `signOut()` 호출을 개별 `try-catch`로 감싸 실패해도 삼켜 로그만 남기고 다음 단계로 진행하게 했다. 이로써 3단계 `clearTokens()`는 Firebase 상태와 무관하게 **항상 실행**된다.

```dart
// 2. Firebase 로그아웃 (실패해도 로컬 정리는 계속 진행)
try {
  await _firebaseAuthDataSource.signOut();
} catch (e) {
  debugPrint('⚠️ Firebase 로그아웃 실패 (무시하고 계속 진행): $e');
}

// 3. 로컬 토큰 삭제 (항상 실행)
await _tokenStorage.clearTokens();
```

- 백엔드 로그아웃(1단계)은 이미 동일한 개별 try-catch 패턴을 갖고 있었고, 이번에 Firebase(2단계)도 같은 방어 패턴으로 통일했다.
- 로컬 토큰 삭제라는 "가장 중요한 정리"를 흐름의 마지막·무조건 실행 지점에 고정한 것이 핵심.

#### 2. 로그아웃 회귀 테스트 — `auth_repository_impl_signout_test.dart` (신규)

- **파일**: `test/features/auth/data/repositories/auth_repository_impl_signout_test.dart`
- Firebase `signOut()`이 예외를 던지는 상황을 재현하고, 두 가지를 검증한다:
  - `signOut()`이 예외 없이 정상 완료된다 (`completes`) — 성공 처리(스낵바 등)의 근거
  - 로컬 토큰 삭제(`clearTokens()`)가 반드시 호출된다 (`verify ... called(1)`) — 세션 부활 방지의 핵심 검증
- **모킹 범위**: 시스템 경계(Firebase SDK, SecureStorage 플랫폼 채널, 백엔드 API)만 mocktail로 모킹. 내부 협력 객체는 실제 사용. (테스트 룰 준수)
- 테스트명 `signOut_clearsTokens_when_firebaseSignOutThrows` — `<subject>_<expected>_when_<condition>` 규칙 준수.

#### 3. Remote Config 키·기본값 상수화 — `remote_config_keys.dart` (신규)

- **파일**: `lib/core/services/remote_config/remote_config_keys.dart`
- `RemoteConfigKeys`: 6개 파라미터 키를 상수로 정의
  - `minimum_version`, `latest_version`, `force_update`, `maintenance`, `maintenance_message`, `ads_enabled`
- `RemoteConfigDefaults.values`: fetch 실패 시 사용하는 fail-safe 기본값 맵. 모든 기본값이 "안전한 꺼짐"(점검 off / 강제업뎃 off / 광고 off)으로 설정되어, 서버 연결 실패 시에도 앱이 정상 진입하고 광고는 비활성 상태로 시작한다.

#### 4. Remote Config 서비스 상수 참조 통일 — `remote_config_service.dart` (수정)

- **파일**: `lib/core/services/remote_config/remote_config_service.dart`
- `setDefaults`에 인라인으로 작성돼 있던 기본값 맵을 `RemoteConfigDefaults.values` 단일 참조로 교체.
- 각 getter(`minimumVersion`, `forceUpdate`, `maintenance` 등)의 `getString(...)`/`getBool(...)` 인자 문자열 리터럴을 `RemoteConfigKeys.*` 상수 참조로 교체.
- **효과**: 키 문자열이 `setDefaults`와 getter 두 곳에 중복 정의돼 있으면, 한쪽만 오타가 나도 컴파일 에러 없이 조용히 기본값을 반환하는 무증상 버그가 생긴다. 단일 상수로 묶어 이 클래스의 오타 위험을 제거했다.

#### 5. 게임 팀 판정 공용 유틸 적용 — `game_event_provider.dart` (수정)

- **파일**: `lib/features/game/presentation/providers/game_event_provider.dart`
- `_handlePlayerLeft()`에서 서버 enum 팀 값(`'POLICE'`/`'ROBBER'`)을 raw 문자열로 직접 비교하던 로직을 `GameTeam.isPolice()` / `GameTeam.isRobber()`로 교체.
  - 알 수 없는 팀 값이 오면 경고 로그를 남기고 도둑 라벨로 폴백한다.
- **효과**: `lib/core/constants/game_team.dart`의 대소문자 무관 판정 유틸을 재사용해, 서버가 `'police'`처럼 다른 케이스로 내려주는 경우의 오분류를 방지하고 팀 판정 로직을 프로젝트 표준 한 곳으로 수렴시켰다.

### 📌 참고사항 / 영향 범위

- **로그아웃 흐름**: 정상 케이스 동작은 변경 없음. Firebase가 예외를 던지는 예외 케이스에서만 거동이 달라진다(토큰 삭제 보장). 백엔드 로그아웃 실패는 기존과 동일하게 무시하고 진행한다.
- **Remote Config**: 배경상 앱 시작 시 `splash_page`에서 fetch하여 버전 게이트·점검 모드·광고 킬스위치를 제어한다. 이번 변경은 키 문자열 관리만 상수화한 것으로, 서버에 등록해야 하는 파라미터 키 값 자체는 동일하다(Firebase 콘솔 설정 변경 불필요).
- **게임 이벤트**: `_handlePlayerLeft`의 팀 라벨 표시 로직만 영향. 팀 판정 결과가 라벨(경찰/도둑 i18n)로만 쓰이므로 상태·집계에는 파급 없음.
- 민감정보(토큰 값·시크릿) 노출 없음. 코드에 등장하는 것은 파라미터 키 상수명뿐이다.
