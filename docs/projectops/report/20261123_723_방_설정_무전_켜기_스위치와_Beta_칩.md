### 📌 작업 개요

방장이 방 설정에서 무전을 켜고 끈다. 기본값은 꺼짐이고, 켠 방에서만 경찰에게 무전 버튼이 보인다. 무전 카드에는 Beta 칩을 붙였다. 서버 쪽은 BE #261(`radioEnabled`, 꺼진 방 400 `RADIO_DISABLED_IN_GAME`)로 dev에 들어가 있다.

### 🎯 구현 목표

| # | 항목 | 수정 전 | 수정 후 |
|---|---|---|---|
| 1 | 무전 켜기 | 상수 `kRadioEnabledDefault = true`, 항상 켜짐 | 방 생성 확인 화면의 무전 카드, **기본 꺼짐** |
| 2 | 대기방 | 없음 | 방장이 게임 설정에서 변경, 참가자는 읽기 전용, 이벤트 게임은 숨김 |
| 3 | 베타 표시 | 없음 | 카드 제목 옆 Beta 칩 |
| 4 | 인게임 | 경찰이면 항상 무전 버튼 | 서버 값이 켜짐인 방의 경찰만 |
| 5 | 꺼진 방 토큰 거절 | 모르는 코드, 10초마다 재시도 | 무전 종료 코드로 처리 |

화면은 구현된 `RadioToggleCard`와 기존 카드들을 임시 진입점에 같은 배치로 띄워 iPhone 17 Pro 시뮬레이터에서 찍었다(대기방은 윗부분만).

### ✅ 구현 내용

- 설정 요청·응답·방 생성 초안에 `radioEnabled`(없으면 false). `PUT /settings`가 통째로 덮어쓰므로 설정 변경 요청은 모두 현재 무전 값을 싣는다(`toRequest`, `toEditRequest`).
- 대기방 진입과 `SETTINGS_UPDATED` 때 참가자 상태에 무전 값을 동기화하고, 재접속 때 `initFromLobby`로 복원한다.
- 인게임 `_hasRadio`는 서버 값으로 판단한다. `kRadioEnabledDefault` 삭제.
- `RADIO_DISABLED_IN_GAME`은 무전 종료 코드와 에러 매핑에 추가("이 방은 무전을 쓰지 않아요").
- `SettingSwitchCard`를 뽑아 `ShrinkToggleCard`와 새 `RadioToggleCard`가 같이 쓴다. 문구 `radioCardDesc`("버튼을 길게 누르는 동안 말해요", 튜토리얼과 같은 문구), `radioBetaChip`("Beta").

### 🧪 테스트 및 검증

- 새 테스트 4파일(설정 모델, 로비 동기화, 재접속 복원, 카드)과 기존 테스트 보강. 전체 `flutter test` 통과, `flutter analyze` 지적 0건.
- 개발 서버 API 문서(v4.4.0, BE #261 배포분)와 대조: 방 생성 `settings.radioEnabled`, 설정 변경 요청·응답, 방 정보 응답, 토큰 400 `RADIO_DISABLED_IN_GAME`의 이름·위치·타입이 앱 코드와 일치.
- #722와 합친 상태에서 최신 API 문서로 전체 테스트 2132개 통과.
- 실제 로그인한 앱으로 방을 만들어 확인하지는 못했다(소셜 로그인만 있어 자동화 불가).

### ⚠️ 주의사항

- **BE #261이 운영에 나가기 전에 이 앱을 출시하면 안 된다.** 응답에 값이 없으면 꺼짐으로 읽어 모든 방에서 무전이 사라진다.
- #722를 먼저 머지한 뒤 이 브랜치를 맞춰야 한다(`error_message_mapper_test.dart` 충돌 1곳, 둘 다 남기면 됨).
- 대기방 소켓이 끊긴 사이 바뀐 값, 무전 끈 방의 튜토리얼 무전 장면은 정하지 않았다.
