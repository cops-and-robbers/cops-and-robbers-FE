### 📌 작업 개요

이슈 #384에 대응하여 세 가지 영역을 개선했다.

1. **토큰 재발급 엣지 케이스 분기 보강 및 관측성 추가** — 일시 장애와 명시 거부를 구분하여 강제 로그아웃 오작동 방지
2. **게임 종료 처리 보강 및 라이트모드 UI 일관성 확보** — GameOver 시 채팅 소켓 정리 누락 및 라이트모드 컬러 누락 수정
3. **i18n 키 의미 기반 정리 및 미사용 JSON 자산 제거** — hex suffix 키를 의미 기반 키로 교체, 사용하지 않는 JSON 자산/문서 정리

---

### 🔍 문제 분석

#### 1. 토큰 재발급 로직의 엣지 케이스 오작동
기존 `AuthInterceptor`는 `/api/auth/reissue` 호출 중 발생하는 **모든 예외**를 catch하여 강제 로그아웃 처리했다. 이로 인해 다음 시나리오에서 사용자가 의도치 않게 로그아웃됐다.

- 일시적 네트워크 단절 / 타임아웃
- 서버 일시 장애 (5xx)
- DNS 실패 등 connection error

refresh token이 실제로 거부된 것이 아닌데도 토큰을 삭제하여 재로그인을 강요하는 UX 이슈가 있었다.

#### 2. GameOver 후 잔여 소켓 연결
GameOver 모달이 표시된 상태에서 앱을 백그라운드 → 포그라운드로 전환하면 `didChangeAppLifecycleState`의 resume 핸들러가 동작하여 종료된 채팅 소켓을 다시 연결하려 시도했다. 또한 게임 종료 시 `gameEventNotifier`는 disconnect하지만 `chatNotifier`의 명시적 disconnect가 누락되어 있었다.

#### 3. 라이트모드 UI 색상 누락
`MyLocationButton`을 비롯한 인게임 액션 버튼들이 `isDarkMode` prop을 받지 않아 라이트모드(경찰 팀)에서 다크모드용 색상이 적용되거나 색상이 누락되는 문제가 있었다.

#### 4. 의미 없는 hex suffix i18n 키
`asset_loading_joinRoom477c`, `asset_loading_createRoomF1fe` 같은 hex suffix 키는 자동 변환 산물이라 의미 파악이 어려웠고, 카테고리별로 동일한 이스터에그 메시지가 중복 정의되어 있었다.

### ✅ 구현 내용

#### 토큰 재발급 강제 로그아웃 분기 보강
- **파일**: `lib/core/network/auth_interceptor.dart`
- **변경 내용**:
  - reissue 실패를 **명시 거부**(400/401/403)와 **일시 장애**(5xx/타임아웃/네트워크)로 분리
  - 명시 거부만 강제 로그아웃, 일시 장애는 토큰을 유지하고 원요청에만 실패 전달
  - refresh token이 빈 문자열인 경우 강제 로그아웃 처리 (기존엔 null만 체크)
  - 200 응답이지만 tokens 파싱 실패(누락/타입 불일치/빈 문자열)도 강제 로그아웃 처리
  - `_parseTokens`, `_logReissueFailure`, `_logTransientReissueFailure`, `_isRefreshTokenRejected`, `_shouldForceLogoutForReissueStatus` 헬퍼 분리
- **이유**: 사용자가 일시 장애로 인해 의도치 않게 재로그인하는 UX 이슈 차단

#### 재발급 일시 실패 관측성 추가
- **파일**: `lib/core/network/auth_interceptor.dart`
- **변경 내용**: `dart:developer`의 `developer.log`를 사용하여 일시 실패 시 다음 정보 기록
  - originalPath: 원래 호출하려던 API 경로
  - reissueStatus: reissue HTTP 상태 코드
  - reissueType: DioException 타입 (timeout / connectionError 등)
  - 에러 스택 트레이스
- **이유**: 릴리즈 빌드에서도 일시 실패 패턴을 추적하여 백엔드 안정성 모니터링 가능

### 🔧 주요 변경사항 상세

#### `AuthInterceptor` 분기 전략

reissue 실패 시 다음 분기로 처리한다.

```
[reissue 호출]
    ↓
  실패?
    ├─ DioException + statusCode ∈ {400, 401, 403}
    │     → refresh token 명시 거부 → 강제 로그아웃
    │
    ├─ DioException + statusCode ∈ {5xx, null} (네트워크/타임아웃 포함)
    │     → 일시 장애 → 토큰 유지, 원요청만 실패 전달
    │     → developer.log로 관측 정보 기록
    │
    └─ 200 응답 but tokens 파싱 실패
          → 강제 로그아웃 (서버 응답 스펙 위반)
```

**특이사항**:
- 현재 reissue API spec은 400/401/500만 정의하지만, 403도 명시 거부로 해석 가능한 방어 분기로 포함시켰다 (주석에 명시)
- 일시 실패 시 원요청 에러로 변환 시 `_asOriginalRequestError`로 새 `DioException` 생성 — 원본 RequestOptions를 보존하여 호출자가 정확한 에러 컨텍스트를 받도록 함

#### `_parseTokens` 헬퍼

응답 body의 tokens 객체가 다음 조건을 모두 만족할 때만 유효 토큰으로 인정한다.

- `data` is Map
- `data['tokens']` is Map
- `accessToken`, `refreshToken` 모두 String
- 양쪽 모두 trim 후 빈 문자열이 아님

조건 하나라도 위반되면 null 반환 → 호출자가 강제 로그아웃 처리

#### i18n 키 네이밍 컨벤션

이번 정리로 다음 패턴이 확립됐다.

- 카테고리별 고유 메시지: `<category><MeaningfulName>` (예: `joinRoomCheckDisguise`)
- 카테고리 무관 공통 메시지: `easterEgg<Topic><Action>` (예: `easterEggCharacterRumor`)
- 더 이상 hex suffix 키를 새로 생성하지 않음
