### 📌 작업 개요

앱의 법적 문서 4종(이용약관 · 개인정보 처리방침 · 위치정보 이용약관 · 마케팅 수신 동의) 본문을 앱 번들 JSON 대신 공식 사이트에서 웹뷰로 가져오도록 전환했다.

같은 문서가 앱 `assets/legals` 와 웹 두 곳에 있었고 사람이 손으로 맞추는 구조였다. 한쪽만 고치면 조용히 어긋나는데 법적 문서라 위험하다. 일본 출시 이후에는 일본 사용자가 한국어 약관을 보고 있었고, 문구 하나 고치려면 앱 배포와 심사를 다시 받아야 했다. 약관은 시행일 전에 공지해야 하는 문서라 심사 기간이 그대로 위험이 된다.

웹을 정본으로 삼는 작업이 웹 레포에서 끝나(dongsim-web #47, #49) 언어별 주소 12개가 프로덕션에 올라가 있는 상태에서 진행했다.

- 커밋 4개 / 파일 23개 / +362 −1,993
- `flutter analyze` 에러 · 경고 0, 테스트 703개 통과

### 🎯 구현 목표

- 문서 본문을 웹뷰로 전환하되 화면이 바뀐 티가 나지 않게 한다
- 로케일에 따라 ko / ja / en 문서를 연다
- 문서와 주소가 어긋날 수 없는 구조로 만든다
- 앱 번들에서 문서와 Google Sites 링크를 걷어낸다

- **이유**: 예전에는 호출부가 JSON 경로와 외부 링크 주소를 따로 넘겨서, 짝이 어긋나도 아무도 못 잡았다. A 약관을 보면서 B 링크를 누르는 사고가 가능한 구조였다

#### 본문을 웹뷰로 교체

- **파일**: `lib/core/widgets/pages/legal_document_page.dart`
- **변경 내용**: JSON 파싱과 섹션 렌더링 코드를 걷어내고 `WebViewWidget` 으로 대체. 앱바는 Flutter 가 그대로 그린다
- **이유**: 웹 화면이 이 페이지의 렌더 방식을 그대로 재현해 두어서(색 · 타이포 · 여백 · 기기 폭 배율) 앱바까지 합치면 예전 화면과 구분되지 않는다. 오히려 텍스트 선택과 확대가 되는 만큼 나아졌다

- **변경 내용**: `externalUrl` 파라미터와 앱바 링크 아이콘 삭제
- **이유**: 웹뷰에 떠 있는 것이 이미 원본이라 같은 문서를 두 번 여는 버튼이 된다. 남기면 문서마다 주소를 두 벌(`/ja/terms` 와 `/ja/legal/terms/embed`) 관리해야 한다

### 🔧 주요 변경사항 상세

#### 자바스크립트 비활성화

웹 쪽을 Route Handler 로 만들어 문서 HTML 에 스크립트가 한 줄도 없다. `JavaScriptMode.disabled` 로 두어 법적 문서 뷰어에 실행 권한을 주지 않는다.

#### 실패 판정 두 가지

`onHttpError` 는 하위 리소스에도 온다. `WebResourceRequest` 에 프레임 정보가 없어서 실패한 주소가 문서 자체인지로 갈랐다. 폰트 하나가 404 나는 것으로 약관 전체를 못 읽게 만들면 안 된다.

같은 호스트 밖으로 나가는 이동은 막는데, 막기만 하면 공용 와이파이 로그인 페이지로 가로채였을 때 스피너가 영원히 돈다. 막을 때 실패 처리도 함께 한다.

#### 로케일 변경 대응

앱 안에서 언어를 바꾸면 앱 전체가 다시 그려지면서 `didChangeDependencies` 가 다시 불린다. 그때 주소가 달라지므로 같은 화면에서 다시 불러온다. 이 시점에 `setState` 를 부르면 빌드 도중 `markNeedsBuild` 가 되므로 필드만 바꾸고 뒤이어 오는 build 에 맡긴다.

#### 불러오기 실패 화면 공용화

- **파일**: `lib/core/widgets/load_failure_view.dart` (신규)
- 약관 설정 화면에 아이콘 + 사유 + 다시 시도 조합이 이미 있어서 하나로 모았다. `EmptyState` 도 검토했으나 버튼이 없어 맞지 않았다

**특이사항**

- `webview_flutter` 는 이미 transitive 의존성으로 들어와 있어 직접 의존성으로 승격만 했다. 실제 증가분은 없다
- 버전은 4.13 대를 유지했다. 4.14 는 Flutter 3.38 이상을 요구해 `pubspec.lock` 의 SDK 하한을 끌어올리는데, 우리가 쓰는 API(JS 비활성화, `NavigationDelegate`, `onHttpError`)는 4.13 에 모두 있다. 그 결과 lock 변경은 `dependency: transitive` → `direct main` 한 줄이다
- lock 의 `meta`, `test_api` 패치 버전 변경은 이번 작업과 무관하다. 의존성을 건드리지 않고 `flutter pub get` 만 돌려도 같은 결과가 나온다
- 안드로이드 핀치 줌은 `webview_flutter_android` 가 기본으로 `setBuiltInZoomControls(true)`, `setDisplayZoomControls(false)` 를 켜주어 추가 설정이 필요 없다
- 로그인 · 가입 동의 화면은 셸 밖 라우트라 바텀 네비가 없다. 루트 네비게이터 처리를 하지 않았다

### 📎 이번 범위에서 제외

**오프라인 열람** — 실시간 세션이라 네트워크가 없으면 게임 자체가 돌아가지 않고, 가입 동의 화면도 로그인 API 를 탄다. 낡은 번들을 폴백으로 남기면 약관을 개정했을 때 시행일이 지난 옛 약관을 현재 약관으로 보여주게 되어 빈 화면보다 위험하다.

**기기 파일 캐시** — 두 번째부터 빨라지는 것은 웹뷰 기본 캐시가 해결하고, 폰트는 재검증 없이 캐시되도록 웹에서 처리했다(dongsim-web #49). 파일 캐시의 순이득은 오프라인 하나인데 그것을 받지 않기로 했다.

**약관 버전 추적** — 지금은 동의 여부와 시각 하나만 저장하는데 문서별 시행일이 서로 다르다. 위치정보 약관만 개정해도 누가 구버전 동의자인지 가릴 수 없다. 백엔드 변경이 필요하다.

**마이페이지 나머지 화면** — 언어 설정과 크레딧은 여전히 탭 스택에 남는다. 마이페이지 안에서 약관만 다르게 동작하는 상태다.

**스토어 콘솔 주소** — App Store Connect 와 Play Console 의 개인정보처리방침 주소도 바꿔야 Google Sites 를 완전히 접을 수 있다. 코드 밖 작업이라 배포 전에 따로 처리해야 한다.
