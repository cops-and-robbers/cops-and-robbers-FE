# ⚙️ [기능추가][커뮤니티] 모집글 목록 정렬·검색 추가 및 변경된 API 연동

### 📌 작업 개요

백엔드 명세가 `v2.18.0 → v2.21.0`으로 오르며 생긴 계약 변경을 앱에 반영했다. 채팅 엔드포인트 4종은 별도 작업이라 제외하고 셋을 다뤘다 — 모임 종료(`ENDED`) 상태, 목록 정렬·키워드 검색 개방, 복사용 지번 주소.

이 중 `ENDED`는 **앱이 모르는 값이라 그 글이 목록에 하나만 섞여도 목록 한 장이 통째로 에러 화면**이 되던 상태였다. 백엔드는 이미 dev에 머지돼 있었다.

---

### 🎯 구현 목표

- 종료 상태를 연동하고, 앱이 모르는 상태값이 와도 화면이 깨지지 않게 한다
- 정렬 3종(최신·마감 임박·거리순)을 서버에 실제로 연결한다 — 그전까지 시트를 눌러도 라벨만 바뀌었다
- 모집글 검색 화면을 신설한다
- 서버가 새로 요구하는 계약(허용 파라미터 8개, 거리순 한정 좌표, 커서 봉인, 검색어 2자)을 앱이 어길 수 없게 만든다

### 🔧 주요 변경사항 상세

#### 커서 계약을 코드가 아니라 구조로 지킨다

정렬·검색어·스코프가 바뀌면 family 키가 바뀌고, 새 인스턴스는 `cursor: null`로 시작한다. "조건이 바뀌면 첫 페이지부터"를 강제하는 코드가 따로 없고, **커서 불일치 400이 발생할 수 있는 코드 경로 자체가 존재하지 않는다.**

검토했다가 버린 대안 둘 — 정렬을 Notifier 내부 상태로 두는 안(진실 소스가 둘이 되고 정렬 왕복 캐시를 잃는다), 검색 전용 Notifier를 따로 두는 안(`loadMore`·`replacePost`·`removePost`가 통째로 복제된다).

#### 거리순 좌표의 수명

첫 페이지에서 한 번 구해 `CommunityFeedState`에 담고 `loadMore`가 재사용한다. 페이지를 넘길 때마다 GPS를 켜지 않기 위해서고, 서버가 커서에 좌표를 일부러 담지 않아(사용자가 이동해도 커서가 막히지 않게) 같은 값을 계속 써도 계약에 어긋나지 않는다. 이동 반영은 당겨서 새로고침이 담당한다.

**특이사항**: 좌표를 못 구하면 최신순으로 물러서는데, 이때 라벨도 함께 "최신순"으로 바뀐다. 라벨만 "거리순"으로 두면 에러 없이 틀린 화면이 된다.

#### 검색어 검증과 전송의 분리

검증은 서버와 같은 규칙(공백을 전부 제거한 뒤 2자 이상)으로 앱이 흉내 내 확정 400을 왕복시키지 않는다. 다만 **서버에는 앞뒤 공백만 정리한 원문**을 보낸다 — 나머지 정규화와 커서에 봉인되는 검색어 해시는 서버가 만든다.

#### 상태 배지 매핑은 두 곳에 그대로 뒀다

카드와 상세 두 곳에 같은 3분기가 있다. 사용처가 둘뿐이고 공유되는 양이 라벨·색 10줄 남짓이라, 위젯으로 빼면 파라미터 배관 비용이 절감을 넘어선다. 양쪽에 "세 번째 사용처가 생기면 추출한다"는 재검토 트리거를 주석으로 남겼다 — 이후 DRY 정리에서 이 중복이 "정리 안 된 것"으로 오해받지 않게 하기 위함이다.

반면 무한 스크롤 목록은 같은 2곳이지만 스크롤 리스너·임계값·중복 요청 가드·에러 스낵바·새로고침·카드 메뉴가 묶여 400줄에 가까워 추출했다. 판단 기준이 "사용처 수"만이 아니라 "공유량의 두께"와 함께여서 결론이 갈렸다.

#### 실행 중 잡은 결함들

리뷰 과정에서 다음이 드러나 함께 고쳤다.

| 결함 | 증상 |
|---|---|
| `loadMore`가 폴백 정렬을 안 따라감 | 거리순인데 좌표가 없으면 1페이지는 최신순으로 조회되는데 2페이지가 거리순으로 나가 **확정 400** |
| `keepAlive` 전환이 국가 조회 수명을 깸 | 글 작성·수정·삭제 때마다 국가 판별 provider가 함께 폐기돼 GPS 재측정과 벤더 호출이 반복됨(실측 `resolveCount` 1→2) |
| 거리순 선택 시 **매번** 국가 재판정 | `ensurePermission()`이 이미 권한이 있으면 그대로 통과하는데 이를 "새로 얻음"으로 취급. 권한 전이일 때만 무효화하도록 수정 |
| 정렬 시트 높이 미조정 | 인기순을 뺐는데 높이가 4항목 기준이라 사공간이 남음 |

**특이사항**: 정렬 시트 높이는 구성 요소로 계산한 값(241)이 실제 렌더링과 약 30px 어긋나 `RenderFlex` 오버플로가 났다. 위젯 테스트로 하한(265)을 실측해 270으로 잡았다. 여유가 5뿐이라 실기기 폰트 렌더링에 따라 빠듯할 수 있고, 어긋남의 근본 원인은 추적하지 못했다.

### 📌 참고사항

**후속 과제로 남긴 것**

- **목록 캐시에 유효 시간이 없다.** 화면을 나갔다 돌아와도 재조회하지 않아, 게임을 하고 돌아오거나 몇 시간이 지나도 처음 받아온 목록 그대로다. 당겨서 새로고침·글 작성·앱 재시작 외에는 갱신 경로가 없다. 별도 이슈로 분리
- 검색 결과 렌더링, 최근 검색어 삭제 경로, 라우트 충돌(`/community/search`가 `postId`로 잡히지 않는지) 테스트
- `LocationPermissionService`가 "GPS 서비스 꺼짐"과 "권한 거부"를 같은 값으로 뭉쳐, 권한은 있고 GPS만 꺼진 경우 문구가 부정확하다
- 최근 검색어가 하나도 없을 때 빈 화면 — 디자인된 빈 상태가 필요하다

**서버가 아직 열지 않은 것**

- `scope`의 `NEARBY`·`MINE`, `sort`의 `POPULAR`. 앱은 토글·시트에서 노출을 막아 두었고 enum과 와이어 매핑은 남겨 뒀다. 서버가 열리면 노출 한 줄만 되돌리면 된다
- `MINE`이 열리면 사용자별 목록이므로 로그인·로그아웃 시 무효화가 함께 필요하다

**별도 이슈로 분리한 것**

- 로그인 요청의 `Accept-Language` 헤더 — 현재 앱이 이 헤더를 보내지 않아 신규 회원 닉네임이 언어와 무관하게 한국어로 발급된다. 인증·다국어 영역이라 커뮤니티와 분리
