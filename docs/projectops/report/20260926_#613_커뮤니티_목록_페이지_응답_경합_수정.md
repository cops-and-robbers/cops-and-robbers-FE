# 커뮤니티 목록 페이지 응답 경합 수정 (#613)

### 📌 작업 개요
게시글 목록에서 추가 로딩 중 글 상태를 바꾸면 다음 페이지가 사라지고 로딩 표시가 멈추던 문제를 수정했다. 알림함에서는 새로고침 후 도착한 이전 페이지 응답이 새 목록과 커서를 오염시켜 알림 일부가 누락되던 문제를 수정했다.

### 🔍 문제 분석
- 게시글 목록은 페이지 요청 당시의 상태 객체와 응답 시점의 객체가 같은지 검사했다. 글 하나를 수정하거나 삭제해도 객체가 바뀌므로 유효한 페이지 응답까지 버리고 `isLoadingMore`를 해제하지 않았다.
- 알림함은 새로고침이 목록을 교체한 뒤에도 이전 커서로 요청한 페이지를 새 목록에 덧붙였다. 중간 알림이 빠지고 `hasMore`가 잘못 종료될 수 있었다.

### ✅ 구현 내용
- `lib/features/community/presentation/providers/community_provider.dart`: 목록 세대를 추가해 새로고침·폐기 때만 이전 페이지 응답을 무효화한다. 같은 목록에서 발생한 글 수정·삭제는 유지하면서, 페이지 성공 시 최신 목록에 결과를 붙이고 실패 시 로딩 상태를 해제한다. 새 첫 페이지가 로딩 중일 때 추가 로딩을 시작하지 않는다.
- `lib/features/community/presentation/providers/community_notification_provider.dart`: 새로고침 성공 시 목록 세대를 바꿔 이전 페이지 응답을 버린다. 새로고침 실패 시에는 기존 페이지 요청을 계속 받아들인다. 겹친 새로고침은 마지막 요청의 결과만 반영하고, 폐기된 상태에는 응답을 적용하지 않는다.
- `test/features/community/presentation/providers/community_pagination_race_test.dart`: HTTP 응답 순서를 제어하는 회귀 테스트 18건을 추가했다. 수정·삭제와 페이지 성공/실패, 새로고침과 이전 페이지 응답 순서, 재시도, 겹친 새로고침, 폐기 후 응답을 확인한다.

### 🧪 테스트 및 검증
- 새 회귀 테스트 18건 통과. 실제 화면 조작과 provider·repository·JSON 파싱을 거치는 재현 4건도 통과했다. 게시글 경합에서 40건을 표시하고 로딩이 종료되며, 알림 경합에서 새 첫 페이지의 커서로 이어서 누락된 알림을 복구할 수 있음을 확인했다.
- 변경한 앱·테스트 파일의 정적 분석 통과.
- 전체 `flutter test`: **1,352건 통과 / 6건 실패**. 실패 6건은 정렬 시트의 `RenderFlex` 하단 넘침으로, 변경 전 실행에서도 동일하게 6건 실패했다.
- 전체 `flutter analyze`: 문서 예제 `docs/superpowers/sdd/task-4-test-fix.dart`에서 **기존 진단 11건**. 변경 전에도 같은 11건이 있었다.

### 📌 참고사항
실서버·실기기에서 두 경합이 발생하는 빈도는 측정하지 않았다. 검증은 응답 순서를 제어한 테스트로 수행했다.
