### 📌 작업 개요

수감된 도둑이 "탈옥 완료" 버튼을 직접 눌러야 탈옥이 처리되던 기존 방식을 폐기하고, 도둑이 감옥 영역에 한 번 들어왔다가 다시 벗어나는 순간을 GPS로 감지하여 자동으로 탈옥 API를 호출하는 시스템으로 전환. 부정행위/조작 여지를 차단하고 "감옥에 갇혔다가 직접 빠져나온다"는 게임 룰을 강제한다. API 실패 시에만 기존 수동 버튼이 폴백으로 노출된다.

### 🎯 구현 목표

- 기존 플레이그라운드 이탈 감지 패턴을 감옥 영역에도 동일하게 응용
- 체포 사이클 단위로 "감옥 첫 진입" 이력을 추적하여 의도된 탈옥만 인정
- 자동 탈옥 발동에 7개 가드 적용 (게임 종료, 재연결 모달, 이미 탈옥, API 진행 중, 게임 영역 미로드 등)
- API 실패 시 사용자가 수동 탈출 가능한 안전망(폴백 모드) 유지
- GPS 정확도(5~15m) 진동을 흡수하기 위한 히스테리시스 적용

### ✅ 구현 내용

#### 신규 도메인 로직 — 감옥 진입/이탈 판정

- **파일**: `lib/features/game/domain/jail_zone_check.dart` (신규)
- **변경 내용**: `JailZoneCheck` 클래스에 `computeIsOutside`, `evaluateTransition` 두 개의 순수 함수 추가. `JailZoneTransition` enum(`entered`/`exited`/`none`)으로 전환 종류 표현. 히스테리시스 buffer 기본값 10m 상수화
- **이유**: GPS 의존성 없는 순수 함수로 분리하여 단위 테스트 가능. `radius`와 `radius + buffer` 사이 band에서는 직전 상태 유지하여 경계선 진동(out↔in 반복)을 흡수

#### 체포 잠금 오버레이 — 자동/폴백 모드 분기

- **파일**: `lib/features/game/presentation/widgets/arrest_lock_overlay.dart`
- **변경 내용**: `showManualFallback` 파라미터 추가 (기본값 `false`). 평시엔 "감옥 영역에 들어갔다가 다시 벗어나면 자동으로 탈옥됩니다" 안내 문구만 표시, 폴백 모드에서만 기존 "탈옥 완료" 버튼 + `GameActionModal` 확인 다이얼로그 노출
- **이유**: 자동 탈옥이 정상 동작하는 환경에서는 수동 조작 여지를 완전히 제거하되, API 실패 시에는 사용자가 진행 가능한 안전망 보존

#### 게임 페이지 — 자동 탈옥 추적/트리거 로직

- **파일**: `lib/features/game/presentation/pages/game_page.dart`
- **변경 내용**:
  - State 필드 5개 추가 (`_lastKnownPosition`, `_wasOutsideJail`, `_hasEnteredJailThisArrestCycle`, `_isEscapeInFlight`, `_autoEscapeFailed`)
  - 메서드 4개 추가 (`_computeIsOutsideJail`, `_checkJailExit`, `_canTriggerAutoEscape`, `_triggerAutoEscape`)
  - `_startHeadingTracking` GPS 스트림 콜백에 두 줄 추가 — 최신 위치 저장 + 감옥 이탈 검사
  - ARREST 리스너에 추적 상태 리셋 분기 추가 (체포 사이클마다 새로 시작)
  - `ArrestLockOverlay` 호출부에 `showManualFallback: _autoEscapeFailed` 전달
- **이유**: 기존 GPS 스트림(`_headingSubscription`)을 재활용하여 별도 stream 비용 없이 감옥 감지. 추적 상태와 트리거 가드를 분리하여 각 책임을 명확히 함

### 🔧 주요 변경사항 상세

#### JailZoneCheck.computeIsOutside (히스테리시스)

```
distance ≤ radius           → 안 (false)
distance > radius + buffer  → 밖 (true)
그 사이 band                 → previousIsOutside 유지
```

GPS 진동으로 경계선에서 out↔in이 반복되면 ARREST/ESCAPE가 깜빡일 수 있음. buffer(10m) 영역에서는 직전 판정을 유지하여 한 번 들어오면 명시적으로 buffer 밖까지 나가야 이탈로 인정. 기본 buffer 10m는 일반적 GPS 오차 범위(5~15m)와 중복되지 않게 설정한 보수적 수치.

#### _checkJailExit — GPS tick마다 호출되는 게이트웨이

매 tick에서 새 isOutside 계산 → 이전 상태와 비교하여 transition 판정 → 진입이면 `_hasEnteredJailThisArrestCycle = true`, 이탈이면 가드 통과 시 `_triggerAutoEscape` fire-and-forget. 마지막에 `_wasOutsideJail` 업데이트.

#### _canTriggerAutoEscape — 7개 가드

```
1. _hasEnteredJailThisArrestCycle    : 이번 사이클 감옥 진입 이력
2. !_isEscapeInFlight                : API 진행 중 아님 (중복 호출 방지)
3. !_gameOverDialogShown             : 게임 종료 다이얼로그 미표시
4. !_isReconnectModalShown           : 재연결 모달 미표시
5. arrestedParticipantIds 포함       : 현재 수감 상태
6. !escapedParticipantIds 포함       : 이미 탈옥 완료 아님
7. (gameAreaProvider 로드 — _computeIsOutsideJail 내부에서 null guard)
```

#### _triggerAutoEscape — 실패 폴백 메커니즘

`escape()` 호출이 throw하지 않는 구조이므로(rollback 패턴), API 호출 후 `arrestedParticipantIds` 재확인으로 실패 판정.
- 내 ID가 잔존 → 서버에서 reject되어 rollback된 것 → `_autoEscapeFailed = true` (폴백 UI 노출)
- 직전 실패 후 재시도 성공 → 즉시 `_autoEscapeFailed = false` (폴백 UI 해제)
- `_isEscapeInFlight`는 finally에서 무조건 false로 복원

#### ARREST 리스너의 리셋 분기

```
_wasOutsideJail = _computeIsOutsideJail(_lastKnownPosition) ?? true;
_hasEnteredJailThisArrestCycle = false;
_isEscapeInFlight = false;
if (_autoEscapeFailed) setState(() => _autoEscapeFailed = false);
```

매 체포 시점에 추적 상태를 리셋하되, `_wasOutsideJail`은 마지막 GPS로 즉시 재계산. **감옥 안에서 잡힌 케이스**(즉시 이탈하면 트리거되는 비정상 시나리오)를 막기 위함 — 잡힌 직후 baseline이 "안"이면 진입 이력 없이 곧장 이탈 검출되는 일은 발생하지 않음. `_autoEscapeFailed`는 UI 영향을 주므로 변경 시에만 setState 호출.

**특이사항**:

- `_lastKnownPosition`은 `_lastSentPosition`과 별개. 후자는 5초 throttle된 서버 송신용이라 baseline 재계산에 부적합
- `_wasOutsideJail` 초기값은 보수적으로 `true` — 게임 시작 직후 우연히 감옥 안이라도 곧 baseline이 갱신되며, 진입 이력 추적은 ARREST 시점부터 시작되므로 영향 없음
- 자동 탈옥 호출은 GPS 콜백에서 sync로 들어오므로 `// ignore: unawaited_futures` 명시
- 폴백 버튼이 떠 있는 동안 GPS 이탈이 다시 감지되면 `_triggerAutoEscape`가 재호출되어 자동 복구 시도 (성공 시 폴백 UI 즉시 해제)

### 📌 참고사항

- `pubspec.yaml`, `version.yml` 변경은 다른 작업의 흔적이며 본 작업과 무관
- 기존 플레이그라운드 이탈 감지(`ZoneExitDetector`)와 코드 패턴은 유사하나, 감옥 감지는 히스테리시스 buffer를 도메인 로직에 내장하고 enum으로 transition을 명시적으로 표현하여 더 엄격한 책임 분리를 적용
- `escape()` API가 throw하지 않고 rollback으로 실패를 표현하는 기존 설계를 변경하지 않고, presentation에서 상태 비교로 실패 판정 — 다른 호출자에게 영향 없음
- 한 게임 내에서 잡히고 탈옥하고 다시 잡히는 사이클이 반복되더라도, ARREST 리스너에서 매번 추적 상태를 초기화하므로 사이클 간 격리됨
