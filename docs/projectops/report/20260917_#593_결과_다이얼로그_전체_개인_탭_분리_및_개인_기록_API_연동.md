### 📌 작업 개요
게임 종료 결과 다이얼로그에 「전체 / 개인」 탭을 추가하고, 개인 탭이 표시할 참가자 개인 기록을 `GET /api/game-results/{gameResultId}/me` API로 연동. 기존에는 결과 카드의 "체포 횟수"가 팀 합계뿐이라 경찰도 도둑도 자기 개인 기록을 볼 수 없었던 문제를 해소.

### 🎯 구현 목표
- 결과 다이얼로그를 두 개로 늘리지 않고 하나를 유지한 채 탭으로 전체/개인 통계를 분리
- 팀별로 의미 있는 개인 지표만 노출 (경찰: 체포 관련, 도둑: 피체포 관련)
- `/me` 실패가 기존 「전체」 탭 동작에 영향을 주지 않도록 독립적으로 처리
- 결과 카드에 남아 있던 로컬 체포/피체포 카운트를 서버 값으로 대체

### ✅ 구현 내용

#### 개인 기록 API 연동
- **파일**: `lib/features/game/data/models/my_game_record_response_model.dart`, `lib/features/game/domain/entities/my_game_record_entity.dart`
- **변경 내용**: `/me` 응답 DTO(`nickname`·`team`·`status`·`arrestCount`·`arrestedCount`·`leftAt` 6필드)와, 화면이 실제로 쓰는 5필드만 남긴 Entity를 새로 추가. `leftAt`은 결과 다이얼로그를 보는 참가자는 항상 끝까지 남아 있던 사람이라 화면에서 쓰지 않아 DTO→Entity 변환 단계에서 제외.
- **이유**: 서버 응답을 그대로 노출하지 않고, 화면이 실제로 필요로 하는 필드만 Entity에 남겨 계층 경계를 지킴.

#### API 클라이언트·Provider
- **파일**: `lib/features/game/data/datasources/game_result_api_datasource.dart`, `lib/features/game/presentation/providers/game_result_provider.dart`, `lib/core/constants/api_endpoints.dart`
- **변경 내용**: `GameResultApi.getMyGameRecord` Retrofit 메서드와 `myGameRecordProvider(gameResultId)` 추가. 기존 `gameResultProvider`와 동일하게 `keepAlive: true`, 인증 전용 `gameResultDioProvider`(전역 AuthInterceptor 미사용) 재사용.
- **이유**: 기존 `gameResultProvider`가 이미 "부가 정보 실패가 강제 로그아웃으로 번지면 안 된다"는 이유로 별도 Dio를 쓰고 있어, 같은 성격의 API이므로 동일 패턴을 그대로 따름.

#### 결과 API 사전 로딩
- **파일**: `lib/features/game/presentation/pages/game_page.dart`
- **변경 내용**: 게임 종료 1단계 팝업(3초) 진입 직전, 기존 `gameResultProvider` 사전 트리거 옆에 `myGameRecordProvider` 사전 트리거를 fire-and-forget으로 추가.
- **이유**: 2단계 결과 다이얼로그가 뜰 때 이미 두 API 응답이 준비되어 있어야 탭 전환 시 로딩이 보이지 않음. 각 Future의 에러는 개별적으로 소비해 미소비 에러가 전역으로 번지지 않게 처리.

#### 결과 다이얼로그 — 탭 UI
- **파일**: `lib/features/game/presentation/widgets/game_over_result_dialog.dart`
- **변경 내용**: 카드 상태에 `_tabIndex`(기본 0=전체) 추가, 제목 아래 공용 `SegmentedToggle`로 「전체/개인」 전환. `_StatsSection`이 `tabIndex`로 팀 합계 3행과 개인 3행을 분기하고, 팀별로 다른 라벨/행 구성을 적용. 값 텍스트에는 `maxLines: 1` + ellipsis를 추가해 닉네임처럼 길어질 수 있는 값이 레이아웃을 깨지 않게 함.
- **이유**: 헤더(제목·토글·날짜·거리·지도)는 두 탭이 공유하고 지도 아래 통계 3행만 바뀌는 구조라 탭을 전환해도 카드 높이가 튀지 않음. 다이얼로그를 하나 더 만드는 대신 탭으로 처리한 이유는 이슈에 적힌 대로 과거(#462) "결과 확인 후 별도 버튼으로 여는 두 번째 다이얼로그" 구조가 도달률 문제로 폐기된 선례가 있기 때문.

#### 팀별 개인 탭 행 구성
개인 탭 통계는 팀에 따라 다른 세 행을 보여준다.
- 경찰: 닉네임 · 내 체포 횟수(`arrestCount`) · 팀 체포 기여도
- 도둑: 닉네임 · 잡힌 횟수(`arrestedCount`) · 종료 시점 상태(`finalStatusLabel`로 ALIVE/JAILED → 생존/수감 변환)

경찰의 잡힌 횟수, 도둑의 체포 횟수처럼 서버 로직상(`validateArrest`) 항상 0으로 오는 값은 애초에 행에 넣지 않는다. 팀 판정은 `/me` 응답의 `team`이 아니라 다이얼로그가 받는 `myTeam` prop 기준 — 응답이 오기 전에도 팀에 맞는 라벨로 placeholder(`-`)를 그려야 하기 때문.

**특이사항**:
- 「전체」 탭의 "체포 횟수" 라벨(팀 합계, 기존 키)과 「개인」 탭의 "내 체포 횟수" 라벨(새 키)을 분리했다. 같은 라벨이 탭에 따라 다른 숫자로 보이는 것을 방지하기 위함.
- 이동 거리 행은 개인 탭에 넣지 않았다 — 카드 헤더의 큰 숫자가 이미 본인 이동 거리라 중복.
- `/me` 실패는 「전체」 탭과 무관하다. 두 Provider가 서로를 읽지 않으므로 개인 탭만 라벨을 유지한 채 값이 `-`가 된다.

#### 공유 이미지 캡처 대응
- **파일**: `lib/features/game/presentation/widgets/game_over_result_dialog.dart`
- **변경 내용**: 탭 토글이 캡처 대상(`RepaintBoundary`) 안에 있어, 캡처 중에는 `Offstage`로 토글을 자리째 접는다.
- **이유**: 토글을 `Opacity`로 숨기면 자리를 차지해 제목-날짜 사이에 빈 띠가 남는다. `Offstage`는 여백까지 같이 접어 캡처 레이아웃이 기능 추가 이전과 동일해진다. 기본 탭이 「전체」이므로 접힌 뒤 캡처 결과는 기존 공유 이미지와 같은 구성이 된다.

#### 팀 체포 기여도 계산
- **파일**: `lib/features/game/presentation/widgets/record_format.dart`
- **변경 내용**: `formatTeamArrestShare({mine, total})` 추가. `mine ÷ total`을 정수 %로 반올림 표시(`3÷7 → 43%`), `total`이 0이면 `-`.
- **이유**: 내 체포 횟수와 팀 총 체포 횟수(결과 API 값)의 조합이라 두 API 응답이 모두 있어야 계산 가능. 결과 API가 아직 준비되지 않았거나 실패한 경우에도 `-`로 안전하게 처리.

#### 로컬 카운트 제거
- **파일**: `lib/features/game/presentation/providers/player_game_record.dart`, `lib/features/game/presentation/providers/player_game_record_provider.dart`, `lib/features/game/presentation/providers/game_event_provider.dart`
- **변경 내용**: `PlayerGameRecord`에서 `myArrestCount`·`myEscapeCount` 필드 제거. `PlayerGameRecordNotifier.incrementEscape()` 삭제, `incrementArrest()`는 `recordArrest()`로 개명.
- **이유**: 서버가 이제 같은 값을 `/me`로 제공하고, 로컬 카운트는 화면 어디에서도 읽히지 않고 있었다. 다만 체포/피체포 **위치** 기록(`arrestLocations`·`caughtLocations`)은 결과 카드 지도에 실제로 렌더되므로 그대로 남겼다. `incrementArrest()`는 카운트를 세지 않게 되면서 이름이 실제 동작과 맞지 않게 되어, 같은 일(위치만 기록)을 하는 `recordCaught()`와 이름 규칙을 맞춰 `recordArrest()`로 바꿨다.
