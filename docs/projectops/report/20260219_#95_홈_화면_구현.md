### 📌 작업 개요

홈 화면 UI 디자인 적용, 설정 페이지 신규 구현, `/api/user/me` API 연동, 닉네임 설정 플로우 네비게이션 수정을 포함한 종합적인 홈 화면 구현 작업

### 🎯 구현 목표

- 완성된 디자인 기반 홈 화면 UI 구현
- 설정 페이지 신규 생성 및 라우터 등록
- `/api/user/me` API 연동으로 정확한 사용자 정보 사용
- 설정에서 닉네임 변경 시 정상적인 네비게이션 동작 보장

### ✅ 구현 내용

#### 1. 홈 화면 UI 디자인 적용

- **파일**: `lib/features/session/presentation/pages/home_page.dart`
- **변경 내용**: 디자인 시안에 맞게 홈 화면 전면 재구성
  - 상단: LOGO + 설정 아이콘 (설정 페이지 이동 연결)
  - 중단: 공지/역할 SVG 아이콘 버튼, 말풍선 위젯, 아바타 이미지
  - 하단: "방 만들기" / "방 참여하기" 버튼 (border 제거 적용)
- **설정 이동**: `context.push(RoutePaths.settings)` 로 push 네비게이션 사용 (뒤로가기 지원)

#### 2. 공통 위젯 추가

- **SpeechBubble** (`lib/core/widgets/speech_bubble.dart`)

  - 텍스트 길이에 따라 자동 크기 조절
  - Shadow 적용 (X:1, Y:1, Blur:8, #000000 10%)

- **SvgIconButton** (`lib/core/widgets/buttons/svg_icon_button.dart`)
  - 흰색 배경 + 라운드 + 그림자 컨테이너에 SVG 아이콘을 감싼 버튼
  - containerSize, iconSize, borderRadius 커스터마이징 지원

#### 3. 설정 페이지 신규 구현

- **파일**: `lib/features/settings/presentation/pages/settings_page.dart` (신규)
- **변경 내용**: 설정 메뉴 구현
  - 닉네임 변경: `/api/user/me` 호출 → 현재 닉네임 가져온 후 nickname_setup_page로 push
  - 알림: Switch 토글 UI (저장 로직은 추후 구현 예정)
  - 버그 제보 / 개인정보 처리방침: 메뉴 아이템 추가 (페이지 연결 추후)
  - 로그아웃: `authNotifierProvider.signOut()` 호출
  - 회원 탈퇴: 메뉴 아이템 추가 (로직 추후)

#### 4. `/api/user/me` API 연동

- **MyPageResponseModel** (`lib/features/user/data/models/my_page_response_model.dart`, 신규)
  - `GET /api/user/me` 응답 DTO (userId, nickname, socialPlatform, allowGamePush, allowMarketingPush)
  - Freezed + JsonSerializable 코드 생성

- **UserProfileEntity** (`lib/features/user/domain/entities/user_profile_entity.dart`, 신규)
  - 도메인 레이어 엔티티 (Freezed 불변 데이터)

- **UserRemoteDataSource** (`lib/features/user/data/datasources/user_remote_datasource.dart`)
  - `getMyPage()` 메서드 추가 (`@GET(ApiEndpoints.myPage)`)

- **UserRepository** (`lib/features/user/domain/repositories/user_repository.dart`)
  - `getMyProfile()` 인터페이스 메서드 추가

- **UserRepositoryImpl** (`lib/features/user/data/repositories/user_repository_impl.dart`)
  - `getMyProfile()` 구현: DataSource → Entity 변환, DioException 에러 핸들링

#### 5. 닉네임 설정 페이지 네비게이션 수정

- **파일**: `lib/features/auth/presentation/pages/nickname_setup_page.dart`
- **변경 내용**: `_navigateAfterComplete()` 헬퍼 메서드 추가
  - `context.canPop() == true` → `context.pop()` (설정에서 push로 진입한 경우, 설정 페이지로 복귀)
  - `context.canPop() == false` → `context.go(RoutePaths.home)` (첫 로그인 리다이렉트로 진입한 경우, 홈 이동)
- **이유**: 기존에는 항상 `context.go(home)` 호출하여 설정에서 진입해도 홈으로 이동하는 문제 수정

#### 6. 라우터 구성

- **파일**: `lib/router/app_router.dart`, `lib/router/route_paths.dart`
- **변경 내용**:
  - `RoutePaths.settings = '/home/settings'` 경로 상수 추가
  - GoRouter에 settings 라우트를 home의 하위 라우트로 등록 (슬라이드 전환 애니메이션)

#### 7. 전체 AppBar centerTitle 통일

### 🔧 주요 변경사항 상세

#### Clean Architecture 구조 준수

`/api/user/me` 연동은 기존 User feature의 Clean Architecture 패턴을 따름:
- Data 레이어: `MyPageResponseModel` (DTO) + `UserRemoteDataSource` (Retrofit)
- Domain 레이어: `UserProfileEntity` + `UserRepository` 인터페이스
- Presentation 레이어: 설정 페이지에서 `userRepositoryProvider`를 통해 호출

#### 네비게이션 분기 로직

`nickname_setup_page.dart`에서 `context.canPop()` 활용으로 진입 경로에 따라 자동 분기:
- 스택에 이전 페이지 존재 (설정에서 push) → `pop()`으로 복귀
- 스택 없음 (첫 로그인 redirect) → `go(home)`으로 이동

**특이사항**:
- 네비게이션을 상태 갱신보다 먼저 수행 (GoRouter refreshListenable이 push된 라우트를 잃는 문제 방지)
- `from` 쿼리 파라미터 없이 `canPop()` 만으로 깔끔하게 동작
