### 📌 작업 개요

이슈 #280 대응. 게임 종료 시 세션 ID만 표시하던 단순 Scaffold를 캐릭터 오버레이 결과 다이얼로그로 교체. GAME_OVER 이벤트 → 게임 결과 조회 API → 통계·승패 캐릭터 렌더링 흐름 신규 구축. PR #281 머지 완료(`d586e1a`).

### 🎯 구현 목표

- 본인 팀(경찰/도둑) × 결과(승리/패배) 4조합 캐릭터 SVG 분기
- 캐릭터 몸통은 다이얼로그 뒤, 좌/우 팔은 다이얼로그 앞 배치로 "팔이 다이얼로그를 잡은" 입체 구도
- `GET /api/game-results/{gameResultId}` 신규 API 연동 (DTO/Entity/Provider 3계층)
- 통계 3행(체포 횟수 / 남은 도둑 / 게임 진행 시간 분:초) + 액션 버튼 2개("홈으로", "한 번 더")
- 기존 `ResultsPage` 제거 및 GamePage 게임 종료 플로우 재정비

### ✅ 구현 내용

#### 게임 결과 조회 API Clean Architecture 3계층 신규 생성
- **Data**
  - `lib/features/game/data/models/game_result_response_model.dart` — Freezed DTO (`winnerTeam`, `durationSeconds`, `totalArrestCount`, `remainingRobberCount`)
  - `lib/features/game/data/datasources/game_result_api_datasource.dart` — Retrofit 클라이언트 (`GET /api/game-results/{gameResultId}`)
  - `lib/core/constants/api_endpoints.dart` — `gameResult(int gameResultId)` 엔드포인트 헬퍼 추가
- **Domain**
  - `lib/features/game/domain/entities/game_result_entity.dart` — Freezed 엔티티 (Data Layer 의존성 없는 순수 Dart)
- **Presentation**
  - `lib/features/game/presentation/providers/game_result_provider.dart` — `@Riverpod(keepAlive: true)` FutureProvider family by `gameResultId`, `DioExceptionHandler.handle`로 에러 변환

#### GameOverResultDialog 위젯 신규 구현
- **파일**: `lib/features/game/presentation/widgets/game_over_result_dialog.dart`
- Stack 4-레이어 구조: 몸통(뒤) → 다이얼로그 본체 → 왼쪽 팔(앞) → 오른쪽 팔(앞)
- 팀별 몸통·팔 크기/여백 상수를 경찰/도둑 각각 독립 정의하여 SVG 비율 차이를 별도 조정 가능
- 순수 함수로 에셋 경로 분기
  - `resolveBodyAsset(myTeam, winnerTeam)`
  - `resolveLeftArmAsset(myTeam, winnerTeam)`
  - `resolveRightArmAsset(myTeam, winnerTeam)`
  - `formatDuration(seconds)` — "분:초" 포맷 변환 (60분 초과 cap 없이 누적)
- 내부 위젯 분리: `_ResultTitle` (승리/패배 색상 분기, 팀 테마 반영), `_StatsSection` (AsyncValue data/loading/error 3상태 분기, 비동기 상태에선 `-` 플레이스홀더 3행), `_ActionButtons`
- `showDialog` 기반 헬퍼 `GameOverResultDialog.show(...)` 제공

### 🔧 주요 변경사항 상세

#### `_showGameOverDialog` 호출 순서 버그 수정 (`b4e7e8d`)
- **원인**: `ref.read(gameEventNotifierProvider.notifier).disconnect()`가 내부에서 `state = const GameEventState()`로 state를 초기화. 해당 호출 이후 `ref.read(gameEventNotifierProvider).gameResultId`를 읽으면 `null` 반환 → `gameResultId == null || winnerTeam == null` 분기에 걸려 fallback `AppDialog`로 빠짐
- **수정**: `gameResultId` 로컬 변수 캡처를 `disconnect()` 이전으로 이동. `disconnect()` 호출부에 "내부에서 state 리셋 수행" NOTE 주석 추가하여 재발 방지
- **검증**: 실기기에서 경찰이 마지막 도둑을 QR로 체포하는 시나리오로 fallback 미발생 및 `GameOverResultDialog` 정상 표시 확인

#### `gameResultProvider` keepAlive 적용 (CodeRabbit 리뷰 대응, `1184be2`)
- **원인**: `@riverpod` 기본값이 `AutoDisposeFutureProvider`. `_showGameOverDialog`에서 사전 트리거 후 `AppPopup` 3초 대기 중 Provider 구독자가 없어 autoDispose 발동 → 다이얼로그 `ref.watch` 시점에 재요청이 발생하여 동일 엔드포인트가 **2번 호출**됨
- **수정**: `@Riverpod(keepAlive: true)`로 변경 후 `dart run build_runner build --delete-conflicting-outputs`로 `.g.dart` 재생성 (`GameResultProvider extends FutureProvider`로 변환됨)
- **검증**: 실기기 로그에서 `/api/game-results/{id}` 요청이 세션당 1회만 발생하는 것을 확인 (이전엔 2회)
