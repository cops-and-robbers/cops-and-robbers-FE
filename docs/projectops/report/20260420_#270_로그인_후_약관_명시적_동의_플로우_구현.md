### 📌 작업 개요
로그인 성공 직후 필수 약관(이용약관·개인정보 처리방침·위치정보 이용약관) 3종 + 선택 약관(마케팅 수신) 1종에 대한 명시적 동의 플로우를 구현. 기존의 묵시적 동의를 제거하고 백엔드 신규 API(`GET/PUT /api/user/agreements`)와 연동하여 법적 명시적 동의 요건을 충족하도록 개선.

### 🎯 구현 목표
- 로그인 응답의 `requiresAgreement` 플래그에 따라 약관 동의 화면 자동 노출
- 필수 3종 + 선택 1종 체크박스 UI 및 `PUT /api/user/agreements` 연동
- 라우팅 분기에서 미동의 사용자의 홈/게임 접근 차단
- 설정 화면에서 동의 현황 조회 및 마케팅 수신 토글 가능
- 게임 방 생성/참여 시 서버가 400으로 차단하면 자동으로 약관 화면 리다이렉트
- 앱 재시작(Cold start) 시에도 온보딩(약관/닉네임) 진행 상태가 복원되도록 영속화

### 🔧 주요 변경사항 상세

#### AgreementNotifier 제출 플로우
`submit()`는 네트워크 연결 확인 → `isSubmitting=true` → `userRepo.updateAgreements(marketing: ...)` 호출 → 결과에 따라 `AgreementSubmitResult` 반환. 호출자(AgreementPage)는 반환값에 따라 스낵바 표시 혹은 `AuthNotifier.markAgreementCompleted()` 호출을 담당하여 Provider 간 강결합을 회피.

**특이사항**:
- 제출 중(`isSubmitting=true`)에는 모든 토글 메서드가 `if (state.isSubmitting) return;` 가드로 차단 — 요청 전송 후 사용자가 체크박스를 바꿔 화면 표시값과 서버 저장값이 어긋나는 것을 방지
- 필수 3종은 `updateAgreements` 내부에서 항상 `true`로 고정 전송 (설정 화면에서 해제 불가능한 이유)

#### 라우터 redirect 4단계
```
step 1. 미인증 → /login (공개 경로 제외)
step 2. requiresAgreement → /agreement
step 3. isNewUser → /nickname-setup
step 4. /agreement 잔류 → /home (동의 완료 탈출)
```
`markAgreementCompleted()` 호출로 `requiresAgreement=false`가 되면 refreshListenable → redirect 재평가 → step 2 통과 → step 3(신규) 또는 step 4(기존)로 자동 진행.

#### agreement_error_handler의 두 경로 대응
`AppException.originalException`이 `DioException`인 경우와 `DioException`이 직접 캐치된 경우 모두 `ApiErrorResponse.tryParse`로 일관되게 처리. `home_page.dart`의 `_joinRoom`은 DioException을 직접 캐치하므로 후자 경로 대응이 필요.
