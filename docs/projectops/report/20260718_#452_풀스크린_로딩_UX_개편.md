# 로딩 UX 개편: 모달 다이얼로그 → 풀스크린 로딩 화면 (#452)

### 📌 작업 개요

비동기 작업(방 생성·참가, 팀 변경, 게임 시작, 설정 저장, 로그아웃, 회원탈퇴 등) 중 표시되던 **작은 모달 로딩 다이얼로그**를 **화면 전체를 쓰는 로딩 화면**으로 전면 교체했다. 동시에 로딩 표시/닫기 타이밍의 책임을 호출부의 `navigator.pop()` 관례에서 컴포넌트(`LoadingHandle`)로 회수했다.

### 🎯 구현 목표

- 도허티 임계(Doherty Threshold, 400ms 이내 피드백)를 지키면서도 짧은 API 응답에서 화면이 번쩍이지 않도록 최소 표시 시간을 보장
- "차단당했다"는 인상을 주는 모달 스피너 대신, 제목 + 안심 서브카피 + 팀 테마 비주얼로 진행 상황을 설명
- 닫기 책임을 호출부의 `if (navigator.canPop()) navigator.pop()` 휴리스틱에서 분리 — 타이밍이 어긋나 로딩이 아닌 다른 화면이 닫히는 위험 제거
- 오버레이(다이얼로그)와 전체 페이지(스플래시·딥링크) 두 진입점이 하나의 뷰를 공유하도록 통합
- 디자이너 자산(SVG/GIF/Lottie) 수령 시 한 파일만 교체하면 되도록 시각 요소를 격리

### ✅ 구현 내용

#### 1. 서브카피 문구 (ARB + `LoadingMessageService`)

- **파일**: `lib/l10n/app_{ko,en,ja}.arb`, `lib/core/services/loading_message_service.dart`
- **변경 내용**: 기존 카테고리별 랜덤 문구(`getMessage`)는 제목으로 승격하고, 카테고리당 고정 1개의 안심 서브카피를 신규 추가(`asset_loading_sub_<category>` 키, 3개 로케일). `LoadingMessageService.getSubtitle(context, category)` / `subtitleFor(l10n, category)`(`@visibleForTesting`)로 노출. `LoadingCategory.reconnect`는 `null` 반환
- **이유**: 제목은 기존 세계관 문구를 재사용해 톤을 유지하고, 서브카피는 "지금 앱을 끄면 취소돼요" 류의 실용적 안내를 별도로 제공해 두 역할을 분리

#### 2. 로딩 비주얼 (`LoadingVisual`)

- **파일**: `lib/core/widgets/loading/loading_visuals.dart` (신규), `assets/loading/police.svg`, `assets/loading/robber.svg` (신규), `pubspec.yaml`
- **변경 내용**: `AnimationController` 1개로 파동 링 3겹을 스태거(0.0/0.33/0.66)로 확산·페이드아웃시키고 중앙에 팀 캐릭터 SVG를 배치. 링 색상은 팀별 명도 계단 상수(`blue100/500/800` 또는 `green100/500/800`), 페이드는 `Opacity` 위젯으로 처리해 `withOpacity`/`withValues` 금지 규칙을 지켰다
- **이유**: 공유 캐릭터 에셋(`assets/characters/`)과 별도로 `assets/loading/` 디렉토리를 신설해, 디자이너가 실제 로딩 전용 일러스트/애니메이션을 넘겨줘도 이 파일의 자산 경로만 바꾸면 되도록 격리

#### 3. 풀스크린 콘텐츠 뷰 (`LoadingContentView`)

- **파일**: `lib/core/widgets/loading/loading_content_view.dart` (신규)
- **변경 내용**: 제목(최대 2줄) + 서브카피(최대 2줄, 있을 때만) + 비주얼(Expanded 중앙 정렬) + 선택적 하단 슬롯으로 구성된 `StatelessWidget`. 팀 테마는 생성자 `isDarkMode` prop으로만 받는다. 배경·텍스트 색은 `AppColors`, 타이포는 `AppTextStyles`(제목: 경찰 `heading_24` / 도둑 `robberHeading24`), 간격은 `AppSpacing`/`AppPadding` 상수만 사용
- **이유**: 오버레이(`AppLoading`)와 전체 페이지(`LoadingPage`) 두 진입점이 동일한 뷰를 공유하도록 만들어 로딩 UI 경로를 하나로 유지

#### 4. 오버레이 진입점 + 닫기 핸들 (`AppLoading` / `LoadingHandle`)

- **파일**: `lib/core/widgets/loading/app_loading.dart` (신규)
- **변경 내용**: `AppLoading.show(context, category)` / `showMessage(context, message:, subtitle:)`가 불투명 배경의 `showGeneralDialog` 라우트를 띄우고 `LoadingHandle`을 반환한다. `PopScope(canPop: false)`로 뒤로가기를 차단하고, 팀 테마(`roleThemeProvider`)는 진입 시점에 한 번만 읽는다. `LoadingHandle.close()`는 표시 시각(`shownAt`)과 현재 시각의 차이를 계산해 최소 표시 시간(600ms) 미달분만큼 대기한 뒤, 캡처해둔 dialog route의 `BuildContext`로 **자기 라우트만** 닫는다. 중복 호출은 idempotent(첫 호출만 유효)
- **이유**: `Navigator.pop()`이 최상단 라우트를 닫는 방식은 타이밍에 따라 로딩이 아닌 다른 화면을 닫을 위험이 있었다. 표시 시간 계산을 틱 카운팅이 아닌 `DateTime` 차이 기반으로 만들어, 앱이 백그라운드로 갔다 와도 정확하게 남은 시간을 계산한다(`08_TIMER_ARCHITECTURE.md`와 동일한 패턴)

#### 5. `LoadingPage` 공용 뷰 전환

- **파일**: `lib/core/widgets/loading/loading_page.dart`
- **변경 내용**: 스플래시·딥링크 참가 등에서 쓰던 `LoadingPage`의 body를 `LoadingContentView`로 교체. `backgroundColor`/`textColor` 파라미터를 삭제하고 `isDarkMode`(기본 `false`)를 추가했다. `progress`가 주어지면 하단 슬롯에 기존 `CustomProgressBar`를 그대로 노출
- **이유**: 부수적으로 기존 코드의 `textColor?.withValues(alpha: 0.7)`(디자인 시스템 위반)가 함께 제거됨

#### 6. 호출부 10곳 전환

- **파일**: `session_creation_flow_page.dart`, `home_page.dart`, `waiting_room_page.dart`(팀 변경/게임 시작), `game_settings_page.dart`, `game_settings_edit_page.dart`, `settings_page.dart`(닉네임 변경/버그 제보/로그아웃/회원탈퇴), `notices_page.dart`, `test_widget_page.dart`
- **변경 내용**: `AppPopup.showRandomLoading(...)` + `if (navigator.canPop()) navigator.pop()` 패턴을 `AppLoading.show(context, category)` + `await loading.close()`로 전환. 에러 UI(스낵바)는 로딩이 **닫힌 뒤** 표시하도록 순서를 재배치. 카테고리가 없는 `notices_page`는 `AppLoading.showMessage()`로 대응하고, 리스너 콜백에서는 `await`가 불가능하므로 핸들을 필드로 들고 있다가 `unawaited(handle.close())`로 닫으며 `dispose()`에서도 정리
- **이유**: 닫기 책임을 컴포넌트로 옮기는 계약 변경을 전 호출부에 일관 적용

### 🔧 주요 변경사항 상세

#### 안정성 보강 — 예외 경로에서도 반드시 닫히도록 안전망 추가

성공/실패 각 분기마다 `loading.close()`를 직접 호출하는 패턴에서, 분기로 처리되지 않은 예외 타입이 발생하면 로딩이 닫히지 않고 남을 수 있었다. 이를 막기 위해 `settings_page.dart`(닉네임 변경·버그 제보·회원탈퇴 3곳), `game_settings_page.dart`, `game_settings_edit_page.dart`, `waiting_room_page.dart`(팀 변경·게임 시작 2곳) 총 **7곳**에 `finally { await loading.close(); }` 안전망을 추가했다. `close()`가 idempotent라 정상 경로에서 이미 닫혔어도 안전망 호출은 즉시 리턴되어 부작용이 없다.

#### 회원탈퇴 로딩 잔존 버그 수정

기존 `_executeDeleteAccount()`의 성공 경로는 로딩을 닫지 않은 채 `context.go(login)`으로 화면을 전환해, 로그인 화면 위에 로딩 dialog route가 남을 수 있었다. 전환 직전에 `await loading.close()`를 호출하도록 순서를 바로잡았다.

#### 팀 변경 중 위젯 dispose 대응

`waiting_room_page.dart`의 `_changeTeam()`은 `loading.close()`의 최소 표시 대기 동안 `KICKED`/`GAME_START` 등 웹소켓 이벤트로 대기실 화면이 먼저 dispose될 수 있다. `close()` 이후 `ref`를 사용하기 전 `if (!mounted) return`으로 가드해 안전하게 처리했다.

**특이사항**:
- `reconnect_modal.dart`는 이번 교체 범위에서 **의도적으로 제외**했다. 재연결 UI는 수동 재시도 버튼이 있는 별도 UX라 수동적인 로딩 오버레이와 성격이 다르다.
- 캐릭터 일러스트는 디자이너 자산 확정 전까지의 플레이스홀더로, `assets/loading/` 전용 디렉토리에 격리했다(공유 캐릭터 에셋과 분리).
- `AppPopup.showLoading` / `showRandomLoading`은 모든 호출부 전환 후 완전히 삭제. `AppPopup`의 나머지 기능(일반 팝업, 자동 닫힘)은 그대로 유지

### 📌 참고사항

- **`LoadingCategory.reconnect`**: 서브카피가 `null`을 반환하도록 명시적으로 분기되어 있으나, 실제로는 `reconnect_modal.dart`가 별도 UI를 쓰므로 이 카테고리의 로딩 오버레이 자체가 호출되지 않는다.
- **디자이너 자산 교체 지점**: `loading_visuals.dart`의 `_assetPolice`/`_assetRobber` 상수와 `assets/loading/` 폴더만 교체하면 다른 파일 변경 없이 실제 일러스트/모션으로 전환 가능하다.
- **진행률(%) 표시**: 서버가 진행률을 제공하지 않아 이번 범위에 포함하지 않았다. `LoadingPage`의 기존 `progress` 파라미터만 유지된다.
