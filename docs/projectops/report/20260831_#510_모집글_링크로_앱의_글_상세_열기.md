### 📌 작업 개요

모집글 링크가 앱의 글 상세로 이어진다.

`https://copsandrobbers.app/g/{id}` (일본어 `/ja/g/{id}`·영어 `/en/g/{id}` 포함)를 누르면 앱이 열리며 그 글의 상세로 이동하고, 상세의 공유 버튼은 글 제목과 이 링크를 OS 공유 시트로 보낸다. 앱 종료·실행 중·미로그인 어느 상태에서 눌러도 결국 그 글에 도착한다.

- 커밋 5개 / 파일 15개 / +544 −23 (문서 제외)
- `flutter analyze` 에러 · 경고 0

### 🎯 구현 목표

- 모집글 링크에서 앱 상세까지의 길을 연다. 웹 모집글 페이지가 열리면 돌기 시작할 링크의 목적지를 앱이 받는다
- 이미 검증된 구조를 재사용한다: 이동은 댓글 푸시의 상세 이동과, 미로그인 보존은 초대 코드와 같은 방식
- 공유 링크는 `/g/{id}` 하나만 만든다. 언어별 정본 경로 판단은 웹이 하므로 규칙이 바뀌어도 앱 업데이트가 필요 없다

### ✅ 구현 내용

#### 경로 파싱과 수신 필터

- **파일**: `deeplink_event.dart`(+생성물), `AndroidManifest.xml`, `deeplink_event_test.dart`
- **변경 내용**: `communityPost(postId)` 이벤트 추가. `/g`·`/ja/g`·`/en/g` 3경로와 커스텀 스킴 `copsandrobbers://open/community/{id}` 파싱, 숫자가 아닌 id 는 unknown. 매니페스트의 App Links 필터에 `pathPrefix` 3개와 스킴 `host="open"` 추가
- **이유**: 언어별 경로는 웹의 정본 주소 규칙과 같다. 지원 언어가 늘면 인증 파일·매니페스트·파서 세 곳을 함께 넓힌다 (DEEPLINK.md 체크리스트)

#### 딥링크 경로의 라우터 별칭

- **파일**: `route_paths.dart`, `app_router.dart`
- **변경 내용**: `/g/:postId` 등 3경로를 `/community/:postId` 로 넘기는 별칭 라우트 추가
- **이유**: 엔진이 실행 중 들어온 인텐트의 원시 URI 경로를 라우터로 전달하는 것을 실측으로 확인했다 (`flutter_deeplinking_enabled=false` 로 막히지 않는다). 딥링크 경로가 실제 라우트로 존재하지 않으면 404 가 목적지 위를 덮는다. `/join` 이 실제 라우트라 멀쩡했던 것과 같은 원리이며, 이 원칙을 DEEPLINK.md 에 규칙으로 남겼다

커스텀 스킴을 `open/{라우터 경로}` 규약으로 정한 것도 같은 이유다. host 에 의미를 두면 엔진이 전달하는 경로가 `/{id}` 로 잘려 안착할 라우트가 없다.

#### 콜드·웜 내비게이션

- **파일**: `deeplink_service.dart`(+생성물), `main.dart`, `splash_page.dart`
- **변경 내용**: 웜은 루트 리스너가 상세를 push (댓글 푸시의 웜과 동일). 콜드는 스플래시가 인증·활성 게임 확인을 마친 뒤 목적지로 go 하며, 활성 게임이 없을 때의 목적지 우선순위는 `푸시 목적지 → 딥링크 상세 → 홈` 이다. 콜드 emit 에서 모집글 이벤트는 제외해 스플래시가 단독 처리한다
- **이유**: 스플래시의 go 와 경합하면 목적지가 유실된다. 댓글 푸시가 같은 이유로 잡아둔 구조를 그대로 따랐다

app_links 가 콜드 스타트를 일으킨 initial link 를 스트림에도 한 번 더 흘리는 것을 실측으로 확인해, 첫 재전달을 서비스에서 걸러냈다. 안 거르면 같은 링크가 콜드와 웜 양쪽에서 이중 처리되어 상세가 두 번 쌓인다. 초대 콜드 스타트의 같은 잠복 이중 처리도 이 필터로 함께 해소된다.

#### 미로그인 보존

- **파일**: `pending_community_post_provider.dart`(신규, +생성물), `main.dart`, `splash_page.dart`
- **변경 내용**: 로그인 전에 들어온 글 id 를 보존했다가, 약관·닉네임까지 진입 절차가 모두 끝난 시점에 소비해 상세로 보낸다. 보존된 초대 코드와 글 id 가 동시에 있으면 초대가 우선이고 글은 버린다
- **이유**: 초대 코드 보존과 같은 자리다. 예외를 던지지 않는 점만 다른데, 글 열람 링크는 저장이 실패하면 조용히 포기하고 홈으로 여는 편이 안내 팝업보다 자연스럽다. 우선순위는 게임 참여가 글 열람보다 앞선다는 판단이다

#### 공유 버튼과 유입 측정

- **파일**: `share_util.dart`, `community_detail_page.dart`, `analytics_service.dart`
- **변경 내용**: 상세 공유 버튼이 "준비 중" 안내 대신 글 제목 + `/g/{id}` 링크를 OS 공유 시트로 보낸다. 분석 이벤트 2종 추가: 공유 버튼 탭, 딥링크 유입(cold·warm·pending 구분)
- **이유**: 제목이 사용자가 쓴 글 그대로라 받는 쪽 언어와 자연히 일치해 별도 문구가 필요 없다. 유입 이벤트는 공유가 실제 유입을 만드는지 측정하기 위한 것이다

#### 안내 화면 손질

- **파일**: `community_detail_page.dart`
- **변경 내용**: 삭제·오류 안내 화면에 돋보기 든 캐릭터(라우터의 없는 페이지 화면과 같은 에셋)를 넣고, 버튼 색을 커뮤니티 파랑으로 맞췄다
- **이유**: 딥링크로 이 화면에 도착하는 경우가 생기는 만큼, 커뮤니티의 톤과 이어지게 한다

### 🔧 주요 변경사항 상세

#### 릴리스 순서 제약

도메인의 앱 링크 인증 파일에는 모집글 경로가 이미 등록되어 있다. 경로 해석 없는 앱이 새 도메인 선언과 함께 나가면 링크가 앱만 열고 글로 이어지지 않으므로, **이 작업은 반드시 v3 와 같은 릴리스로 나가야 한다.** 부득이 빠지면 웹 인증 파일에서 `/g` 경로를 임시로 뺀다.

**특이사항**:
- 존재하지 않는 글 id 는 상세의 기존 안내 화면이 받는다. 해석할 수 없는 링크(`/g/abc`)는 무시되며, 원시 경로가 라우터로 전달되는 경우에도 별칭이 같은 안내 화면으로 받아준다
- 구버전 앱 사용자의 링크는 브라우저로 열려 웹 상세가 받는다
- 기존 `copsandrobbers://join/{code}` 스킴은 open 규약 이전의 형태라 정비를 별도 작업으로 남겼다 (DEEPLINK.md)

### 🧪 테스트 및 검증

- 실행 중 링크: `/g`·`/ja/g` 경로와 커스텀 스킴 모두 상세가 열리고, 원시 경로가 별칭 라우트로 수렴하는 것을 이동 로그로 확인
- 종료 상태 링크: 스플래시를 거쳐 상세로 정확히 1회 이동, 뒤로 가기는 커뮤니티 목록으로 떨어짐
- 재실행(링크 아님): 상세 재진입 없이 홈, 보존값 찌꺼기 없음
- 미로그인: 링크 진입 → 로그인 화면 → 로그인 완료 직후 보존해 둔 글 상세가 자동으로 열림
- 초대 우선: 초대 코드와 글 id 가 함께 보존된 상태에서 로그인하면 초대 흐름만 진행되고 글은 버려짐
- 잘못된 링크: 존재하지 않는 글 id 는 삭제 안내 화면, 해석할 수 없는 링크는 무시
- 공유 버튼: 공유 시트에 "글 제목 + 링크" 형태 확인
- 안내 화면: 캐릭터와 커뮤니티 파랑 버튼 적용 확인
