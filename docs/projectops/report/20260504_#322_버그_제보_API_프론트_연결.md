### 📌 작업 개요

백엔드 `api-docs.json v2.5.0`에 추가된 버그 제보 API(`POST /api/bugs`)를 프론트에 연동. 설정 화면의 "버그 제보" 항목에서 텍스트 입력 → API 제출 → 결과 피드백까지 전체 플로우 구현.

기존 설정 페이지에서는 TODO 주석으로 placeholder만 존재했고, 실제 백엔드 연결이 없는 상태였음.

---

### 🎯 구현 목표

- Clean Architecture 3계층(Data/Domain/Presentation) 구조에 맞춰 `bug` feature 신설
- Retrofit 기반 `BugRemoteDataSource` 추가 및 JWT 자동 주입(AuthInterceptor) 활용
- 1000자 제한·빈 문자열 차단 등 서버 스펙(0~1000자) 준수
- 로딩/성공/실패/인증 만료 케이스별로 사용자 피드백 분기

---

### ✅ 구현 내용

#### 1) API 엔드포인트 상수 추가
- **파일**: `lib/core/constants/api_endpoints.dart`
- **변경 내용**: `static const String reportBug = '/api/bugs';` 추가
- **이유**: 엔드포인트 중앙화 정책에 따라 모든 API 경로는 `ApiEndpoints`에 등록

#### 2) DTO 모델 정의 (Freezed)
- **파일**: `lib/features/bug/data/models/bug_report_request_model.dart`
- **변경 내용**: `BugReportRequestModel({required String content})` 정의
- **이유**: 서버 스펙 `content` 필드만 존재. Freezed로 불변 객체 + JSON 직렬화 자동 생성

#### 3) Retrofit DataSource 추가
- **파일**: `lib/features/bug/data/datasources/bug_remote_datasource.dart`
- **변경 내용**: `@RestApi()` + `@POST(ApiEndpoints.reportBug)` 메서드 1개
- **이유**: 응답 본문이 없는 201 응답이라 반환 타입은 `Future<void>`. 토큰은 AuthInterceptor가 자동 주입하므로 헤더 처리 불필요

#### 4) Domain Repository 인터페이스 + 구현체
- **파일**:
  - `lib/features/bug/domain/repositories/bug_repository.dart`
  - `lib/features/bug/data/repositories/bug_repository_impl.dart`
- **변경 내용**: `reportBug({required String content})` 단일 메서드. 구현체에서 `DioExceptionHandler.handle(e)`로 `DioException → AppException` 변환
- **이유**: 프로젝트 표준 에러 처리 패턴 적용. catch 블록에서 try-catch만으로 충분

#### 5) Riverpod Provider 추가
- **파일**: `lib/features/bug/presentation/providers/bug_provider.dart`
- **변경 내용**: `bugRemoteDataSourceProvider`, `bugRepositoryProvider` 두 개의 Function Provider
- **이유**: 단순 일회성 호출이라 별도 Notifier 없이 Repository만 노출. UI에서 직접 호출

#### 6) `TextSubmitPage`에 `maxLength` 옵션 추가
- **파일**: `lib/core/widgets/pages/text_submit_page.dart`
- **변경 내용**: `int? maxLength` 파라미터 추가, `TextField.maxLength`에 전파
- **이유**: 서버 스펙(최대 1000자)을 입력 단계에서 차단. Material 기본 카운터(`현재/최대`)가 자동 표시되어 별도 카운터 위젯 불필요

#### 7) 설정 페이지에 실제 API 연동
- **파일**: `lib/features/settings/presentation/pages/settings_page.dart`
- **변경 내용**: 기존 TODO placeholder 제거 → `_submitBugReport()` 메서드로 교체. `maxLength: 1000` 적용
- **이유**: 실제 백엔드 호출 + 로딩 다이얼로그 + 결과 피드백 일원화

#### 8) 로딩 메시지 카테고리 추가
- **파일**:
  - `lib/core/services/loading_message_service.dart`
  - `assets/messages/loading_messages.json`
- **변경 내용**: `LoadingCategory.bugReport` enum 추가, JSON에 5개 메시지(예: "신고서 작성 중...", "본부에 보고서 제출 중...") 등록
- **이유**: 게임 컨셉(경찰/도둑)에 맞는 도메인 친화적 로딩 문구 제공

### 🔧 주요 변경사항 상세

#### `_submitBugReport()` 결과 처리 플로우 (settings_page.dart)

API 호출 결과별로 Navigator 스택 정리 정책을 분리한 부분이 핵심.

```dart
await AppPopup.showRandomLoading(...);  // ① 로딩 다이얼로그 표시

try {
  await ref.read(bugRepositoryProvider).reportBug(content: content);
  // ② 성공: loading + 입력 페이지 모두 닫고 설정으로 복귀
  if (navigator.canPop()) navigator.pop(); // loading
  if (navigator.canPop()) navigator.pop(); // TextSubmitPage
  AppSnackbar.show(context, message: '버그 제보가 접수되었어요');
} on AuthException {
  // ③ 인증 만료: AuthInterceptor가 강제 로그아웃 + 로그인 화면 이동을 처리
  //    단, 로딩 다이얼로그는 Navigator 스택에 남으므로 명시적으로 닫아준다
  if (navigator.canPop()) navigator.pop();
  return;
} on AppException catch (e) {
  // ④ 일반 실패: loading만 닫고 입력 페이지는 유지(재시도 가능)
  if (navigator.canPop()) navigator.pop();
  AppSnackbar.show(context, message: e.message, backgroundColor: AppColors.red);
}
```

**특이사항**:
- `AuthException` 분기는 빈 catch처럼 보일 수 있지만 의도적임. 강제 로그아웃은 `AuthInterceptor`가 콜백으로 처리하기 때문에 UI는 다이얼로그만 닫으면 됨
- 일반 실패 시 입력 페이지를 유지해 재시도 가능하도록 설계 (성공 시에만 두 단계 pop)
- `mounted` 체크로 위젯 dispose 후 BuildContext 사용 방지

#### `TextSubmitPage` `maxLength` 동작

- `maxLength: 1000` 설정 시 TextField가 1001번째 글자 입력 자체를 차단
- 우측 하단에 `현재/최대` 카운터 자동 표시 (`2/1000` 형식)
- `maxLength: null`일 때는 카운터 미표시 → 다른 화면(이용 후기 등)과의 호환성 유지

#### 위젯 테스트 추가 (`text_submit_page_max_length_test.dart`)

세 가지 행동 검증:
1. `limits_input_to_maxLength_when_maxLength_is_set` — 11자 입력 시도 → 10자만 저장
2. `shows_character_counter_when_maxLength_is_set` — `2/1000` 텍스트 노출 확인
3. `omits_counter_when_maxLength_is_null` — `/` 포함 텍스트 미노출 확인

테스트 컨벤션(`.claude/rules/Agents.md`)에 맞춰 행동 기반 명명, 시스템 경계가 아닌 위젯 자체 동작만 검증.
