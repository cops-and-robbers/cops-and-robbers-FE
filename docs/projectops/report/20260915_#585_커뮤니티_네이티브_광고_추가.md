### 📌 작업 개요

기존 AdMob 초기화와 Firebase Remote Config의 `ads_enabled` 전역 스위치를 재사용해 커뮤니티 목록 및 게시글 상세에 네이티브 광고를 추가했다.
광고를 서버 응답과 분리된 화면 요소로 조합해 콘텐츠 조회, 빈 상태 안내, 댓글 및 채팅 기능이 광고 로드 결과에 영향받지 않도록 구성했다.

### 🎯 구현 목표

- 전체 목록, 우리 동네, 내 모임, 게시글 상세에 화면별 광고 배치 적용
- 커뮤니티 카드와 어울리는 Android·iOS 네이티브 광고 레이아웃 제공
- 광고 비활성화·초기화 실패·로드 실패 시 기존 콘텐츠 흐름 유지
- 검색·스크랩·알림 목록 제외

### ✅ 구현 내용

#### 광고 공통 서비스 및 단위 ID

- **파일**: `lib/core/services/ads/ad_service.dart`, `lib/core/services/ads/ad_unit_ids.dart`
- **변경 내용**: `ads_enabled`의 현재 값과 실시간 변경을 전달하는 Provider 및 SDK 초기화 상태 조회 추가. 커뮤니티 네이티브 광고용 플랫폼별 단위 ID 분기 추가
- **이유**: 전면 광고와 네이티브 광고가 같은 전역 광고 게이트와 초기화 흐름을 공유하고, 개발 빌드에서는 공식 테스트 광고를 사용하도록 구성
- **식별 정보**: 운영 및 테스트 광고 단위 ID는 `{ADMOB_AD_UNIT_ID}`로 마스킹

#### 공통 네이티브 광고 카드

- **파일**: `lib/features/community/presentation/widgets/community_native_ad.dart`
- **변경 내용**: 광고 활성화 확인, SDK 초기화, 슬롯별 `NativeAd` 로드, 표시 및 해제를 담당하는 공통 위젯 추가
- **이유**: 각 화면은 배치만 결정하고 광고 생명주기와 실패 처리는 한 컴포넌트에서 관리하도록 구성

광고가 꺼져 있거나 아직 로드되지 않았거나 로드에 실패하면 빈 공간을 남기지 않는다. 로드된 광고는 화면 이탈 시 해제하며, 표시 높이는 글자 크기와 미디어 영역의 최소 크기를 반영한다. AdChoices는 우측 상단에 두고 동영상은 음소거 상태로 시작하도록 요청한다.

#### 커뮤니티 화면별 배치

- **파일**: `lib/features/community/presentation/pages/community_page.dart`, `lib/features/community/presentation/widgets/community_feed_list.dart`, `lib/features/community/presentation/widgets/community_chat_room_list.dart`, `lib/features/community/presentation/pages/community_detail_page.dart`
- **변경 내용**:
  - 전체: 첫 게시글 위에 광고 1개, 이후 실제 게시글 5개마다 광고 1개 배치
  - 우리 동네: 기존 준비 중 안내 위에 광고 1개 배치
  - 내 모임: 첫 채팅방 위에 광고 1개, 이후 실제 채팅방 5개마다 광고 1개 배치. 빈 목록에서도 광고 아래에 기존 빈 상태 안내 유지
  - 게시글 상세: 댓글 수 표시 다음, 댓글 목록 앞에 광고 1개 배치. 댓글이 없어도 게시글 상세가 표시되면 광고 슬롯 유지
- **이유**: 광고를 콘텐츠 모델과 페이지 커서에 섞지 않고 실제 콘텐츠 개수를 기준으로 일관된 간격을 유지

검색 결과는 `showAds` 기본값 `false`를 사용하며, 스크랩과 알림 화면에는 네이티브 광고 컴포넌트가 연결되지 않았다. 로그인하지 않은 내 모임 화면은 기존 로그인 안내 분기를 유지한다.

#### Android 네이티브 광고 UI

- **파일**: `android/app/src/main/kotlin/com/elipair/copsandrobbers/CommunityNativeAdFactory.kt`, `android/app/src/main/kotlin/com/elipair/copsandrobbers/MainActivity.kt`
- **변경 내용**: `communityNative` 팩토리 등록·해제 및 Android `NativeAdView` 레이아웃 구현
- **이유**: Flutter에서 전달한 광고 배지, 글자 크기, 색상 값을 사용해 앱 카드 스타일과 맞추고 SDK가 제목, 본문, 광고주, 아이콘, 행동 유도 문구 및 미디어 자산을 관리하도록 구성

미디어 영역은 120×120으로 고정하고 `CENTER_INSIDE`를 적용했다. 상단에는 광고 배지와 AdChoices 영역을 확보했으며 앱의 Pretendard 글꼴을 재사용한다.

#### iOS 네이티브 광고 UI

- **파일**: `ios/Runner/CommunityNativeAdFactory.swift`, `ios/Runner/AppDelegate.swift`, `ios/Runner.xcodeproj/project.pbxproj`
- **변경 내용**: `communityNative` 팩토리 등록, iOS `NativeAdView` 레이아웃 구현 및 Swift 소스의 빌드 대상 등록
- **이유**: Android와 동일한 정보 구조와 크기의 커뮤니티 카드형 광고를 제공하고 Google Mobile Ads 플러그인이 네이티브 자산의 표시와 터치를 처리하도록 구성

미디어 영역은 120×120, `scaleAspectFit`으로 구성했다. 광고 배지, 제목, 본문, 광고주, 아이콘 및 행동 유도 문구를 SDK 뷰에 연결하고 Pretendard 글꼴 등록 실패 시 시스템 글꼴을 사용한다.

#### 다국어 광고 표기

- **파일**: `lib/l10n/app_ko.arb`, `lib/l10n/app_en.arb`, `lib/l10n/app_ja.arb`, `lib/l10n/app_localizations.dart`, `lib/l10n/app_localizations_ko.dart`, `lib/l10n/app_localizations_en.dart`, `lib/l10n/app_localizations_ja.dart`
- **변경 내용**: 네이티브 광고 배지 문구를 한국어·영어·일본어로 추가하고 생성된 현지화 접근자에 반영
- **이유**: 광고임을 사용 언어에 맞게 명확히 표시

### 🔧 주요 동작 흐름

1. 화면이 `adsEnabledProvider`에서 `ads_enabled` 값을 확인한다.
2. 활성 상태이면 공통 광고 카드가 기존 `AdService`의 SDK 초기화를 기다린다.
3. 초기화 완료 후 플랫폼에 맞는 `{ADMOB_AD_UNIT_ID}`와 `communityNative` 팩토리로 광고를 요청한다.
4. Android 또는 iOS 팩토리가 SDK 자산을 커뮤니티 카드형 레이아웃에 연결한다.
5. 광고가 로드되면 슬롯을 표시하고, 실패하거나 비활성화되면 슬롯 전체를 숨긴다.
6. 위젯이 제거되면 보유한 광고 객체를 해제한다.

### 📌 참고사항

- Remote Config의 `ads_enabled` 기본값은 `false`이며 초기화되지 않은 상태에서도 광고를 표시하지 않는다.
- 클라이언트는 `MediaView`를 사용하며 수신한 광고 자산을 표시한다. 제공 가능한 미디어 유형은 광고 단위 및 AdMob 게재 설정의 영향을 받는다.
- 광고 로드 실패는 기존 게시글, 준비 중 안내, 빈 채팅방 안내, 댓글 목록 및 입력 기능을 막지 않는다.
