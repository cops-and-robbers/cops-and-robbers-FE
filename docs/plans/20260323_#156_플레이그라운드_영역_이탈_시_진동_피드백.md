# 🎯 플레이그라운드 영역 이탈 시 진동 피드백

**이슈**: [#156](https://github.com/cops-and-robbers/cops-and-robbers-FE/issues/156)
**브랜치**: `20260322_#156_플레이그라운드_영역_이탈_시_진동_피드백`

---

## 1. 요약

게임 중 GPS 위치 업데이트 시 플레이그라운드 반경 이탈을 감지하여 진동 피드백 제공.
삼각함수 없는 제곱 거리 비교로 배터리 최적화. 서버 통신 불필요 (클라이언트 단 로직).

---

## 2. 배경 및 목적

- **문제**: 플레이그라운드 외부 오버레이가 지도에 표시되지만, 게임에 집중하면 이탈 인지 어려움
- **목표**: 이탈 시 촉각 피드백으로 즉각적 알림
- **범위**: 클라이언트 단 로직만

---

## 3. 요구사항

### 필수 (P0)

- [ ] 플레이그라운드 반경 벗어나면 강한 진동
- [ ] 연속 진동 방지 (상태 전환 시에만 진동)
- [ ] 배터리 최적화 (제곱 거리 비교, 삼각함수 0회/프레임)

### 중요 (P1)

- [ ] 경계 근처(90%) 접근 시 약한 진동 경고
- [ ] 체포된 도둑 / 게임 종료 시 진동 비활성화

### 제외 (Out of Scope)

- 서버에 이탈 정보 전송
- 이탈 시 UI 알림 (배너/다이얼로그)

---

## 4. 접근 방식

### 선택: 기존 `_startHeadingTracking()` GPS 스트림에 이탈 감지 로직 추가

- 이미 양 팀 공통으로 `distanceFilter: 0` GPS 스트림 존재
- 새 스트림 추가 불필요 → 배터리 영향 없음
- `game_page.dart` 1개 파일만 수정

### 기각된 대안

| 대안 | 기각 이유 |
|------|----------|
| 별도 `_startBoundaryChecking()` 스트림 | GPS 구독 중복 → 배터리 낭비 |
| `Geolocator.distanceBetween()` | Haversine 삼각함수 6회/프레임 → 불필요한 연산 |
| `vibration` 패키지 | `HapticFeedback`이 이미 flutter/services.dart에 포함 |

---

## 5. 거리 계산 최적화 (수학적 접근)

### 캐싱할 값 (area 로드 시 1회 계산)

```
_pgCenterLat          // 플레이그라운드 중심 위도
_pgCenterLng          // 플레이그라운드 중심 경도
_cosLat               // cos(centerLat × π / 180) — 경도 보정 계수
_sqRadiusDeg          // (radius / 111320)² — 이탈 판단 임계값
_sqWarningDeg         // _sqRadiusDeg × 0.81 — 90% 경고 임계값 (0.9²)
```

### GPS 업데이트 시 연산 (매 프레임)

```
dx = lat - _pgCenterLat
dy = (lng - _pgCenterLng) × _cosLat
sqDist = dx² + dy²

if sqDist > _sqRadiusDeg   → 이탈 (강한 진동)
elif sqDist > _sqWarningDeg → 경고 (약한 진동)
else                        → 안전 (진동 없음)
```

**연산량**: 곱셈 3회 + 뺄셈 2회 + 비교 2회. 삼각함수 0회.
**정확도**: 플레이그라운드 반경 수백m~수km 범위에서 평면 근사 오차 < 0.1%

---

## 6. 상태 머신 (연속 진동 방지)

```
상태: _inside → _warning → _outside

전이 규칙:
  _inside  + sqDist > _sqWarningDeg  → _warning  (약한 진동 1회)
  _warning + sqDist > _sqRadiusDeg   → _outside  (강한 진동 1회)
  _outside + sqDist ≤ _sqRadiusDeg   → _warning  (진동 없음)
  _warning + sqDist ≤ _sqWarningDeg  → _inside   (진동 없음)

같은 상태 유지 시 → 진동 없음 (연속 진동 방지)
복귀 시 → 무음 (진동 없음) — 자연스러운 UX
```

## 7. 구현 계획

### 수정 파일: `lib/features/game/presentation/pages/game_page.dart`

#### Step 1: import 추가

- `flutter/services.dart` import 추가 (`HapticFeedback` 사용)
- 현재 game_page.dart에 미포함 상태

#### Step 2: 필드 추가

- `_BoundaryState` enum (`inside`, `warning`, `outside`) — 파일 상단 또는 클래스 외부
- `_boundaryState = _BoundaryState.inside`
- 캐싱 필드: `_pgCenterLat`, `_pgCenterLng`, `_cosLat`, `_sqRadiusDeg`, `_sqWarningDeg` (모두 `double?`)

#### Step 3: area 로드 시 캐싱 (라인 761-773 확장)

- 기존 `ref.listen(gameAreaProvider)` 콜백 내부에서 캐싱 값 계산
- `cos()` 1회만 호출 (이후 `_cosLat`으로 재사용)
- `_sqRadiusDeg = (radius / 111320)²`, `_sqWarningDeg = _sqRadiusDeg × 0.81`

#### Step 4: `_checkBoundary(Position)` 메서드 추가

- 캐싱 값 null 체크 → null이면 early return
- 체포 상태 체크: `ref.read(gameEventNotifierProvider).arrestedParticipantIds.contains(widget.participantId)` → 스킵
- 게임 종료 체크: `ref.read(gameEventNotifierProvider).isGameOver` → 스킵
- 제곱 거리 계산 (곱셈 3회 + 뺄셈 2회)
- 상태 전환 판단 → 전환 시에만 `HapticFeedback` 호출

#### Step 5: `_startHeadingTracking()` 콜백 확장 (라인 337-344)

- 기존 `_updateHeadingMarker(pos)` 호출 후 `_checkBoundary(pos)` 추가
- heading 스트림은 `distanceFilter: 0`이므로 모든 GPS 업데이트에서 호출됨

#### Step 6: 진동 실행

- 이탈 (`_warning → _outside`): `HapticFeedback.heavyImpact()`
- 경고 (`_inside → _warning`): `HapticFeedback.lightImpact()`
- 복귀 (`_outside → _warning`, `_warning → _inside`): 진동 없음 (무음 복귀)

## 8. 고려사항

| 항목 | 처리 방법 |
|------|----------|
| 체포된 도둑 | `arrestedParticipantIds.contains(participantId)` → 스킵 |
| 게임 종료 | `isGameOver` → 스킵 |
| area 미로드 | `_pgCenterLat == null` → 스킵 |
| 더미 모드 | `widget.isDummy` → 스킵 (heading 스트림 자체가 비활성) |
| import | `flutter/services.dart` 추가 필요 (현재 미포함) |
| ref 접근 | `ConsumerState`이므로 콜백 내 `ref.read()` 사용 가능 |
| 복귀 시 진동 | 영역 복귀 시 무음 (진동 없음) — 자연스러운 UX |
