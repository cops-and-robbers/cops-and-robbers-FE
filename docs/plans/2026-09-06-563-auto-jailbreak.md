## 목표와 범위

일반 게임의 수감된 본인이 이번 체포 이후 감옥 안에 들어온 뒤 경계를 확실히 벗어나면 기존 탈옥 API를 호출한다. 원형·폴리건 모두 지원한다. 수동 탈옥 버튼과 확인 모달은 항상 제공하고, 요청 중에만 중복 조작을 막는다. 기존 지도 차단 모달 구조는 유지한다.

지도 차단 해제·카메라 이동·새 하단 카드·서버 체포 규칙 변경·새 위치 추적 플러그인·위치 이력 디스크 저장은 이번 범위에서 제외한다.

## 동작 계약

자동 감지 상태는 `진입 대기 → 이탈 감시 → 요청 대기/처리`로 제한한다. 네트워크 요청 소유권은 notifier 한 곳에서 관리하고, GPS 판정기는 API·Riverpod·Position 타입을 알지 못하게 한다.

| 입력/사건 | 처리 |
| --- | --- |
| 본인 체포 | 새 로컬 주기 시작, 이전 위치 후보·진입 이력·재시도 폐기 |
| 감옥 밖에서 체포 | 밖에 머물러도 요청하지 않음 |
| 감옥 안에서 체포 | 체포 이후 유효한 내부 표본으로 진입 확정 가능. 밖에 나갔다 재진입할 필요 없음 |
| 내부 진입 확정 | 이탈 감시 시작 |
| 이탈 확정 | 연결·서버 동기화 완료·게임 진행·수감·미요청 상태 확인 후 자동 요청 |
| 이탈 후보 중 내부/불확실 위치 | 연속 이탈 후보 초기화. 이미 확정한 이번 주기의 진입 이력은 유지 |
| 본인 ESCAPE / 서버 ALIVE | 자동 감지 종료 |
| 재체포 / 구역 변경 / 재연결 | 이전 자동 감지 주기 무효화. 재연결은 서버 동기화 완료 후 새 내부 표본부터 시작 |
| 게임 종료 / 퇴장 / dispose | 감지와 요청 결과 적용 중지. 과거 finally가 새 요청 상태를 해제하지 못함 |
| 수동 탈옥 | GPS 진입/정확도/이탈 조건 없이 동일 API 경로 사용. 본인 수감 등 기존 권한·상태 조건은 유지 |

### GPS 판정 초깃값

아래 값은 실측 결과가 아닌 구현·실기 검증 출발점이다. 실제 구현은 `JailEscapeDetector` 생성자 기본값에 단위를 명시한다. 설정 화면이나 Remote Config는 추가하지 않는다.

| 항목 | 초기 제안 |
| --- | --- |
| 표본 유효성 | 유한하고 범위 안인 좌표, 유한한 양수 accuracy ≤ 10m, 표본 나이 0~5초 |
| 순서 | 동일 timestamp 또는 역순 표본은 연속 표본으로 세지 않음 |
| 내부 확정 | 서로 다른 유효 내부 표본 2개 이상, 1초 이상 지속 |
| 외부 확정 | contains=false이며 경계 밖 거리 > max(3m, 표본 accuracy), 서로 다른 유효 표본 2개 이상, 2초 이상 지속 |
| Android 요청 주기 | 기존 단일 위치 스트림에 2초를 명시. OS의 실제 전달 간격을 보장하지는 않음 |
| 수신 공백 | 10초 넘는 표본 간격은 연속 후보를 끊음. 새 표본으로 다시 확인. 표본 나이 제한 5초는 유지 |

경계 거리: 원형은 abs(중심 거리−반경), 폴리건은 현재 지점을 기준으로 위경도를 로컬 미터 좌표로 환산한 뒤 모든 선분까지 거리의 최솟값. 선분 투영은 끝점으로 clamp하고 길이 0인 변도 처리한다. 내부/외부 부호는 기존 contains로 결정한다. 다각형 변 순서는 서버가 준 순서를 유지하며 재정렬하지 않는다. 기존 한국·게임 규모 평면 근사 범위를 유지한다.

작거나 좁은 감옥에서는 위 기준으로 자동 판정이 늦거나 실패할 수 있다. accuracy는 보장이 아닌 추정치이므로 오탈옥을 완전히 막는다고 주장하지 않는다. 작은 원·좁은/오목한 폴리건 실기에서 오탈옥·미감지·이탈 후 지연을 기록해 보정한다. 안전한 자동 판정이 어려운 경우 수동 버튼을 사용한다.

## 구현 순서

### 1. 도형과 순수 판정기

- `area_shape.dart`: `distanceToBoundaryInMeters(GeoPoint)` 추가. contains·카메라·기존 플레이그라운드 판정은 변경하지 않음.
- `domain/jail_escape_detector.dart` 신규: 좌표·정확도·표본 시각·현재 시각을 받아 진입/이탈 후보를 추적하고 이탈 준비 여부만 반환. 새 타이머·위치 구독 없음.
- `JailEscapeDetector` 생성자 기본값으로 판정값을 정의해 중복 설정을 두지 않는다.
- 기존 `area_shape_test.dart` 확장과 신규 `jail_escape_detector_test.dart`에서 경계·오목한 부분·표본 연속성·체포 초기화의 실패 테스트를 먼저 작성한다. 내부 기하 함수나 엔티티를 mock하지 않는다.

### 2. 공통 탈옥 요청 경합 보호

- `game_event_provider.dart`: escape의 결과를 성공/실패/무시/동기화 필요로 구분하는 작은 enum으로 반환한다. 기존 예외 흡수 정책은 유지한다.
- 별도 escape 요청 토큰으로 자동·수동 중복을 차단한다. 전역 isApiLoading만으로 가드하지 않는다(다른 참가자 이벤트도 이 값을 변경함).
- 요청 시작 시에는 수감 상태를 유지한다. HTTP 성공 또는 본인 ESCAPE로 확정한다. 실패 때문에 수감 상태를 무조건 다시 쓰는 rollback을 없앤다.
- 본인 체포·서버 재동기화·연결 단절·종료 시 로컬 상태 revision을 갱신하고 요청이 캡처한 revision과 비교한다. 늦은 성공/실패/finally가 새 상태를 변경하지 못한다. 일반 체포 카운터는 타인 체포/닉네임에도 의존하므로 주기 키로 재사용하지 않는다.
- 서버 ESCAPE가 HTTP보다 먼저 오면 그 상태를 유지한다. 뒤늦은 HTTP 오류로 수감 복원/실패 알림을 만들지 않는다. 이후 ARREST가 왔다면 새 수감 상태를 유지한다.
- 두 수동 호출자는 확인 모달을 연 시점의 주기를 캡처해 확인 시 재검사한다. 이전 체포에서 연 모달이 재체포 후 새 탈옥을 요청하지 못하게 한다.
- 기존 provider 테스트의 REST·STOMP 경계 fake에 지연 응답을 추가해 실제 notifier의 상태 순서를 검증한다.

### 3. 위치 스트림과 재연결 연결

- `game_page.dart`: 기존 스트림의 서버 송신 가드 이전에 순수 판정기를 호출한다. 진입 이력은 _lastSentPosition으로 만들지 않는다.
- 기존 종료·재연결·수감 상태에 더해 서버 동기화 진행/실패 중에는 자동 요청을 막는다.
- `_syncGameStateOnReconnect`의 본인 상태 적용은 로컬 revision도 확인한다. 조회 중 본인 체포 상태 이벤트가 발생하면 오래된 본인 snapshot을 적용하지 않는다. 집합이 동일한 JAILED→ALIVE→JAILED 테스트를 포함한다. 동기화 요청끼리 역순 완료해도 최신 요청만 적용한다.
- 연결이 유지되고 새 체포/동기화가 없는 짧은 로컬 가드 동안만 이탈 준비 상태를 유지하며, 가드 해제 후 최신 유효 외부 표본으로 재평가한다. 실제 재연결/상태 불명확 구간을 넘어서는 진입 이력은 유지하지 않는다.
- API 오류 후에는 먼저 서버 상태를 재조회한다. 이미 ALIVE면 종료, JAILED거나 조회 실패면 수동 버튼을 안내하고 자동 요청을 반복하지 않는다. 명확한 새 내부→외부 확인에서만 자동 재시도한다. 밖에 계속 머문 사용자는 수동으로 재시도할 수 있다.
- 프로세스 재시작 시 이력을 디스크에서 복원하지 않는다. 같은 체포인지 구분할 서버 주기 ID가 없으므로 수감 동기화 후 새 진입 확인을 요구하고, 이미 밖이면 수동으로 처리한다.

### 4. 기존 모달 안내와 수동 버튼

- `arrest_lock_overlay.dart`: 구조·지도 차단을 유지하면서 자동 감지 안내와 수동 탈옥 버튼을 함께 표시한다. 버튼은 실패 여부와 무관하게 보이고 요청 중에만 비활성화한다.
- `participant_overlay.dart`: 같은 요청 가드 및 확인 시 주기 재검사 적용.
- `app_ko.arb`, `app_en.arb`, `app_ja.arb`: 자동 탈옥 안내/실패 시 수동 재시도 안내를 추가한다. 안내는 실제 상태 이상으로 성공을 약속하지 않는다.
- 기존 GameActionModal의 체포 용도는 변경하지 않는다. 탈옥 성공 진동·시스템 메시지는 기존 STOMP 경로를 유지해 HTTP 성공에서 중복 발생시키지 않는다.

### 5. 검증과 인수 기준

| 검증 | 반드시 증명할 결과 |
| --- | --- |
| 원형·폴리건 | 내부·경계·외부, 오목한 홈과 꼭짓점에서 실제 도형 기준 판정 |
| GPS | 유효한 이번 주기 내부→외부에서만 자동 요청. 오래됨·부정확·중복·역순·긴 공백은 연속 이탈을 만들지 않음 |
| 반복 플레이 | 체포→탈옥→재체포가 반복되어도 이전 진입·요청·모달이 새 주기에 영향 없음 |
| 비동기 | 자동+수동 동시 조작은 요청 하나. HTTP 성공/실패·ESCAPE·ARREST·동기화의 역순 완료가 최신 상태를 덮지 않음 |
| 생명주기 | 종료·퇴장·dispose 이후 늦은 응답으로 상태/로딩/UI 변경 없음 |
| 복구 | 실패/재연결/재시작 시 오탈옥·tick별 요청 폭주 없음. 수동 버튼으로 회복 가능 |
| UI 회귀 | 모달 지도 차단 유지, 수동 버튼 상시 표시 및 확인 유지, 요청 중 비활성화, 긴 번역/큰 글씨에서 overflow 없음 |
| 실기 | Android/iOS의 원형·작은 감옥·좁은/오목한 폴리건, 화면 켜짐/꺼짐, 네트워크 단절/복귀를 분리 측정 |

각 단계는 실패하는 행동 테스트 → 최소 구현 → 해당 테스트 통과 순서로 진행한다. 중요한 순서 보호를 잠시 제거하면 해당 회귀 테스트가 실패하는지 검증한다. 새 테스트 프레임워크 없이 기존 flutter_test·경계 fake·Completer·제어된 시각을 사용한다.

명령: 관련 `flutter test <경로>` → `flutter gen-l10n` → `python3 docs/i18n/_lint_tone.py` → `flutter test` → `flutter analyze` → `git diff --check`. 생성 어노테이션 변경 시에만 build_runner 실행. 테스트 실행 SDK는 프로젝트 wrapper 설치 여부를 확인해 선택한다. 실기 미검증은 별도로 표시하고 정적 테스트 통과로 대체하지 않는다.

## FE만으로 보장할 수 없는 범위

현실에서 다시 잡혔지만 서버가 아직 JAILED이면 현재 계약은 재체포를 거절한다. 위치만으로 현실의 재체포를 추측하지 않는다. 또한 로컬 revision은 오래된 응답의 화면 덮어쓰기를 막을 뿐, 이미 전송된 HTTP 요청의 서버 실행을 취소하지 않는다. 서버 주기 ID/조건부 탈옥/이벤트 순서 계약 없이 임의의 서버 처리 역전까지 해결했다고 주장하지 않는다. 해당 문제가 재현되면 BE 계약 후속으로 분리한다.

이벤트 eventId·timestamp는 필드 존재만 확인됐다. eventId 중복 제거는 중복 관측 근거와 서버 계약을 확인해 필요한 범위에만 적용하고 timestamp를 검증 없이 전역 정렬 키로 쓰지 않는다.

## 완료 기준

일반 게임에서 원형·폴리건 자동 탈옥과 수동 복구가 동작하고, 위 경합/회귀 테스트가 통과하며, 실기 검증 결과 또는 미검증 한계가 기록되어야 구현 완료로 보고한다. 이번 문서 작성은 구현 완료가 아니다. 커밋·push·기존 이슈/볼트 상태 변경은 포함하지 않는다.

## 백그라운드 리뷰 후 보강

- 자동 판정에서 재연결 모달 표시 여부를 제거했다. 프레임이 정지해 모달 닫힘이 보류돼도 연결·참가자 동기화가 완료되면 GPS 판정은 진행한다.
- Android 위치 요청 주기는 2초, 연속 표본 허용 간격은 10초로 조정했다. 정확도·표본 나이·경계 거리 검사는 유지한다.
- 실제 STOMP disconnected/error, ERROR 프레임, 의도적 disconnect에서 이전 탈옥 응답과 수동 확인 주기를 무효화한다. 이미 전송한 HTTP 요청의 서버 실행을 취소하는 것은 아니다.
- 참가자 동기화 실패 시 연결이 살아 있는 동안 2초·4초 뒤 최대 두 번 재시도한다. 재연결·dispose에서 예약을 취소하고, 소진 후에는 앱 복귀 시 다시 동기화한다.
- 실제 GamePage와 notifier를 사용한 통합 테스트에서 paused 중 추가 프레임 0회로 재연결→HTTP 실패→재시도→GPS 내부/외부→탈옥 API 호출을 검증한다. 기존 모달 가드를 복원하면 API 호출 0회로 실패하는 음성 대조도 확인했다.
- Android/iOS 실기에서 화면 끄기·다른 앱 전환·절전 정책·위치 권한 조합은 아직 검증하지 않았다. 앱 종료(terminated) 후 실행 보장은 범위 밖이다.
- 최종 검증: 관련 테스트 5개 파일의 60개 테스트 통과, `flutter analyze` 이슈 없음, `git -c core.whitespace=cr-at-eol diff --check` 통과. 전체 테스트 스위트는 이번 보강에서 재실행하지 않았다.
