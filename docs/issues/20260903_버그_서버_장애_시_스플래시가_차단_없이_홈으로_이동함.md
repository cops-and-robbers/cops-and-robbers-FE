# ❗ [버그][Flutter][스플래시] 서버 장애 시 스플래시가 차단 없이 홈으로 이동함

## 🗒️ 설명

서버가 내려가 있거나 5xx를 내는 동안 앱을 콜드 스타트하면, 스플래시가 **아무 안내 없이 홈으로 이동**한다. 사용자는 서버 문제인 줄 모른 채 홈에서 다시 실패를 겪고, 진행 중이던 게임이 있어도 복귀하지 못한다.

> [!WARNING]
> 게임 중이던 사용자가 홈에 갇힌다. 홈의 활성 게임 안전망(`home_page.dart:112`)도 같은 API를 부르므로 서버가 내려간 동안은 복구가 안 된다.

**원인**

스플래시의 활성 게임 조회(`_navigateToNextScreen`) 실패 처리가 두 갈래 모두 홈 fallback으로 끝난다.

| 실패 종류 | 예외 | 현재 동작 | 위치 |
|---|---|---|---|
| 연결 거부·타임아웃 (서버 다운) | `NetworkException` | 비복구 모드에서 홈 fallback | `splash_page.dart:320-328` |
| 500·502·503 | `ServerException` | "비네트워크 에러"로 분류돼 홈 fallback | `splash_page.dart:338-346` |

기기 연결 사전 체크(`connectivity.isConnected()`)는 이미 통과한 뒤라, 이 실패는 사실상 전부 **서버 쪽 문제**다. 그런데 `isNetworkFailure`(`network_failure_detector.dart:20`)는 5xx를 명시적으로 false로 두고, 재시도(`_fetchActiveGameWithRetry`, `splash_page.dart:502`)는 네트워크성 실패만 대상이라 5xx는 즉시 rethrow돼 generic catch로 떨어진다.

같은 화면에 있는 "네트워크 연결 실패" 재시도 모달(`_showNetworkErrorDialog`)은 원시 `DioException`에만 걸리는데, Repository가 항상 `AppException`으로 변환하므로 실제로는 도달하지 않는다.

<br>

## 🔄 재현 방법

1. 서버를 내리거나 프록시가 502/503을 내도록 한다 (기기 인터넷은 연결된 상태)
2. 로그인된 계정으로 앱을 완전히 종료했다가 콜드 스타트
3. 스플래시가 약 2초 뒤 홈으로 이동하고, 안내가 전혀 없음

<br>

## ✅ 예상 동작

- 기기 오프라인과 같은 방식으로 스플래시에서 **차단하고 재시도**를 받는다. 문구는 오프라인("인터넷 연결이 필요해요")과 구분되는 서버 장애 안내("서버에 문제가 생겼어요")
- 재시도가 성공하면 원래 흐름(홈 / 대기실 / 게임 복귀)으로 이어진다
- 파싱 에러 같은 진짜 비네트워크 실패만 지금처럼 홈 fallback으로 남긴다

<br>

## 📌 참고

- PR #228 (스플래시 활성 게임 자동 복귀·홈 안전망)에서 "비네트워크 에러 → 홈 fallback" 행이 생겼다. 그때는 콜드 스타트 타임아웃이 대상이라 5xx·서버 다운은 분류 밖에 남았다
- #362 (API 호출 전 네트워크 상태 사전 검증)는 기기 연결만 보므로 이 문제를 잡지 못한다
- Remote Config 점검 모드는 fail-open이라 서버 장애 시 게이트가 열리지 않는다 — 이 차단 화면이 그 자리를 대신한다
