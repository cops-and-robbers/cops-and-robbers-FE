## 본문

## 📝 현재 문제점

- 게임 상태("WAITING", "IN_PROGRESS", "FINISHED" 등), 팀("POLICE", "ROBBER"), 참가자 상태("ALIVE", "JAILED") 같은 값들이 코드 곳곳에서 문자열 리터럴(매직 스트링)로 직접 비교·사용되고 있음
- 동일한 값이 여러 파일에 흩어져 반복 비교되어, 값이 바뀌거나 추가될 때 누락 위험이 큼
- 팀 값이 대문자("POLICE")와 소문자("police")로 혼재되어 있어 불필요한 대소문자 변환 처리가 발생하고 오타·불일치 가능성이 있음
- 상태 값들이 일부 데이터 모델에는 주석으로만 정의되어 있고 실제 코드에서는 활용되지 않아, 오타 시 컴파일 타임에 잡히지 않음
- 채팅 scope/team(`chat_constants.dart`)과 신고 유형(`report_categories.dart`)은 이미 상수/enum으로 잘 정리되어 있으나, 게임·세션·참가자·인증 영역은 정리되지 않아 일관성이 떨어짐
- api-docs.json의 enum 정의(게임 상태, 참가자 상태, 팀, 소셜 로그인 제공자, 디바이스 타입 등)와 코드의 문자열 리터럴이 따로 관리되어 서버 스펙 변경 시 동기화 누락 위험이 있음

## 🛠️ 해결 방안 / 제안 기능

- 흩어진 매직 스트링을 enum 또는 상수(또는 helper 함수)로 추출하여 한 곳에서 관리
- 문자열 직접 비교를 상수/enum 기반 비교로 대체하여 가독성과 타입 안전성 향상
- 팀 값의 대소문자 표현을 통일하고 변환 로직을 중앙화
- 데이터 모델의 주석에만 존재하던 상태 값 정의를 실제 코드 자산으로 전환
- 기존에 잘 정리된 chat_constants.dart / report_categories.dart 패턴을 기준으로 동일한 스타일로 통일

## 🎯 기대 효과

- 오타로 인한 비교 실패를 컴파일 타임 또는 코드 자동완성 단계에서 차단
- 상태/타입 값이 추가·변경될 때 수정 지점이 한 곳으로 모여 누락 위험 감소
- 비즈니스 분기 코드의 가독성 향상 (문자열 비교 → 의미 있는 식별자 비교)
- 서버 api-docs.json enum과의 대응 관계가 명확해져 스펙 동기화 용이

## ⚙️ 작업 내용

조사 결과 아래 영역에서 매직 스트링이 사용되고 있으며, 우선순위 순으로 정리합니다. (작업 중 추가 발견 가능)

- (P0) 게임 상태: "WAITING" / "IN_PROGRESS" / "FINISHED" / "CANCELED" — splash, game_page, game_over_guard, session_creation_flow, home_page, waiting_room, active_game_route 등 약 12개 파일
- (P0) 팀: "POLICE" / "ROBBER" (대문자), "police" / "robber" (소문자) — game_page, waiting_room, participant_overlay, participant_card, team_section, character_assets 등 약 20개 파일, 대소문자 혼재 정리 포함
- (P1) 참가자 상태: "ALIVE" / "JAILED" / "POLICE_WAITING" — game_page, participant_overlay, participant_card 등 약 6개 파일
- (P1) 소셜 로그인 제공자: "GOOGLE" / "APPLE" / "KAKAO" — auth_repository_impl 등에서 하드코딩
- (P1) 디바이스 타입: "IOS" / "ANDROID" — device_info_service, auth_repository_impl, firebase_messaging_service
- (P2) 게임 종료 사유: "ALL_ARRESTED" / "TIME_OVER" — game_page
- (P2) 승리 팀 판정: "POLICE" / "ROBBER" — game_page, game_over_result_dialog
- (P2) 로비/게임 이벤트 type 값("ENTER", "EXIT", "TEAM_UPDATE", "READY_UPDATE", "HOST_CHANGED", "GAME_START", "AREA_UPDATED", "SETTINGS_UPDATED", "KICKED", "ARREST", "ESCAPE", "GAME_OVER", "POLICE_MOVE_START", "LOCATION_REVEAL" 등) — 약 16곳 정리 검토
- (P3, 선택) 기타 매직 스트링(언어 코드 "ko"/"en"/"ja", 스킨 식별자, 에러 코드 등) 정리 검토
- 데이터 모델 주석에만 정의된 상태 값(game_state_model, in_game_participants_response, game_result_response_model)을 상수/enum과 연계
- 참고: 채팅(chat_constants.dart)·신고 유형(report_categories.dart)은 이미 정리되어 있으므로 동일 패턴을 다른 영역에 확장
