## 제목

🚀 [기능개선][게임][QR] 도둑 체포 QR에 만료시각(TTL) 추가하여 재사용 방지

## 본문

## 📝 현재 문제점

- 도둑 체포용 QR 페이로드가 `{"pid": <참가자ID>}` 로 참가자 ID만 인코딩된 정적 값
- 스크린샷이나 사진으로 QR을 미리 저장해두면 동일한 QR로 이후에도 체포 판정이 성립하는 리플레이 공격 위험이 존재
- 특히 도둑이 탈옥한 뒤 경찰이 저장해둔 구 QR을 다시 스캔하면 재체포가 성립될 수 있음
- 체포 판정이 프론트 측에서 이루어지므로 프론트에서 만료 검증을 추가하는 것만으로 해당 시나리오를 차단 가능

## 🛠️ 해결 방안

- QR 페이로드에 만료시각(`exp`) 필드를 추가하여 시간 기반 유효성 부여
- 페이로드 포맷 예시: `{"pid": 102, "exp": 1729508430000}` (exp는 Unix millisecond)
- 도둑 화면에서 QR을 주기적으로 자동 재생성하여 항상 신선한 만료시각 유지 (TTL 30초)
- 경찰 스캐너에서 스캔 시 현재 시각과 `exp`를 비교하여 만료된 QR은 거부 후 안내 문구 표시
- 백엔드 API 스펙은 변경 없음 (체포 요청 시 참가자 ID만 전달)

## ⚙️ 작업 내용

- QR 페이로드 포맷을 `{pid, exp}` 로 확장
- QR 인코딩 / 디코딩 / 만료 검증을 담당할 공통 유틸리티 추출 (도둑 측과 경찰 측이 동일한 포맷을 공유하도록 단일 진실 공급원 확보)
- 도둑 QR 표시 다이얼로그에 주기적 QR 재생성 로직 추가
- 도둑 화면에 QR 갱신 상태를 시각적으로 알려주는 UI 추가 (카운트다운 또는 재생성 펄스 애니메이션)
- 경찰 스캔 플로우의 `onParse` 콜백에서 공통 유틸을 이용해 `exp` 검증 추가
  - QR 스캐너 위젯 자체(범용 스캐너)는 수정하지 않음. 검증은 스캐너 호출측(`game_page.dart`)에서 처리
- 만료된 QR 스캔 시 스캐너를 닫고 스낵바로 안내 (예: 만료된 QR입니다. 도둑에게 QR 새로고침을 요청하세요)
  - 기존 이미 체포된 도둑 스낵바 처리와 동일한 패턴으로 구현하여 일관성 유지
- TTL / 갱신 주기 상수는 구성 파일에서 관리하여 추후 조정 가능하도록
- 공통 유틸리티에 대한 단위 테스트 작성 (만료 판정 경계, 잘못된 페이로드 파싱 등)

## 🎯 정책 결정 사항

- TTL 값: 30초
- 하위 호환 정책: `exp` 없는 구버전 QR은 즉시 거부 (`exp` 필드 필수)
  - 전제: Remote Config 기반 최소 버전 강제 업데이트로 구버전 접근 차단
  - 이유: 한시적 허용 구간에는 리플레이 공격 취약성이 그대로 남아 본 이슈 목적이 반감됨. 또한 멀티플레이 매칭 특성상 참가자 버전이 혼재되면 UX 일관성이 깨짐
