## 📝 현재 문제점

### 강제 노출 지점 4곳

| # | 위치 | 무엇이 강제인가 |
|---|---|---|
| 1 | `home_page.dart:129` | 홈 첫 진입 시 코치마크 자동 시작 (1스텝) |
| 2 | `setup_playground_page.dart:166` | 구역 설정 첫 진입 시 코치마크 자동 시작 (1스텝) |
| 3 | `waiting_room_page.dart:611` | 대기방 첫 진입 시 코치마크 자동 시작 (**4스텝**) |
| 4 | `waiting_room_page.dart:682` | 3번이 끝나면 곧바로 안내 다이얼로그 → 인게임 튜토리얼 페이지 |

**빠져나갈 방법이 없는 게 핵심이다.**

- 코치마크는 `AppTutorialStyle.show()`가 `hideSkip: true`로 생성한다 → **건너뛰기 버튼이 없다.** 4스텝을 전부 눌러야 대기방을 쓸 수 있다
- 4번 다이얼로그는 `barrierDismissible: false` + 버튼 **1개**(`buttonViewInGamePreview`) → 바깥을 눌러도 안 닫히고, 닫는 유일한 선택지가 "튜토리얼 보러 가기"다

게임 시작 직전 대기방, 즉 **가장 시간 압박이 큰 순간**에 이 둘이 연달아 뜬다.

<details><summary>4번 코드 — 취소 버튼이 아예 없다</summary>

```dart
// waiting_room_page.dart:682
await AppDialog.show<void>(
  context: context,
  title: l10n.dialogInGamePreviewTitle,
  message: l10n.dialogTutorialPromptMessage,
  confirmText: l10n.buttonViewInGamePreview,   // 버튼 1개
  barrierDismissible: false,                    // 바깥 탭으로 못 닫음
  onConfirm: () => context.push('/tutorial/in-game'),
);
```
</details>

### 2단계 — `introduction_screen` 온보딩 신설

| 항목 | 값 |
|---|---|
| 패키지 | [`introduction_screen`](https://pub.dev/packages/introduction_screen) 4.0.0 (2025-08-27, 좋아요 2,963, 30일 다운로드 48,787, 점수 150/160) |
| 노출 | 앱 설치 후 **최초 1회**, 스플래시 직후 · 로그인 화면 **앞** |
| 저장 | `SharedPreferences` 키 1개 (`onboarding_seen`) — **로그인 상태와 무관** |
| 건너뛰기 | 항상 노출 (패키지 기본 제공) |
| 재열람 | 마이페이지 "앱 소개 다시 보기" |

**훅 위치는 스플래시 한 곳이다.** `splash_page.dart`의 초기화 분기(`context.go(RoutePaths.login)` 등)에 손대지 않고, 분기 **전에** 한 번만 끼운다.

```dart
// splash_page.dart — 초기화 분기가 시작되기 전
if (!await OnboardingPrefs.seen()) {
  await context.push(RoutePaths.onboarding);   // 닫히면 아래 기존 흐름 그대로 진행
  await OnboardingPrefs.markSeen();
}
```

> [!IMPORTANT]
> **로그아웃 시 초기화는 하지 않는다.** 지금은 `auth_provider`가 로그인·로그아웃마다 `resetAll()`을 불러 이미 본 사람에게 튜토리얼을 다시 띄운다 — 이번에 없애려는 동작과 같은 부류다. 온보딩은 "이 앱이 뭐 하는 앱인지"라서 계정이 아니라 **기기가 처음인지**의 문제고, 앱을 지우면 `SharedPreferences`도 함께 사라져 "설치 후 1회"가 정확히 성립한다. 다시 보고 싶은 사용자는 마이페이지 진입점으로 간다.

**왜 코치마크 계열 패키지로 갈아타지 않는가** — `showcaseview`(좋아요 3,114)나 현행 `tutorial_coach_mark`(30일 20.7만 다운로드, 2026-06 갱신)나 **하는 일이 같은 순차 스포트라이트**다. 패키지만 바꾸면 사용자 입장에선 아무것도 안 바뀐다. 현행 패키지가 낡아서 걷어내는 게 아니라 **자동·순차 강제라는 방식**을 걷어내는 것이므로, 화면 밖 캐러셀인 `introduction_screen`으로 형태를 바꾼다.

> [!WARNING]
> 이번 변경으로 **화면별 조작 안내는 사라진다.** `introduction_screen`은 화면 밖 캐러셀이라 "슬롯을 눌러 팀을 바꾼다" 같은 안내를 하지 못한다. 그건 UI가 스스로 설명하게 두고, 부족하다고 판명되면 그때 별도 이슈로 붙인다 — 지금처럼 선제적으로 깔지 않는다.

## 📌 참고

- 이미 쓰이지 않는 파일이 하나 있다 — `lib/features/tutorial/presentation/styles/app_tutorial_style.dart`를 import하는 곳이 없고, 3개 화면은 전부 `lib/core/tutorial/app_tutorial_style.dart`를 쓴다. #336에서 core → feature로 옮길 때 core 사본이 남은 것으로 보인다. 이번에 둘 다 사라지므로 별도 조치는 불필요
- `game_page.dart`에는 튜토리얼 참조가 없다 — #336에서 인게임 코치마크를 이미 걷어냈다. 인게임 화면은 이번 작업의 영향을 받지 않는다
- #336 완료 리포트가 남긴 판단 — "학습용 오버레이를 실 플레이 위에 얹으면 노출 타이밍을 통제할 수 없다". 별도 화면으로 뺀 것까지는 맞았고, **자동·강제로 띄운 부분이 남은 문제**였다
- 삭제 커밋 해시를 이 이슈에 남긴다 — 온보딩 문구를 짤 때 기존 튜토리얼 문구를 참고할 복구 경로
