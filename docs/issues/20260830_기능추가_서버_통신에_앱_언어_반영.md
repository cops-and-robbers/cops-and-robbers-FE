⚙️ [기능추가][Flutter][다국어] 서버 통신에 앱 언어를 실어 닉네임·공지를 현재 언어로 받기

🔥 구현 기능
---

앱이 갖고 있는 언어 설정(ko·en·ja)을 서버 통신에 실어, 언어에 따라 달라지는 응답을 현재 언어로 받습니다.

| 표면 | 내용 |
|---|---|
| 모든 API 요청 | `Accept-Language` 헤더로 현재 앱 언어 전송 |
| 공지사항 목록 | `language` 쿼리로 현재 언어의 제목·본문 수신, 번역 없으면 한국어 폴백 |
| 닉네임 입력 | 상한 10자 → 20자 (서버 허용치와 일치) |

📝 현재 문제점
---

> [!WARNING]
> 앱은 한국어·영어·일본어 설정을 갖고 있지만 서버 요청 어디에도 언어가 실리지 않는다. 서버가 사용자의 언어를 알 방법이 없다.

- 영어·일본어 사용자도 가입하면 한국어 닉네임("민첩한괴도5308" 같은)을 받는다
- 공지사항은 서버가 언어별 본문을 내려줄 수 있게 되었는데, 앱이 언어를 붙이지 않아 항상 기본값인 한국어 본문만 받는다
- 닉네임 입력 상한이 10자다. 서버는 20자까지 받도록 늘었고, 알파벳 닉네임은 10자로는 부족하다

🛠️ 해결 방안 / 제안 기능
---

- 모든 API 요청에 `Accept-Language` 헤더로 현재 앱 언어를 싣는다. 언어는 설정에서 언제든 바뀔 수 있으므로 요청마다 인터셉터에서 읽는다
- 공지 목록 조회에 `language` 쿼리를 붙여 현재 언어의 제목·본문을 받는다. 번역이 없는 공지는 서버가 한국어로 내려주므로 빈 화면은 생기지 않는다
- 닉네임 입력 상한을 20자로 늘린다

⚙️ 작업 내용
---

- dio 클라이언트에 Accept-Language 인터셉터 추가 (현재 로캘 provider 를 요청마다 읽기)
- 공지 datasource 에 language 쿼리 추가, repository 와 provider 로 현재 언어 전달
- 닉네임 설정 화면 maxLength 10 → 20
- 한국어·영어·일본어 각각으로 가입 닉네임 생성과 공지 화면 확인

📌 참고
---

> [!IMPORTANT]
> 서버는 모르는 쿼리 파라미터를 400 으로 거절하므로, `language` 를 보내는 앱은 서버 운영 반영 뒤에 나가야 한다. PR base 는 `20260812_#470_v3_앱_전면_개편` 이다.

- 서버는 준비되어 있다. 닉네임 언어별 생성·20자 허용과 공지 `language` 쿼리가 dev 에 반영되어 있다
- 언어를 바꿔도 이미 만들어진 닉네임은 바뀌지 않는다. 원하면 닉네임 변경에서 직접 바꾼다
- 검증 중 확정: 영어 라벨("Check duplication")이 공용 `ActionChip` 고정 너비(100)를 넘쳐 overflow 가 났다. 너비 미지정 칩은 내용에 맞춰 넓어지게 함께 고친다
