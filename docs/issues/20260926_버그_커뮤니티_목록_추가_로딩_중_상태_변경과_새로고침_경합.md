# ❗ [버그][커뮤니티] 목록 추가 로딩 중 상태 변경과 새로고침이 겹치면 게시글·알림 누락

## 🗒️ 설명

커뮤니티 게시글 목록과 알림함에서 **다음 페이지를 불러오는 도중 다른 목록 변경이 끼어들 때** 페이지 응답을 잘못 처리한다. 게시글은 추가 로딩이 끝나지 않은 상태로 멈추고, 알림함은 일부 알림을 건너뛴 채 더 불러올 수 없게 된다. 두 경합을 프론트 상태 관리에서 함께 수정한다.

| 화면 | 겹치는 동작 | 현재 결과 |
|---|---|---|
| 게시글 목록 | 2페이지 로딩 중 카드 메뉴에서 모집 마감 | 새 페이지 20건이 버려지고 `isLoadingMore=true`가 남음 |
| 알림함 | 오래된 페이지 로딩 중 당겨서 새로고침 | 새 목록 뒤에 오래된 페이지가 붙어 중간 알림이 누락되고 `hasMore=false`가 됨 |

<br>

## 🔄 재현 방법

1. 게시글이 20개보다 많은 목록에서 아래로 내려 2페이지 요청을 시작한다.
2. 응답 전 카드 메뉴에서 모집글 하나를 마감한 다음, 2페이지 응답을 받는다. 요청이 끝나도 목록은 20개이고 로딩 상태가 남는다.
3. 알림이 20개보다 많은 알림함에서 다음 페이지 요청을 시작한다.
4. 그 사이 새 알림이 들어온 조건으로 당겨서 새로고침한 다음, 오래된 페이지 응답을 받는다. 새 첫 페이지와 오래된 페이지 사이의 알림이 빠진다.

테스트에서는 실제 화면 조작·provider·repository·JSON 파싱을 사용하고 HTTP 응답 순서만 제어했다. 순서가 겹치지 않는 대조군 2건은 통과했고, 위 경합 2건은 실패했다. 실서버·실기기에서의 발생 빈도는 확인하지 않았다.

<br>

## 📸 원인 및 코드 근거

조사 기준: `main` / `2656f39b`.

- 게시글: `lib/features/community/presentation/providers/community_provider.dart:329-385`의 `loadMore()`는 요청 당시 `pending` 상태와 응답 시점 상태가 동일한 객체인지 확인한다. 같은 파일의 `toggleStatus()` → `replacePost()` (`446-459`, `491-503`)가 게시글 하나를 바꾸면서 상태 객체도 교체한다. 이를 새로고침으로 오인해 유효한 페이지 응답을 버리고, `isLoadingMore`도 해제하지 않는다.
- 알림함: `lib/features/community/presentation/providers/community_notification_provider.dart:52-90`의 `refresh()`는 첫 페이지를 새로 저장하지만, 이전 `loadMore()`는 현재 상태에 과거 커서의 응답을 그대로 덧붙인다. 이때 과거 응답의 `nextCursor`와 `hasMore`도 새 목록에 덮어쓴다.

제어된 재현에서 게시글 대조군은 40건·로딩 종료, 겹친 경우는 20건·로딩 지속이었다. 알림함 대조군은 다음 페이지 조회가 가능했지만, 겹친 경우 ID 25~21이 빠졌고 `hasMore=false`라 이후 스크롤로 복구되지 않았다.

<br>

## ✅ 예상 동작

- 게시글의 모집 상태 변경 중에도 유효한 추가 페이지는 목록에 반영되고 로딩이 종료된다.
- 실제 새로고침으로 기준 목록·커서가 바뀐 경우에만 이전 페이지 응답을 폐기한다.
- 알림함 새로고침 후 이전 커서 응답이 새 목록과 커서·`hasMore`를 오염시키지 않는다.
- 추가 로딩·새로고침의 성공과 실패 순서가 바뀌어도 목록과 로딩 상태가 일관된다.
