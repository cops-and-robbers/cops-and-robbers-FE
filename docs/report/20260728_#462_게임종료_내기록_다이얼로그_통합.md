### 📌 작업 개요

게임 종료 후 별도로 열리던 `MyRecordDialog`(내 기록 다이얼로그)를 `GameOverResultDialog`에 흡수해, 게임이 끝나는 즉시 승패·이동 거리·이동 경로·게임 통계가 한 화면에 보이게 통합했다. 기존 2단 구조(결과 다이얼로그 → "내 기록 보기" 버튼 → 별도 다이얼로그)를 없애고, 공유하기는 우상단 아이콘 하나로 축약했다. 경로 표시 방식도 `CustomPaint` 기반 궤적에서 실제 구글 지도로 전환했다.

### 🎯 구현 목표

- 결과 다이얼로그와 내 기록 다이얼로그를 하나의 카드로 통합
- 이동 경로를 실지도(`GoogleMap` + `Polyline`) 위에 표시
- 공유하기를 카드 우상단 아이콘으로 이동, 캡처 이미지에는 버튼 대신 브랜드 로고 노출
- 통합 과정에서 중복·시안에 없는 요소(승패 배지, 개인 통계 2칸, 마커 범례, 기존 워터마크) 정리

### ✅ 구현 내용

#### 카드 본체 통합 — `GameOverResultDialog` (수정)
- **파일**: `lib/features/game/presentation/widgets/game_over_result_dialog.dart`
- **변경 내용**: 카드 본체를 `_GameOverCard`(`ConsumerStatefulWidget`)로 분리해 캡처용 `GlobalKey`와 `_capturing` 상태를 갖게 함. `Stack` 4레이어(몸통 → 카드 → 좌팔 → 우팔) 구조는 유지하되, 카드 안에 타이틀+공유 아이콘 → 종료 일시 → 이동 거리(숫자/단위 분리) → `RecordRouteMap` → 통계 3행 → 액션 버튼 순서로 배치. `gameResultProvider`와 `playerGameRecordNotifierProvider`를 한 위젯에서 동시에 구독한다(기존엔 두 다이얼로그에 나뉘어 있었음)
- **이유**: 캡처 대상(`RepaintBoundary`)이 버튼·아이콘을 포함한 카드 전체를 감싸야 캡처 시 숨김 처리가 가능하고, 두 provider를 한곳에서 봐야 화면 재구성 없이 통합 렌더가 가능하다

#### 실지도 경로 위젯 — `RecordRouteMap` (신규)
- **파일**: `lib/features/game/presentation/widgets/record_route_map.dart`
- **변경 내용**: `GoogleMap` + `Polyline`으로 내 경로를 그리는 결과 카드 전용 위젯 신규 작성. `routeBounds(route)`로 경로 전체를 담는 `LatLngBounds`를 계산해 `onMapCreated` 150ms 뒤 카메라를 자동 맞춤(`newLatLngBounds`가 지도 크기 미확정 시 실패하는 문제 회피). 점이 2개 미만이거나 전부 동일 좌표면 `null`을 반환해 고정 줌(`newLatLngZoom`)으로 폴백. 마커는 경찰=체포 지점 / 도둑=잡힌 지점을 빨간 기본 마커로 표시. 스크롤·줌·회전 등 모든 제스처를 껐고, 다크 모드는 `MapStyles.dark` 적용. 경로가 비면 지도 대신 `labelNoRoute`("이동 기록 없음") 문구를 표시
- **이유**: 인게임 `GoogleMapView`는 마커 애니메이션·구역·핑까지 얹은 큰 위젯이라 재사용하지 않고, 결과 카드에 맞는 얇은 읽기 전용 지도를 새로 뒀다. Static Maps API가 아니라 인게임에서 이미 쓰던 네이티브 지도 SDK를 그대로 재사용하므로 이번 PR로 새로 생기는 API 요금이 없다(Maps SDK for Android/iOS는 별도 SKU 과금 없이 사용 가능). 폴리라인 좌표 자체는 클라이언트에서 그려지므로 이를 위한 추가 API 호출은 없지만, 지도 타일 로드는 기존 인게임 지도와 동일하게 네트워크 요청을 수반한다

#### 경로 데이터 정확도 재확인 (설계 단계 검증, 코드 변경 없음)
- 경로가 웹소켓 전송 주기로 성기게 찍힐 거라는 우려가 있었으나, `game_page.dart`의 위치 스트림은 `distanceFilter: 0`으로 모든 GPS 틱을 받고 있고 `_recordNotifier.addPoint(...)` 호출이 웹소켓 전송 게이트(5초 throttle + 10m)보다 위에 있어 영향을 받지 않음을 확인
- 경로에 걸린 필터는 `player_game_record_provider.dart`의 2m 최소 이동 거리 하나뿐이라 이미 원본 GPS 해상도이며, 별도 도로 스냅 보정 API는 도입하지 않았다(이 게임은 도로 밖을 다니므로 스냅이 오히려 궤적을 왜곡함)

#### 거리 값/단위 분리 — `record_format.dart` (수정)
- **파일**: `lib/features/game/presentation/widgets/record_format.dart`
- **변경 내용**: `formatDistanceParts(meters)` 신규 추가 — `({String value, String unit})` 레코드 반환. 1km 미만은 정수 `m`, 이상은 소수 2자리 `Km`(대문자 K는 시안 표기 기준). 기존 단일 문자열 `formatDistance()`는 참조가 사라지며 함께 제거
- **이유**: 시안에서 숫자(56px)와 단위(24px)의 폰트 크기가 달라 단일 문자열로는 렌더할 수 없다. 카드에서는 `Text.rich`로 두 스타일을 이어 붙인다

#### 공유 캡처 이식 및 브랜드 로고 대체 — `_GameOverCardState` / `locale_brand_assets.dart`
- **파일**: `lib/features/game/presentation/widgets/game_over_result_dialog.dart`, `lib/core/i18n/locale_brand_assets.dart`

### 🔧 주요 변경사항 상세

#### GoogleMap 캡처 리스크
`GoogleMap`은 플랫폼 뷰라 `RepaintBoundary.toImage()`로 캡처하면 지도 영역이 비어 나올 수 있다는 것이 이번 작업에서 가장 큰 리스크로 식별됐다. 자동 테스트로는 검증할 수 없어(위젯 테스트에서 플랫폼 뷰가 렌더되지 않음) 실기기 확인이 필요한 상태로 남겨뒀다. 비어 나올 경우 대응 순서는 (1) Android `liteModeEnabled: true`로 정적 비트맵 렌더 시도 → (2) `GoogleMapController.takeSnapshot()`으로 지도만 따로 떠서 합성 → (3) 최후 수단으로 공유 이미지에서 지도 제외.

#### 타이틀 + 공유 아이콘 배치
설계 단계에서는 `Row`(타이틀 + 고정폭 `SizedBox` + 아이콘)로 검토했으나, 실제 구현은 `Stack`(타이틀을 중앙 정렬하고 아이콘을 `Positioned(right: ...)`로 얹는 방식)으로 짜여 있다. 아이콘 폭이 타이틀 중심을 밀어내는 걸 막기 위한 선택으로, 타이틀은 카드 폭 기준 정중앙에, 아이콘은 카드 우측 고정 위치에 독립적으로 자리한다.

#### 카드 padding 이중 들여쓰기
카드 최외곽 padding(`left/right 16`)과 별개로, 날짜·거리·지도·통계 영역을 감싼 `Padding`이 `horizontal8`을 한 번 더 준다. 통계 3행에는 거기서 `horizontal8`을 한 번 더 얹어 시안의 콘텐츠 폭(272)에 맞춘다. 타이틀 행과 버튼 행은 이 추가 들여쓰기 없이 카드 padding만 적용된다.

#### 거리 숫자 폰트
`AppTextStyles.semibold_56`을 이번에 신규 추가했다(DartDoc에 "게임 결과 이동 거리" 용도로 명시). 설계 문서 초안은 44px을 검토했으나 실제 구현은 56px로 확정됐다.

### 📌 참고사항

**실기기 수동 확인 필요** — 자동 테스트로 덮이지 않는 항목이다.

1. **공유 이미지에 지도가 찍히는지** — 가장 큰 리스크. 플랫폼 뷰 캡처 특성상 비어 나올 가능성이 있다
2. 지도 위 빨간 기본 마커 크기가 172h 높이 지도에서 과하지 않은지
3. 다크 모드 지도(`MapStyles.dark`) 위 폴리라인(도둑 팀 초록) 대비
4. 캡처 순간 버튼 숨김에 따른 한두 프레임 깜빡임이 거슬리는 수준인지
5. 작은 기기(iPhone SE급)에서 카드가 화면을 넘치지 않는지

**보류된 삭제 대상**: `route_painter.dart`, `route_geometry.dart`는 참조가 0이 됐지만 이번에 삭제하지 않았다. 위 1번 리스크(지도 캡처)가 실기기에서 깨질 경우 `CustomPaint` 궤적 폴백으로 되살려야 하므로, 검증이 끝난 뒤 별도로 정리할 예정이다.

**워터마크 정책 변경**: 기존에는 화면에 항상 보이는 워터마크가 있었으나, 이번 통합에서는 라이브 화면에 로고가 없고 캡처 순간에만 버튼 자리를 대신해 노출된다. 시안에 따른 결정이나, 공유 이미지 유입 관점에서는 이전보다 노출 빈도가 낮아진 셈이다(캡처 시에는 계속 남으므로 완전히 사라진 것은 아니다).
