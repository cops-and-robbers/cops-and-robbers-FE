# 약관 페이지 진입 시 서버 동의 상태 조회

### 📌 작업 개요
약관 동의 페이지 진입 시 `GET /api/user/agreements`를 호출하여 서버의 현재 동의 상태로 체크박스를 초기화하도록 변경. 백엔드가 정책 갱신으로 특정 약관만 false로 갱신한 경우, 이미 동의한 약관은 체크된 상태로 표시되어 사용자가 변경된 약관만 새로 체크하면 되도록 한다.

### 🔍 문제 분석
기존 흐름에서 `AuthNotifier`가 cold start 시 `GET /api/user/agreements`를 호출하긴 하지만 `hasAllRequired` boolean만 추출하고 개별 항목 상태는 폐기. `AgreementNotifier.build()`는 `const AgreementState()`로 모든 체크박스를 false 디폴트로 초기화하여, 백엔드가 일부 약관만 false로 갱신해도 화면은 4개 모두 미체크로 표시됨. 사용자는 이미 동의했던 이용약관·개인정보 처리방침까지 다시 일일이 체크해야 했다.

### 🔧 주요 변경사항 상세

#### AgreementNotifier — build() 내 초기 로드 패턴
```
build()
  ├─ ref.onDispose(() => disposed = true)   ← dispose 가드 등록
  ├─ Future.microtask(() => _loadInitial(...))  ← 비동기 초기 로드 큐잉
  └─ return const AgreementState()  ← isLoading=true 디폴트
```

`_loadInitial()`은 try-catch로 감싸며 성공 시 4개 필드 + isLoading=false 갱신, 실패 시 isLoading만 false로 갱신하여 전부 미체크 상태로 폴백한다. 디버그 로그(`✅`/`⚠️`)로 추적 가능.

**특이사항**:
- Riverpod의 일반 Notifier에는 `ref.mounted`가 없어 `var disposed` 플래그와 `ref.onDispose`로 직접 가드
- 일반 Notifier(`@riverpod class`)의 build()를 동기로 유지하여 UI가 `ref.watch`로 받는 타입을 `AsyncValue<AgreementState>`가 아닌 `AgreementState`로 유지 → 페이지 코드 변경 최소화

#### AgreementSettingsPage와의 패턴 정합성
설정 화면의 약관 관리 페이지(`AgreementSettingsPage`)가 이미 `initState`에서 `getAgreements()`를 호출하여 로컬 state로 채우는 패턴을 사용. 동일한 데이터 흐름을 Notifier 안에서 재현하여 일관성 유지.

**특이사항**:
- 약관 페이지 진입 시 `GET /api/user/agreements`가 cold start 1회 + 이번 화면 진입 1회 호출됨 (총 2회). 두 호출의 목적이 다르므로(라우팅 판정 vs UI 초기화) 중복 호출 허용. 정합성 우선.

#### 테스트의 autoDispose 대응
`@riverpod`는 기본 autoDispose이므로 ProviderContainer에서 `read`만 하면 read 사이에 dispose되어 `state = copyWith(...)`로 갱신한 값이 초기화되는 현상 발견. 명시적 `container.listen<AgreementState>(provider, (_, _) {})`로 lifecycle을 유지하여 해결.

**특이사항**:
- `_flushInitialLoad()`는 `Future<void>.delayed(Duration.zero)`를 5회 yield하여 nested microtask chain(build → microtask → fake repo async → continuation)을 모두 비움
- 일부러 `_flushInitialLoad()`를 호출하지 않는 "초기 로드 중에는 toggle이 무시된다" 테스트로 동시성 가드를 검증
