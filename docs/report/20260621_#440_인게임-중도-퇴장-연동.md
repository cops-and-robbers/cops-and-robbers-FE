# 인게임 중도 퇴장 기능 프론트엔드 연동

## 📌 작업 개요

게임 진행 중 플레이어가 자발적으로 나갈 수 있는 "능동 퇴장" 기능을 프론트엔드에 연동했다. 기존에는 게임 화면을 벗어날 수 없었으나, 이번 작업으로 앱바 좌측 나가기 버튼 및 시스템 뒤로가기로 퇴장이 가능해졌다. 서버가 퇴장한 팀의 인원이 0명이 되면 몰수패(`POLICE_FORFEITED` / `ROBBER_FORFEITED`) GAME_OVER를 브로드캐스트하는 흐름도 포함되어, 다른 참가자 화면에 퇴장 배너 및 게임 종료 사유가 정상적으로 표시되도록 처리했다.

---

## 🎯 구현 목표

- 게임 화면에서 능동 퇴장 진입점(앱바 나가기 버튼 / 시스템 뒤로가기) 구현
- 퇴장 API(`DELETE /api/games/{gameId}/participants`) 호출 후 소켓·위치 정리 → 홈 이동
- API await 창에 도착하는 자기 몰수 GAME_OVER를 결과 다이얼로그로 표시하지 않고 차단
- 다른 참가자 화면에서 `PLAYER_LEFT` 이벤트를 수신해 배너 알림 및 참가자 목록 갱신
- 몰수패 사유(`POLICE_FORFEITED` / `ROBBER_FORFEITED`)를 GAME_OVER 팝업에 현지화 표시
- 신규 i18n 키 3종(`gameLeaveConfirmTitle`, `gameLeaveConfirmMessage`, `gameLeaveFailedMessage`) 및 이벤트·사유 키 3종을 ko/en/ja ARB에 추가

## ✅ 구현 내용

### 1. 퇴장 진입점 및 흐름 — `game_page.dart`

- **파일**: `lib/features/game/presentation/pages/game_page.dart`
- `_isLeaving` 필드를 `bool`로 추가. 퇴장 흐름이 시작되면 `true`로 세워 진입을 중복 차단하고, GAME_OVER 리스너·resume 핸들러·재연결 모달 진입을 모두 가드함
- `_confirmLeaveGame()`: 중복/충돌 가드 후 확인 다이얼로그(`l10n.gameLeaveConfirmTitle` / `gameLeaveConfirmMessage`) 표시. 더미 모드에서는 서버 호출 없이 즉시 홈으로 이동
- `_leaveGameActively()`: `_isLeaving = true` 세팅 후 `leaveGameProvider(_gameId).future` await. 성공 시 참가자 상태 초기화(`gameParticipantNotifierProvider.clear()`) → `_prepareGameOverPresentation()`(소켓/위치/채팅 정리) → `_exitGameAfterAd(choice: 'leave_mid_game', destination: _homeAfterGameExit)` 순으로 실행. 실패 시 `_isLeaving = false`로 복구하고 스낵바(`gameLeaveFailedMessage`)를 표시하며 잔류
- `_requestLeaveGameSilently()`: 정상 게임 종료 후 서버가 플레이어를 WAITING 상태로 남기는 경우를 위한 fire-and-forget 퇴장 요청. 실패해도 흐름을 막지 않음
- **B-3 타이밍 처리**: API await 창에 자기 몰수 GAME_OVER가 도착해도 `_isLeaving` 가드로 결과 다이얼로그를 차단. API가 실패로 빠진 뒤 `eventState.isGameOver`가 true이면 그때 `_showGameOverDialog`를 복구 호출
- `_homeAfterGameExit = '${RoutePaths.home}?fromGameExit=true'` — 홈에서 stale WAITING 상태로 인한 로비 자동이동을 방지하는 쿼리 파라미터
- `PopScope(canPop: false)`: 시스템 뒤로가기를 가로채 `_confirmLeaveGame()` 호출
- `_buildAppBar()` 좌측 나가기 버튼: 대기방 leading과 동일한 `FlatIconButton(assetPath: 'assets/icons/icon_exit.svg')` + `left: 18.w` 패딩으로 배치. `onPressed: _confirmLeaveGame`
- `_reconnectSocketsIfNeeded()` 및 `_checkGameStatusOnResume()`, GAME_OVER 리스너 모두 `if (_isLeaving) return;` 가드 추가

### 2. PLAYER_LEFT 이벤트 처리 — `game_event_provider.dart`

- **파일**: `lib/features/game/presentation/providers/game_event_provider.dart`
- `GameEventState`에 `leftParticipantIds: Set<int>` 필드 추가(기본값 `const {}`). 퇴장한 참가자 ID를 누적 집합으로 관리
- `_handlePlayerLeft(Map<String, dynamic> data)` 신규 핸들러: `participantId`를 `leftParticipantIds`에 추가하고 `bannerMessage`에 `GameEventMessageKey.playerLeftNotice`(args: `[nickname, teamLabel]`)를 설정. `_startBannerTimer()`로 배너 자동 소거
- `_handleEvent` switch에 `GameEventType.playerLeft` 케이스 추가
- FCM 좀비 소켓 복구를 위해 `firebase_messaging_service.dart`의 `_gameSystemEventTypes`에 `'PLAYER_LEFT'` 추가

### 3. GameEventType 확장 — `game_event_model.dart`

- **파일**: `lib/features/game/data/models/game_event_model.dart`
- `GameEventType` 열거형에 `@JsonValue('PLAYER_LEFT') playerLeft` 추가
- `@JsonKey(unknownEnumValue: GameEventType.unknown)`으로 미인식 타입은 안전하게 `unknown`으로 처리 (기존 구조 그대로 유지)

### 4. 몰수패 사유 처리 — `game_result_reason.dart`

## 🔧 핵심 설계 결정

### API-first 퇴장 (낙관적 UI 미사용)

퇴장은 API 성공이 확정된 이후에만 소켓을 끊고 화면을 이동한다. 퇴장이 실패하면 소켓은 그대로 유지되고 플레이어는 게임에 잔류한다. 반면 체포·탈옥은 낙관적 UI를 사용해 즉시 반영하고 실패 시 롤백하는 방식과 대비된다. 퇴장 실패 시 상태가 모호해지는 것을 막기 위해 API가 반드시 선행한다.

### `_isLeaving` 가드의 역할

`_isLeaving = true`를 세우는 순간부터 아래 세 가지가 차단된다:
1. GAME_OVER 리스너에서 자기 몰수 결과 다이얼로그 진입
2. `lifecycleState resumed` 핸들러에서 소켓 재연결 시도
3. 재연결 모달 신규 표시

API 실패 시에만 `_isLeaving = false`로 복구되며, 이때 이미 도착해 있는 GAME_OVER가 있으면 그 자리에서 결과 다이얼로그를 표시한다.

### 단일 정리 경로 재사용

능동 퇴장 성공 시 `_prepareGameOverPresentation()`을 그대로 호출해 소켓, 위치 스트림, 채팅 연결을 정리한다. 별도 정리 로직을 두지 않아 게임 종료와 능동 퇴장 간 정리 경로가 일치한다.

### `leftParticipantIds: Set<int>` 누적 집합

단순 카운터나 마지막 ID 단일 값 대신 집합을 사용한다. `ParticipantOverlay`가 `prev?.leftParticipantIds != next.leftParticipantIds`로 변경을 감지하고, 여러 명이 연달아 퇴장해도 각 이벤트마다 갱신 호출이 트리거된다.

## 📌 알려진 한계 및 참고사항

- **`_isLeaving` 가드가 없는 추가 진입점**: 현재 구현에서 사용자가 확인 다이얼로그를 띄운 상태에서 GAME_OVER가 먼저 도달하면, 다이얼로그 cancel 이후 `_isLeaving`이 false이므로 GAME_OVER 리스너가 결과창을 표시한다. 이는 의도된 동작(취소했으면 게임 결과를 보여줌)이다.
- **`_requestLeaveGameSilently` 실패 무시**: GAME_OVER 후 서버 퇴장 silent 호출이 실패해도 서버상 WAITING 상태로 잔존할 수 있다. 이후 콜드스타트 복구 흐름(`getMyActiveGame`)이 WAITING 감지 시 로비로 안내하는 안전망이 존재한다.
- **퇴장 직전 FCM 알림 경유 복구**: `firebase_messaging_service.dart`에 `PLAYER_LEFT`를 추가해 FCM이 백그라운드 STOMP를 깨우도록 처리했으나, 이미 소켓이 끊긴 상태의 수신자에 한해 재연결 후 이벤트를 놓칠 수 있다. 이는 기존 이벤트 유실 복구 메커니즘(resumed 시 게임 상태 재조회)과 동일한 수준의 한계다.
