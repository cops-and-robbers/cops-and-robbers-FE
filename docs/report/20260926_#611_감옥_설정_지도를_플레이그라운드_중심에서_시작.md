### 📌 작업 개요
새 감옥 설정 지도가 항상 현재 GPS 위치에서 열리던 동작을 **플레이그라운드 중심에서 시작**하도록 변경. 감옥 화면 안에서 이미 가진 플레이그라운드 정보로 중심을 구하므로, 방 생성(홈·모집글)·방 수정 등 진입 경로와 무관하게 같은 규칙이 적용된다.

**보고서 파일**: `docs/report/20260926_#611_감옥_설정_지도를_플레이그라운드_중심에서_시작.md`

### 🔍 문제 분석
- #605 이후 모집글 채팅방에서 만든 게임은 플레이그라운드 지도가 모임 장소에서 시작하지만, 다음 단계인 감옥 지도는 다시 현재 위치로 돌아갔다.
- `SetupPrisonPage`는 기존 감옥(`initialJail`)이 있을 때만 `_currentCenter`를 채운다. 새 감옥이면 null.
  - 원형 모드: null인 `_currentCenter`를 `ZoneSettingWidget.initialCenter`로 넘김 → `initialCenter ?? 현재 위치 ?? 기본 좌표` 규칙에 따라 현재 위치 사용
  - 핀 모드: `PinZoneSettingWidget`에 `initialCenter`를 넘기지 않음 → 감옥 꼭짓점이 없으면 현재 위치 사용

### ✅ 구현 내용

#### 플레이그라운드 중심을 새 감옥의 시작 위치로 사용
- **파일**: `lib/features/session/presentation/pages/setup_prison_page.dart`
- **변경 내용**: `_playgroundMiddle` getter 추가. 핀 플레이그라운드면 꼭짓점 중심(`AreaShape.centroid`), 원형이면 원의 중심을 반환. 원형 지도는 `_currentCenter ?? _playgroundMiddle`, 핀 지도는 `initialCenter: _playgroundMiddle`로 전달
- **이유**: 감옥은 플레이그라운드 안에 있어야 하므로 플레이그라운드 가운데가 가장 자연스러운 시작점. 진입 경로별로 모임 장소를 따로 전달하는 방식보다 변경 범위가 작고 모든 경로에 일관되게 적용된다

#### 회귀 테스트 추가
- **파일**: `test/features/session/presentation/pages/setup_playground_initial_location_test.dart`
- **변경 내용**: 원형·핀 플레이그라운드에서 새 감옥이 플레이그라운드 중심에서 시작하는지, 기존 감옥이 있으면 그 위치가 우선하는지 검증하는 테스트 3개 추가
- **이유**: 기존 플레이그라운드 초기 위치 테스트의 GPS·지도 플랫폼 페이크를 그대로 재사용

### 🔧 주요 변경사항 상세

#### 시작 위치 우선순위
| 모드 | 우선순위 |
|---|---|
| 원형 | 기존 감옥 중심 → 플레이그라운드 중심 → 현재 위치 |
| 핀 | 기존 감옥 꼭짓점 중심 → 플레이그라운드 중심 → 현재 위치 |

`_playgroundCenter`·`_playgroundPinPoints`는 인자로 들어온 경우와 로컬 초안에서 복원한 경우 모두 채워지므로 두 경로 모두 적용된다.

**특이사항**:
- 방 수정에서 플레이그라운드 타입을 바꾸면(원형↔핀) 기존 감옥이 초기화되므로 새 감옥도 플레이그라운드 중심에서 시작한다.
- 내 위치 버튼은 기존대로 현재 위치로 이동한다.

#### 테스트 하네스 보정
테스트의 `_pumpApp`이 핀 핸들 아이콘을 파란색(플레이그라운드)만 미리 캐시하고 있었다. 감옥은 빨간색 아이콘을 쓰므로 fake async 안에서 실제 이미지 인코딩이 돌며 `pumpAndSettle`이 실행 순서에 따라 타임아웃됐다. 빨간색도 함께 미리 캐시하도록 수정.
