### 📌 작업 개요

게임 방 생성 API(`POST /api/games`) 연동 작업. Clean Architecture(Data/Domain/Presentation) 기반으로 Retrofit DataSource, Freezed DTO, Repository, Riverpod Provider를 구현하고, 기존 세션 생성 플로우 페이지에 실제 API 호출을 연결. API 연동 과정에서 발견된 `Future already completed` 버그 수정, 구역 설정 지도 UX 개선(현재 위치 버튼 맵 내 배치, 감옥 설정 시 플레이그라운드 참조 구역 표시), API 스펙 문서 정비, 슬라이더 범위 API 스펙 일치 수정, 토큰 재발급 진단 로그 추가 포함.

**브랜치**: `20260207_#74_Game_방_생성_api_연동`
**커밋 수**: 18개 (전체)

### 🔧 주요 변경사항 상세

#### Future already completed 버그 수정

**문제 현상**: "방 생성하기" 클릭 → API 호출 성공 (gameId, inviteCode 발급) → 직후 `Bad state: Future already completed` crash

**발생 원인**:
1. `@riverpod`는 기본적으로 autoDispose provider 생성
2. `session_creation_flow_page.dart`에서 `ref.read()`만 사용하여 provider 구독 유지 안 됨
3. 첫 API 호출이 401 → AuthInterceptor가 토큰 재발급 → 재시도하는 긴 async gap 발생
4. 이 gap 동안 아무도 `ref.watch()`하지 않아 Riverpod이 provider를 autoDispose
5. 내부 Completer가 이미 complete된 상태에서 `state = AsyncValue.data(result)` 시도 → crash

**해결 방법**:
- `build()`에 `ref.watch(sessionCreationNotifierProvider)` 추가하여 provider 생존 보장
- 수동 try/catch + `rethrow`를 `AsyncValue.guard()`로 교체하여 상태 설정 안전성 확보
- 결과 처리를 try/catch 대신 `sessionState.when(data:, error:, loading:)` 패턴으로 전환

#### Clean Architecture 계층 구조

```
Presentation (session_creation_flow_page.dart)
    ↓ ref.read(sessionCreationNotifierProvider.notifier)
Presentation (session_provider.dart - SessionCreationNotifier)
    ↓ ref.read(sessionRepositoryProvider)
Domain (session_repository.dart - 인터페이스)
    ↑ implements
Data (session_repository_impl.dart)
    ↓ _dataSource.createGame()
Data (session_remote_datasource.dart - Retrofit)
    ↓ POST /api/games
Backend
```

#### 감옥-플레이그라운드 범위 검증 로직

```dart
// 감옥 중심 ~ 플레이그라운드 중심 거리 + 감옥 반경 ≤ 플레이그라운드 반경 + epsilon
static const double _epsilonMeters = 1.0;

bool _isJailInsidePlayground() {
  final distance = Geolocator.distanceBetween(center, playgroundCenter);
  return (distance + _currentRadius) <= (playgroundRadius + _epsilonMeters);
}
```

- 플레이그라운드 미설정 → 완료 불가 + "플레이그라운드를 먼저 설정해주세요"
- 범위 초과 → 완료 불가 + "감옥이 플레이그라운드 범위를 벗어났어요"

### 📌 참고사항

- **api-docs.json 알려진 버그 2건** (백엔드 확인 필요):
  1. `GameJoinResponse` — 스키마 `{gameId, participantId}`와 예시 `{gameId, userId, nickname, isHost, joinedAt}` 불일치
  2. `NicknameCheckResponse` — 예시에 `"ture"` 오타 (`true`여야 함)
- **미구현 API**: 게임 참가(`POST /api/games/{gameId}/participants`), 퇴장(`DELETE`), 팀 변경(`PATCH .../team`), 준비 상태 토글(`PATCH .../ready`), 게임 시작(`POST .../start`)
- `@riverpod` autoDispose provider 사용 시 비동기 작업 중 `ref.watch()`로 provider 구독 유지 필수
- `_plainDio`는 `LogInterceptor` 미적용이므로 reissue 디버깅은 `auth_interceptor.dart` 내 수동 로그에 의존
- 감옥 설정 시 플레이그라운드 참조 영역은 `CircleZoneShape(circleId: 'reference_zone')`으로 구분되어 기존 zone_circle과 충돌하지 않음
