### 📌 작업 개요

#177에서 진행된 채팅 오버레이 UX 개선 작업이 드래그 핸들 시트 올림 불가 등 복합 버그를 유발하여,
`chat_overlay.dart`와 `chat_input_bar.dart`를 PR #127 상태로 롤백하고,
근본 원인인 프로그래매틱 포커스 복원 문제를 ChatInputBar 내부에서 차단하는 방식으로 재구현

### 🔍 문제 분석

#### 근본 원인: Flutter의 showGeneralDialog 포커스 복원 메커니즘

Flutter의 `Navigator`는 route마다 `FocusScopeNode`를 관리한다.
`showGeneralDialog`로 다이얼로그(Route B)가 push되면, 이전 route(Route A)의 포커스 정보를 **비활성화하되 보존**한다.
다이얼로그가 pop되면 Route A의 포커스를 **자동 복원**한다.

```
Route A (게임 화면)              Route B (다이얼로그)
├── FocusScopeNode A            ├── FocusScopeNode B
│   └── ChatOverlay             │   └── 확인/취소 버튼
│       └── ChatInputBar
│           └── TextField ← 포커스 보존됨
```

이로 인해 다음 버그가 발생:
1. 채팅 입력 → TextField에 포커스 획득
2. 채팅 시트 접기 → unfocus() 호출
3. 체포/탈옥/게임규칙 다이얼로그 열림 → showGeneralDialog가 route push
4. 다이얼로그 닫힘 (버튼 클릭 또는 빈 공간 탭) → route pop
5. **Flutter가 TextField로 포커스를 자동 복원**
6. 키보드 올라옴 → LayoutBuilder가 `keyboardHeight > 0` 감지 → 시트 75% 강제 확장

#### #166 수정이 불완전했던 이유

#166에서 `_inputBarTouched` 플래그로 `_onInputFocused()` 콜백을 가드했으나,
**키보드 올라옴 → LayoutBuilder의 `effectiveMinSize = _snap75`** 경로는 완전히 별개 코드 패스라 우회됨.
또한 다이얼로그마다 수동으로 `FocusScope.unfocus()`를 넣는 방식이라 누락 케이스가 발생.

#### #177 UX 개선이 새 버그를 유발한 이유

`_inputBarTouched` 감지 방식 변경, 입력바 드래그 이벤트 제거, 시트 닫힘 중복 호출 방지 등
여러 상태 플래그가 복합적으로 얽히면서 드래그 핸들로 시트가 올라가지 않는 버그 발생.
원인 특정이 어려워 롤백 결정.

### ✅ 구현 내용

#### 1. 채팅 파일 PR #127 상태로 롤백
- **파일**: `chat_overlay.dart`, `chat_input_bar.dart`
- **변경 내용**: #166, #177에서 추가된 `_inputBarTouched` 플래그, `Listener` 래핑, 시트 닫힘 중복 방지(`_collapseScheduled`), 입력바 드래그 이벤트(`onVerticalDragUpdate`), `onFocusLost` 콜백 등 채팅 UX 변경 전체 원복
- **이유**: 복합 상태 플래그 간 상호작용으로 인한 버그 원인 특정 불가

#### 2. ChatInputBar에 `_userTapped` 플래그 추가
- **파일**: `chat_input_bar.dart`
- **변경 내용**: `Listener(onPointerDown)`으로 TextField 직접 탭 감지, `_onFocusChanged`에서 `_userTapped == false`이면 다음 프레임에서 `unfocus()` 호출
- **이유**: 프로그래매틱 포커스 복원을 TextField 레벨에서 차단. `Listener.onPointerDown`은 포커스 변경보다 먼저 발생하므로 타이밍 문제 없음

**동작 흐름**:
- 직접 탭: `onPointerDown` → `_userTapped = true` → 포커스 → `onFocusGain` 호출 → 정상 확장
- 프로그래매틱 복원: `_userTapped == false` → 다음 프레임 unfocus → 키보드/시트 안 올라감
- 포커스 상실 시: `_userTapped = false`로 리셋

#### 3. 키보드 높이 기반 시트 확장 재적용
- **파일**: `chat_overlay.dart`
- **변경 내용**: `MediaQuery.viewInsets.bottom`으로 키보드 높이 감지, 키보드 열림 시 `effectiveMinSize = _snap75`, 하단 마진을 키보드 높이로 설정
- **이유**: PR #127 상태에는 키보드 대응 로직이 없어서 별도 추가 필요

#### 4. 빈 공간 탭 시 시트 닫힘 제거
- **파일**: `chat_overlay.dart`
- **변경 내용**: `_isExpanded` 상태에서 `Positioned.fill` + `GestureDetector`로 빈 공간 탭 시 시트를 접는 로직 제거
- **이유**: 드래그 핸들로만 시트를 접도록 단순화

#### 5. 유지된 기존 수정 (별도 파일, 이미 main에 반영)
- `AppDialog._buildAndShow()`에 `FocusScope.unfocus()` 일괄 적용 (`app_dialog.dart`) — 모든 다이얼로그에서 근본 차단
- `participant_overlay.dart`에 체포·탈옥 모달 전 `FocusScope.unfocus()` — 명시적 의도 표현

### 🔧 주요 변경사항 상세

#### ChatInputBar._userTapped 플래그

`_inputBarTouched`(#166)와의 차이점:
- `_inputBarTouched`는 `ChatOverlay`(부모)에서 관리 → 부모-자식 간 상태 동기화 복잡
- `_userTapped`는 `ChatInputBar`(자신) 내부에서 관리 → 포커스와 직접 관련된 위젯이 스스로 판단
- `Listener.onPointerDown`이 포커스 변경보다 먼저 발생하므로 타이밍 이슈 없음

**특이사항**:
- `_userTapped` 리셋 시점이 중요. 포커스 획득 직후가 아닌 **포커스 상실 시**에 리셋해야, 키보드가 올라오면서 rebuild되어도 플래그가 유지됨
- `canRequestFocus: false` 방식은 TextField 내부의 text input connection을 끊어 시스템 컨텍스트 메뉴 에러 발생 → 사용 불가

### 🧪 테스트 및 검증
- 채팅 입력 후 시트 접기 → 게임 규칙 다이얼로그 열기/닫기 → 시트 안 올라옴 확인
- 채팅 입력 후 시트 접기 → 체포 모달 열기/닫기 → 시트 안 올라옴 확인
- 채팅 입력바 직접 탭 → 시트 확장 + 키보드 올라옴 정상 확인
- 키보드 닫기 → 시트 현재 위치 유지 (자동으로 내려가지 않음) 확인
- 드래그 핸들로 시트 올리기/내리기 정상 동작 확인

### 📌 참고사항
- `AppDialog._buildAndShow()`의 `unfocus()`와 `ChatInputBar._userTapped`는 이중 방어 구조. 하나만으로도 대부분 케이스를 커버하지만, Flutter의 포커스 복원 타이밍이 일관적이지 않아 양쪽 모두 유지
- 키보드 닫힐 때 시트를 자동으로 내리는 로직(`_isCollapsingFromKeyboard`)은 제거. 사용자가 드래그로 직접 내리는 방식으로 단순화
