# 도둑 팀 재접속/초기 진입 시 이전 공개 발자국이 복구되어 노출됨 (#289)

### 📌 작업 개요

도둑 플레이어가 앱 강제 종료 후 재접속하거나, 뒤늦게 게임에 처음 진입했을 때 이미 공개된 동료 발자국이 지도에 즉시 복구 표시되던 버그 수정. 경찰 이동 시작 시각을 기준으로 복구 호출 자체를 게이팅하는 방식으로 해결.

### 🔍 문제 분석

#### 원인

- STOMP `connected` 상태 콜백에서 `_fetchLastRobberLocations` 를 **무조건** 호출
- 이 API(`GET /api/games/{gameId}/robbers/location`)는 팀 구분 없이 마지막 공개 위치를 반환
- 결과적으로 첫 진입/재접속 시점에도 과거 공개된 발자국이 한꺼번에 지도에 복구됨
- 특히 도둑 팀 입장에서는 끊고 다시 들어오면 그동안 노출된 동료의 이력이 전부 보이는 셈이 되어 게임 밸런스를 해침

#### 설계 판단

이슈는 "도둑 팀만" 복구를 차단하는 방향으로 예상 동작을 정의했으나, 다음 이유로 **시간 기반 공통 가드**로 구현 방향을 수정함:

1. 원인을 팀 구분이 아닌 "reveal이 발생 가능한 시점인가"로 잡으면 경찰/도둑 모두 첫 진입에서 과거 데이터 노출이 차단됨
2. `_hasConnectedOnce` 플래그 방식은 notifier 인스턴스 수명과 묶여있어 **앱 kill 후 재진입** 케이스를 잡지 못함
3. 경찰이 게임 중반에 새로 참여(앱 kill 후 재진입 포함)하는 경우에도 복구가 정상 동작해야 함
4. 서버 응답이 이전 게임 잔존 데이터를 내려주는 상황이 관측되어, 프론트 방어가 필요

시간 기반 판정(`now >= gameStartTime + policeWaitMinutes`)은 notifier 인스턴스 수명과 무관하게 동작하므로 앱 kill/재진입 케이스까지 커버됨.

### ✅ 구현 내용

#### 1. 복구 호출 게이트 추가 (시간 기반)

- **파일**: `lib/features/game/presentation/providers/game_event_provider.dart`
- **변경 내용**: `_fetchLastRobberLocations` 초입에 "경찰 이동 시작 전이면 skip" 가드 추가
- **이유**: reveal이 발생할 수 있는 시점이 아니라면 서버 응답이 비어있든 스테일하든 UI에 노출할 이유가 없음

#### 2. STOMP 연결 전 설정 로드 보장

- **파일**: `lib/features/game/presentation/pages/game_page.dart`
- **변경 내용**: `_initGameConnections` 를 `async` 로 변경하고 `_initSettingsFromApiIfNeeded()` 를 먼저 `await` 한 뒤에 `_connectGameEvents()` 실행
- **이유**: 위의 시간 기반 가드가 `participantInfo.gameStartTime` / `policeWaitMinutes` 에 의존하므로, STOMP 연결 시점엔 이 값이 반드시 로드되어 있어야 함. splash 경유 재진입(앱 kill 후 복귀) 케이스에서 race 발생 가능성이 있었음

### 🔧 주요 변경사항 상세

#### `_fetchLastRobberLocations` 가드 로직

```dart
Future<void> _fetchLastRobberLocations(int gameId) async {
  // 경찰 이동 시작 전에는 reveal 발생 불가 → API 호출 자체를 skip.
  final participantInfo = ref.read(gameParticipantNotifierProvider);
  final gameStartTimeStr = participantInfo?.gameStartTime;
  final policeWaitMinutes = participantInfo?.policeWaitMinutes;
  if (gameStartTimeStr == null || policeWaitMinutes == null) {
    debugPrint('[GameEventNotifier] ⏭️ 발자국 복구 skip (게임 설정 미로드)');
    return;
  }
  final startTime = DateTime.tryParse(gameStartTimeStr);
  if (startTime == null) {
    debugPrint('[GameEventNotifier] ⏭️ 발자국 복구 skip (startTime 파싱 실패)');
    return;
  }
  final policeMoveTime = startTime.add(Duration(minutes: policeWaitMinutes));
  if (DateTime.now().isBefore(policeMoveTime)) {
    debugPrint('[GameEventNotifier] ⏭️ 발자국 복구 skip (경찰 대기 중)');
    return;
  }

  // ... 이후 기존 fetch 로직
}
```

- 기존 race 가드(`lastLocationRevealTime` 스냅샷 비교)는 그대로 유지
- `participantInfo` 미로드 / 파싱 실패 시 보수적으로 skip

#### `_initGameConnections` 순서 조정

```dart
Future<void> _initGameConnections() async {
  if (_isLocationPermissionDenied) {
    setState(() => _isLocationPermissionDenied = false);
  }
  _connectChat();

  // STOMP 연결 전에 설정 로드 보장 (가드가 participantInfo에 의존)
  await _initSettingsFromApiIfNeeded();
  if (!mounted) return;

  _connectGameEvents();
  _loadGameArea();
  _showPoliceTimerIfNeeded();
  _sendGameStartSystemMessages();

  WidgetsBinding.instance.addPostFrameCallback((_) {
    _showTutorialIfNeeded();
  });
}
```

- 로비 경유 진입 시 `_initSettingsFromApiIfNeeded` 는 early return → 지연 없음
- splash 재진입 시에만 settings API 1회 호출 비용 발생 (~수백 ms)
- 기존 `_initSettingsAndStartMessages` 래퍼 메서드는 제거 (본 메서드에 흡수)

**특이사항**:

- **이슈와 구현 방향의 차이**: 이슈는 "도둑 팀에서만 복구 스킵"을 제안했으나, 시간 기반 공통 가드로 구현. 양 팀 동일하게 "경찰 대기 구간 동안은 skip, 이후는 fetch". 실제 결과는 이슈가 원한 동작(도둑 첫 진입/재접속 시 과거 노출 차단 + 경찰 재접속 시 복구 정상)을 포함하면서, 경찰 초기 진입 시 서버 스테일 응답 노출 리스크도 함께 차단함
- **앱 kill 재진입 케이스**: 초기 `_hasConnectedOnce` 플래그 접근이 notifier 수명에 묶여 실패. 시간 기반으로 전환하면서 해결

### 📌 참고사항

- **시계 드리프트**: `DateTime.now()` 기반이므로 기기 시계가 심하게 틀어지면 오판정 가능. 다만 기존 `canPoliceArrest` 로직과 동일한 기준이라 새로운 리스크는 아님
- **settings API 실패 시**: 복구 skip (조용히 넘어감). 게임 진행 자체엔 영향 없음. 다음 네트워크 재연결에서 다시 시도될 수 있음
- **향후 개선 여지**: 라인 740의 `DateTime.tryParse` 는 기존 코드베이스의 "API 응답은 직접 tryParse, STOMP 이벤트는 `_parseTimestamp` 정규화" 컨벤션을 따름. Dart의 `DateTime.tryParse` 는 7자리 이상 fractional second도 내부적으로 microsecond로 truncate하므로 실질적으로 동등하게 동작하며, 추가 변경 불필요
