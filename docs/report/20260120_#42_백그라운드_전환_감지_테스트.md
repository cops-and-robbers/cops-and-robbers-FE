## 📋 개요

Flutter 앱의 생명주기 상태(resumed, inactive, hidden, paused, detached)를 실시간으로 모니터링하고 시각화하는 개발자 도구를 구현했습니다. 게임 최적화(위치 추적, WebSocket 연결 관리)를 위한 생명주기 기반 제어의 기반을 마련했습니다.

## 🐛 해결한 주요 문제

### 문제 1: "ref after disposed" 에러 (CRITICAL)

**증상**:
```
StateError: Cannot use "ref" after the widget was disposed.
```

**원인**:
Widget의 `dispose()`에서 `ref.read()`를 호출했으나, 이미 ref가 dispose된 상태

**해결**:
```dart
// ❌ Before
@override
void dispose() {
  ref.read(appLifecycleServiceProvider).deactivate();
  super.dispose();
}

// ✅ After
@override
void dispose() {
  // Provider가 자동으로 deactivate 및 dispose 처리
  super.dispose();
}
```

Provider의 `ref.onDispose`로 자동 정리:
```dart
ref.onDispose(() {
  if (service.isActive) {
    service.deactivate();
  }
  service.dispose();
});
```

### 문제 2: "Cannot add new events after calling close" 에러 (CRITICAL)

**증상**:
```
Bad state: Cannot add new events after calling close
```

**원인**:
빠른 페이지 전환 시 StreamController가 닫힌 후에도 생명주기 이벤트가 계속 발생

**해결**:
`didChangeAppLifecycleState`에서 StreamController 닫힘 상태 체크:
```dart
@override
void didChangeAppLifecycleState(AppLifecycleState state) {
  if (_stateController == null || _stateController!.isClosed) {
    stateStream; // ignore: unnecessary_statements (getter로 재생성)
  }
  _currentState = state;
  _addLog(state);
  _stateController!.add(state);
  debugPrint('🔄 AppLifecycleState: ${state.name}');
}
```

### 문제 3: 빠른 페이지 전환 시 Race Condition (CRITICAL)

**증상**:
- "⚠️ 이미 활성화되어 있습니다" 경고
- "⚠️ StreamController가 이미 닫혔습니다" 에러
- 로그가 즉시 나타나지 않음

**원인**:
싱글톤 서비스의 StreamController가 닫혔지만 인스턴스는 유지되어, 재진입 시 닫힌 Stream 사용 시도

**설계 결정**:
싱글톤 패턴 유지 (게임 화면 재사용성을 위해)

**해결**: **StreamController 재생성 패턴**

```dart
// StreamController를 nullable로 선언
StreamController<AppLifecycleState>? _stateController;

// getter에서 자동 재생성
Stream<AppLifecycleState> get stateStream {
  // null이거나 닫혔으면 새로 생성
  if (_stateController == null || _stateController!.isClosed) {
    _stateController = StreamController<AppLifecycleState>.broadcast();
    debugPrint('🔄 AppLifecycleService: StreamController 재생성');
  }
  return _stateController!.stream;
}

// dispose에서도 null 체크
void dispose() {
  if (_isActive) {
    deactivate();
  }
  if (_stateController != null && !_stateController!.isClosed) {
    _stateController!.close();
  }
  debugPrint('🔚 AppLifecycleService: 서비스 종료');
}
```

**효과**:
- 페이지 재진입 시 자동으로 새 StreamController 생성
- 싱글톤 패턴 유지하면서도 안전한 재사용
- 게임 화면 등 다른 곳에서도 활용 가능

### 문제 4: Flutter 3.13+ `hidden` 상태 미지원

**해결**:
모든 switch 문에 `hidden` 케이스 추가 (파란색, visibility_off 아이콘)

### 문제 5: Flutter Analyze 경고 (5개)

**해결**:
- 불필요한 import 제거
- `withOpacity` → `withValues(alpha: 0.1)` (deprecated 해결)
- `Ref` → `WidgetRef` 타입 명시

## 🧪 테스트 시나리오

### 기본 생명주기 테스트
1. **홈 버튼 누르기**
   - 예상: inactive → hidden → paused
   - 확인: 상태 카드 색상 변화, 로그 3개 추가

2. **앱 복귀하기**
   - 예상: hidden → inactive → resumed
   - 확인: 녹색 resumed 상태로 복귀

3. **앱 스와이프 종료** (환경에 따라 다름)
   - 예상: detached (일부 환경)
   - 확인: 빨간색 detached 상태

### 빠른 페이지 전환 테스트 (Race Condition)
1. **테스트 화면 진입 → 즉시 홈으로 → 재진입**
   - 예상: 에러 없이 정상 동작
   - 확인: "StreamController 재생성" 로그, 상태 정상 표시

2. **여러 번 반복 전환**
   - 예상: 메모리 누수 없음, 에러 없음
   - 확인: "이미 활성화" 경고 없음, 로그 정상 누적

### Provider 생명주기 테스트
1. **테스트 화면 → 뒤로가기**
   - 예상: "ref after disposed" 에러 없음
   - 확인: 정상 홈 화면 복귀

2. **로그 초기화 버튼**
   - 예상: 로그 목록 클리어
   - 확인: 빈 리스트 표시, Snackbar 확인

## 🏗️ 아키텍처 특징

### 1. 싱글톤 패턴
```dart
static AppLifecycleService? _instance;

static AppLifecycleService instance() {
  _instance ??= AppLifecycleService._();
  return _instance!;
}
```

**장점**:
- 앱 전역에서 단일 인스턴스 공유
- 게임 화면, 위치 추적 등 다양한 곳에서 재사용 가능

### 2. StreamController 재생성 패턴
```dart
StreamController<AppLifecycleState>? _stateController;

Stream<AppLifecycleState> get stateStream {
  if (_stateController == null || _stateController!.isClosed) {
    _stateController = StreamController<AppLifecycleState>.broadcast();
  }
  return _stateController!.stream;
}
```

**장점**:
- 페이지 재진입 시 자동 복구
- 싱글톤 패턴과 안전하게 호환
- 명시적 초기화 불필요

### 3. Provider 기반 자동 정리
```dart
ref.onDispose(() {
  if (service.isActive) {
    service.deactivate();
  }
  service.dispose();
});
```

**장점**:
- Widget dispose 시 자동으로 Observer 제거
- ref 생명주기 문제 방지
- 메모리 누수 방지

## 🎓 학습 포인트

### 1. WidgetsBindingObserver 활용
- Flutter 앱의 생명주기를 실시간으로 감지
- `didChangeAppLifecycleState` 콜백으로 상태 변화 처리
- 위치 추적, WebSocket 연결 최적화에 활용 가능

### 2. StreamController 생명주기 관리
- `isClosed` 체크로 닫힌 Stream 사용 방지
- nullable StreamController로 재생성 패턴 구현
- broadcast Stream으로 다중 구독 지원

### 3. Riverpod Provider 생명주기
- `ref.onDispose`로 자동 정리
- Widget dispose 후 `ref.read()` 호출 금지
- Provider가 Widget보다 생명주기가 긴 경우 주의

### 4. Flutter 3.13+ 변경사항
- `AppLifecycleState.hidden` 추가 (백그라운드 전환)
- `withOpacity` deprecated → `withValues(alpha: ...)` 사용
