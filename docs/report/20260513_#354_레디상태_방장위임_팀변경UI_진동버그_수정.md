# 레디 상태에서 방장 위임 시 팀 변경 UI 미표시 버그 수정

## 📌 작업 개요

대기방에서 두 가지 버그를 수정합니다.

1. 레디 상태인 참가자가 방장 권한을 위임받아도 `_isReady` 로컬 상태가 초기화되지 않아 팀 변경 UI가 숨겨지는 버그
2. 대기방 입장/퇴장 시마다 진동이 발생하는 UX 문제

---

## 🔍 문제 분석

### 버그 1 — 방장 위임 후 팀 변경 UI 미표시

`TeamSection` 위젯의 `onAddSlotTap`은 `_isReady` 값이 `false`일 때만 콜백을 전달합니다.

```dart
onAddSlotTap: !_isReady ? () => _changeTeam(...) : null
```

`_isReady = true`인 상태에서 `HOST_CHANGED` 이벤트를 수신하면 Provider 상태(`isHost`)는 갱신되지만, `StatefulWidget` 로컬 상태 `_isReady`는 여전히 `true`로 남아있습니다. 그 결과 팀 변경 카드(`AddSlotCard`)가 렌더링되지 않습니다.

**원인**: `_isReady`(StatefulWidget 로컬 상태) 와 `isHost`(Riverpod Provider) 간 동기화 로직 누락

---

### 버그 2 — 대기방 입장/퇴장 진동

`LobbyEventType.enter`, `exit` 이벤트 수신 시 `VibrationService.playerJoinLeave()`가 무조건 호출되는 구조였습니다. 참가자가 많아질수록 입퇴장마다 진동이 반복되어 UX를 저해합니다.

---

## ✅ 구현 내용

### 버그 1 수정 — HOST_CHANGED 이벤트 시 레디 상태 초기화

- **파일**: `lib/features/session/presentation/pages/waiting_room_page.dart`
- **변경 내용**: `HOST_CHANGED` 이벤트 핸들러에서 내가 새 방장임이 확인될 때 `_isReady`를 `false`로 초기화
- **이유**: 방장은 레디 상태가 없어야 하며, 팀 변경 UI가 즉시 노출되어야 함

```dart
// 수정 전: isHost Provider 갱신만 처리
final iAmNewHost = myPid == newHostId;
ref.read(gameParticipantNotifierProvider.notifier).setIsHost(iAmNewHost);

// 수정 후: 내가 방장이 되면 레디 상태도 함께 초기화
if (iAmNewHost && _isReady) {
  setState(() => _isReady = false);
}
```

### 버그 2 수정 — 입장/퇴장 진동 제거

- **파일**: `lib/features/lobby/presentation/providers/lobby_provider.dart`
- **변경 내용**: `ENTER`/`EXIT` 이벤트 시 `playerJoinLeave()` 진동 호출 코드 제거
- **이유**: 다수 참가자 환경에서 입퇴장 빈도가 높아질수록 불필요한 진동 반복 발생

## 🧪 테스트 시나리오

1. 참가자 A가 대기방 입장 후 **레디 상태**로 전환
2. 기존 방장이 퇴장하거나 A에게 방장 위임
3. A의 화면에서 **팀 변경 UI(AddSlotCard)가 즉시 노출**되는지 확인
4. 대기방에 참가자가 입장/퇴장할 때 **진동이 발생하지 않는지** 확인
5. 게임 시작 시 진동은 **정상적으로 울리는지** 확인 (gameStart 진동은 유지됨)
