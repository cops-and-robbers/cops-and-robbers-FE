# 공지사항 API 프론트 연결 #320

### 📌 작업 개요

`api-docs.json`에 추가된 공지사항 API(`GET /api/notices`)를 프론트와 연결. `lib/features/notice/`에 Clean Architecture 3계층(data / domain / presentation)을 신설하고, 기존 정적 더미 데이터를 사용하던 `notices_page.dart`를 Riverpod Provider 기반 실데이터 화면으로 전환. 페이지네이션·고정 공지 핀 아이콘·로딩/에러 표준 패턴까지 함께 적용.

### 🎯 구현 목표

- 공지사항 목록을 백엔드에서 페이지 단위로 조회
- 고정 공지(`pinned=true`)는 백엔드 응답 정렬을 그대로 따르고, UI에서 제목 앞에 핀 아이콘으로 시각적 구분
- 로딩은 `AppPopup.showLoading`, 에러는 `AppSnackbar`(빨간색) 표준 패턴 적용
- `AuthException`은 `AuthInterceptor`가 처리하므로 UI 무반응
- 페이지 전환 시 화면 깜빡임·중복 요청·dispose 후 stale context 방어

### 🛑 비범위 (이슈 요구사항 대비 의도적 제외)

이슈 작업 항목에는 **공지사항 단건 조회 API**(`GET /api/notices/{noticeId}`) 및 **상세 화면 UI**가 포함돼 있었지만, 분석 결과 다음 이유로 **의도적으로 제외**:

- 현재 화면은 **아코디언(펼침/접기)** 방식 — 항목 탭 시 같은 화면에서 본문이 펼쳐짐
- 백엔드의 목록 응답(`NoticeResponse`)에 `content`(본문) 필드가 이미 포함 → 목록 조회 한 번으로 본문까지 모두 채움
- 단건 조회를 추가해도 호출 시점이 없음 (YAGNI)
- 향후 별도 상세 페이지 도입 시 5분 작업으로 추가 가능

### ✅ 구현 내용

#### 1) API 엔드포인트 상수 추가

- **파일**: `lib/core/constants/api_endpoints.dart`
- **변경 내용**: `Notice API` 섹션 신설, `getNotices = '/api/notices'` 상수 추가
- **이유**: 엔드포인트 중앙 관리 + 기존 `reportChat`/`reportBug` 패턴(한 줄 DartDoc) 일관성 유지

#### 2) DTO (Freezed) — 응답 1:1 매핑

- **파일**: `lib/features/notice/data/models/notice_response_model.dart`
- **변경 내용**: 한 파일에 3개 DTO 클래스
  - `NoticeResponseModel` (id, title, content, pinned, createdAt, updatedAt)
  - `NoticeListResponseModel` (content, page)
  - `PageInfoModel` (size, number, totalElements, totalPages)
- **이유**: 백엔드 스키마 그대로 반영. 모든 필드 `required`로 NPE 방지

#### 3) Domain Entity (Freezed) — 외부 의존성 없는 비즈니스 객체

- **파일**: `lib/features/notice/domain/entities/notice_entity.dart`
- **변경 내용**: `NoticeEntity` + `NoticePageEntity` (DTO에서 사용하지 않는 `updatedAt`·`size`·`totalElements` 제외)
- **이유**: Clean Architecture 의존성 역전. JSON 직렬화 미지원

#### 4) Repository 인터페이스 + 구현체

- **파일**: 
  - `lib/features/notice/domain/repositories/notice_repository.dart` (인터페이스)
  - `lib/features/notice/data/repositories/notice_repository_impl.dart` (구현체)
- **변경 내용**: `getNotices({page, size})` 메서드. DTO → Entity 변환 + `DioExceptionHandler.handle(e)` + 일반 `catch (e)`로 비-Dio 예외(JSON 파싱 등)도 `ServerException`으로 통일
- **이유**: UI에서 `error is AppException`을 가정하므로 raw 예외가 새어나가지 않게 차단. 기존 `bug_repository_impl` / `report_repository_impl` 표준 패턴과 동일

#### 5) Retrofit DataSource

- **파일**: `lib/features/notice/data/datasources/notice_remote_datasource.dart`
- **변경 내용**: `@RestApi()` 추상 클래스, `@GET(ApiEndpoints.getNotices)` + `@Query('page')` + `@Query('size')`
- **이유**: `AuthInterceptor`가 JWT 자동 주입 — 헤더 수동 처리 불필요

#### 6) Riverpod Provider + Notifier

- **파일**: `lib/features/notice/presentation/providers/notice_provider.dart`
- **변경 내용**: 3개 `@riverpod` 선언
  - `noticeRemoteDataSource` (DataSource 인스턴스)
  - `noticeRepository` (Repository 구현체)
  - `NoticesNotifier` (페이지 상태 관리, `_pageSize = 10` 고정)
- **이유**: 단순 조회 1종이라 UseCase 미생성(`Design.md` 가이드). `build()`는 `ref.watch`(선언적 의존성), `fetchPage()`는 `ref.read`(액션 메서드)로 Riverpod 컨벤션 준수
- **특이사항**: `fetchPage`에서 `AsyncValue.loading().copyWithPrevious(state)` 사용 — 페이지 전환 중 이전 데이터를 보존해 화면 깜빡임 방지

#### 7) 페이지 UI 연결

- **파일**: `lib/features/notice/presentation/pages/notices_page.dart`
- **변경 내용**: `StatefulWidget` → `ConsumerStatefulWidget` 전환, `noticesNotifierProvider` 연결
- **이유**: 기존 정적 더미 데이터 제거 + 실 API 데이터 표시
- **주요 동작**:
  - 첫 진입 시 `AppPopup.showLoading('공지사항을 불러오는 중...')` 표시 (post-frame callback)
  - `ref.listen`으로 state 변화 감지 → 팝업 자동 닫기, 스크롤 상단 복귀, 펼친 항목 자동 접기
  - 빈 결과 시 페이지 중앙에 "등록된 공지사항이 없습니다" placeholder
  - 에러 시 빨간 `AppSnackbar` (단, `AuthException`은 무시)
  - `pinned == true` 항목 제목 앞에 `icon_pin.svg`(16×16) + 8px 간격

#### 8) 핀 아이콘 자산 추가

- **파일**: `assets/icons/icon_pin.svg`
- **변경 내용**: 16×16 SVG 아이콘 추가
- **이유**: 고정 공지 시각적 구분 (디자인 시안 확정 시 교체 가능한 임시 자산)

#### 9) build_runner 산출물

- **파일**: 5개 generated 파일 (`.freezed.dart` 2개 + `.g.dart` 3개) + `lib/features/game/presentation/providers/game_event_provider.g.dart` 부수 갱신
- **변경 내용**: `dart run build_runner build --delete-conflicting-outputs` 실행 결과
- **이유**: Freezed / json_serializable / Retrofit / Riverpod 코드 생성

### 🔧 주요 변경사항 상세

#### 페이지 전환 깜빡임 방지

`fetchPage`에서 단순 `AsyncValue.loading()`을 set하면 `state.value`가 `null`로 떨어져 화면이 비워질 수 있음. `copyWithPrevious(state)`로 직전 페이지 데이터를 그대로 보존한 채 로딩 플래그만 켬. UI는 `state.value`(이전 데이터)를 그대로 그리고 그 위에 로딩 팝업이 떠 있는 형태가 돼 페이지 클릭 → 새 페이지 도착까지 깜빡임 0.

#### 첫 진입 race 방어

매우 빠른 응답(캐시 등)에서 `ref.listen` 콜백이 `addPostFrameCallback`보다 먼저 실행되면, listen은 닫을 팝업이 없어 early return하고 그 후 post-frame이 팝업을 띄움 → stuck. 방어책: post-frame 안에서 `ref.read(noticesNotifierProvider).isLoading`을 한 번 더 체크하고 이미 응답이 도착한 상태면 팝업을 띄우지 않음.

#### 중복 fetch 방지

페이지 번호를 빠르게 연속 클릭할 경우 `fetchPage`가 중복 호출됨. `_onPageChanged`에서 `ref.read(noticesNotifierProvider).isLoading`을 가드로 두어 진행 중이면 무시.

#### `mounted` 체크 순서 교정

`_handleStateChange`의 `data`/`error` 분기에서 `_closeLoadingPopupIfShown()`(내부에서 `Navigator.of(context)` 사용)을 `mounted` 가드 **앞**에 두면 dispose 후 stale context 접근 가능. 모든 분기에서 첫 번째 `context` 사용 직전에 `if (!mounted) return;` 배치.

- 수동 검증 시나리오:
  - 공지사항 페이지 진입 → 로딩 팝업 → 1페이지 목록 표시
  - pinned 공지가 위쪽에 위치하고 제목 앞 핀 아이콘 표시
  - 페이지네이션 2 → 3 → 1 이동, 매번 팝업 → 닫힘 + 스크롤 상단 + 펼친 항목 접힘
  - 빈 결과 시 placeholder 텍스트
  - 비행기 모드에서 페이지 변경 → 빨간 스낵바
  - 페이지 진입 즉시 뒤로가기 → 잔여 팝업 없음

### 📌 참고사항

- 핀 아이콘(`icon_pin.svg`)은 임시 — 디자인 시안 확정 시 크기/색상 조정 가능
- 단건 조회 API와 상세 페이지가 향후 필요해지면 DataSource에 메서드 한 줄 + Repository 한 줄 + 라우트 추가만 하면 됨 (현재 아키텍처에 자연스럽게 확장 가능)
