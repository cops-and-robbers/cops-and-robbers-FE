### 📌 작업 개요

서버 API와 맞물리는 상태/팀/타입 문자열("WAITING", "POLICE", "ALIVE" 등)이 코드 곳곳에서 문자열 리터럴(매직 스트링)로 흩어져 사용되던 것을 상수 클래스 + helper로 일원화. 동작 변화 없는 순수 리팩토링.

모델 필드는 `String`을 유지하고 비교/할당 지점만 상수 참조로 교체하는 전략을 채택. 팀 값의 대소문자 혼재는 helper로 중앙화.

### 🔧 주요 변경사항 상세

#### GameTeam helper — 대소문자 혼재 중앙화

서버는 팀을 대문자("POLICE")로 내려주지만, 에셋 경로(`character_assets.dart`)는 소문자 키("police")를 사용. 이 변환이 약 22곳에 `.toUpperCase()` / `.toLowerCase()`로 산재해 있었음.

```dart
static bool isPolice(String? value) => value?.toUpperCase() == police; // null 안전 + 대소문자 무관
static String toLowerKey(String value) => value.toLowerCase();          // 에셋 경로용 소문자 키
```

- 비교: `widget.team == 'ROBBER'` → `GameTeam.isRobber(widget.team)`
- 에셋 소문자 값: `team: 'robber'` → `team: GameTeam.toLowerKey(GameTeam.robber)` (값 'robber' 그대로 보존)

**특이사항**:
- `isPolice`/`isRobber`는 `toUpperCase()`로 정규화하므로, 소문자 입력(예: chat_message_bubble의 정규식 그룹 'police')도 동일하게 동작 → 기존 동작과 결과 동일
- `winnerTeam == widget.team` 같이 두 동적 팀 값을 비교하는 곳(리터럴 없음)은 변경하지 않음

#### 디바이스 타입 중복 로직 통합

`auth_repository_impl.dart`에서 `Platform.isIOS ? 'IOS' : 'ANDROID'`로 직접 분기하던 것을 `DeviceInfoService.getDeviceType()` 호출로 통합. 미사용이 된 `dart:io` import 제거.

#### active_game_route switch 패턴

```dart
return switch (info.gameStatus) {
  GameStatus.waiting => ...,      // static const String → const 패턴으로 유효
  GameStatus.inProgress => ...,

```
