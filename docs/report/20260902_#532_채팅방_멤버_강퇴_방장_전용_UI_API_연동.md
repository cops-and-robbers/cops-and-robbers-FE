### 📌 작업 개요
커뮤니티 채팅방 참가자 목록에 방장 전용 강퇴 기능을 추가한다. 강퇴 API 연동, 참가자 행 UI 개편(방장 배지 + 내보내기 칩), 글 작성/삭제 시 채팅방 목록 갱신 트리거를 함께 다룬다.

### 🎯 구현 목표
- 방장이 참가자 목록에서 다른 멤버를 강퇴할 수 있게 한다
- 강퇴 대상은 방장 자신 제외, 방장이 아닌 사용자에게는 강퇴 칩이 보이지 않게 한다
- 강퇴 후 멤버 목록은 로컬 삭제가 아니라 서버에서 다시 받아 정합성을 지킨다
- 글 작성/삭제가 채팅방 생성/삭제로 이어지는 부수효과를 채팅방 목록에도 반영한다

### ✅ 구현 내용

#### 강퇴 API 연동
- **파일**: `lib/features/community/data/datasources/community_remote_datasource.dart`, `.g.dart`
- **변경 내용**: `DELETE {postId}/chat/members/{userId}` 호출하는 `kickChatMember` 추가
- **이유**: 방장이 아니면 403, 대상이 멤버가 아니면 404, 자기 자신이면 400을 서버가 돌려준다 — UI 제한은 1차 방어일 뿐 서버가 최종 검증

#### Repository 계층 연동
- **파일**: `lib/features/community/domain/repositories/community_chat_repository.dart`, `data/repositories/community_chat_repository_impl.dart`
- **변경 내용**: `kickMember(postId, userId)` 추가, 공통 에러 가드(`_guard`)로 감싸 `errorCommunityChatKickGeneric` 메시지 키 연결

#### Notifier — 강퇴 후 서버 재조회
- **파일**: `lib/features/community/presentation/providers/community_chat_rooms_provider.dart`, `.g.dart`
- **변경 내용**: `CommunityChatMembersNotifier.kick(userId)` 추가 — 강퇴 API 호출 후 `getMembers`로 목록을 다시 받아 `state`에 반영
- **이유**: 강퇴 성공 응답만 믿고 로컬에서 지우면, 강퇴와 동시에 다른 사용자가 들어오거나 나간 변화를 놓친다 (게임 로비 강퇴 ISS-0061과 같은 판단)

#### 참가자 목록 UI 개편
- **파일**: `lib/features/community/presentation/pages/community_chat_room_info_page.dart`
- **변경 내용**:
  - `_MemberRow`에 `canKick`/`onKick` 추가. `canKick`은 `isAuthor && !m.isAuthor` — 보는 사람이 방장이고 대상이 방장이 아닐 때만 참
  - 방장 배지를 기존 `Text`에서 채워진 `_Chip`으로 교체, 강퇴 버튼은 테두리만 있는 `_Chip`으로 추가
  - 로컬 `_Chip` 위젯 신설 — `core/widgets/chips/ActionChip`은 최소 폭 100.w·높이 40.h 고정이라 이 행 크기에 맞추려면 파라미터를 더 뚫어야 해서 지역 위젯으로 대체
  - `_confirmKick`: `AppDialog.confirm`으로 확인 후 `kick` 호출, 실패 시 `AppException` 메시지를 스낵바로 노출
  - 나가기 다이얼로그의 확인 버튼 텍스트를 `communityChatLeave` → `buttonLeave`로 교체 (제목이 이미 "채팅방에서"이므로 버튼은 동사만)

#### 채팅방 목록 갱신 트리거
- **파일**: `community_create_page.dart`, `community_detail_provider.dart`, `community_provider.dart`
- **변경 내용**: 글 작성 성공 시, 글 삭제 시 `communityChatRoomsProvider`가 이미 생성돼 있으면(`ref.exists`) invalidate
- **이유**: 서버가 글 작성자를 자동으로 채팅 멤버 등록하지만 새 방은 메시지 0건이라 소켓 이벤트가 없고, 채팅방 목록은 `keepAlive`라 스스로 다시 받지 않는다 (LSN-0042). 아직 프로바이더가 생성되지 않았다면 건드리지 않는다 — 여기서 invalidate하면 그 자리에서 빌드되어 로그인 상태·소켓까지 끌고 온다

#### i18n 문구
- **파일**: `lib/l10n/app_ko.arb`, `app_en.arb`, `app_ja.arb` (+생성 파일)
- **변경 내용**: `communityChatKickConfirmMessage` 추가 — 게임 로비의 `dialogKickConfirmMessage`를 재사용하지 않는다. 채팅방 강퇴는 재입장 제한이 없어(DEC-0043) 문구가 다르다

### 🔧 주요 변경사항 상세

#### `_Chip` (신규 지역 위젯)
방장 배지(채워진 배경)와 강퇴 버튼(테두리만) 두 모양을 하나의 위젯으로 그린다. `borderColor`가 없으면 배지, 있으면 강퇴 버튼 모양이 된다. `onTap`이 없으면 `GestureDetector`를 씌우지 않는 순수 표시용 칩이 된다.

**특이사항**:
- 강퇴 칩은 `AppTextStyles.tag_10` Medium을 쓴다 — 행마다 반복되는 액션이라 Bold를 쓰면 닉네임보다 먼저 읽혀서다
- 방장 배지는 채도 높은 배경 위 10px 흰 글자라 대비(4.85:1)를 지키려 Bold를 쓴다
- 폭이 모자라면 닉네임(`Expanded`)이 양보하고, 배지·칩 폭은 고정이다

### 📌 참고사항
- 서버 에러 코드: 403 `FORBIDDEN_NOT_CHAT_HOST`, 404 `CHAT_MEMBER_NOT_FOUND`, 400 `CANNOT_KICK_SELF`
- 강퇴는 소켓 세션을 끊지 않고 `KICK` 시스템 메시지만 브로드캐스트한다 — 실시간 반영은 소켓 쪽 별도 흐름
- 관련 결정: DEC-0043(재입장 제한 없음), 관련 교훈: LSN-0042(keepAlive 프로바이더 수동 invalidate 시점)
