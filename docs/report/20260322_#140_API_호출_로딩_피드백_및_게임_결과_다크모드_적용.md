### 📌 작업 개요

API 호출 시 로딩 피드백이 없어 사용자가 앱이 멈춘 것으로 인식하는 문제를 해결하고, 토큰 재발급 실패 시 에러 메시지를 사용자에게 전달하며, 도둑팀 게임 결과 팝업에 다크모드를 적용한다.

### 🎯 구현 목표

- API 호출 시 게임 테마에 맞는 재치있는 로딩 메시지를 랜덤으로 표시
- reissue 실패 시 백엔드 에러 메시지(RFC 7807 detail)를 로그인 화면 스낵바로 전달
- 도둑팀 게임 결과 팝업에 다크모드(배경, 폰트, 버튼 색상) 적용

### ✅ 구현 내용

#### 1. 카테고리별 랜덤 로딩 메시지 시스템

- **파일**: `assets/messages/loading_messages.json` (신규)
- **변경 내용**: 9개 카테고리(방 참여/생성, 팀 변경, 게임 시작, 영역 수정, 설정 저장, 프로필 로드, 로그아웃, 회원탈퇴)별 로딩 메시지 JSON 데이터 구성
- **이유**: 게임 컨셉(경찰과 도둑)에 맞는 재치있는 문구를 카테고리별로 랜덤 표시하여 UX 향상

- **파일**: `lib/core/services/loading_message_service.dart` (신규)
- **변경 내용**: `LoadingCategory` enum + `LoadingMessageService` 클래스 구현. JSON 에셋을 최초 1회 로드 후 메모리 캐싱하고, 카테고리별 랜덤 메시지를 반환
- **이유**: 매번 JSON을 파싱하지 않고 캐싱하여 성능 확보. fallback 메시지로 로드 실패 시에도 안정적 동작

#### 2. AppPopup 로딩 헬퍼 메서드 추가

- **파일**: `lib/core/widgets/dialogs/app_popup.dart`
- **변경 내용**: `showLoading()`, `showRandomLoading()` 두 가지 static 메서드 추가
- **이유**: API 호출부마다 로딩 UI를 직접 구성하지 않고 한 줄로 호출 가능하도록 공용화. `showRandomLoading`은 카테고리만 지정하면 메시지 로드 → 팝업 표시까지 자동 처리

**특이사항**:
- `showRandomLoading`의 Future는 **메시지 로드 완료 시** resolve. 팝업 닫힘 시가 아님 (fire-and-forget 패턴)
- 팝업 닫기는 호출부에서 `Navigator.of(context).pop()`으로 직접 수행

#### 3. 강제 로그아웃 에러 메시지 전파 체인

- **파일**: `lib/core/network/auth_interceptor.dart`
- **변경 내용**: `onForceLogout` 콜백 시그니처에 `{String? message}` 파라미터 추가. reissue 실패 시 RFC 7807 `detail` 필드를 파싱하여 메시지 전달
- **이유**: 토큰 재발급 실패 사유를 사용자에게 구체적으로 알리기 위함

- **파일**: `lib/core/network/dio_client.dart`
- **변경 내용**: `ForceLogoutFn` typedef에 `{String? message}` 추가. `forceLogoutMessageProvider` (StateProvider) 신규 추가. Dio Provider에서 콜백 호출 시 message 전달
- **이유**: core → auth 간 메시지 전달 매개체 역할

- **파일**: `lib/features/auth/presentation/providers/auth_provider.dart`
- **변경 내용**: 강제 로그아웃 콜백 등록부에서 `message`를 `forceLogoutMessageProvider`에 저장
- **이유**: 로그인 화면에서 consume 가능하도록 StateProvider에 보관

- **파일**: `lib/features/auth/presentation/pages/login_page.dart`
- **변경 내용**: `initState`에서 `forceLogoutMessageProvider`를 읽고, 값이 있으면 빨간색 스낵바로 표시 후 null로 초기화 (1회 소비)
- **이유**: 강제 로그아웃 후 리다이렉트된 로그인 화면에서 사유 메시지를 표시

**메시지 전파 흐름**:
```
AuthInterceptor (reissue 401 → RFC 7807 파싱)
  → DioClient (onForceLogout 콜백 호출)
    → AuthNotifier (forceLogoutMessageProvider에 저장)
      → LoginPage (스낵바 표시 후 소비)
```

| 페이지 | 카테고리 | 파일 |
|--------|----------|------|
| 홈 (방 참여) | `joinRoom` | `home_page.dart` |
| 세션 생성 | `createRoom` | `session_creation_flow_page.dart` |
| 대기실 (팀 변경) | `changeTeam` | `waiting_room_page.dart` |

| 게임 설정 수정 | `saveSettings` | `game_settings_edit_page.dart` |
| 설정 (닉네임 변경) | `loadProfile` | `settings_page.dart` |
| 설정 (로그아웃) | `logout` | `settings_page.dart` |
| 설정 (회원탈퇴) | `deleteAccount` | `settings_page.dart` |

**적용 패턴** (공통):
```dart
await AppPopup.showRandomLoading(context: context, category: LoadingCategory.xxx);
await apiCall();
if (navigator.canPop()) navigator.pop(); // 로딩 팝업 닫기
```

**특이사항**:
- 기존 회원탈퇴의 인라인 로딩 UI를 `showRandomLoading`으로 통일
- try/catch의 에러 분기에서도 `navigator.pop()`으로 로딩 팝업을 닫아 누수 방지

### 🧪 테스트 및 검증

- 각 API 호출부에서 로딩 팝업이 정상 표시되고 API 완료/실패 시 닫히는지 확인
- 네트워크 느린 환경에서 로딩 메시지가 랜덤으로 변경되는지 확인
- reissue 401 발생 시 로그인 화면에서 에러 메시지 스낵바 표시 확인
- 도둑팀으로 게임 종료/결과 팝업 진입 시 다크모드 스타일 적용 확인
- 경찰팀으로 동일 팝업 진입 시 기존 라이트모드 유지 확인

### 📌 참고사항

- `showRandomLoading`은 fire-and-forget 패턴으로 팝업의 Future를 await하지 않음. 호출부에서 반드시 `navigator.pop()`으로 닫아야 함
- `forceLogoutMessageProvider`는 1회 소비(consume) 패턴. 로그인 화면 진입 시 읽고 즉시 null로 초기화하여 중복 표시 방지
- 로딩 메시지 JSON은 앱 번들에 포함되며, 최초 1회 로드 후 메모리 캐싱하여 이후 호출 시 추가 I/O 없음
