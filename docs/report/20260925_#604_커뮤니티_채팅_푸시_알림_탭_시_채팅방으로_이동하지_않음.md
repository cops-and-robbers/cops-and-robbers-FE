### 📌 작업 개요
커뮤니티 채팅 푸시(일반 채팅·게임 초대·고정 채팅 등록/수정/삭제)를 탭해도 채팅방으로 가지 않던 문제를 고쳤다. 함께, 게임·대기실 중에는 커뮤니티 채팅·댓글 알림을 탭해도 이동하지 않고 스낵바로 안내하도록 막았다 — 게임 위에 커뮤니티 화면이 얹힌 뒤 그 화면이 스택을 갈아엎으면 게임 화면이 사라지며 소켓과 백그라운드 위치 전송이 끊기기 때문이다.

**보고서 파일**: `docs/report/20260925_#604_커뮤니티_채팅_푸시_알림_탭_시_채팅방으로_이동하지_않음.md`

### 🔍 문제 분석

#### 채팅방으로 이동하지 않음
- 서버(`CommunityChatFcmNotifier`)는 커뮤니티 채팅 푸시를 `{type: TEXT | GAME_INVITE, postId}`, 고정 채팅 푸시를 `{type: PIN_REGISTERED | PIN_UPDATED | PIN_DELETED, postId}`로 보낸다. 채팅방은 글당 하나라 `postId`만으로 목적지가 정해진다
- 앱의 `PushNavigationEvent.fromData`는 `CHAT`(인게임 채팅)과 `COMMENT`·`REPLY`(게시글 상세)만 이동 이벤트로 바꾸고 나머지는 `null`을 돌려줘, 탭해도 앱만 열렸다
- 서버 변경은 필요 없다

#### 게임 중 알림 탭으로 게임이 끊길 수 있음
- 게임 중 앱이 백그라운드일 때(화면 잠금 등) 알림을 탭하면, 기존에는 댓글·답글 알림(#500)이 게임 화면 위로 게시글 상세를 push했다
- 상세·채팅방의 뒤로가기(`context.pop()`)는 게임으로 돌아온다 — go_router가 비어 버린 탭 셸까지 함께 걷어낸다
- 그러나 채팅방의 강퇴(`community_chat_room_page.dart:73`)·게시글 보기(`community_chat_room_info_page.dart:143`)·나가기(`:233`)는 `go`로 스택을 교체해 게임 화면을 없앤다. 이때 `GamePage.dispose()`가 게임 소켓·채팅을 끊고 백그라운드 위치 서비스를 멈춘다(`game_page.dart:396`)
- 게임 복귀 경로는 홈 탭의 활성 게임 확인(최초 1회) 또는 앱 재시작뿐이다
- 서버는 게임 참여 여부로 커뮤니티 푸시를 거르지 않는다(수신자 결정에 게임 조건 없음) — 앱에서 막아야 한다

### ✅ 구현 내용

#### 커뮤니티 채팅 푸시 판별
- **파일**: `lib/core/services/fcm/push_navigation_event.dart`
- **변경 내용**: `PushNavigationEvent.communityChat(postId)` 추가. `fromData`가 `TEXT`·`GAME_INVITE`·`PIN_*` + `postId`를 채팅방 이벤트로 바꾼다
- **이유**: 서버가 이미 보내는 값만으로 목적지를 정할 수 있다

#### 알림 탭 판단 분리
- **파일**: `lib/router/push_tap_action.dart` (신규)
- **변경 내용**: `resolvePushTap(event, stack)`이 세 가지 중 하나를 돌려준다
  - 인게임 채팅 → 게임 쪽 리스너로 넘김(게임 중에도 막지 않음)
  - 게임·대기실 중 커뮤니티 알림 → 이동 차단
  - 그 외 → 목적지로 이동(`pushDestination`: 채팅방 `/community/:postId/chat`, 상세 `/community/:postId`)
- **이유**: `main.dart` 리스너 안에 있던 판단을 테스트할 수 있게 하고, 콜드 스타트와 목적지를 한 곳에서 쓰기 위해

#### 게임 중 판정
- **파일**: `lib/router/active_game_route.dart`
- **변경 내용**: `isInGameFlow(stack)` — 라우터 스택의 최상위 match에 게임·대기실 라우트가 있으면 게임 중으로 본다(맨 위 화면만 보지 않음)
- **이유**: 게임 위에 신고 화면 등이 떠 있어도 아래 게임을 지켜야 한다. 앱은 게임·대기실에 항상 `go`로 들어가 둘은 스택 최상위에 있다

#### 실행부 연결
- **파일**: `lib/main.dart`, `lib/features/auth/presentation/pages/splash_page.dart`
- **변경 내용**
  - 앱이 살아 있을 때: `resolvePushTap` 결과대로 push / 스낵바 / 인게임 채팅 전달만 실행
  - 콜드 스타트: `pushDestination`으로 목적지 결정(채팅방은 상세의 하위 라우트라 `go`하면 상세가 아래에 깔림). 게임·대기실 참여 중이면 기존대로 게임 복귀가 우선이라 목적지를 쓰지 않음
- **이유**: 판단과 실행을 나눠 실행부는 결과만 따르게 함

#### 안내 문구
- **파일**: `lib/l10n/app_ko.arb`, `app_en.arb`, `app_ja.arb`
- **변경 내용**: `communityPushUnavailableInGame` — "지금은 커뮤니티 알림을 열 수 없어요" / "You can't open community notifications right now" / "現在コミュニティの通知を開けません"
- **이유**: 탭했는데 반응이 없으면 고장으로 보인다. 기존 인게임 채팅 알림의 안내 방식과 맞춤

### 🔧 주요 변경사항 상세

#### 알림 탭 동작

| 알림 | 평소 | 게임·대기실 중(백그라운드에서 탭) | 앱 종료 상태에서 탭 |
|---|---|---|---|
| 커뮤니티 채팅·게임 초대·고정 채팅 | 채팅방으로 이동(신규) | 이동 없이 스낵바 | 게임·대기실 복귀 우선(기존) |
| 댓글·답글 | 게시글 상세(기존) | 이동 없이 스낵바(신규 차단) | 게임·대기실 복귀 우선(기존) |
| 인게임 채팅 | 기존 동작 | 기존 동작 | 기존 동작 |

**특이사항**:
- 앱이 포그라운드일 때는 모든 푸시를 시스템 알림으로 띄우지 않는 기존 정책(iOS 표시 옵션 off, Android 로컬 알림 미표시) 그대로다. 탭 가능한 알림은 앱이 백그라운드일 때만 생긴다
- `isInGameFlow`는 스택 최상위만 본다. 게임·대기실을 `push`로 여는 곳이 생기면 push된 match 안까지 봐야 한다(코드에 한계 주석)
