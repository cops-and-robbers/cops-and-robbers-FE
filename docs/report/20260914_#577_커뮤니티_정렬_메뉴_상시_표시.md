### 📌 작업 개요
커뮤니티 피드의 조회 상태와 관계없이 정렬 메뉴를 항상 표시하도록 수정했습니다.
인기순 조회 결과가 비거나 조회가 실패해도 사용자가 최신순 등 다른 정렬로 돌아갈 수 있습니다.

### 🔍 문제 분석
정렬 메뉴를 만드는 `_buildSortLabel`이 게시글 목록을 그리는 분기에서만 호출되어, 빈 결과·로딩·오류 상태에서는 메뉴가 함께 사라졌습니다. 인기순처럼 결과가 없는 정렬을 선택하면 다른 정렬로 바꿀 진입점이 없어지는 문제가 있었습니다.

### ✅ 구현 내용

#### 정렬 메뉴를 조회 상태에서 분리
- **파일**: `lib/features/community/presentation/widgets/community_feed_list.dart`
- **변경 내용**: 정렬 라벨을 `feed.when` 바깥의 공통 상단 영역으로 이동하고, 조회 상태별 화면은 아래 `Expanded` 영역에서 렌더링하도록 구성
- **이유**: 게시글 유무와 로딩·오류 여부가 정렬 메뉴의 표시를 결정하지 않도록 하기 위해 수정

#### 빈 결과·오류 상태 회귀 테스트 추가
- **파일**: `test/features/community/presentation/widgets/community_feed_list_test.dart`
- **변경 내용**: 인기순 조회 중과 조회 완료 후에도 정렬 메뉴가 노출되고, 최신순을 다시 선택할 수 있는지 검증하는 위젯 테스트 2건 추가
- **이유**: 빈 결과 또는 요청 실패 뒤 정렬 메뉴가 사라지는 문제의 재발을 방지

### 🔧 주요 변경사항 상세

#### `community_feed_list.dart`
정렬 라벨과 상태별 콘텐츠를 하나의 `Column`으로 배치했습니다. 정렬 라벨은 항상 먼저 렌더링되고, 목록·빈 상태·로딩·오류 화면은 남은 영역에서 전환됩니다.

거리 좌표가 없어 거리순 요청이 최신순으로 대체된 경우 최신순을 표시하는 기존 동작과, 정렬 시트에 실제 선택값을 전달하는 동작은 유지됩니다. 이 위젯을 공유하는 커뮤니티 목록과 검색 결과에 동일하게 적용됩니다.

#### `community_feed_list_test.dart`
인기순 요청을 지연시켜 로딩 상태에서도 `인기순` 라벨을 누를 수 있는지 확인합니다. 요청 완료 후에는 빈 결과와 네트워크 오류를 각각 재현한 뒤 정렬 시트를 다시 열고 최신순으로 전환되는지 검증합니다.
