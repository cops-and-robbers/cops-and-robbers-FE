### 📌 작업 개요

커뮤니티 네이티브 광고 카드 높이를 122pt로 줄이고 Android·iOS 레이아웃을 3행 구조로 정리했다.
목록별로 중복됐던 광고 삽입 로직은 `CommunityAdList`로 통합해 전체, 우리 동네, 내 모임에서 같은 상단·5개 간격·빈 상태 규칙을 사용하도록 변경했다.

### 🎯 구현 목표

- 120pt 미디어와 상하 1pt 여유를 사용하는 122pt 광고 카드 제공
- 플랫폼별 네이티브 광고 자산을 제목·본문·메타데이터 3행으로 배치
- AdMob Validator가 광고 경계를 정확히 판정할 수 있도록 iOS 네이티브 뷰 생성 순서 보완
- 상단 1개, 콘텐츠 5개마다 1개, 빈 목록에도 상단 1개 규칙 공통화
- 기존 `ads_enabled` 게이트와 상세 댓글 영역 광고 유지

### ✅ 구현 내용

#### 광고 카드 높이 축소

- **파일**: `lib/features/community/presentation/widgets/community_native_ad.dart`
- **변경 내용**: 슬롯 너비와 계산된 높이를 플랫폼 팩토리에 전달하고, 미디어 최소 높이 120pt에 상하 1pt를 더한 122pt 기준으로 카드 높이 계산
- **이유**: 커뮤니티 콘텐츠 사이에서 광고가 차지하는 세로 공간을 줄이면서 동영상 미디어 최소 크기와 광고 경계 여유를 함께 확보

글자 확대 시에는 제목, 본문, 메타데이터 3행의 실제 필요 높이가 120pt보다 커질 경우 계산된 높이를 사용한다. 광고 비활성화·미로드·실패 시 기존처럼 공간을 남기지 않고, 위젯 제거 시 광고 객체를 해제한다.

#### Android 3행 네이티브 레이아웃

- **파일**: `android/app/src/main/kotlin/com/elipair/copsandrobbers/CommunityNativeAdFactory.kt`
- **변경 내용**: 좌측 텍스트 영역과 우측 120×120 미디어를 가로 배치하고, 좌측을 `광고 배지 + 제목`, 본문, `아이콘 + 광고주 + 행동 유도 문구`의 3행으로 구성
- **이유**: 필수 광고 자산을 유지하면서 122pt 카드 안에 정보 밀도를 맞추고 커뮤니티 카드와 동일한 가독성 제공

외부 여백은 상하 1pt, 좌우 22pt를 사용한다. 누락된 선택 자산은 숨기고, 미디어는 `CENTER_INSIDE`로 표시한다.

#### iOS 3행 레이아웃 및 Validator 경계 보완

- **파일**: `ios/Runner/CommunityNativeAdFactory.swift`
- **변경 내용**: Android와 동일한 3행 정보 구조와 우측 120×120 미디어 구성 적용. Flutter에서 전달한 슬롯 너비·높이로 `NativeAdView` 프레임을 먼저 생성하고 레이아웃을 확정한 뒤 광고 객체 등록
- **이유**: 광고 등록 시점에 SDK가 완성된 화면 경계를 인식하도록 해 AdMob Validator의 경계 판정 오류 방지

숨겨진 아이콘·광고주·본문·행동 유도 문구는 해당 SDK 뷰 연결에서도 제외한다. 상하 1pt 제약과 `layoutIfNeeded()` 적용 후 광고를 등록하며, 미디어는 `scaleAspectFit`으로 표시한다.

#### 광고 목록 배치 공통화

- **파일**: `lib/features/community/presentation/widgets/community_ad_list.dart`
- **변경 내용**: 광고와 콘텐츠를 조합하는 공통 `CustomScrollView` 추가
- **이유**: 전체 모집글과 내 모임 채팅방에 중복된 광고 위치 계산을 한곳에서 관리하고, 빈 목록과 오류 안내에도 동일한 상단 광고 규칙 적용

`CommunityAdList`는 다음 규칙을 담당한다.

- 광고 활성 배치에서는 목록 상단에 광고 1개 표시
- 실제 콘텐츠 5개마다 광고 1개 추가
- 콘텐츠가 없어도 상단 광고와 기존 빈 상태 안내 함께 표시
- 추가 로딩 표시가 있으면 마지막 콘텐츠 뒤에 배치
- 광고 배치를 끈 화면은 콘텐츠 간격과 하단 여백만 유지

#### 전체·우리 동네·내 모임 재사용

- **파일**: `lib/features/community/presentation/widgets/community_feed_list.dart`, `lib/features/community/presentation/widgets/community_chat_room_list.dart`, `lib/features/community/presentation/pages/community_page.dart`
- **변경 내용**:
  - 전체: `CommunityFeedList`가 `CommunityAdList`를 사용해 상단 광고, 매 5개 광고, 빈 상태 및 추가 로딩 표시 구성
  - 우리 동네: 준비 중 안내를 `CommunityAdList`의 빈 상태로 전달해 상단 광고와 함께 표시하고, 토글 아래 첫 광고 간격을 26pt로 축소
  - 내 모임: 채팅방 목록과 참여 중인 채팅방 없음 안내를 같은 공통 목록으로 구성하고, 토글 아래 첫 광고 간격을 26pt로 축소
- **이유**: 세 탭의 광고 규칙을 동일한 구현으로 유지하고 콘텐츠 유무와 광고 요청을 분리

검색 화면은 `showAds` 기본값 `false`를 유지한다. 내 모임의 로그인 필요, 로딩 및 오류 상태는 기존 분기를 유지하며 로그인 후 데이터가 반환된 목록과 빈 상태에서 공통 광고 배치를 사용한다.

#### 게시글 상세 및 전역 광고 게이트 유지

- **파일**: `lib/features/community/presentation/pages/community_detail_page.dart`, `lib/core/services/ads/ad_service.dart`
- **변경 내용**: 상세의 댓글 수 아래, 댓글 목록 위 광고 배치를 유지하고 `ads_enabled`의 현재 값과 실시간 변경을 네이티브 광고 표시 조건으로 계속 사용
- **이유**: 댓글이 없는 상세에서도 광고 기회를 유지하면서 Remote Config 전역 스위치로 전면 광고와 네이티브 광고를 함께 제어

광고 초기화 또는 로드 실패는 상세 댓글 목록과 입력 기능, 각 목록의 빈 상태 및 콘텐츠 탐색을 막지 않는다.

### 🔧 주요 동작 흐름

1. 각 커뮤니티 탭이 콘텐츠, 빈 상태, 여백 및 광고 표시 여부를 `CommunityAdList`에 전달한다.
2. 공통 목록이 상단 슬롯과 실제 콘텐츠 5개 간격 슬롯을 구성한다.
3. 각 슬롯은 `ads_enabled`가 활성화된 경우에만 기존 광고 SDK 초기화를 기다린다.
4. 초기화 완료 후 플랫폼별 `{ADMOB_AD_UNIT_ID}`와 등록된 네이티브 팩토리로 광고를 요청한다.
5. 팩토리가 122pt 기준 3행 카드에 광고 자산을 연결하고, 로드 완료 시 Flutter 슬롯을 표시한다.
6. 광고가 꺼지거나 로드에 실패하면 슬롯을 숨기며 콘텐츠와 빈 상태는 그대로 유지한다.

### 📦 의존성 변경

- 새 패키지 의존성 없음
- 기존 `google_mobile_ads`, Firebase Remote Config 및 앱 디자인 토큰 재사용
- 운영·테스트 광고 단위 ID는 `{ADMOB_AD_UNIT_ID}`로 마스킹

### 🧪 테스트 및 검증

- `CommunityAdList` 관련 테스트 통과: 콘텐츠 0·4·5·6·10개에서 상단 및 5개 간격 슬롯 수, 빈 상태, 광고 비활성 배치와 간격 확인
- 관련 커뮤니티 위젯·페이지 테스트 통과
- 전체 테스트: 1,228개 통과, 기존 커뮤니티 정렬창 오버플로 6개 실패
- 정적 분석 통과
- iOS 시뮬레이터에서 전체·우리 동네·내 모임 3개 탭의 상단 광고 및 빈 상태 표시 확인
- iOS AdMob Native Ad Validator 통과 확인

### 📌 참고사항

- 122pt는 기본 글자 크기 기준이며 접근성 글자 확대 시 필요한 높이만큼 증가한다.
- 광고 미디어는 120×120 영역 안에서 비율을 유지해 표시한다.
- `ads_enabled` 기본값과 전역 광고 제어 방식은 변경하지 않았다.
- 게시글 상세 광고 위치, 검색·스크랩·알림의 광고 제외 정책도 유지한다.
