### 📌 작업 개요

수감된 도둑이 이번 체포 이후 감옥 내부에 진입한 뒤 경계를 확실히 벗어나면 기존 탈옥 API를 자동 호출하도록 구현했다. GPS 판정 실패나 통신 오류에 대비해 기존 `탈옥하기` 버튼과 확인 다이얼로그는 유지했다.

### 🎯 구현 목표

- 원형과 폴리건 감옥의 실제 경계를 기준으로 이탈 판정
- 불안정한 GPS 표본과 감옥 밖 체포로 인한 오탈옥 방지
- 자동·수동 요청 및 재체포 이벤트 사이의 비동기 경합 방지
- 화면이 멈춘 백그라운드 상태에서도 위치 콜백 기반 자동 탈옥 처리

### ✅ 구현 내용

#### 감옥 이탈 판정기

- **파일**: `lib/features/game/domain/entities/area_shape.dart`, `lib/features/game/domain/jail_escape_detector.dart`
- **변경 내용**: 원형·폴리건의 실제 경계까지 거리를 계산하고, 체포 후 감옥 진입과 확실한 이탈을 순서대로 확인하는 순수 판정기 추가
- **이유**: 폴리건 외접 원이나 단일 GPS 표본으로 판정할 때 생길 수 있는 오탈옥 방지

#### 자동 탈옥 실행 및 백그라운드 복구

- **파일**: `lib/features/game/presentation/pages/game_page.dart`, `lib/core/services/location/device_location_service.dart`
- **변경 내용**: 기존 단일 위치 스트림에서 자동 탈옥 판정을 수행하고 Android 위치 요청 주기를 2초로 명시. 재연결 후 참가자 동기화가 실패하면 2초·4초 뒤 제한적으로 재시도
- **이유**: 별도 위치 구독 없이 기존 백그라운드 위치 흐름을 사용하고, 화면 프레임이 정지한 상태에서도 GPS·STOMP 콜백으로 처리

#### 탈옥 요청 경합 보호

- **파일**: `lib/features/game/presentation/providers/game_event_provider.dart`
- **변경 내용**: 탈옥 요청 결과와 요청 세대를 추적하고, 본인 체포·탈옥·연결 단절 때 이전 요청과 확인 다이얼로그 주기를 무효화
- **이유**: 늦게 도착한 HTTP 응답이 재체포 상태를 덮거나 자동·수동 요청이 중복 전송되는 문제 방지

#### 수동 탈옥 유지

- **파일**: `lib/features/game/presentation/widgets/arrest_lock_overlay.dart`, `lib/features/game/presentation/widgets/participant_overlay.dart`, `lib/l10n/app_*.arb`
- **변경 내용**: `탈옥하기` 버튼과 기존 확인 다이얼로그 유지. 요청 중 버튼 비활성화 및 한국어·영어·일본어 안내 문구 반영
- **이유**: 위치 판정이나 통신이 실패해도 사용자가 수동 경로로 복구 가능

### 🔧 주요 판정 기준

| 항목 | 기준 |
| --- | --- |
| 위치 정확도 | `accuracy ≤ 10m` |
| 표본 나이 | 5초 이하 |
| 감옥 진입 | 유효 내부 표본 2개, 1초 이상 |
| 감옥 이탈 | 경계 밖 거리 `> max(3m, accuracy)`, 유효 외부 표본 2개, 2초 이상 |
| 표본 수신 공백 | 10초 초과 시 연속 후보 초기화 |
| 동기화 재시도 | 2초·4초 뒤 최대 2회 |

### 🧪 테스트 및 검증

- 관련 테스트 5개 파일, 총 60개 테스트 통과
- `flutter analyze` 이슈 없음
- 원형·폴리건 경계, 부정확·오래된·중복·역순 GPS 표본 검증
- 자동·수동 중복 요청, 늦은 성공·실패, 재체포·연결 단절 경합 검증
- 실제 `GamePage`에서 `paused` 상태의 추가 프레임 없이 재연결 → 동기화 재시도 → GPS 이탈 → 탈옥 API 호출 검증

### 📌 참고사항

- 기존 체포 모달의 지도 차단 구조는 변경하지 않았다.
- Android/iOS 실기기의 화면 끄기, 다른 앱 전환, 절전 정책 및 위치 권한 조합은 추가 확인이 필요하다.
- 앱이 종료된 `terminated` 상태의 자동 처리와 서버 체포 규칙 변경은 범위에 포함하지 않았다.
- 이미 전송된 탈옥 HTTP 요청의 서버 실행 자체는 프론트엔드에서 취소할 수 없다. 로컬에서는 늦은 응답이 최신 상태를 덮지 않도록 처리했다.
