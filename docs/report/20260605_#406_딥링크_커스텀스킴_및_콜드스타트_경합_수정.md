# 딥링크 초대 진입 안정화 (#406)

### 📌 작업 개요

설치된 앱에서 초대 딥링크가 앱 대신 스토어로 가거나, 진입에 성공해도 홈에 갇히는 문제를 앱 측에서 해소. 두 가지 변경으로 구성:

1. 커스텀 스킴(`copsandrobbers://`) 등록 및 파싱 — 인앱 브라우저/QR 환경에서 웹 브릿지가 앱을 직접 깨울 수 있는 "문"을 앱에 추가.
2. 콜드 스타트 딥링크 네비게이션 경합 수정 — 오래 idle 후 진입 시 join은 성공했는데 UI가 홈에 머무는 버그 제거.

---

### 🔍 문제 분석

#### 문제 1 — 인앱 브라우저/QR에서 앱이 안 열리고 스토어로 이동

- 카카오톡·인스타·당근 인앱 브라우저, QR(브라우저 경유), 주소창 직접 입력은 OS의 https 링크 가로채기(App Links/Universal Links)가 발동하지 않아 웹 랜딩 페이지로 진입.
- 앱 네이티브 설정·도메인 검증 파일(assetlinks.json/AASA)은 정상(메모/문자 탭은 앱이 정상 실행되는 것이 증거).
- 막힌 환경에서 앱을 깨우려면 웹 페이지가 능동적으로 앱을 호출해야 하는데, iOS는 같은 도메인 Universal Link를 웹페이지에서 재실행할 수 없고 `intent://`도 없어, **커스텀 스킴이 유일한 수단**. 그러나 앱에 커스텀 스킴이 등록돼 있지 않았음.

#### 문제 2 — 콜드 스타트 시 join 성공인데 홈에 갇힘

- 앱을 오래 사용하지 않다가(액세스 토큰 만료) 딥링크로 진입하면 발생. 방금 사용 후 종료한 경우는 정상.
- 원인: 콜드 스타트에 네비게이터가 둘. SplashPage가 `최소 2초 + 활성게임 조회` 후 목적지로 이동하고, 딥링크 흐름은 `/join` 진입 후 join 성공 시 대기방으로 이동한다.
- 토큰 만료 시 join API가 `401 → 토큰 재발급 → 재시도`로 지연 → splash의 활성게임 조회가 먼저 끝나 "참가 안 함"으로 오판 → `홈으로 이동`이 딥링크 페이지를 언마운트 → 뒤늦게 끝난 `대기방 이동`이 `mounted == false`로 폐기 → 홈에 갇힘.

### ✅ 구현 내용

#### 1. iOS 커스텀 스킴 등록
- **파일**: `ios/Runner/Info.plist`
- **변경 내용**: `CFBundleURLTypes` 배열에 `copsandrobbers` 스킴 항목 추가
- **이유**: 웹 브릿지가 `copsandrobbers://join/{code}`로 앱을 직접 실행할 수 있게 함(iOS는 이 방식이 유일하게 신뢰 가능)

#### 2. Android 커스텀 스킴 intent-filter 추가
- **파일**: `android/app/src/main/AndroidManifest.xml`
- **변경 내용**: 기존 https App Links intent-filter와 별개로 `copsandrobbers://join` 커스텀 스킴 intent-filter 추가
- **이유**: 양 플랫폼이 동일 스킴을 받도록 대칭성 확보(Android는 `intent://`(https)로도 동작하므로 보조 경로)

#### 3. 커스텀 스킴 URI 파싱
- **파일**: `lib/core/deeplink/deeplink_event.dart`
- **변경 내용**: `DeeplinkEvent.fromUri`에 커스텀 스킴 분기 추가 — `copsandrobbers://join/{code}`(scheme=copsandrobbers, host=join, path=[code])를 기존과 동일한 `InviteJoinEvent`로 변환
- **이유**: https/커스텀 두 형태 모두 같은 이벤트로 정규화 → 그 아래 입장 로직(인증 확인·join API·라우팅) 전부 재사용

#### 4. 콜드 스타트 단일 소스 프로브 신설
- **파일**: `lib/core/deeplink/deeplink_service.dart`
- **변경 내용**: `coldStartDeeplink` 프로바이더 추가 — `getInitialLink()` 읽기와 dedup(직전 처리 URI 비교)을 한 곳으로 단일화해 "이번 콜드 스타트에서 실제 처리할 이벤트(없으면 null)"를 반환. `deeplinkEvents`의 콜드 스타트 emit이 이 결과를 공유
- **이유**: SplashPage의 "양보 판단"과 `deeplinkEvents`의 "emit 여부"가 같은 dedup 결론을 갖게 해, 양보했는데 딥링크가 스킵돼 splash에 갇히는 불일치를 차단

#### 5. SplashPage 네비게이션 양보
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart`
- **변경 내용**: 점검/강제업데이트 게이트 직후, auth·활성게임 분기 이전에 `coldStartDeeplink` 결과가 `InviteJoinEvent`면 splash가 네비게이션을 하지 않고 종료(양보)
- **이유**: 딥링크 흐름이 입장·대기방 이동을 단독 담당 → 토큰 재발급으로 join이 아무리 지연돼도 splash가 홈으로 덮지 않음(타이밍 무관)

### 🔧 주요 변경사항 상세

#### DeeplinkEvent.fromUri
https는 도메인이 `copsnro66ers.site`라 `join`이 경로(`pathSegments=['join', code]`)지만, 커스텀 스킴은 도메인이 없어 `join`이 호스트(`host='join'`, `pathSegments=[code]`)가 된다. 두 구조를 각각 매칭하되 결과는 동일한 `InviteJoinEvent(inviteCode)`로 통일.

#### coldStartDeeplink ↔ deeplinkEvents 공유
콜드 스타트의 초기 링크 읽기·dedup·마킹을 `coldStartDeeplink` 한 곳에서 수행(keepAlive로 1회 계산·캐시). `deeplinkEvents`는 이 결과를 받아 emit하고, SplashPage는 같은 결과를 보고 양보 여부를 결정한다. warm(앱 실행 중 클릭) 경로는 기존대로 항상 처리.

**특이사항**:
- 콜드 스타트 dedup은 의도된 동작 — Android `singleTop`이 recents 재실행 시 launch intent를 재전달해 매 실행마다 자동 재진입하는 것을 막는다. recents 재실행은 보통 수 분~수 시간 뒤라, "시간 창(N초)" 방식으로 바꾸면 정작 막아야 할 재진입을 못 막으므로 단순 URI 비교 유지.
- 실제 진입 경로(카톡/QR/직접 탭, https/커스텀 스킴)는 모두 `getInitialLink()` 한 지점으로 수렴하므로, 위 변경이 모든 경로에 동일하게 적용된다.

### 📌 참고사항

- 이 작업은 앱 측 "문 열기"까지다. 카톡/QR에서 실제로 앱이 열리려면 **웹 랜딩 페이지(`copsnro66ers.site/join/[code]`, 별도 Next.js/Vercel 레포)가 능동 핸드오프(인앱 감지 → 외부 브라우저 탈출 → 커스텀 스킴/`intent://` 호출)로 개선**되어야 한다. 해당 작업은 별도 이슈로 분리.
- iOS는 커스텀 스킴이 앱에 등록돼야 동작하므로 **App Store 재배포 후** 적용된다. Android는 기존 https App Links로 웹 변경만으로 동작 가능.
- `flutter_deeplinking_enabled=false` / `FlutterDeepLinkingEnabled=false`는 `app_links` 직접 처리를 위한 의도된 값이며 이 문제와 무관 — 건드리지 않음.
