# 네이티브 코드 기반 동적 앱 아이콘 변경 (#383)

### 📌 작업 개요

인앱 언어 설정(한국어/English/日本語)에 맞춰 **홈 화면 앱 아이콘을 런타임에 전환**하는 기능. iOS·Android 모두 **third-party 패키지 없이 자체 네이티브 코드(Swift / Kotlin)** 로 구현했다. 양 플랫폼이 동일한 MethodChannel(`cops_and_robbers/app_icon`)과 단일 Dart 클라이언트를 공유한다.

관련 커밋:
- `61d7372` feat : iOS 로케일 기반 동적 앱 아이콘 전환 (초기 — alternate 아이콘 에셋 등록)
- `cf1cabb` feat : Android 지원 + 자체 네이티브 채널 전환 (third-party 제거)
- `35c0f17` fix : 미지원 언어 기본 로케일 ko→en
- `0f12dd5` fix : 부팅 앱 아이콘 적용 실패 시 예외 흡수 처리 (코드 리뷰 대응)

---

### 🎯 구현 목표

- 인앱 로케일 → 런처 아이콘 자동 전환 (ko/ja는 전용 아이콘, en은 기본 아이콘)
- iOS는 즉시 적용, Android는 **사용 중 강제 종료 없이** 안전한 시점에 적용
- 외부 패키지 의존 없이 OS 표준 API만으로 동작

### ✅ 구현 내용

#### iOS — AppDelegate 네이티브 핸들러

- **파일**: `ios/Runner/AppDelegate.swift`
- **변경 내용**: `cops_and_robbers/app_icon` MethodChannel 핸들러 추가. `UIApplication`의 표준 alternate-icon API 직접 호출.
  - `isSupported` → `UIApplication.shared.supportsAlternateIcons`
  - `getCurrentIcon` → `alternateIconName ?? "app_icon_en"` (Primary는 `app_icon_en`으로 표현)
  - `setIcon` → `"app_icon_en"`은 Primary(nil)로, 그 외(`app_icon_ko`/`app_icon_ja`)는 그대로 `setAlternateIconName(_:completionHandler:)` 호출
- **이유**: iOS alternate 아이콘 에셋은 이미 빌드에 등록(`ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES = "app_icon_ko app_icon_ja"`, `app_icon_ko/ja.appiconset`)되어 있어, 네이티브 API 직접 호출만으로 전환 가능. 외부 패키지 불필요.

#### Android — MainActivity 네이티브 핸들러 + activity-alias

- **파일**: `android/app/src/main/kotlin/com/elipair/copsandrobbers/MainActivity.kt`
- **변경 내용**: 동일 채널(`cops_and_robbers/app_icon`) 핸들러 추가. `PackageManager`로 activity-alias 토글.
  - `getCurrentIcon` → enabled 상태인 alias 반환, 없으면 기본값 `app_icon_en` (설치 직후 `COMPONENT_ENABLED_STATE_DEFAULT` 케이스 처리)
  - `setIcon` → **타깃 alias를 먼저 enable → 나머지 disable**, 전부 `PackageManager.DONT_KILL_APP` 플래그
- **이유**: enable-우선 순서 + `DONT_KILL_APP`으로 런처 컴포넌트가 한순간도 0개가 되지 않게 해 아이콘 소실/프로세스 종료를 최소화.

- **파일**: `android/app/src/main/AndroidManifest.xml`
- **변경 내용**: `activity-alias` 3개(`app_icon_en` 기본 enabled, `app_icon_ko`/`app_icon_ja` disabled) 추가. `MainActivity`의 LAUNCHER intent-filter는 alias로 이전하고, 딥링크(App Links `/join/*`) VIEW 필터는 유지. `<application android:icon>`·FCM 알림 아이콘(`@mipmap/ic_launcher`)은 변경하지 않음.

- **파일**: `android/app/src/main/res/**`
- **변경 내용**: 로케일별 런처 아이콘 리소스 33개 추가 — adaptive XML(`mipmap-anydpi-v26/ic_launcher_{en,ko,ja}.xml`) + foreground/legacy mipmap PNG(밀도별 en/ko/ja). 기존 `ic_launcher*`는 유지.

#### Dart — 단일 클라이언트로 통일

- **파일**: `lib/core/services/app_icon/dynamic_icon_client.dart`
- **변경 내용**: `NativeAppIconClient`(iOS·Android 공통, 채널 호출) + `NoopIconClient`(미지원 플랫폼). 외부 의미는 `null = Primary(en)` 유지하고, **네이티브 진입 직전에만** `null → "app_icon_en"` 변환. 채널 미구현/예외 시 안전 기본값 반환.
- **파일**: `lib/core/services/app_icon/app_icon_service.dart`
- **변경 내용**: 플랫폼별 client 선택(iOS·Android → `NativeAppIconClient`, 그 외 → Noop). 현재 아이콘이 목표와 같으면 set 호출 안 함(불필요한 토글/알럿 방지), 에러는 swallow.
- **파일**: `lib/core/services/app_icon/app_icon_identifiers.dart`
- **변경 내용**: `en = 'app_icon_en'` 식별자 추가(iOS·Android 양쪽 식별자 문자열 일치).

#### 적용 시점 (트리거)

- **파일**: `lib/core/services/app_icon/locale_app_icon_observer.dart`(신규), `lib/main.dart`, `lib/features/settings/presentation/pages/language_settings_page.dart`
- **변경 내용**:
  - **콜드 부팅**: `main.dart`에서 저장 로케일 기준 1회 적용(양 플랫폼).
  - **언어 변경 즉시**: iOS만 즉시 적용. Android는 미적용(연기).
  - **백그라운드 전환**: Android 전용 옵저버가 `paused`/`hidden`/`detached` 시 재적용.
- **이유**: Android의 아이콘 교체는 `ActivityManager`가 activity-alias를 토글하는 방식이라 포그라운드에서 호출하면 런처가 앱 태스크를 재시작/종료시킬 수 있음. 따라서 사용 중에는 적용하지 않고, 저장 로케일을 진실 공급원으로 두어 부팅·백그라운드 시점에만 reconcile.

### 🔧 주요 변경사항 상세

#### iOS↔Android 채널 계약 대칭

두 네이티브 모두 `"app_icon_en"`을 "기본/Primary"로 약속하고, Dart 클라이언트가 `"app_icon_en" → null`로 역변환한다. 덕분에 **단일 클라이언트·단일 채널**로 양 플랫폼을 처리한다.

- `setIcon(ko)`: Dart `"app_icon_ko"` → iOS `setAlternateIconName("app_icon_ko")` / Android `app_icon_ko` alias enable
- `setIcon(en/기본)`: Dart `null → "app_icon_en"` → iOS Primary(nil) / Android `app_icon_en` alias enable

**특이사항**:
- iOS 아이콘 변경 시 시스템 알럿("아이콘이 변경되었습니다")이 1회 노출되는 것은 OS 표준 동작이며, 같은 아이콘이면 skip 처리해 불필요한 알럿을 막는다.
- 런처별(삼성/Pixel/서드파티) 아이콘 캐시 갱신 타이밍 차이는 OEM 한계로 즉시 100% 보장은 불가(설계상 비목표).

### 📦 의존성 변경

이번 작업의 핵심 변경. 초기엔 외부 패키지를 쓰려 했으나 양쪽 다 빌드 차단 이슈가 있어 **모두 제거하고 자체 네이티브로 전환**했다.

- **제거**: `flutter_dynamic_icon` — `android/build.gradle`에 `namespace` 미선언(AGP 8 설정 실패) + 제거된 v1 embedding `PluginRegistry.Registrar` 사용(컴파일 실패)으로 Android 빌드 차단.
- **제거**: `flutter_dynamic_icon_plus` — iOS 코드가 `SwiftTryCatch`에 의존하는데 원본 저장소가 삭제(404)되어 `pod install` 실패.
- **결과**: 동적 앱 아이콘 기능에 third-party 의존 **0**. iOS·Android 모두 OS 표준 API + 자체 MethodChannel.
- **파일**: `pubspec.yaml`(의존성 제거), `pubspec.lock`, `ios/Podfile.lock`.

### 🔧 후속 수정 — 부팅 아이콘 적용 예외 흡수 (코드 리뷰 대응)

CodeRabbit 리뷰에서 `applyStartupLocaleIcon()`이 `resolveStartupLocale()`을 try-catch 없이 await한다는 지적. 이 함수는 내부적으로 `SharedPreferences.getInstance()`를 호출하는데, `main.dart`의 `unawaited(applyStartupLocaleIcon())` 경로에서 실행되므로 드물게 prefs 로드가 실패하면 처리되지 않은 비동기 에러로 새어나갈 수 있음.

- **파일**: `lib/core/services/app_icon/startup_app_icon.dart`
- **변경 내용**: `applyStartupLocaleIcon()` 전체 적용 흐름(`resolveStartupLocale` + `applyLocaleIcon`)을 try-catch로 감싸고, 실패 시 `debugPrint`로 로그만 남기고 흡수.
- **이유**: 부팅 아이콘 적용은 비핵심 side effect라 실패해도 앱 흐름을 깨면 안 됨. `main.dart` FCM 초기화의 `catch (e, stackTrace)` + 로그 패턴과 동일하게 맞춤.

**특이사항**:
- MethodChannel 경로(`supportsAlternateIcons`/`currentAlternateIconName`/`setAlternateIconName`)는 이미 내부 catch로 방어되어 있어, 노출된 미보호 async는 `resolveStartupLocale()` 하나뿐이었음.
- Custom Exception 래핑은 적용하지 않음 — 예외를 UI/도메인으로 전달하지 않고 삼키는 흐름이라 커스텀 예외 생성은 과함. 프로젝트의 다른 초기화 코드(FCM 등)도 동일하게 debugPrint + continue 패턴 사용.

### 📌 참고사항

- **미지원 언어 기본값 ko→en**(`35c0f17`): 중국어 등 미지원 시스템 언어 + "시스템 따름"일 때 아이콘이 한국어로 폴백되던 문제 수정. Android 런처 이름은 `values/strings.xml`(영어)이 기본이므로, `kDefaultLocale`을 en으로 통일해 **아이콘·런처 이름·인앱 UI를 모두 영어로 일치**. 지원 언어(ko/en/ja)·명시적 선택은 영향 없음.
- iOS는 **iPhone 전용**(`TARGETED_DEVICE_FAMILY = 1`)이라 iPad 아이콘 슬롯은 렌더링되지 않음. alternate 세트의 iPad 40×40@1x 누락 슬롯은 Primary와 일관성을 위해 채워둠.
- 향후 아이콘 변경 시 Android 리소스는 손으로 관리(`flutter_launcher_icons`는 Android 재생성 비활성화 — 로케일 변형을 덮어쓰지 않도록).
