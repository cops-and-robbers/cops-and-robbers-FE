### 작업 개요

백엔드 Auth API와 프론트엔드를 연동하여 소셜 로그인(Google/Apple) 전체 플로우를 구현.
Firebase 소셜 로그인 → 백엔드 JWT 토큰 발급 → 자동 토큰 재발급 → 로그아웃까지 E2E 인증 흐름 완성.
닉네임 중복확인/변경 API 연동 및 GoRouter 기반 인증 상태별 라우팅 분기 구현.
CodeRabbit PR 리뷰 기반 인증 인프라 안정성 개선 포함.

---

### 구현 목표

- Firebase 소셜 로그인 → 백엔드 `/api/auth/login` JWT 토큰 발급 연동
- JWT Access Token 자동 주입 및 401 시 자동 재발급 (AuthInterceptor)
- 로그아웃 시 백엔드 + Firebase + 로컬 토큰 삭제 3중 처리
- 닉네임 중복확인/변경 API 연동 (User Feature 모듈)
- 신규 유저 / 기존 유저 GoRouter 리다이렉트 분기
- API 명세서(API_SPEC.md) 작성
- 인증 인프라 안정성 개선 (CodeRabbit 리뷰 반영)

#### 4. 네트워크 인프라 구축

- **파일**: `lib/core/network/dio_client.dart` (신규)
- **내용**: Dio 인스턴스 팩토리 — AuthInterceptor + LogInterceptor(디버그 모드) 자동 구성
  - `baseOptions` 공유하는 `plainDio` 인스턴스도 함께 생성 (인터셉터 없음)

- **파일**: `lib/core/network/auth_interceptor.dart` (신규, 267줄)
- **내용**: JWT 인증 인터셉터
  - `onRequest`: Bearer Token 자동 주입 (공개 경로 제외)
  - `onError` (401): Lock 패턴으로 중복 방지 + refreshToken 기반 자동 재발급
  - 재발급 성공 시 원래 요청 재시도, 실패 시 강제 로그아웃 콜백 실행
  - 공개 경로: `/api/auth/login`, `/api/auth/reissue`, `/api/user/check-nickname`
  - 무한 루프 방지: `_isRetry` 플래그 + reissue 경로 401 감지 → 즉시 강제 로그아웃
  - **plainDio**: reissue 전용 plain Dio 인스턴스로 인터셉터 재진입 방지

- **파일**: `lib/core/network/dio_exception_handler.dart` (신규)
- **내용**: DioException → AppException 변환 핸들러
  - RFC 7807 Problem Details 형식 에러 응답 파싱 (`title`, `status`, `detail`, `instance`)
  - HTTP 상태 코드별 적절한 AppException 서브타입 반환

- **파일**: `lib/core/network/api_error_response.dart` (신규)
- **내용**: RFC 7807 에러 응답 모델 (`ApiErrorResponse`)

### 주요 기술적 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 토큰 재발급 동시성 | Lock 패턴 + pending queue | 여러 API가 동시에 401을 받아도 reissue 1회만 실행 |
| reissue Dio 인스턴스 | plainDio (인터셉터 없음) | reissue 401 시 인터셉터 재진입으로 이중 강제 로그아웃 방지 |
| 인프라 Provider 생명주기 | `@Riverpod(keepAlive: true)` | 화면 전환 시 Dio/Storage dispose 방지 |
| 에러 응답 형식 | RFC 7807 Problem Details | 백엔드가 `{title, status, detail, instance}` 형식으로 반환 |
| 토큰 저장 | flutter_secure_storage | 안전한 JWT 토큰 저장 (iOS Keychain, Android EncryptedSharedPreferences) |
| userId 영속화 | SecureTokenStorage | 앱 재시작 시 userId 복원 (하드코딩 0 제거) |
| 중첩 모델 직렬화 | build.yaml `explicit_to_json` | Freezed 중첩 모델(TokensModel) toJson 정상 동작 |
| FCM 토큰 에뮬레이터 | try-catch 빈 문자열 fallback | 에뮬레이터에서 FCM 미지원 시에도 로그인 가능 |
| 로그아웃 실패 처리 | 백엔드 실패해도 로컬 정리 계속 | 네트워크 오류 시에도 로컬 세션은 반드시 정리 |
| 닉네임 미변경 | API 호출 스킵 | 서버 생성 닉네임은 이미 유니크하므로 불필요한 네트워크 요청 방지 |
| ReissueResponse 구조 | 중첩 `{tokens: {accessToken, refreshToken}}` | LoginResponse와 동일한 중첩 구조 확인 후 반영 |

### 인증 플로우 요약

```
[사용자] → Google/Apple 로그인 버튼 탭
    ↓
[Firebase] 소셜 로그인 → Firebase ID Token 획득
    ↓
[백엔드] POST /api/auth/login (idToken + fcmToken + deviceId)
    ↓
[응답] {userId, nickname, tokens: {accessToken, refreshToken}, isNewUser}
    ↓
[저장] JWT 토큰 + userId → SecureTokenStorage
    ↓
[분기] isNewUser?
    ├── true  → /nickname-setup (닉네임 설정 페이지)
    │             ↓ 닉네임 확인/변경 완료
    │             ↓ authNotifier.updateNicknameCompleted()
    │             └── /home
    └── false → /home (메인 화면)
```

```
[API 요청] Authorization: Bearer {ACCESS_TOKEN}
    ↓
[401 응답] Access Token 만료
    ↓
[AuthInterceptor] Lock 획득 → plainDio로 POST /api/auth/reissue (refreshToken)
    ├── 성공 → 새 토큰 저장 → 원래 요청 재시도
    └── 실패 → 강제 로그아웃 (Firebase signOut + 토큰 삭제 + /login 이동)
```

```
[앱 재시작] SecureTokenStorage에서 토큰 + userId 복원
    ├── 토큰 있음 → AuthResultEntity(userId, isNewUser: false) → /home
    └── 토큰 없음 → null → /login
```
