### 📌 작업 개요
커뮤니티 목록 정렬 시트에 인기순 노출. 서버가 `sort=POPULAR`에 400을 주던 시기에 의도적으로 숨겨둔 항목을, BE #175(Swagger v2.24.0)가 인기순을 구현하면서 되돌림

**보고서 파일**: `.report/20260902_#545_커뮤니티_목록_정렬에_인기순_노출.md`

### 🎯 구현 목표
- 정렬 시트에 인기순 항목 노출 (최신순·인기순·거리순·마감 임박순 4개)
- 인기순 선택 시 `GET /api/community-posts?sort=POPULAR` 호출
- "POPULAR는 400" 전제로 쓰인 낡은 주석 정리

- **변경 내용**: `_order` 리스트에 `CommunitySortOption.popular` 추가 (최신순 다음). 시트 고정 높이 270 → 355 상향
- **이유**: 숨김 당시 주석에 적어둔 예정 경로("서버가 열렸을 때 여기 한 줄만 되돌리면 된다", DEC-0020) 그대로 실행. 높이는 항목 4개 기준으로 위젯 테스트 실측 — 270에서는 4번째 항목이 58px 오버플로우

- **파일**: `community_sort_option.dart`, `community_provider.dart`, `community_remote_datasource.dart`, `error_message_mapper.dart`, `community_wire.dart`

- **이유**: 숨김이 스펙이었던 시절의 테스트를 새 스펙으로 교체

### 🔧 주요 변경사항 상세

#### 인기순 외 추가 연동 코드가 없는 이유
FE는 숨김 당시에도 enum·와이어 매핑(`POPULAR`)·라벨(ko/en/ja)·에러 매핑을 전부 갖춰 두었다. 좌표는 repository 기존 가드가 거리순에만 싣고, 커서는 서버가 점수를 봉인해 내려주는 불투명 값이라 FE 변경 불필요. 정렬 변경 시 커서 없이 첫 페이지부터 재조회하는 기존 구조도 그대로 적용된다.

**특이사항**:
- 인기순 점수 = 좋아요×1 + 스크랩×2 + 채팅 참여 멤버×3, 최근 7일 글만 대상, 마감 글 맨 뒤 (BE 결정 DEC-0039)
- 가중치 최대 항목인 채팅 참여 인원이 목록 카드에 안 보여 순위가 어색해 보일 수 있음 — 서버 목록 응답에 참여 인원 필드가 없어 카드 노출은 BE 선행이 필요한 별도 건 (#545 참고 절 기재)
