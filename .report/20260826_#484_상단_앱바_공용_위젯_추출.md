## 🚀 [기능개선][Flutter][공용컴포넌트] 화면마다 중복된 상단 앱바를 공용 위젯으로 추출

### 📌 작업 개요

화면 26곳이 각자 조립하던 상단 앱바를 공용 위젯 `AppTopBar` 하나로 모았다. 배경색·표면 틴트·그림자 제거·뒤로가기 버튼·가운데 정렬·타이틀 글자 스타일이 매 화면에 그대로 복사돼 있었고, 그 탓에 일부 화면만 설정이 빠지는 식으로 이미 미세하게 어긋나 있었다. 화면에 보이는 결과는 바꾸지 않는 것을 원칙으로 삼았다.

### 🎯 구현 목표

- 반복되는 앱바 구성을 한 곳에 모으고, 화면은 다른 부분만 넘긴다 — 제목, 뒤로가기 동작, 우측 버튼, 팀 테마 여부
- 색·간격·글꼴 등 렌더링 결과는 유지 (순수 리팩토링)
- 앱바 규격 변경 시 한 파일만 고치면 되도록 한다

### 🔍 추출 전 전수 조사

공용화 전에 `AppBar` 사용처를 전부 세어 동작 유형이 섞이지 않는지 확인했다.

| 그룹 | 곳 | 형태 |
| --- | --- | --- |
| A. 라이트 고정 | 10 | `white` + 표면 틴트 제거 + `elevation 0` + `PreviousButton` + 가운데 정렬 + `heading_20(black)` — 완전 일치 |
| B. 팀 테마 | 8 | 위와 같고 색만 `isDark` 분기. 파생식이 6개 파일 전부 동일 |
| C. 크레딧 검정 | 2 | `black` 배경 + 흰 뒤로가기 + 타이틀 없음 |
| D. 제목/leading만 다름 | 6 | 검색(입력창), 채팅방(좌측 정렬), 채팅방 정보(제목 없음), 작성(닫기 아이콘), 단계 표시기 2곳 |
| E. 대상 제외 | 9 | 인게임, 대기방, 개발용 테스트 3곳, 라우터 폴백 2곳, placeholder, onboarding |

A~D 26곳이 전부 정적 헤더로 동작 유형이 같아 추출 대상으로 판단했다. E는 구조가 근본적으로 달라 제외했다 — 인게임 화면은 애초에 `AppBar`가 아니라 지도 위에 겹쳐 그리는 `Stack` 안 컨테이너고, 대기방은 투명 배경에 초대 코드 타이틀과 별도 leading 폭을 쓴다.

### ✅ 구현 내용

#### 공용 위젯 `AppTopBar` 신규

- **파일**: `lib/core/widgets/navigation/app_top_bar.dart` (74줄)
- **변경 내용**: `AppBar`를 상속해 생성자에서 기본값만 채우는 형태. `PreferredSizeWidget` 구현과 `actions`·`bottom` 등 나머지 파라미터는 상속으로 확보
- **이유**: 별도 `StatelessWidget`으로 감싸면 `build()`와 슬롯 배관이 새로 생긴다. 상속하면 새 클래스가 채우는 것은 기본값뿐이고, 이 위젯이 안 다루는 파라미터도 호출부가 그대로 쓸 수 있다

#### 앱바 26곳 전환

- **파일**: 24개 화면 파일
- **변경 내용**: 반복 크롬을 제거하고 다른 부분만 인자로 전달
- **이유**: 호출부 기준 150줄 감소. 남은 줄은 대부분 화면마다 다른 우측 버튼 블록

전환 예시 — 9줄이 2줄이 된다.

```dart
// 전
appBar: AppBar(
  backgroundColor: AppColors.white,
  surfaceTintColor: Colors.transparent,
  elevation: 0,
  leading: PreviousButton(onPressed: () => context.pop()),
  centerTitle: true,
  title: Text(l10n.pageNoticesTitle,
      style: AppTextStyles.heading_20.copyWith(color: AppColors.black)),
),

// 후
appBar: AppTopBar(
  title: l10n.pageNoticesTitle,
  onBack: () => context.pop(),
),
```

#### 죽은 설정값·지역 변수 정리

- **파일**: `game_settings_page.dart`, `session_creation_flow_page.dart`, `session_step_layout.dart`, `setup_prison_page.dart`, `setup_playground_page.dart`, `game_settings_edit_page.dart`
- **변경 내용**: 아무 아이콘도 읽지 않는 `iconTheme` 3곳, 앱바에서만 쓰이던 `titleStyle`·`textColor` 지역 변수 제거
- **이유**: `iconTheme`은 leading이 색 필터를 직접 쓰는 `PreviousButton`이고 actions가 여백뿐이라 실제로 아무 위젯도 참조하지 않는 상태였다

### 🔧 주요 변경사항 상세

#### 팀 테마 전달 방식

기존 결정(팀 테마는 상위 화면이 값으로 내려준다)을 그대로 따라 `isDarkMode` 인자로 받는다. 공용 위젯이 `roleThemeProvider`를 직접 구독하지 않는다. 이 하나로 배경(`black900`/`white`), 타이틀 색(`white`/`black`), 뒤로가기 색(`black200`/`black800`)이 함께 결정된다 — 팀 테마 화면 6개 파일이 전부 같은 파생식을 쓰고 있었다.

#### 도둑 모드 타이틀 글꼴 분기

**특이사항**: 팀 테마 화면 8곳 중 게임 설정과 구역 미리보기 2곳만 도둑 모드에서도 Pretendard(`heading_20`)를 쓰고, 나머지 6곳은 Moneygraphy(`robberHeading`)를 쓴다. 의도된 예외로 확인돼 `useRobberFont` 인자로 분기했다.

```dart
style: (isDarkMode && useRobberFont
        ? AppTextStyles.robberHeading   // Moneygraphy — 기본
        : AppTextStyles.heading_20)     // Pretendard
    .copyWith(color: isDarkMode ? AppColors.white : AppColors.black),
```

호출부에서 스타일을 재조립하지 않고 인자 한 줄로 표현되므로, 예외라는 사실이 코드에서 바로 읽힌다.

#### 렌더링 결과 유지를 위해 확인한 것

**특이사항**: 다음 세 가지는 값이 달라 보여도 렌더링 결과가 같음을 확인한 뒤 통일했다.

- 표면 틴트 — 기존에는 `Colors.transparent`와 배경색이 섞여 있었고 아예 안 넘기는 화면도 3곳 있었다. 배경색과 같은 값으로 두면 셋 다 결과가 같다. 미지정 3곳은 본문이 스크롤되지 않는 화면이라 스크롤 겹침 상태 자체가 없다
- 뒤로가기 자동 생성 — 항상 끄고 `onBack` 유무로만 판단한다. 마이페이지는 탭 루트라 원래도 자동 화살표가 뜨지 않는다
- 가운데 정렬 — 검색 화면만 미지정이었는데 실효값이 `false`였다(Android 기본, iOS도 우측 버튼 2개라 `false`). 기본값이 `true`라 명시적으로 넘겼다

#### 크레딧 화면 배경

**특이사항**: 크레딧 2곳은 팀 테마의 `black900`이 아니라 고정 `black`이고 뒤로가기도 순백이다. 팀 테마로 흡수하면 색이 미세하게 바뀌므로 `backgroundColor` 인자로 정확히 유지했다.

### 📌 참고사항

- 우측 버튼 아이콘의 좌우 여백이 화면마다 6·8·16·20으로 제각각이다. 통일은 디자인 판정이 필요해 이번 범위에서 제외하고 각 화면이 넘기던 값을 그대로 유지했다
- 타이틀에 한 줄 제한을 기본값으로 넣지 않았다. 지금 긴 제목이 넘치는 화면이 있는데 기본값으로 넣으면 말줄임이 새로 생겨 렌더링 결과 유지 원칙을 깬다
- 인게임 화면과 대기방은 구조가 달라 제외했다. 향후 이 둘까지 흡수하려면 앱바가 아닌 형태를 어떻게 다룰지 별도 판단이 필요하다
