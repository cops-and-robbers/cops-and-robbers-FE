# 커뮤니티 알림 수신 설정 3단 연동 (전체 동의·게시글별·댓글별)

### 📌 작업 개요
백엔드 #182(Swagger v2.26.0)가 "알림을 어디까지 받을지" 정하는 값 3개를 열어 응답에 실어 보내고
있었으나, **앱이 셋 다 버리고 있었다.** freezed가 모르는 키를 조용히 무시해 `flutter analyze`도
테스트도 울지 않는 상태였다. 세 값을 읽어 화면에 붙이고, 각 값을 바꾸는 API 3종을 연결했다.

**보고서 파일**: `.report/20260830_#501_커뮤니티_알림_수신_설정_3단_연동.md`

| 단계 | 값 | 화면 | 끄면 |
|---|---|---|---|
| 전체 동의 | `allowCommunityPush` | 마이페이지 | 커뮤니티 **푸시만** 안 옴 — 알림함에는 그대로 쌓임 |
| 게시글별 | `notificationSettings{comment,reply}` | 게시글 상세 ⋯ 메뉴 | 그 글의 알림이 **저장 자체가 안 됨** |
| 댓글별 | `replyNotificationsEnabled` | 내 댓글 ⋯ 메뉴 | 그 댓글의 대댓글 알림만 안 옴 |

### 🎯 구현 목표
- 마이페이지 "앱 설정"에 커뮤니티 알림 스위치 추가 (게임 알림 행 아래)
- 게시글 상세 더보기 메뉴에서 그 글의 알림 켜기/끄기
- 내가 쓴 댓글의 더보기 메뉴에서 대댓글 알림 켜기/끄기
- 세 토글 모두 낙관적 갱신 — 서버 응답을 기다리지 않고 먼저 뒤집고, 실패하면 되돌린 뒤 사유를 알림

### 🔧 주요 변경사항 상세

#### 남의 글에서도 켤 수 있다 — 백엔드 코드로 확인한 수신자 규칙
`CommunityNotificationService.resolveRecipients`가 댓글 생성 시점에 받을 사람을 확정한다:
**글 작성자** + **그 글을 명시적으로 켠 제3자**(설정 행이 있는 사람) + **부모 댓글 작성자**.
즉 게시글별 토글은 내 글 전용 기능이 아니라 "이 글 알림 받기"라는 구독 스위치다. 스웨거 설명만
읽으면 놓치는 부분이라 서버 코드로 확인했고, 그래서 메뉴 항목을 남의 글에도 노출한다.

설정 행이 없을 때 서버가 내려주는 기본값도 역할에 따라 갈린다 — 내 글 `(댓글 on, 답글 off)`,
남의 글 `(off, off)`.

#### 토글 하나가 서버 값 둘을 함께 움직인다
`PUT /{postId}/notification-settings`는 `commentNotificationsEnabled`·`replyNotificationsEnabled`를
**둘 다 필수**로 받는다(하나만 보내면 400). 화면 토글은 하나뿐이므로 켜기 = `{true, true}`,
끄기 = `{false, false}`로 함께 보낸다. 표시 상태는 **둘 중 하나라도 켜져 있으면 "켜짐"**(OR)이다 —
AND로 보면 내 글 기본값 `(true, false)`가 "꺼짐"으로 보인다.

#### 전체 동의를 꺼도 하위 토글을 흐리게 하지 않는다
전체 동의는 **푸시만** 막고 알림함 적재는 그대로다. 반면 게시글별·댓글별은 알림함 저장 자체를
좌우한다. 서버 의미가 독립이므로 전체 동의가 꺼졌다고 하위 토글을 비활성화하면 "에러 없이 틀린
화면"이 된다. 마이페이지 행 설명 문구로 그 차이를 알린다 — *"댓글·대댓글·채팅 푸시를 받아요.
꺼도 알림함에는 쌓여요"*.

#### 노출 조건 3종
- **게시글별**: 로그인 상태이고 서버가 설정을 보낸 경우에만. 목록 카드 경유·비로그인 조회는 값이
  없어 항목을 그리지 않는다
- **댓글별**: 내가 쓴 **1단 댓글**에만. 대댓글(2단)에는 대댓글을 달 수 없어 값이 무의미하므로 숨긴다
- **비로그인**: 기존대로 로그인 유도 항목만

#### 라벨과 아이콘이 같은 것을 가리키게 했다
메뉴 라벨은 기존 관행대로 "지금 누르면 무엇이 되는지"를 쓴다(모집중↔마감 항목과 같은 규칙).
처음에는 아이콘만 현재 상태를 쓰게 했는데, 한 줄 안에서 라벨과 아이콘이 반대를 가리켜 헷갈렸다.
**아이콘도 동작 기준으로 정렬**했다 — 켜져 있으면 `icon_bell_block`("알림 끄기"), 꺼져 있으면
`icon_bell`("알림 켜기"). 색까지 맞아떨어져 켜는 쪽이 선명한 종으로 보인다.

**특이사항**: 채팅방 정보 화면의 앱바 종 아이콘은 그대로 뒀다. 라벨 없이 아이콘만 있는 표면에서는
아이콘이 유일한 상태 표시라 현재 상태를 쓰는 것이 맞다.

#### "답글" → "대댓글" 어휘 통일
한국 정서상 1단은 "댓글", 댓글에 다는 2단은 "대댓글"이 자연스럽다는 판단으로 한국어 문구를 전부
바꿨다 — `대댓글 달기`, `대댓글을 남겨보세요`, `새 대댓글: {내용}`, `대댓글에는 대댓글을 달 수 없어요` 등.
영어·일본어에는 대응하는 별도 낱말이 없어 `reply` / `返信` 그대로 뒀다.

다음 사람이 다시 "답글"을 쓰지 않도록 `docs/i18n/glossary.md`에 「커뮤니티 용어」 절을 신설했다
(용어집은 번역 시 반드시 따르도록 규정돼 있다).

#### 세 토글 모두 같은 실패 처리
낙관적 갱신 → 실패 시 원복 + `rethrow` → 화면이 스낵바로 사유 노출(`errorByException`).
좋아요·스크랩이 쓰는 "이미 그 상태면 409 삼키기"는 쓰지 않았다. PUT은 멱등이라 삼킬 상태가 없고,
**403 `FORBIDDEN_NOT_COMMENT_AUTHOR`는 남의 댓글에 토글을 그렸다는 화면 버그의 신호**라 반드시
드러나야 한다.

상세 화면의 낙관적 갱신 골격(`_optimistic`)은 좋아요·스크랩이 쓰던 것을 재사용하되, 호출할
Repository가 달라져 시그니처를 한 단계 좁혔다(레포를 인자로 받는 대신 클로저가 잡는다). 좋아요·
스크랩 동작은 그대로다.

댓글 쪽 롤백은 목록 전체를 이전 스냅샷으로 되돌리지 않고 **해당 댓글 하나만 역방향으로 다시
뒤집는다**. 통째로 되돌리면 그 사이 달린 댓글이 사라진다.

#### 리뷰에서 잡은 결함 2건 — 엔티티 통째 교체가 설정을 흘리거나 지웠다
`notificationSetting`을 게시글 엔티티에 얹으면서, 글을 **통째로 대입하는 지점**들이 그 값을 밟는
문제가 드러났다. 개별 기능 단위로는 보이지 않고 화면 흐름을 이어 봐야 보이는 결함이었다.

1. **마감·수정하면 알림 항목이 사라졌다** — 서버의 수정·상태 변경 응답에는 `notificationSettings`가
   실리지 않는다(단건 조회에서만 채운다). 응답으로 글을 갈아끼우는 순간 값이 `null`이 되어, 마감
   한 번에 메뉴에서 항목이 없어지고 화면을 나갔다 들어와야 돌아왔다.
   → 응답에 설정이 없으면 **들고 있던 값을 유지**하도록 병합한다.
2. **피드 카드에 눌러도 아무 일 없는 항목이 생겼다** — 상세에서 좋아요·스크랩·알림을 누르면 그
   글을 목록 카드에 반영하는데, 이때 설정까지 딸려 가 목록 카드 메뉴에도 알림 항목이 그려졌다.
   목록 쪽 처리는 no-op이라 눌러도 반응이 없었다.
   → 목록으로 넘길 때 설정을 **벗겨서** 넘긴다.

### 📌 참고사항

**실기기 확인 대기** — 아래는 서버·기기가 필요해 코드 검증으로는 덮이지 않는다(dev 서버, 계정 2개):
1. 마이페이지 스위치 off → 다른 계정이 내 글에 댓글 → 푸시 안 옴, 알림함에는 쌓임
2. 남의 글에서 "알림 켜기" → 제3자가 댓글 → 내 알림함에 뜸
3. 내 글에서 "알림 끄기" → 댓글이 와도 알림함에 안 쌓임
4. 내 댓글 "대댓글 알림 끄기" → 대댓글 → 안 뜸 / 다시 켜면 뜸
5. 비로그인으로 상세 진입 → 메뉴에 로그인 유도만, 알림 항목 없음

**범위 밖(별도 이슈)** — 백엔드 #182가 연 나머지 항목: 채팅 읽음 처리(`POST /chat/read`),
채팅방 음소거, 유저 알림 채널 구독, 채팅 푸시 탭 이동. 마이페이지의 `allowGamePush`·
`allowMarketingPush`도 이번 범위에서 제외했다.

**알아둘 점**
- 게시글 알림을 껐다 켜면 서버 값이 `(댓글 on, 답글 on)`이 된다. 내 글 기본값이 `(on, off)`이므로
  껐다 켠 뒤에는 답글 알림도 받게 된다 — 사용자가 손해 보는 방향은 아니라 그대로 뒀다
- 알림을 끈 기간에 생긴 알림은 **소급되지 않는다**. 서버가 발생 시점에 저장 여부를 정하기 때문이며,
  켜기 전 댓글은 애초에 행이 만들어지지 않는다
- `docs/i18n/glossary.md`에 커뮤니티 용어(댓글/대댓글)가 등재됐다. 이후 문구 작업은 이 표를 따른다
