## [#287] 대기실 대기중 카드 삭제 기능 개선 구현 보고서

### 📌 작업 개요

대기방 화면의 "대기중" 카드(`EmptySlotCard`) 렌더링 로직과 관련 `maxPerTeam` 파라미터 제거. 실제 입장한 참가자만 카드로 표시하도록 UI 정리. 작업 중 발견된 방장 플로우의 튜토리얼/초대코드 다이얼로그 경쟁 상태 버그도 같은 브랜치에서 함께 수정.

**관련 브랜치**: `20260423_#287_대기중_카드_삭제_기능_개선`
**커밋**: `fd6bbee`(이슈 본체) + `b052cab`(관련 버그 수정)

---

### 🎯 구현 목표

- 대기방 "대기중" 카드 노출 완전 제거
- 실제 입장한 참가자만 카드로 표시
- 팀 변경 용도로 쓰이는 반대 팀 `AddSlotCard` 만 유지
- 불필요해진 `maxPerTeam` 파라미터 정리
- 구현 중 드러난 튜토리얼 오버레이/초대 다이얼로그 겹침 버그 수정

### 🔧 주요 변경사항 상세

#### `EmptySlotCard` 제거의 파급 효과

기존에는 팀별로 `maxPerTeam` 만큼 슬롯을 미리 그리고 빈 자리마다 `EmptySlotCard` 로 채우는 구조였음. 이제는 **현재 참가자 수만큼만 카드를 생성** 하고, 반대 팀에 팀 변경 유도용 `AddSlotCard` 하나만 뒤에 덧붙이는 단순한 구조.

**특이사항**:
- 팀별 최대 인원 제한이 UI 레벨에서는 사라짐. 백엔드의 인원 제한만 남음.
- 튜토리얼의 "팀 변경" 스텝은 반대 팀의 `AddSlotCard` 를 타겟으로 하므로 반대 팀 정원이 꽉 차서 `AddSlotCard` 가 렌더링되지 않은 경우 해당 스텝은 자동 스킵되도록 기존 방어 로직이 그대로 작동.

#### 경쟁 상태 가드의 작동 방식

초대 다이얼로그 가드는 두 플래그의 OR 로 구성:

- `_pendingInviteDialog`: "다이얼로그를 곧 띄울 예정" 윈도우 — 위치 권한 체크 후 `_initWaitingRoom` 에서 true 로 세팅되고 `_fetchAndInitParticipants` 가 `await _showInviteCodeDialog()` 호출 직전에 false 로 내림.
- `_isInviteDialogOpen`: "다이얼로그가 실제로 떠 있는 동안" — `_showInviteCodeDialog` 시작 시 true, `try/finally` 의 `finally` 에서 false.

두 플래그를 OR 로 묶었기 때문에 "다이얼로그를 띄울 예정" 구간과 "실제 오픈된 구간" 사이에 틈이 없음. 리스너/STOMP 경로로 `_showTutorialIfNeeded` 가 호출돼도 이 가드에서 조용히 early return.

다이얼로그가 닫힌 뒤에는 `_fetchAndInitParticipants` 말미의 명시적 `_showTutorialIfNeeded` 호출이 fallback 으로 튜토리얼을 띄우므로 누락 없음.

**특이사항**:
- `_showInviteCodeDialog` 의 다이얼로그 인자(QR, 복사 GestureDetector, 닫기/공유하기 버튼 등) 내용은 원본과 동일하게 유지.
- `dart format` 적용 과정에서 `_showInviteCodeDialog` 본문 들여쓰기가 `try` 블록 기준으로 한 단계 내려가 diff 라인이 실제 로직 변경량보다 크게 보임 (순수 포맷 재정렬 포함).
