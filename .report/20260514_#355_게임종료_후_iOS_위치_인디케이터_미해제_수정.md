# 게임 종료 후 iOS 위치 인디케이터 미해제 버그 수정

### 📌 작업 개요

게임이 종료된 후 결과 다이얼로그가 표시되는 동안, iOS 상태바의 파란색 위치 인디케이터("위치정보 공유 중")가 계속 표시되는 버그 수정. 인게임에서만 위치 수집이 활성화되어야 하며, 게임 종료 시점에 즉시 해제되어야 한다.

---

### 🔍 문제 분석

#### 근본 원인: 위치 구독 해제 시점이 너무 늦음

`GamePage`에는 두 개의 위치 스트림 구독이 존재한다:

| 구독 | 대상 | 용도 |
|------|------|------|
| `_locationSubscription` | ROBBER 전용 | GPS 좌표를 서버에 주기적 전송 |
| `_headingSubscription` | 전 팀 공통 | 구역 이탈 감지용 위치 트래킹 |

두 구독 모두 `DeviceLocationService`를 통해 생성되는데, iOS 설정에 `allowBackgroundLocationUpdates: true`, `showBackgroundLocationIndicator: true`가 적용되어 있다. 이 설정이 iOS 파란 인디케이터의 직접적인 원인이다.

**기존 흐름의 문제:**

```
GAME_OVER 이벤트 감지
    ↓
_showGameOverDialog() 호출
    ↓  (위치 스트림 여전히 활성)
3초 팝업 (AppPopup.show)
    ↓  (위치 스트림 여전히 활성)
결과 다이얼로그 (GameOverResultDialog.show)
    ↓  (위치 스트림 여전히 활성)
"한 번 더" 또는 "홈으로" 탭
    ↓
context.go() → GamePage dispose()
    ↓  ← ✅ 여기서야 비로소 cancel
_locationSubscription?.cancel()
_headingSubscription?.cancel()
```

결과 다이얼로그가 떠 있는 수십 초 동안 위치 스트림이 살아있기 때문에, 사용자가 이 시점에 앱을 백그라운드로 내리면 iOS가 CLLocationManager가 활성화되어 있다고 판단하여 파란 인디케이터를 표시한다.

#### iOS에서 BackgroundServiceIos가 no-op인 이유

`_handleGameOver()`에서 호출되는 `BackgroundServiceIos.stop()`은 내부 플래그 변경만 수행하는 완전한 no-op이다. CLLocationManager를 직접 정지시키지 않으므로 위치 인디케이터 해제에 아무런 영향을 주지 않는다. Android는 FGS(Foreground Service)를 실제로 정지시키므로 동일 문제가 발생하지 않는다.

### ✅ 구현 내용

#### 게임 종료 시점에 위치 구독 즉시 해제

- **파일**: `lib/features/game/presentation/pages/game_page.dart`
- **변경 위치**: `_showGameOverDialog()` 진입 직후 (`_clearZoneExitWarning()` 다음)

```dart
// iOS 파란 위치 인디케이터 즉시 해제: 게임 종료 이후 위치 수집 불필요.
// dispose()까지 미루면 결과 다이얼로그 표시 시간 내내 인디케이터가 유지된다.
_locationSubscription?.cancel();
_locationSubscription = null;
_headingSubscription?.cancel();
_headingSubscription = null;
```

`_showGameOverDialog()`는 이미 `_clearZoneExitWarning()`(진동 타이머), `disconnect()`(STOMP 해제) 등 게임 종료 시점의 정리 로직을 담당하는 메서드다. 위치 구독 해제를 이곳에 추가하여 종료 정리 로직을 한 곳에 응집시켰다.

**수정 후 흐름:**

```
GAME_OVER 이벤트 감지
    ↓
_showGameOverDialog() 호출
    ↓  ← ✅ 즉시 cancel
_locationSubscription?.cancel() → null
_headingSubscription?.cancel() → null
    ↓  (위치 스트림 비활성, CLLocationManager 정지)
3초 팝업
결과 다이얼로그
    ↓  (앱 백그라운드 전환해도 인디케이터 없음)
"한 번 더" → 대기방 이동
```

---

### 🔧 주요 변경사항 상세

#### null 대입의 역할

`cancel()` 후 `null`을 대입하는 것은 `dispose()`에서의 이중 cancel을 방지하기 위함이다. `dispose()`의 기존 cancel 코드(`_locationSubscription?.cancel()`)는 `?` null 체크를 이미 포함하고 있으므로, `null` 대입 후에는 해당 라인이 아무 동작도 하지 않는다.

#### `_headingSubscription` 주석 불일치

코드 내 `_headingSubscription`의 선언부 주석에 "POLICE 전용 heading 스트림"이라고 되어 있으나, 실제로는 `_connectGameEvents()`에서 ROBBER/POLICE 구분 없이 모든 팀에 대해 `_startHeadingTracking()`이 호출된다. 구역 이탈 감지는 양 팀 모두에 필요하기 때문이다. 이번 수정에서 주석 수정은 범위 외로 두었다.

### 🧪 테스트 및 검증

- 게임 종료 후 3초 팝업 표시 중 앱 백그라운드 전환 → 파란 인디케이터 미표시 확인
- 결과 다이얼로그 표시 중 앱 백그라운드 전환 → 파란 인디케이터 미표시 확인
- "한 번 더" 탭 후 대기방 이동 → 파란 인디케이터 미표시 확인
- "홈으로" 탭 후 홈 화면 이동 → 파란 인디케이터 미표시 확인

---

### 📌 참고사항

- 해당 버그는 iOS 전용 증상이다. Android는 `BackgroundServiceAndroid.stop()`이 실제 FGS를 정지시키므로 동일한 visible 증상이 발생하지 않는다.
- `DeviceLocationService`의 `AppleSettings(showBackgroundLocationIndicator: true)` 설정은 인게임 중 위치 수집 중임을 사용자에게 투명하게 알리기 위한 의도적 설정이므로 변경하지 않았다.
