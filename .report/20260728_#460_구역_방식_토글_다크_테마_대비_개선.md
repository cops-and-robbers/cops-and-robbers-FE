# 구역 방식 토글 다크 테마 대비 개선

## 📌 작업 개요

대기방에서 방 설정 변경으로 구역 설정 화면에 진입하면 도둑 팀은 다크 배경에서 화면을 본다. 이때 구역 방식 토글(거리로 설정 / 핀으로 설정)만 라이트 색상으로 고정되어 있어 선택 상태를 알아볼 수 없었다. 토글에 `isDarkMode` 파라미터를 추가하고 트랙·pill·비선택 라벨 색상을 팀 테마에 따라 분기했다.

## 🔍 문제 분석

`setup_playground_page.dart`는 편집 모드일 때 `roleThemeProvider`로 다크 여부를 계산해 지도 위젯, 화면 타이틀, 뒤로가기 버튼에 모두 전달한다. 그런데 `AreaTypeToggle`에만 이 값을 넘기지 않았고, 토글 내부 색상은 전부 라이트 고정값이었다.

그 결과 다크 배경(`black900`) 위에서 다음 상태가 됐다.

| 대비 항목 | 색상 | 대비비 | 문제 |
| --- | --- | --- | --- |
| 선택 pill ↔ 트랙 | `white` ↔ `black100` | 1.09:1 | 어느 쪽이 선택됐는지 구분 불가 |
| 비선택 라벨 ↔ 트랙 | `black400` ↔ `black100` | 2.23:1 | 읽기 어려움 |
| 트랙 ↔ 화면 배경 | `black100` ↔ `black900` | — | 흰 덩어리가 화면에서 튐 |

단순히 "덜 보이는" 수준이 아니라 토글의 핵심 기능인 선택 상태 표시가 동작하지 않는 상태였다.

## ✅ 구현 내용

### AreaTypeToggle에 팀 테마 분기 추가

- **파일**: `lib/features/session/presentation/widgets/area_type_toggle.dart`
- **변경 내용**: `isDarkMode` 생성자 파라미터 추가(기본값 `false`). 트랙 배경, 선택 pill, 비선택 라벨 색상을 다크에서 분기
- **이유**: 프로젝트 표준은 하위 위젯이 `roleThemeProvider`를 직접 구독하지 않고 상위 페이지에서 `isDarkMode`를 prop으로 내려받는 방식이다. 같은 화면의 `ZoneSettingWidget`, `PinZoneSettingWidget`도 동일한 형태(`this.isDarkMode = false`)를 쓴다

### 페이지에서 토글로 테마 전달

- **파일**: `lib/features/session/presentation/pages/setup_playground_page.dart`
- **변경 내용**: `AreaTypeToggle`에 `isDarkMode: isDark` 전달
- **이유**: 같은 화면의 다른 위젯들이 이미 받고 있던 값을 토글에만 빠뜨린 것이 원인이었다

## 🔧 주요 변경사항 상세

### 색상 매핑

| 요소 | 라이트 (변경 없음) | 다크 | 선택 근거 |
| --- | --- | --- | --- |
| 트랙 배경 | `black100` | `black800` | 같은 화면 반경 슬라이더의 다크 트랙과 동일한 값 |
| 선택 pill | `white` | `black200` | 트랙 대비 7.53:1. 선택 위치는 또렷하되 화면에서 가장 밝은 덩어리가 되지 않음 |
| 선택 라벨 | `black800` | `black800` (분기 없음) | pill 위에 얹히므로 트랙 색과 무관. `black200` pill 위에서 7.53:1 |
| 비선택 라벨 | `black400` | `black300` | `black800` 트랙 위에서 `black400`은 4.33:1로 WCAG AA(4.5:1) 미달. `black300`은 5.73:1 |

**특이사항**:

- 선택 pill을 다크에서 `white` 그대로 두면 트랙 대비 11.04:1로, 어두운 화면에서 가장 밝은 요소가 되어 시선을 과하게 끈다. 선택 위치를 알아볼 수 있는 선에서 한 단계 낮춰 `black200`으로 정했다
- 비선택 라벨의 다크 색은 디자인 시스템 문서의 권장 매핑(보조 텍스트 다크 = `black400`)과 다르다. 그 매핑은 배경이 `black`/`black900`일 때 기준이며, 여기서는 한 단계 밝은 `black800` 트랙 위에 얹히므로 라벨도 한 단계 밝혀야 대비가 확보된다
- 라벨 타이포는 라이트·다크 모두 `paragraph_14`로 유지했다. 팀 테마별 타입페이스 분기 규칙상 다크에서 `robberParagraph`(Moneygraphy)로 바꾸는 선택지가 있었으나, Moneygraphy는 픽셀 폰트라 14sp 토글 라벨에서 가독성이 오히려 떨어질 수 있고 세그먼트 폭이 고정이라 ko/en/ja 글자폭 증가 시 잘릴 위험이 있다. 이번 작업은 대비 문제 해결이 목적이므로 폰트는 건드리지 않았다

### 기본값이 `false`인 이유

`isDarkMode`를 필수 파라미터로 만들지 않고 기본값 `false`를 뒀다. 방 생성 플로우는 편집 모드가 아니라 항상 라이트이고, 개발용 위젯 카탈로그(`test_widget_page.dart`)도 이 토글을 쓴다. 기본값이 있으면 두 호출부 모두 수정 없이 기존 동작을 유지한다.

## 📌 참고사항

**실기기 확인 필요**

1. 대기방 → 방 설정 변경 → 구역 설정 진입(도둑 팀) → 토글 트랙이 어둡고 선택 pill이 또렷하게 구분됨
2. 거리/핀 전환 시 물방울 squash-stretch 애니메이션이 기존과 동일하게 동작
3. 방 생성 플로우(경찰·라이트)에서 토글이 기존과 동일하게 보임
4. 선택 pill의 밝기가 화면에서 과하지 않은지 육안 확인. 더 낮춰야 하면 `black300`이 다음 후보이나, 현재 비선택 라벨이 `black300`이라 같은 톤이 겹치므로 라벨을 `black400`으로 되돌려야 한다(대비 4.33:1로 AA 미달 감수)
