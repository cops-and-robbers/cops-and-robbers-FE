# 채팅방에서 게임 생성 및 초대 전송

### 📌 작업 개요

모집글 채팅방 상단 모임 카드에 방장 전용 "게임 시작" 버튼 추가. 버튼 탭 시 기존
세션 생성 플로우로 진입해 방을 만들고, 생성 성공 직후 발급된 초대 코드를 STOMP
`GAME_INVITE` 메시지로 해당 채팅방에 자동 전송. 서버 계약(BE #162)은 이미 열려
있었고 앱 쪽 트리거만 없던 공백을 채우는 작업.

**보고서 파일**: `.report/20260831_#516_채팅방에서_게임_생성_및_초대_전송.md`

### 🎯 구현 목표

- 채팅방 안에서 게임 생성 진입점 제공 — 방장(게시글 작성자)에게만 노출
- 방 생성은 기존 세션 생성 플로우(`POST /api/games` 경유) 그대로 재사용, 새 API 없음
- 발급된 `inviteCode`를 `SEND /publish/community/{postId}/chat`에
  `messageType: GAME_INVITE`, `gameInvite: {inviteCode}` 형식으로 전송 (서버 계약 준수 —
  본문에 닉네임 미포함, `messageKey`는 앱 생성 UUID)
- 수신 측(초대 카드 → 기존 게임 참가 API)은 #480에서 구현 완료 — 이번 범위 아님

### ✅ 구현 내용

#### ① 모임 카드 방장 버튼
- **파일**: `lib/features/community/presentation/widgets/community_chat_meeting_card.dart`
- **변경 내용**: `onStartGame`(nullable VoidCallback) 추가. null이면 버튼 미표시,
  non-null이면 카드 우측에 `AppButton`(88×36, logo 배경·white `paragraph14Semibold`·
  radius large·테두리 없음·텍스트 전용) 렌더. 버튼이 폭을 가져가며 안쪽 Row(모임
  시각·장소 보기)가 넘치는 문제를 시각 텍스트 `Flexible` + ellipsis로 방어
- **이유**: 새 컴포넌트 대신 기존 `AppButton` 축소 사용 — 같은 화면 초대 수신 카드
  (`community_chat_invite_card.dart`)의 기존 패턴 재사용

#### ② 방장 판별·플로우 진입
- **파일**: `lib/features/community/presentation/pages/community_chat_room_page.dart`,
  `lib/router/app_router.dart`
- **변경 내용**: `post.writerId == currentUserIdProvider`일 때만 콜백 전달. 탭 시
  `context.push(sessionCreationFlow, extra: postId)`. 라우터가 extra를
  `SessionCreationFlowPage(communityPostId:)`로 전달 (홈 진입은 extra 없음 → null)
- **이유**: 방장 = 게시글 작성자(서버 `AUTHOR_CANNOT_LEAVE` 규칙과 동일 기준)

#### ③ 생성 성공 시 GAME_INVITE 자동 전송
- **파일**: `lib/features/session/presentation/pages/session_creation_flow_page.dart`
- **변경 내용**: `createGame` 성공 블록에서 대기방 이동(`context.go`) 직전에
  `communityPostId != null`이면 `sendGameInvite` 동기 호출. 실패(소켓 미연결) 시
  스낵바 "채팅방에 초대를 보내지 못했어요" 표시 후 정상 진행
- **이유**: 화면 이탈 전 동기 호출로 dispose 후 ref 사용 배제. 소켓은 로그인 수명이라
  정상 경로에선 항상 연결 상태 — 실패는 알리되 생성 자체는 막지 않음

#### ④ 전송 계층
- **파일**: `lib/features/community/data/datasources/community_chat_stomp_datasource.dart`,
  `lib/features/community/domain/repositories/community_chat_repository.dart`,
  `lib/features/community/data/repositories/community_chat_repository_impl.dart`
- **변경 내용**: `publishGameInvite` / `sendGameInvite(postId, {messageKey, inviteCode})`
  추가. 와이어 바디 `{messageKey, gameInvite: {inviteCode}, messageType: "GAME_INVITE"}`.
  미연결이면 전송 없이 `false` 반환
- **이유**: TEXT와 달리 낙관적 말풍선이 없는 단발 발신 — 호출부가 실패를 알 길이
  반환값뿐이라 `bool`로 설계. 자기 에코는 타임라인 `receive()`가 미지 키를 그대로
  append하므로 별도 처리 불필요

#### ⑤ 참가 확인 다이얼로그
- **파일**: `lib/features/community/presentation/widgets/community_chat_invite_card.dart`
- **변경 내용**: 초대 카드 "게임 참여" 탭 시 즉시 참가하지 않고 공용 `AppDialog`로
  확인 다이얼로그 표시 — 캡션 "게임 초대장", 본문 "{닉네임}님이 게임에 초대했어요",
  방 코드, 거절(회색)/입장(blue) 버튼. 입장을 눌러야 기존 초대코드 참가 흐름 진행
- **이유**: 오탭 방지 및 시안 반영. 공용 다이얼로그 재사용으로 신규 컴포넌트 없음
