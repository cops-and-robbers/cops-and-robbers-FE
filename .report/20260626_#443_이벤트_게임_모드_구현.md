# 이벤트 게임 모드 로직 분기 구현 (#443)

### 📌 작업 개요

일반 게임과 별개로 동작하는 **이벤트 게임 모드**를 추가. 이벤트방은 **참가자 전원이 경찰**로 입장해, 맵에 배치된 **운영진(도둑 역할)을 QR로 검거**하고 검거할 때마다 **증거 이미지를 수집**한다. 일반 모드의 수감/감옥/승패 흐름과 충돌하지 않도록 `isEventGame` 플래그로 분기한다.

핵심 차이는 "검거해도 운영진은 ALIVE로 유지"된다는 점이다. 즉 전역 수감 집합(`arrestedParticipantIds`)을 건드리지 않고, 경찰 기기마다 **로컬 검거 집합**만 따로 누적·영속화한다.

### 🎯 구현 목표

- 서버 응답(`isEventGame`)으로 이벤트방 여부를 받아 참가/게임 흐름 분기
- 경찰의 운영진 검거 → 증거 공개 다이얼로그 → 게임 종료 시 증거 결과 보드
- 검거 집합을 기기 로컬에 영속화(재진입 복원, 다른 게임 자동 리셋)
- 일반 모드 동작에 영향 0 (플래그 미존재 시 false 기본값)

### ✅ 구현 내용

#### 1. 세션·딥링크 이벤트 분기

- **파일**: `lib/features/session/data/models/join_game_response.dart`, `game_settings_response.dart`, `lib/features/session/domain/entities/game_join_result.dart`
- **변경 내용**: 응답/엔티티에 `isEventGame` 필드 추가(기본값 `false`)
- **이유**: 백엔드가 필드를 안 내려주는 구버전에서도 안전하게 일반 모드로 동작(백워드 호환)

- **파일**: `lib/features/session/presentation/providers/deeplink_join_notifier.dart`, `game_participant_provider.dart`, `pages/deeplink_join_page.dart`
- **변경 내용**: 딥링크 join 결과에 `isEventGame`/`participantId` 전파, 참가자 정보(`GameParticipantInfo`)에 `isEventGame` 보관
- **이유**: 게임 화면이 참가자 정보만 보고 이벤트 여부를 판단할 수 있도록 단일 출처화

#### 2. 게임 이벤트 모드 검거 흐름

- **파일**: `lib/features/game/presentation/providers/game_event_provider.dart`
- **변경 내용**: `arrestRobberForEvent`, `loadMyArrests` 추가. 전역 수감 집합 대신 로컬 `myArrestedRobberIds`만 갱신·영속화하고 (증거 인덱스, 운영진 닉네임) 반환
- **이유**: 운영진을 ALIVE로 유지하면서 경찰별 검거 수만 누적하기 위함

- **파일**: `lib/features/game/data/services/event_arrest_storage.dart`
- **변경 내용**: `SharedPreferences` 단일 레코드(`{gameId, arrestedRobberIds}`)로 저장. 같은 `gameId` 재진입 시 복원, 다른 게임/손상 레코드는 **제거**해 자동 리셋
- **이유**: 앱 재시작·재접속 후에도 검거 수가 유지되되, 다른 게임으로 부활하지 않도록 보장

- **파일**: `lib/features/game/domain/arrest_lock_visibility.dart`
- **변경 내용**: 순수 도메인 함수 `shouldShowArrestLock` — 이벤트 모드에서는 검거되어도 감옥 잠금 오버레이를 `false` 반환
- **이유**: 검거된 운영진이 일반 모드처럼 "수감" 상태로 보이지 않도록 UI 게이팅

- **파일**: `lib/features/game/presentation/pages/game_page.dart`
- **변경 내용**: QR 체포 분기에서 `isEventGame`이면 이미 검거한 대상(`myArrestedRobberIds.contains`) 차단 후 `arrestRobberForEvent` 호출, 성공 시 증거 다이얼로그 표시. 게임 진입 시 `loadMyArrests`를 **체포 가능 시점 이전에 await**
- **이유**: 복원 전에 체포가 일어나면 재검거/카운트 오류가 생기므로 순서를 강제

#### 3. 증거 UI 위젯

- **이유**: 검거 즉시 피드백으로 수집 증거를 보여줘 몰입감 부여

### 🔧 주요 변경사항 상세

#### 검거 영속화의 동시성·실패 처리 (`arrestRobberForEvent`)

- `_pendingArrestId`로 **재진입 차단**(같은 대상 연타 무시)
- 체포 API 실패 시 상태 롤백 + 에러 메시지, `_pendingArrestId` 해제
- 체포 API 성공 이후의 **로컬 저장 실패는 체포 성공을 무효화하지 않음**(저장은 try/catch로 감싸고 해제 로직은 항상 실행)
- 비동기 도중 Notifier dispose 대비 `_isDisposed` 가드 후 상태 기록

#### 자동 리셋 보장 (`event_arrest_storage.load`)

저장된 `gameId`가 현재와 다르거나 JSON이 손상된 경우 레코드를 즉시 제거한다. 따라서 새 이벤트 게임에 들어가면 이전 게임의 검거 수가 절대 따라오지 않는다.

**특이사항**:
- 저장은 **경찰 기기별 로컬**이라 경찰 간 공유되지 않는다(각자 자기 검거 수만 본다).
- `EventArrestSuccessDialog`/`EventResultBoard`는 모두 라이트 테마 고정 — **이벤트방은 경찰 전용 입장**이라 도둑(다크 테마) 플레이어가 존재하지 않으므로 의도된 설계다.

### 📌 참고사항

- **에셋 커밋 주의**: 증거 이미지는 `flutter run` 로컬에서는 디스크에 있으면 통과하지만, 커밋에서 누락되면 릴리스 빌드에서 이미지가 깨진다. 이번 작업에서 PNG를 정상 커밋(증거 에셋 커밋 분리)했음.
- **커밋 구성**: 기능 단위 5개로 분리 — `docs` / `chore`(에셋) / `feat`(i18n) / `feat`(세션·딥링크) / `feat`(게임 코어).
- **사전 배포 점검 결과**: 정적 검증에서 제기된 일부 위험(메모리 누수·텍스트/스택 오버플로·게임 간 상태 오염)은 코드 재확인 결과 모두 방어돼 있어 오탐으로 확인됨 — `@riverpod` autoDispose + `ref.onDispose` 정리, 닉네임 2~10자 검증 cap, `gameId` 필터 자동 리셋. 남은 항목은 선택적 테스트 보강/리팩토링이며 배포를 막지 않음.
