# 이벤트 게임 모드 로직 분기 구현 (#443)

### 📌 작업 개요

일반 게임과 별개로 동작하는 **이벤트 게임 모드**를 추가. 이벤트방은 **참가자 전원이 경찰**로 입장해, 맵에 배치된 **운영진(도둑 역할)을 QR로 검거**하고 검거할 때마다 **증거 이미지를 수집**한다. 일반 모드의 수감/감옥/승패 흐름과 충돌하지 않도록 `isEventGame` 플래그로 분기한다.

핵심 차이는 "검거해도 운영진은 ALIVE로 유지"된다는 점이다. 즉 전역 수감 집합(`arrestedParticipantIds`)을 건드리지 않고, 경찰 기기마다 **로컬 검거 집합**만 따로 누적·영속화한다. 검거 집계는 HTTP 응답이 아니라 **서버의 STOMP `ARREST` 브로드캐스트**를 기준으로 한다(스펙 §3).

### 🎯 구현 목표

- 서버 응답(`isEventGame`)으로 이벤트방 여부를 받아 참가/게임 흐름 분기
- 경찰의 운영진 검거 → 증거 공개 다이얼로그 → 게임 종료 시 증거 결과 보드
- 검거 집합을 기기 로컬에 영속화(재진입 복원, 다른 게임 자동 리셋)
- 검거 카운트를 STOMP `ARREST` 수신 기준으로 처리 → 네트워크 불안정에도 정확
- 일반 모드 동작에 영향 0 (플래그 미존재 시 false 기본값)

#### 2. 게임 이벤트 모드 검거 흐름 (STOMP 기준)

- **파일**: `lib/features/game/presentation/providers/game_event_provider.dart`
- **변경 내용**: 검거 카운트를 **STOMP `ARREST` 수신 기준**으로 처리. `_handleArrest` 이벤트 분기에서 `data.police.participantId == 내 participantId`일 때만 로컬 `myArrestedRobberIds`를 갱신·영속화하고 증거 다이얼로그 신호(`myArrestSeq`)를 올린다. 체포 요청은 트리거 전용 `requestEventArrest`(성공 여부 bool 반환)가 담당. `loadMyArrests`로 재진입 시 로컬 집합 복원
- **이유**: 운영진을 ALIVE로 유지하며 경찰별 검거 수만 누적하되, 카운트를 HTTP 응답이 아니라 서버의 권위 신호(ARREST 브로드캐스트)에 묶어 **재연결과 체포가 겹쳐 응답이 유실돼도** 정확히 집계되도록 함

- **파일**: `lib/features/game/data/services/event_arrest_storage.dart`
- **변경 내용**: `SharedPreferences` 단일 레코드(`{gameId, arrestedRobberIds}`)로 저장. 같은 `gameId` 재진입 시 복원, 다른 게임/손상 레코드는 **제거**해 자동 리셋. `save`는 `setString` 실패(false)를 throw하여 조용히 넘기지 않음
- **이유**: 앱 재시작·재접속 후에도 검거 수가 유지되되, 다른 게임으로 부활하지 않도록 보장. 저장 실패를 호출측이 인지 가능하도록 노출

- **파일**: `lib/features/game/domain/arrest_lock_visibility.dart`
- **변경 내용**: 순수 도메인 함수 `shouldShowArrestLock` — 이벤트 모드에서는 검거되어도 감옥 잠금 오버레이를 `false` 반환
- **이유**: 검거된 운영진이 일반 모드처럼 "수감" 상태로 보이지 않도록 UI 게이팅

- **파일**: `lib/features/game/presentation/pages/game_page.dart`
- **변경 내용**: QR 체포 분기에서 `isEventGame`이면 이미 검거한 대상(`myArrestedRobberIds.contains`) 차단 후 `requestEventArrest`로 체포 요청만 전송(실패 시 스낵바). 증거 다이얼로그는 `myArrestSeq` 변화를 `ref.listen`으로 감지해 표시(HTTP 응답과 분리). 게임 진입 시 `loadMyArrests`를 **체포 가능 시점 이전에 await**. 인게임 증거보드 버튼(경찰 전용)으로 진행 현황 조회
- **이유**: 복원 전 체포 시 재검거/카운트 오류가 생기므로 순서를 강제. 다이얼로그를 STOMP 신호 기준으로 분리해 응답 유실 시에도 정확히 노출

### 🔧 주요 변경사항 상세

#### STOMP 기준 검거 집계 (스펙 §3 — 카운트 미증가 버그 해결)

- **카운트 단일 권위 신호 = `ARREST` 이벤트 수신**. `_handleArrest`에서 `data.police.participantId == 내 id`이고 아직 집계 안 된 도둑이면 `myArrestedRobberIds`에 추가 + 영속화 + `myArrestSeq`를 올려 UI에 증거 다이얼로그 신호를 보낸다. 타 경찰 검거나 같은 도둑 중복 수신은 배너만 갱신(이중 카운트 방지)
- **HTTP는 트리거 전용**(`requestEventArrest`). 응답이 timeout/유실돼도 서버가 ARREST를 브로드캐스트하면 카운트가 정확히 반영됨 — 재연결과 체포가 동시에 일어나 검거가 조용히 누락되던 문제를 해결
- `_pendingArrestId`로 체포 요청 **동시 중복 전송 차단**(연타 무시)
- 로컬 영속화 실패는 인메모리 집계를 무효화하지 않음(`_persistMyArrests` best-effort, 실패 시 로그만)

#### 자동 리셋 보장 (`event_arrest_storage`)

저장된 `gameId`가 현재와 다르거나 JSON이 손상된 경우 `load`가 레코드를 즉시 제거한다. 따라서 새 이벤트 게임에 들어가면 이전 게임의 검거 수가 절대 따라오지 않는다.

**특이사항**:
- 저장은 **경찰 기기별 로컬**이라 경찰 간 공유되지 않는다(각자 자기 검거 수만 본다).
- **로컬 전용 집계의 경계**: STOMP 자체가 도착하지 않는 순간(끊김 구간에 발생한 체포)은 그 1건이 유실될 수 있다. 서버가 경찰별 검거 수를 추적하지 않는 설계의 본질적 한계로, 영속화는 "같은 폰" 재접속까지 보장한다(폰 교체 시 리셋).
- `EventArrestSuccessDialog`/`EventResultBoard`는 모두 라이트 테마 고정 — **이벤트방은 경찰 전용 입장**이라 도둑(다크 테마) 플레이어가 존재하지 않으므로 의도된 설계다.

### 📌 참고사항

- **검거 카운트 미증가 버그**: 초기 구현은 카운트를 HTTP 체포 응답으로 올렸으나, 재연결과 체포가 겹치면 응답이 유실돼 검거가 조용히 누락됐다. STOMP `ARREST` 수신 기준(스펙 §3)으로 전환해 해결.
- **에셋 커밋 주의**: 증거 이미지는 `flutter run` 로컬에서는 디스크에 있으면 통과하지만, 커밋에서 누락되면 릴리스 빌드에서 이미지가 깨진다. PNG 정상 커밋 확인.
- **dev 정리**: 개발용 모달 QA 섹션(`test_widget_page.dart`)은 위젯 테스트로 대체되어 제거.
- **일반 모드 무영향**: 모든 이벤트 분기는 `isEventGame`(또는 `if (isEvent)`) 안에서만 동작 — 일반 게임 체포 경로(`arrestRobber`/전역 `arrestedParticipantIds`)는 한 줄도 변경 없음.
- **백엔드 의존**: `join`·`GET /api/games/{id}`의 `isEventGame`(v2.12.0), `/lobby/start` 팀 구성 체크 완화(운영진 도둑만으로 시작)에 의존. 엔진 룰 분기(JAILED 미적용 등)는 백엔드 확인 후 반영.
