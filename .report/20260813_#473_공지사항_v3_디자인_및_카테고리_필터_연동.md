# 공지사항 v3 디자인 적용 및 카테고리 필터 연동 (#473)

### 📌 작업 개요

공지사항 화면을 v3 디자인(흰 AppBar + 연하늘 배경 + 흰 카드 리스트)으로 재구성하고, 백엔드 v2.14.0에서 추가된 카테고리 필터를 칩 UI로 연동. 앱은 조회 전용이며 생성·수정·삭제는 어드민 웹 담당.

부수적으로 백엔드 API 명세를 v2.15.0으로 갱신하고, 바텀 네비게이션에 탭 진동과 안드로이드 하단 여백 보정을 추가.

### 🎯 구현 목표

- 공지사항 화면에 v3 디자인 언어 적용 (홈 화면 리뉴얼에서 확립된 `#F4FAFF` 배경 + 흰 카드)
- `GET /api/notices`의 `category` 쿼리 파라미터 연동 (`NOTICE | MAINTENANCE | EVENT | UPDATE`)
- 카테고리 필터 칩 추가 (가로 스크롤)

### 🔍 사전 검토 — 웹뷰 전환 여부

공지사항을 웹에서 웹뷰로 내장하는 방안을 먼저 검토했으나 네이티브 유지로 결론. 웹뷰가 오히려 작업량이 큰 것으로 확인:

- `dongsim-web`에는 관리자 작성 콘솔(`app/admin/notices`)만 있고 사용자용 공개 페이지가 없어 Next.js로 신규 개발 필요
- `AuthInterceptor`가 `/api/**` 전체를 막고 예외가 `/api/auth/**`, `/api/user/check-nickname`, `/actuator/health` 셋뿐이라(`cops_and_robbers-BE` `WebConfig.java:27`) 웹뷰에 JWT를 넘길 경로를 백엔드에 신설해야 함
- `/api/notices/**` CORS 허용 오리진에 신 도메인 `copsandrobbers.app`이 없어 백엔드 수정 필요(`WebConfig.java:67`)
- 앱에 웹뷰 패키지 미설치(`url_launcher`만 존재)

웹뷰의 강점인 리치 콘텐츠 렌더링도 어드민 에디터가 plain `<textarea>`이고 `content`가 `string`이라 현재는 이점 없음. 캠퍼스 대항전 배너 웹뷰 도입 시 재검토 예정.

### ✅ 구현 내용

#### 카테고리 도메인 enum과 와이어 매핑 분리

- **파일**: `lib/features/notice/domain/entities/notice_category.dart` (신규), `lib/features/notice/data/models/notice_category_query.dart` (신규)
- **변경 내용**: 도메인은 `enum NoticeCategory { all, notice, maintenance, event, update }`로 순수 타입만 두고, 서버 문자열(`'NOTICE'` 등)은 data 계층 extension의 `queryValue`에만 존재
- **이유**: 이 저장소가 이미 쓰는 규칙(`game_area_model.dart`의 `GameAreaType` ↔ `area_shape.dart`의 `AreaShape`)을 따름. `queryValue`는 `default`/`_` 없는 exhaustive switch라 카테고리가 추가되면 매핑을 채우기 전까지 컴파일이 실패

`@JsonValue`를 쓰지 않은 이유: 이 어노테이션은 json_serializable이 `fromJson`/`toJson`을 만들 때만 읽히고 결과가 `.g.dart`의 private `_$...EnumMap`에 들어감. 카테고리 값은 JSON 본문이 아니라 쿼리스트링으로 나가 Retrofit의 `@Query`가 그 맵에 닿지 못하므로 동작에 관여하지 않는 장식이 됨.

#### 데이터 계층에 category 파라미터 추가

- **파일**: `lib/features/notice/data/datasources/notice_remote_datasource.dart`, `lib/features/notice/domain/repositories/notice_repository.dart`, `lib/features/notice/data/repositories/notice_repository_impl.dart`
- **변경 내용**: 데이터소스에 `@Query('category') String? category`, Repository 인터페이스에 `NoticeCategory category = NoticeCategory.all` 추가. 문자열 변환은 `NoticeRepositoryImpl`에서만 수행
- **이유**: Repository 인터페이스가 도메인 타입을 받아야 presentation이 와이어 포맷을 몰라도 됨

`NoticeCategory.all`은 `queryValue`가 `null`이고, retrofit_generator가 nullable 파라미터에 대해 `queryParameters.removeWhere((k, v) => v == null)`을 생성하므로 "전체 = 파라미터 생략"이라는 백엔드 계약이 그대로 성립.

#### 선택 카테고리 상태 관리

- **변경 내용**: `SelectedNoticeCategory` provider 추가. `NoticesNotifier.build()`가 이를 `watch`, `fetchPage()`는 `read`
- **이유**: 카테고리가 바뀌면 `build()`가 재실행되며 0페이지부터 자동 재조회됨. 페이지 리셋 로직을 별도로 짤 필요가 없음

### 🔧 주요 변경사항 상세

#### 치수를 고정값이 아닌 최소값으로 둔 두 곳

**칩 폭 74** — `BoxConstraints(minWidth: 74.w)`로 처리. 한국어 라벨은 74 안에 들어가지만 영어 `Maintenance`(11자)와 일본어 `メンテナンス`·`アップデート`는 74를 넘김. 폭을 하드코딩하면 해당 로케일에서 글자가 잘림. 칩 행이 가로 스크롤이라 넓어져도 레이아웃이 깨지지 않으므로 늘어나게 두고 `ellipsis`는 쓰지 않음(카테고리 이름이 잘리면 뜻을 잃음).

**카드 높이 76** — `BoxConstraints(minHeight: 76.h)`로 처리. 카드가 아코디언이라 펼치면 본문만큼 늘어나야 하고, 시스템 글자 크기를 키우면 접힘 상태에서도 76을 넘김. 높이를 박으면 클리핑 때문에 경고 없이 글자가 잘림. 기본 배율에서는 내부 계산값이 70이라 `minHeight: 76`이 실제로 걸려 시안대로 76이 나옴.

카드 폭도 362를 하드코딩하지 않고 `double.infinity`로 가용 폭을 채움 — designSize 393에서 좌우 패딩 16을 빼면 361로 시안의 362와 사실상 같고, ScreenUtil이 기기별로 비례 축소함.

#### 시안에 없는 "공지" 칩을 추가한 이유

시안의 칩은 전체 / 점검 / 이벤트 / 업데이트 4개였으나 `NOTICE`(공지) 칩을 더해 5개로 구성. `NOTICE`는 백엔드가 category 생략 시 자동으로 채우는 기본값이라 실제 데이터에서 가장 많을 값인데, 칩이 없으면 이 카테고리만 따로 걸러볼 수단이 없음. "전체"는 필터 없음이라 `NOTICE` 자리를 대신하지 못함.

#### 카테고리 전환 실패 시 재시도 경로

전환이 실패하면 칩은 새 선택으로 남고 목록은 이전 데이터가 유지됨. 이때 같은 칩을 다시 눌러도 동일 카테고리 가드에 막혀 재시도가 불가능했음.

`hasError` 상태에서의 같은 칩 재탭을 재시도로 받되, `select()`가 아니라 `ref.invalidate(noticesNotifierProvider)`를 사용.

**특이사항**:
- `select()`로 구현하면 안 됨. Riverpod의 `Notifier.updateShouldNotify`가 `!identical(prev, next)`로 비교하는데 enum 상수는 같은 인스턴스라 알림이 나가지 않음. 그러면 Notifier가 재빌드되지 않아 로딩 팝업이 닫히지 않는 상태가 됨
- 대안으로 검토했던 "에러 시 이전 선택 복원" 방식도 채택하지 않음. 복원하려면 `select(이전값)`을 호출해야 하는데 `build()`의 watch가 다시 걸려 요청과 에러 스낵바가 두 번씩 발생

#### 첫 로드 실패 시 화면 깨짐

- **파일**: `notices_page.dart`
- **변경 내용**: `asyncState.value` → `asyncState.valueOrNull`
- **이유**: 이전 값이 없는 `AsyncError`에서 `.value`는 원래 예외를 rethrow 해 위젯 트리가 ErrorWidget으로 대체됨. 비행기 모드로 첫 진입할 때 발생. 브랜치 이전부터 있던 코드

#### 핀 아이콘 비율 수정

- **파일**: `notice_card.dart`
- **변경 내용**: `16 × 16` → `10 × 15`
- **이유**: `icon_pin.svg`의 viewBox가 `0 0 10 15`라 정사각으로 그리면 가로로 늘어남. 색상(`#F64C4F`)이 SVG에 박혀 있어 `colorFilter`는 주지 않음

#### 사용자 피드백 반영

- 카테고리 전환 시 전체화면 로딩 팝업 제거 — 칩 색이 탭 즉시 바뀌는 것이 이미 피드백이고, 응답이 올 때까지 이전 목록이 보이므로 화면을 가릴 이유가 없음. 첫 진입(`initState`)과 페이지 이동(`_onPageChanged`)의 팝업은 유지
- 칩 사이 간격 8 → 12, 칩 행과 첫 카드 사이 16 → 24
- 카드 쉐도우(`AppShadows.ver2`) 제거 — 연하늘 배경 위의 흰 카드라 색 차이만으로 경계가 드러남

#### 바텀 네비게이션

- **파일**: `lib/core/widgets/navigation/app_bottom_nav.dart`
- **변경 내용**: 탭 시 `VibrationService.instance().buttonTap()` 호출, 안드로이드에서 하단 인셋에 20 추가
- **이유**: 진동은 `AppButton`·`PreviousButton`과 같은 방식. 이미 선택된 탭이어도 진동을 주는 것은 터치가 먹혔다는 확인이 목적이라 화면이 안 바뀌는 경우에 오히려 더 필요. 안드로이드는 제스처 인셋이 없거나 작아 기존 계산이 0으로 클램프되는 경우가 많음

### 📌 참고사항

**미수행 — 실기기 확인**

아직 눈으로 검증하지 않은 항목:
- 칩 가로 스크롤 동작과 카드 간격
- 기기 언어를 English / 日本語로 바꿨을 때 칩 라벨 잘림 여부
- 카테고리 전환 시 목록 갱신과 페이지네이션 바 동작

**범위 제외 항목**

- **검색** — 시안 우상단에 돋보기 아이콘이 있으나 `GET /api/notices`의 쿼리가 `page`/`size`/`category` 셋뿐이라 서버 검색 불가. 현재 페이지의 10건만 거르는 클라이언트 검색은 "2페이지의 공지가 안 찾아지는" 반쪽짜리가 되므로 만들지 않음. 백엔드에 `keyword` 파라미터가 생기면 추가
- **응답 DTO의 category 필드** — 시안의 카드에 카테고리 배지가 없어 소비할 곳이 없음. `NoticeResponseModel`·`NoticeEntity` 미변경. 배지가 생기면 그때 추가
- **단건 조회** — `GET /api/notices/{noticeId}`는 존재하나 아코디언 방식이라 목록 응답의 `content`를 그대로 펼쳐 씀

**향후 확인 필요**

- 칩 탭 영역이 30dp로 권장 최소 탭 타깃(48dp)에 미달. 시각적 크기를 유지한 채 히트 영역만 넓히는 방법 검토 가능
- 페이지네이션 바가 표시되지 않는 경우(총 1페이지)에도 하단 여백 60이 붙음. 브랜치 이전부터 있던 동작
- AppBar 상단 여백이 안드로이드에서 좁아 보이는 건 코드 결함이 아니라 OS 상태바 높이 차이(iPhone 16은 59, 일반 안드로이드는 24~36). ScreenUtil이 이 인셋은 비례 축소하지 않으며, 디자인 기준이 iPhone 16(393×852)이라 상대적으로 좁게 보임. 보정하려면 `appBar: AppBar(...)`를 쓰는 19곳을 공용 위젯으로 통일하는 별도 작업이 필요
