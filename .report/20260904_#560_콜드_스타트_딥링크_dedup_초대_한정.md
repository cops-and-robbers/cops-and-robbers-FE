### 📌 작업 개요
앱을 종료한 뒤 같은 모집글 링크(`/g/{id}`)를 다시 누르면 상세 대신 홈에 도착하던 문제 수정. 콜드 스타트 딥링크 중복 방지(dedup)를 초대 이벤트에만 적용하도록 범위를 좁혔다

**보고서 파일**: `.report/20260904_#560_콜드_스타트_딥링크_dedup_초대_한정.md`

### 🔍 문제 분석
`deeplink_service.dart`의 `coldStartDeeplink`는 `getInitialLink()` 결과를 SharedPreferences `last_handled_deeplink_uri`와 비교해 같으면 null을 돌려준다(Android singleTop 액티비티가 보관한 launch intent의 recents 재전달 차단). 이 키는 콜드 평가 시점과 웜 처리(`markHandled`) 양쪽에서 기록된다.

이 규칙은 초대 링크의 성질에 맞춰 설계됐다 — 초대 코드는 방마다 새로 발급돼 같은 URI를 두 번 탭할 일이 없고, join API는 재참가 부작용이 있어 재전달 차단이 필요하다. 모집글 링크는 글 하나에 URI가 고정이라 같은 링크를 다시 여는 것이 정상 사용인데, 같은 규칙이 두 번째 탭부터 전부 버렸다. 웜에서 한 번 열어본 링크는 이후 콜드에서 매번 스킵돼 재현이 100%였다.

초대에서 증상이 안 보인 이유: 같은 URI 재탭이 사실상 없고, 있어도 이미 그 방에 참가한 상태라 스플래시의 활성 게임 복구가 대기방으로 보내 가려진다.

배제한 후보:
- 유니버설 링크·App Links 설정 — AASA(`/g/*`·`/ja/g/*`·`/en/g/*`), entitlements, 매니페스트 pathPrefix, assetlinks.json 모두 정상. 앱이 열린다는 것 자체가 OS 연결이 된다는 뜻
- `/g` GoRouter 별칭 — 엔진이 원시 경로를 라우터로 미는 웜 케이스용. 콜드 경로는 스플래시가 `/community/{id}`로 직접 `go` 하므로 무관
- 웹 `/g/{id}` 브릿지 — 웜에서 상세로 들어간다는 증거로 링크가 앱에 도달함이 확인돼 배제(브릿지는 웹 #101로 별도 반영됨)

#558(콜드 프로브 타임아웃)과는 별개 원인이며 #558 수정 후에도 재현됐다

### ✅ 구현 내용

#### 1. dedup을 초대 이벤트로 한정
- **파일**: `lib/core/deeplink/deeplink_service.dart`
- **변경 내용**: `coldStartDeeplink`에서 URI를 먼저 `DeeplinkEvent.fromUri`로 파싱하고, last-handled 비교·기록 블록을 `if (event is InviteJoinEvent)` 안으로 옮김. 모집글·unknown 이벤트는 dedup 없이 그대로 반환
- **이유**: dedup 키를 읽는 곳이 이 함수 하나라 호출자(스플래시·`emitColdStart`)는 손대지 않고 전부 고쳐진다. 글 열람은 두 번 열려도 무해하므로 재전달 차단이 필요 없다

#### 2. 문서 주석 정합
- **파일**: `lib/core/deeplink/deeplink_service.dart`, `lib/features/auth/presentation/pages/splash_page.dart`
- **변경 내용**: `coldStartDeeplink`·`deeplinkEvents` 문서 주석 3곳에 dedup이 초대 한정임을 명시. 스플래시 #558 주석의 "dedup 때문에 같은 링크 재클릭도 스킵될 수 있다" 문장 삭제(이제 초대에만 해당하고 그 경로는 어차피 양보하므로 빈 말)
- **이유**: 주석이 옛 범위를 말하면 다음 작업자가 모집글도 dedup된다고 믿는다

#### 3. 회귀 테스트 (신규)
- **파일**: `test/core/deeplink/deeplink_service_test.dart`
- **변경 내용**: `ProviderContainer`에 `coldStartDeeplinkUriProvider`(app_links 플랫폼 채널) 오버라이드 + SharedPreferences 인메모리 목으로 3건 — ①같은 모집글 URI가 last-handled와 같아도 `CommunityPostEvent` 반환·키 불변 ②같은 초대 URI는 null(재참가 차단 유지) ③첫 초대 URI는 이벤트 반환 + 키 기록
- **이유**: 목은 플랫폼 채널과 저장소 두 경계뿐, 파싱·판단은 실제 코드. ①의 키 불변 단언은 누군가 "일관성" 명목으로 모집글 기록을 되살려 초대 키를 덮는 회귀를 막는다

### 🔧 주요 변경사항 상세

#### deeplink_service.dart
```dart
final event = DeeplinkEvent.fromUri(initial);
if (event is InviteJoinEvent) {
  // 기존 prefs 비교·기록 블록 그대로
}
return event;
```

**변경하지 않은 것**: 웜 `markHandled`(모집글 URI도 계속 기록 — 보호 효과는 0이고 초대 dedup 키를 덮을 수 있으나 변경 전부터 같았고 이번 범위 밖. 다음에 `InviteJoinEvent`만 기록하도록 맞추면 키 의미가 "마지막 초대"로 일관), 스플래시 #558 회수·안전망 로직, `main.dart` 리스너, 웹.

**특이사항**:
- 트레이드오프: 프로세스가 죽은 뒤 recents로 재실행하면 모집글 상세가 한 번 더 열린다. 글 열람은 멱등이라 감수
- 스플래시·`emitColdStart`가 같은 `coldStartDeeplinkProvider`를 보는 경합 방지 구조는 그대로. `initialEchoSkipped`는 URI 기준이라 dedup 결과와 무관하고, #558 늦은 프로브 회수(`valueOrNull`)는 이제 모집글 재탭에도 이벤트를 받는다
