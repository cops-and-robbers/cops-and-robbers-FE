# 에러 문구 순화 + Firebase 변환 지점 디버그 로그

### 📌 작업 개요
사용자에게 노출되는 인증/네트워크 에러 문구를 개발자 용어(Firebase, 토큰, 리소스) 없이 순화하고, 순화로 사라진 실제 원인은 디버그 로그로 보존한다. `ko/en/ja` 3개 로케일 동시 반영.

**핵심**: UI 문구는 친화적으로 순화하되, 원인 추적 정보는 별도 채널(디버그 로그)로 유지하여 CS 대응·디버깅 능력은 그대로 보존.

### 🎯 구현 목표
- 사용자 노출 문구에서 내부 기술 용어 제거 (Firebase, 인증 토큰, 리소스 등)
- 문구 순화로 잃어버린 실제 실패 원인을 개발 모드 로그로 보존
- 3개 로케일(한국어/영어/일본어) 일관 적용

### ✅ 구현 내용

#### Firebase → AuthException 변환 지점 디버그 로그 추가
- **파일**: `lib/features/auth/domain/utils/firebase_auth_error_handler.dart`
- **변경 내용**: `createAuthException()` 진입부에 `kDebugMode` 조건 디버그 로그 추가. 원본 `e.code`, `e.message`를 변환 시점에 출력
- **이유**: 사용자에겐 순화된 `messageKey` 문구만 노출되므로, 실제 원인은 변환 지점에서 반드시 로그로 남겨야 디버깅 가능

#### 에러 문구 순화 (ARB 정본)
- **파일**: `lib/l10n/app_ko.arb`, `app_en.arb`, `app_ja.arb`
- **변경 내용**: 내부 용어가 노출되던 에러 문구를 사용자 친화적으로 교체
- **이유**: 일반 사용자에게 "Firebase 인증 토큰", "리소스" 같은 개발자 용어는 불필요하고 불안감 유발

주요 순화 항목:

| 키 | 변경 전 | 변경 후 |
|----|---------|---------|
| `errorNotFound` | 요청한 **리소스**를 찾을 수 없습니다 | 요청한 정보를 찾을 수 없습니다 |
| `errorConflict` | 요청이 현재 상태와 충돌합니다 | 요청을 처리할 수 없습니다. 잠시 후 다시 시도해주세요 |
| `errorAuthTokenIssueFailed` | **인증 토큰 발급**에 실패했습니다 | 인증에 실패했습니다. 다시 시도해주세요 |
| `errorAuthTokenValidationFailed` | **Firebase 인증 토큰 검증**에 실패했습니다 | 로그인 정보가 만료되었습니다. 다시 로그인해주세요 |
| `errorAuthFirebaseConfig` | **Firebase 설정**에 문제가 있습니다 | 일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요 |
| `errorAuthFirebaseInternal` | **Firebase 내부 오류**가 발생했습니다 | 일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요 |
| `errorAuthTokenMissing` | **인증 토큰**을 가져올 수 없습니다 | 로그인 정보를 확인할 수 없습니다. 다시 로그인해주세요 |

#### AppLocalizations 재생성
- **파일**: `lib/l10n/app_localizations*.dart` (4개)
- **변경 내용**: ARB 수정 후 `flutter gen-l10n`으로 자동 재생성
- **이유**: ARB가 정본이며 코드는 생성물. 직접 편집이 아닌 재생성으로 반영

### 🔧 주요 변경사항 상세

#### 채널 분리 원칙
문구 순화와 원인 보존은 서로 다른 대상을 향한다:
- **UI 채널**: `messageKey` → ARB 친화 문구 (일반 사용자 대상)
- **디버그 채널**: `AuthException.message` + `code`, 변환 지점 `debugPrint` (개발자 대상)

**특이사항**:
- `@key`의 `description` 메타데이터에는 여전히 "Firebase 인증 — 토큰 검증 실패" 같은 내부 설명 유지 → 개발자가 ARB만 봐도 어떤 상황인지 파악 가능
- `errorCode*` 백엔드 매핑 블록은 미변경 (사용자 노출 문구 아님)
- 디버그 로그는 `kDebugMode` 가드로 프로덕션 빌드에서 제외
