### 📌 작업 개요

백엔드 API v2.7.0 명세 변경사항을 Flutter 클라이언트에 반영. 게임 상태 조회 API 신규 도입과 도둑 위치 조회 API deprecated 마이그레이션, 게임 푸시 알림 수신 동의 토글 기능, 타임스탬프 KST → 단말 local 표준화가 핵심. v2.7.0 명세 정합성 정리 및 CodeRabbit 리뷰 반영으로 마무리.

### 🎯 구현 목표

- 게임 상태 조회 API(`GET /api/games/{gameId}/state`) 신규 연동 — 소켓 재연결 시 화면 복원용
- 도둑 위치 조회 API deprecated 처리 → `gameState`로 통합 마이그레이션
- 게임 푸시 알림 수신 동의 API 연동(`GET/PUT /api/user/agreements/game-push`) + 설정 페이지 토글 UI
- 타임스탬프 처리 일원화: 서버는 `+09:00` suffix 포함 송신, 단말은 항상 `toLocal()` 정규화 후 표시
- v2.7.0 명세 변경(운동장 → 플레이그라운드, timezone suffix 누락 버그 수정) 클라이언트 측 반영

### ✅ 구현 내용

#### 1. 게임 상태 조회 API 신규 도입

- **파일**: `lib/features/game/data/datasources/game_system_api_datasource.dart`
- **변경 내용**: `GET /api/games/{gameId}/state` 엔드포인트 추가. `GameStateModel`/`ParticipantInfoModel`/`RobberLocationInfoModel` DTO export
- **이유**: 소켓 재연결 시 누락된 LOCATION_REVEAL/참가자 상태를 한 번의 호출로 복원하기 위함

- **변경 내용**: `robberLocations`(생존 도둑 위치) + `participants`(전체 참여자 팀·상태) 두 필드를 가진 응답 DTO 정의. 모두 빈 배열 기본값 보장
- **이유**: 경찰 대기 중 또는 첫 공개 전이면 `robberLocations`가 빈 배열로 내려오므로 null 안전을 위해 `@Default([])` 적용

- **변경 내용**: `gameState(int gameId)` 엔드포인트 헬퍼 추가 (`/api/games/$gameId/state`)

#### 2. 도둑 위치 조회 API deprecated 마이그레이션

- **파일**: `lib/features/game/presentation/providers/game_event_provider.dart`
- **변경 내용**: `_fetchLastRobberLocations` 내부 호출을 deprecated 도둑 위치 API에서 `getGameState(gameId).robberLocations` 사용으로 전환. participants 필드는 본 메서드에서 사용하지 않음을 주석으로 명시
- **이유**: 백엔드 v2.6.0에서 도둑 위치 조회 API가 deprecated되고 `state` API로 통합됨. 동일한 위치 복구 로직을 새 엔드포인트로 유지

**특이사항**:
- 경찰 대기 시간 중에는 API 호출 자체를 skip하는 가드 유지 (이전 게임 잔존/스테일 데이터 노출 방지)
- `await` 도중 새 LOCATION_REVEAL 이벤트가 도착하면 fetch 결과를 무시 (race condition 방어)

### 🔧 주요 변경사항 상세

#### GameStateModel 응답 처리

`getGameState(gameId)` 호출 결과는 다음과 같이 분기되어 소비된다.

```
robberLocations  ──→ _fetchLastRobberLocations (발자국 복구)
participants     ──→ (별도 흐름 — 본 세션에서는 미사용)
```

`participants` 필드는 향후 오버레이/재연결 동기화 통합 시 사용 예정이며 현재는 기존 `syncFromParticipants` 흐름이 유지됨을 주석으로 명시.

#### GamePushNotifier 낙관적 업데이트 패턴

```text
toggle() → state = next (즉시 UI 반영)
        → PUT API 호출
        ├─ 성공 → 그대로 유지
        └─ 실패 → state = current 원복 + rethrow
```

UI(`settings_page.dart`)는 `rethrow`된 예외를 try-catch로 잡아 `AppException.message`를 SnackBar로 표시.

#### CreateSessionResponse createdAt 직렬화 가드

`@JsonKey(toJson: _dateTimeToIso)`로 직렬화 시 항상 UTC `Z` suffix 포함을 강제. 단방향 보호이며 `fromJson`은 `json_serializable` 기본 동작(DateTime.parse) 사용.

**특이사항**:
- DTO 단계에서는 timezone 정보가 살아 있고, Entity 경계(`Repository.createGame`)에서 `toLocal()` 호출로 단말 local 정규화 — 책임 분리 명확
- 테스트 케이스 `createdAt_is_normalized_to_local_datetime_when_response_has_kst_offset`에서 KST 01:25:37 입력이 UTC 2026-01-15 16:25:37과 동일 시각인지 검증

#### 채팅 타임스탬프 정규화

```text
서버 timestamp: "2026-01-26T14:30:15.123456789+09:00"  (nanosecond + KST suffix)
                                  ↓
_microRegex로 ns→us 절단:    "2026-01-26T14:30:15.123456+09:00"
                                  ↓
DateTime.parse().toLocal():  단말 시계 기준 DateTime
                                  ↓
HH:MM 포맷:                  사용자에게 자연스러운 시각 표시
```

#### deprecated API 호출 제거 후 백엔드 정리 대기
- `GET /api/games/{gameId}/robbers/location`은 백엔드에서 호출 가능 상태로 유지 중이나, 본 작업으로 클라이언트 마이그레이션 완료
- 백엔드는 프론트 마이그레이션 완료 후 해당 엔드포인트 삭제 예정 — 별도 후속 PR/이슈 추적 필요

#### 게임 알림 토글 사전 검증 제거 (9d5b2c9)
- 토글 직전 네트워크 사전 체크 로직 제거 — Repository의 `DioException` 변환과 낙관적 업데이트 원복으로 동일 UX 보장
- 사전 체크는 race condition을 만들 뿐 사용자 경험에 기여하지 않는다는 판단

#### 타임스탬프 책임 분리 원칙
- **DTO 계층**: timezone 정보 보존 (UTC로 파싱된 DateTime)
- **Entity 경계(Repository)**: `toLocal()` 호출로 단말 local 정규화
- **UI**: 정규화된 local DateTime을 그대로 표시
- 향후 새 API에서 시각 필드를 노출할 때 동일 패턴 적용 필요
