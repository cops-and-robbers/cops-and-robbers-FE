### 📌 작업 개요

기존 인게임 화면에 떠 있던 코치마크 오버레이를 제거하고, 별도 **인게임 튜토리얼 페이지**로 분리.
설정 → "튜토리얼 다시 보기"를 통해 노출되는 **카탈로그 페이지**를 신설하고, 신규 사용자에게는 대기방 코치마크 종료 직후 1회 자동 다이얼로그로 인게임 튜토리얼을 강제 노출.

---

### 🎯 구현 목표

- 인게임 코치마크(GamePage 위에 떠 있던 4개 타깃)를 페이지 단위로 분리해 실제 게임 플레이와 분리된 환경에서 학습 가능하도록 변경
- 신규 사용자가 인게임 화면 동작을 모르고 게임에 진입하는 문제 차단 — 대기방 코치마크 종료 직후 1회 강제 노출
- 설정 메뉴 / 카탈로그 페이지 / 게임 규칙 다이얼로그 / 자동 다이얼로그 — 4개 진입점에서 동일한 `/tutorial/in-game` 라우트로 수렴
- 코치마크 시스템의 잔재(GlobalKey, 동적 코드)는 제거하되, 코치마크 자체(대기방·세션 생성)는 유지

### 🔧 주요 변경사항 상세

#### InGameTutorialPage — 실제 GamePage 외형 정밀 복제

핵심 설계 원칙은 **외형은 픽셀 단위로 복제하되, 동적 의존성은 0**.

- **지도 placeholder**: 실 `GoogleMapView` 대신 격자 `CustomPainter` + 안내 텍스트 + 팀 시점 토글 (위치 권한 요청 회피)
- **채팅 collapsed 시트**: 실제 `ChatOverlay`의 `kChatOverlayCollapsedFixedHeight(112)` + 시스템 네비 inset 그대로 복제 (28h 드래그 핸들 + 8h gap + 64h 입력바 + 12h spacer + safeBottom). 핸들/입력바 탭 시 안내 스낵바
- **우측 액션 버튼**: 실 `GamePage._kActionButtonChatGap(45)` + 채팅 높이 + 시스템 inset 동일하게 계산하여 위치 일치
- **참가자 목록**: 실 `TeamSection` + `ParticipantCard` 그대로 재사용 (stateless 순수 위젯이라 데이터만 정적 fixture로 주입). 호스트(경찰1) / 본인(도둑이게아니게) / 도주 중 2명 + 수감 1명으로 데모 데이터 구성

**미션 시스템**:
- 3단계(`_missionStep` 0 → 1 → 2 → 3) 진행
- 활성 타깃 버튼에 레이더 핑 펄스 애니메이션 — 외곽 ring 1.0 → 1.8 확장 + opacity 1.0 → 0.0 페이드아웃, 버튼 본체는 sin 곡선 1.0 → 1.18 → 1.0 왕복
- 미션 3 완료 시 500ms 텀 두고 `AppDialog`("튜토리얼 끝내기" 1버튼) → `context.pop()`으로 caller-agnostic 복귀

**팀 시점 토글**: `_isDarkMode` state로 경찰(라이트) / 도둑(다크) 시점 즉시 전환. 가독성을 위해 지도 placeholder 중앙에 배치 (실 게임에선 별도 UI 없음)

#### waiting_room_page.dart — 1회 자동 노출 로직

```
대기방 코치마크 시작
  ↓ 모든 step 통과
onFinish 콜백:
  1. TutorialService.markCompleted(TutorialKeys.waitingRoom)
  2. _showInGameTutorialPromptIfNeeded() 호출
       ↓ inGamePrompt 미완료 확인
       ↓ mark 먼저 수행 (다이얼로그 중단 대비)
       ↓ AppDialog 노출 (barrierDismissible: false, "보러 가기" 1버튼)
       ↓ confirm → context.push('/tutorial/in-game')
       ↓ 튜토리얼 페이지 "튜토리얼 끝내기" → context.pop() → 대기방 복귀
```

**1회 보장**: `TutorialKeys.inGamePrompt` SharedPreferences 키. mark는 다이얼로그 노출 **전에** 수행. "튜토리얼 초기화" 메뉴에서 함께 reset되어 재노출 가능.

**거절 정책**: 거절 버튼 없음 → 의도적 강제. 사용자는 "보러 가기"만 누를 수 있고 그 즉시 키가 mark됨.

**구조적 안전성**: 코치마크 진행 중에는 사용자가 "준비 완료" 버튼을 못 누르고, 호스트도 게임을 못 시작함 → "튜토리얼 보는 도중 GAME_START 도착" 시나리오 차단

#### TutorialCatalogPage — 5항목 중 1개 활성

- 4개 카드(방 만들기 / 방 참여하기 / 대기방 / 인게임) 렌더링
- 인게임만 `route: '/tutorial/in-game'` 보유 → `isActive == true`
- 비활성 카드는 회색 배경 + "준비 중" 배지 + 탭 비활성 (`onTap: null`)
- subtitle은 각 항목의 핵심 학습 키워드 (인게임: "타이머·지도·참가자·채팅·QR")

#### game_rules_content.dart — 2버튼 구조 전환

```
[ 확인 ]  [ 인게임 보기 ]
 cancel    confirm (primary)
```

다크모드(도둑팀)는 confirm 색상을 자동 분기. `context.push`로 push 전환이라 대기방으로 자연 복귀.

#### 검증 방법

- **자동 노출**: SharedPreferences 초기화 → 대기방 첫 진입 → 코치마크 종료 시 다이얼로그 1회 노출 확인 / 두 번째 진입 시 미노출 확인
- **재방문**: 설정 → "튜토리얼 다시 보기" → 카탈로그 → 인게임 카드 → 인게임 튜토리얼 페이지 진입 확인
- **게임 규칙 진입**: 대기방 ⓘ 버튼 → 게임 규칙 다이얼로그 → "인게임 보기" → 인게임 튜토리얼 페이지 진입 확인
- **초기화**: 설정 → "튜토리얼 초기화" → 대기방 재진입 시 코치마크 + 다이얼로그 모두 재노출 확인
- **caller-agnostic 복귀**: 카탈로그 / 자동 / 게임 규칙 / 설정 어느 진입점에서도 "튜토리얼 끝내기" 탭 시 정확히 직전 화면으로 복귀

### 📌 참고사항

- **인게임 코치마크 제거에 따른 부수 변경**: `lib/features/game/presentation/pages/game_page.dart`에서 `IsoTimestampParser` 의존성이 함께 정리되어 일부 타임스탬프 파싱이 `DateTime.tryParse`로 인라인화됨. 코치마크 제거 commit과 동일 묶음(b5d6f5a)에 포함
- **튜토리얼 페이지의 위치 권한 회피**: 인게임 튜토리얼에서 실 `GoogleMapView`를 쓰지 않고 격자 placeholder를 쓰는 이유는 위치 권한 요청을 학습 단계에서 발생시키지 않기 위함. 학습 → 본 게임 진입 시 권한 요청이 자연스럽게 한 번만 발생
- **차후 확장 여지**: 카탈로그 4개 항목 중 3개("방 만들기·방 참여하기·대기방")는 동일 패턴으로 페이지를 추가하면 그대로 활성화 가능. `_TutorialCatalogItem.route` 필드에 라우트만 채우면 됨
- **waiting_room_page 위젯 테스트 미작성 사유**: 코치마크 라이브러리의 GlobalKey 마운트 + 다수 Riverpod provider mock이 필요해 비용 대비 가치가 낮음. 분기 로직은 SharedPreferences 체크 1번 + 1개의 새 메서드라 수동 스모크 테스트로 검증
