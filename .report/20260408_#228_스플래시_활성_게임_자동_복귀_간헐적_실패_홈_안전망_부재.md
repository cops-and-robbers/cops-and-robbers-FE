### 📌 작업 개요
앱을 장시간 미사용 후 재실행 시, 참여 중인 게임이 있음에도 홈 화면으로 이동되는 간헐적 버그 수정. 스플래시 재시도 로직, 네트워크 에러 모달, 홈 화면 안전망 3단계 방어 구조를 구현하여 활성 게임 복귀 안정성을 강화.

**보고서 파일**: `.report/20260408_#228_스플래시_활성_게임_자동_복귀_간헐적_실패_홈_안전망_부재.md`

---

### 🔍 문제 분석

#### 직접 원인: 콜드 스타트 네트워크 에러
- 스플래시의 `getMyActiveGame` API 호출이 앱의 **첫 번째 실제 네트워크 요청**
- `authNotifierProvider.build()`은 로컬 상태(Firebase currentUser, SecureStorage)만 확인하므로 auth 통과 ≠ 네트워크 정상
- 장시간 백그라운드/종료 후 재실행 시 OS가 네트워크 소켓을 해제한 상태 → DNS 캐시 만료, TLS 핸드셰이크 재수행 → Dio connectTimeout 초과 또는 일시적 연결 실패
- DioException 발생 → catch 블록 → 홈 fallback

#### 구조적 문제: 홈 안전망 부재
- 활성 게임 체크가 스플래시와 로그인 직후(`_resolvePostLoginDestination`)에서만 수행
- 홈 화면과 GoRouter redirect에 활성 게임 확인 분기 없음
- 스플래시 실패 시 복구 경로 전무

#### 잠재적 결함: QueuedInterceptor 재시도 데드락
- `AuthInterceptor._retryRequest()`에서 토큰 재발급 후 `_dio.fetch()`로 재시도 시, QueuedInterceptor 순차 처리 큐에서 교착 상태 발생 가능
- 현재 증상의 직접 원인은 아니나(데드락 시 스플래시 행, 홈 도달 불가), access token 만료 상태에서 앱이 영구 멈출 수 있는 잠재적 결함

### ✅ 구현 내용

#### 1. AuthInterceptor QueuedInterceptor 데드락 방지
- **파일**: `lib/core/network/auth_interceptor.dart`, `lib/core/network/dio_client.dart`
- **변경 내용**: `_retryRequest()`에서 `_dio.fetch()` → `_plainDio.fetch()`로 변경. 미사용된 `_dio` 필드 및 생성자 파라미터 제거. `RequestOptions`를 `copyWith()`로 불변 복사하여 원본 변형 방지
- **이유**: `QueuedInterceptor`는 인터셉터 콜백을 순차 처리하므로, `onError` 핸들러 내에서 같은 Dio 인스턴스로 재시도하면 교착 상태 발생. `_plainDio`는 인터셉터가 없으므로 큐 우회

#### 2. 스플래시 getMyActiveGame 재시도 로직
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart`
- **변경 내용**: `_fetchActiveGameWithRetry()` 메서드 추가. DioException 발생 시 1초 간격으로 최대 2회 재시도 (총 3회 시도). `Future.delayed` 후 `mounted` 체크로 위젯 해제 상태에서의 안전성 확보
- **이유**: 콜드 스타트 시 네트워크 스택 초기화 지연으로 첫 번째 API 호출이 실패할 수 있으므로, 재시도로 네트워크 안정화 대기

#### 3. 스플래시 네트워크 에러 모달
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart`
- **변경 내용**: catch 블록을 DioException과 일반 Exception으로 분리. DioException 시 `AppDialog`로 "네트워크 연결 실패" 모달 표시, "재시도" 버튼 탭 시 `_navigateToNextScreen()` 재실행. 비네트워크 에러만 기존대로 홈 fallback
- **이유**: 네트워크 문제로 홈에 도달하는 것을 1차 차단. 사용자가 네트워크 확인 후 직접 재시도 가능

#### 4. 홈 화면 활성 게임 안전망
- **파일**: `lib/features/session/presentation/pages/home_page.dart`
- **변경 내용**: `_activeGameChecked` static 플래그 추가 (세션당 1회). `_checkActiveGameAndRedirect()` 메서드로 홈 진입 시 백그라운드 활성 게임 체크. WAITING/IN_PROGRESS 상태 시 대기실/게임으로 자동 리다이렉트. `resetSafetyNotice()`에 플래그 초기화 연동
- **이유**: 스플래시에서 어떤 이유로든 실패했을 때의 최후 방어선. 기존 `_safetyNoticeShown` 패턴과 동일한 방식으로 일관성 유지

### 🔧 주요 변경사항 상세

#### 3단계 방어 구조

```
스플래시 재시도 (3회) → 네트워크 에러 모달 (재시도 버튼) → 홈 안전망 (최후 방어)
```

| 단계 | 대상 에러 | 동작 | 파일 |
|------|----------|------|------|
| 1단계 | DioException | 1초 간격 최대 2회 재시도 | splash_page.dart |
| 2단계 | 재시도 실패 (DioException) | "네트워크 연결 실패" 모달 + 재시도 버튼 | splash_page.dart |
| 2단계 | 비네트워크 에러 | 기존대로 홈 fallback | splash_page.dart |
| 3단계 | 홈 도착 시 | 백그라운드 활성 게임 체크 → 자동 리다이렉트 | home_page.dart |

#### auth_interceptor.dart
- 생성자에서 `dio` 파라미터 제거, `_dio` 필드 삭제
- `_retryRequest()`가 `_plainDio.fetch()`를 사용하여 QueuedInterceptor 큐 우회
- `RequestOptions.copyWith()`로 불변 패턴 적용, `_isRetry` 플래그 제거

**특이사항**:
- `_plainDio`에는 AuthInterceptor가 없으므로 무한 루프 방지를 위한 `_isRetry` 플래그가 불필요. 기존 `onError`의 `_isRetry` 체크 가드는 방어 코드로 유지
- `dio_client.dart`에서도 `AuthInterceptor` 생성 시 `dio` 파라미터 제거 반영

#### splash_page.dart
- `_fetchActiveGameWithRetry()`: DioException만 재시도, FormatException 등 비네트워크 에러는 즉시 rethrow
- `_showNetworkErrorDialog()`: `AppDialog.show()`에 `barrierDismissible: false` 설정으로 모달 외부 탭 방지
- catch 블록 분리: `on DioException` → 모달, `catch (e)` → 홈 fallback

#### home_page.dart
- `_activeGameChecked` static 플래그로 세션당 1회만 체크
- `build()` 내 `addPostFrameCallback`으로 비동기 체크 (UI 블로킹 없음)
- 라우팅 로직은 splash_page.dart와 동일한 패턴 (WAITING → 대기실, IN_PROGRESS → 게임)
