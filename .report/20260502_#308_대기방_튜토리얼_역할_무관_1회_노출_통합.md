# 대기방 튜토리얼 역할 무관 1회 노출 통합

**주된 이슈**: [#308](https://github.com/cops-and-robbers/cops-and-robbers-FE/issues/308) — 대기방 튜토리얼을 팀과 무관하게 1회만 노출
**브랜치**: `20260430_#308_대기방_튜토리얼을_팀과_무관하게_1회만_노출`
**연관 PR**: #317
**선행 작업**: [#278](https://github.com/cops-and-robbers/cops-and-robbers-FE/issues/278) — 팀별 키 2개로 분리해 최대 2회 노출하던 설계 (이번에 합치는 대상)

### 📌 작업 개요

대기방 튜토리얼이 팀별 키(`tutorial_waiting_room_police`, `tutorial_waiting_room_robber`)로 분리되어 한 사용자에게 최대 2회 노출되던 동작을, 단일 키(`tutorial_waiting_room`)로 통합해 **사용자당 1회만 노출**되도록 변경. 1번 스텝 문구를 팀 중립으로 바꾸고, 팀 변경 시 튜토리얼을 강제 종료/재트리거하던 리스너를 제거.

### 🔍 문제 분석

| 문제 | 원인 |
|---|---|
| 같은 사용자에게 거의 같은 안내가 최대 2회 노출 | 팀별 키로 완료 상태를 분리 저장 (`tutorial_waiting_room_police` / `tutorial_waiting_room_robber`) |
| 1번 스텝 문구가 팀에 종속 | `'이 버튼을 눌러 도둑팀(또는 경찰팀)으로 이동할 수 있어요'` 분기 처리 |
| 팀 변경 시 튜토리얼 강제 종료 + 재시작 | `ref.listen(gameParticipantNotifierProvider)` 내부 `controller.finish()` + `_showTutorialIfNeeded(nextTeam)` 재호출 |

4개 스텝 중 1번(팀 변경)·2번(초대 코드)·3번(게임 설정)·4번(준비 버튼) 모두 양 팀에서 동일한 안내라, 1번 스텝 문구만 팀 중립으로 바꾸면 키 통합이 가능하다고 판단.

### 🎯 구현 목표

- 대기방 튜토리얼 완료 상태를 단일 키 `tutorial_waiting_room`에 저장
- 1번 스텝 description을 `'이 버튼을 눌러 다른 팀으로 이동할 수 있어요'`로 통합
- 1번 스텝 타겟은 기존과 동일: 현재 팀의 반대 팀 첫 빈 `AddSlotCard`
- 반대 팀 정원이 가득 차서 빈 슬롯이 없는 경우 1번 스텝 스킵, 나머지 3스텝만 노출 후 완료 처리
- 팀 변경 재트리거 로직 제거 → 단일 진입점은 `_fetchAndInitParticipants()` 종료 시점

- **이유**: 리스너 제거 후 단일 진입점이 됐다는 사실을 코드 옆에 명시해 다음 독자의 혼동 방지.

### 🔧 주요 변경사항 상세

#### `TutorialKeys.waitingRoom` 단일 키
역할 무관 단일 SharedPreferences 키. 1번 스텝 타겟(현재 팀의 반대 팀 첫 빈 슬롯)은 키와 무관하게 호출 시점 `team` 값으로 결정.

```dart
// 대기실 튜토리얼: 역할(경찰/도둑) 무관 사용자당 1회만 노출.
// 모든 스텝(팀 변경·초대 코드·게임 설정·준비 버튼)이 양 팀에서 동일한
// 안내이므로 팀별 분리가 불필요. 1번 스텝 타겟만 "현재 팀의 반대 팀 첫
// 빈 슬롯"으로 호출 시점의 team 값으로 결정된다(키와 무관).
static const waitingRoom = 'tutorial_waiting_room';
```

#### `_showTutorialIfNeeded(String team)` 호출 흐름
1. 중복 호출 가드(`_isTutorialShowing`, `_pendingInviteDialog`, `_isInviteDialogOpen`)
2. `TutorialKeys.waitingRoom` 완료 여부 확인
3. `endOfFrame` 대기 후 `currentTeam != team` 체크 (낡은 호출 차단)
4. `team` 기준 반대 팀 `AddSlotCard` GlobalKey 선택 (`opponentKey.currentContext`가 null이면 1번 스텝 스킵)
5. 4개 스텝 노출, 종료 시 `markCompleted(waitingRoom)`

**특이사항**:
- 진행 중 팀 변경은 정상 흐름에서 거의 발생하지 않음 — `tutorial_coach_mark` 오버레이가 사용자 탭을 흡수해 4스텝 종료 전까지 팀 버튼 탭이 다음 스텝 진입으로 소비됨
- 서버 푸시 `TEAM_UPDATE` 같은 드문 케이스에서 1번 스텝 타겟 GlobalKey의 `currentContext`가 null이 되면 하이라이트가 어색해질 수 있으나, 사용자가 탭하면 다음 스텝으로 진행되어 4스텝 끝까지 완주 가능

#### 팀 변경 리스너 제거 후 단일 진입점
```dart
// 튜토리얼 트리거 단일 진입점.
// 단일 키 정책으로 팀 변경 재트리거 리스너가 제거되었으므로, 본 호출이
// 유일한 진입 경로다. STOMP 재연결 등으로 _fetchAndInitParticipants 가
// 여러 번 호출되어도 _isTutorialShowing 가드와 isCompleted 가드로
// 중복 노출이 차단된다.
if (mounted && myTeam != null) {
  _showTutorialIfNeeded(myTeam);
}
```

### 📌 참고사항

- **마이그레이션 미수행**: SharedPreferences에 남은 레거시 키(`tutorial_waiting_room_police`, `tutorial_waiting_room_robber`)는 명시적으로 삭제하지 않음. 참조하는 코드가 없어 동작에 영향 없음.
- **이전 버전 사용자 영향**: 이미 한쪽 또는 양쪽 팀 키만 true인 사용자도 신규 키 `tutorial_waiting_room`은 false 상태이므로, 업데이트 후 다음 대기방 입장에서 1회 추가 노출됨. 마이그레이션 비용 대비 영향이 작아 1회성 비용으로 수용. 코드 리뷰 단계에서 이 회귀를 명시적으로 합의함.
- **1번 스텝 타겟 분기**: 키는 단일이지만 1번 스텝 타겟(반대 팀 슬롯 GlobalKey)은 호출 시점 `team` 값에 따라 분기되므로, `_showTutorialIfNeeded(String team)`의 파라미터는 그대로 유지됨.
- **건너뛰기 버튼 별도 분리**: 튜토리얼 전반에 "건너뛰기" 버튼 도입은 다른 튜토리얼(홈/방 만들기/게임 등 6개)과의 일관성 결정이 필요해 별도 이슈로 분리 예정.
