### 📌 작업 개요
서버가 내려가 있거나 5xx를 내는 동안 콜드 스타트하면 스플래시가 안내 없이 홈으로 이동하던 문제 수정. 서버 장애를 오프라인과 같은 방식으로 **차단 화면 + 재시도**로 받고, 실패 분류를 헬퍼 하나로 모음

**보고서 파일**: `.report/20260903_#554_서버_장애_시_스플래시가_차단_없이_홈으로_이동함.md`

### 🎯 구현 목표
- 사전 연결 체크 통과 후의 연결 실패·5xx를 홈 fallback이 아니라 서버 장애 안내 페이지로
- 안내 페이지는 점검·강제 업데이트 페이지와 같은 구성(로고·제목·본문·하단 버튼)
- 네트워크·5xx·4xx·기타 분류를 한 곳에서 (`classifyFailure`)
- 파싱 에러 같은 진짜 비네트워크 실패만 기존 홈 fallback 유지

### ✅ 구현 내용

#### 실패 분류 헬퍼
- **파일**: `lib/core/network/network_failure_detector.dart`
- **변경 내용**: `isServerFailure(e)`(원인 Dio 응답 상태 코드 ≥ 500) 추가, `classifyFailure(e) → FailureKind {network, server, client, other}` 추가. 기존 `isNetworkFailure`는 그대로
- **이유**: 스플래시가 `on NetworkException` / `on DioException` / generic catch 세 갈래로 흩어져 있어 5xx가 "비네트워크 → 홈"으로 빠졌다. 화면은 "무엇을 안내할지"만 정하고 판정은 한 곳에서 한다. 4xx는 요청 자체가 거절된 것이라 전면 차단 대상이 아니며 errorCode별 문구는 기존 `errorByException` 관행을 따른다

#### 서버 장애 안내 페이지
- **파일**: `lib/core/widgets/pages/server_error_page.dart` (신규)
- **변경 내용**: `ServerErrorPage(onRetry:)` — `MaintenancePage`·`ForceUpdatePage`와 같은 레이아웃. 제목 `pageServerErrorTitle`("서버에 문제가 생겼어요"), 본문 `pageServerErrorMessage`, 하단 `AppButton(buttonRetry)`
- **이유**: 점검 페이지는 Remote Config `maintenance`로만 열리고 fail-open이라 서버 장애 시 게이트가 열리지 않는다. 같은 자리에 재시도 가능한 페이지가 필요

#### 스플래시 실패 분기 재구성
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart`
- **변경 내용**:
  - `bool _isOffline` → `_BlockReason? _block {offline, serverError}`. 서버 장애면 `ServerErrorPage`, 오프라인이면 기존 인라인 뷰
  - 활성 게임 조회 catch 세 갈래를 `switch (classifyFailure(e))` 하나로. `network`(비복구) · `server` → 차단, `client`·`other` → 홈 fallback
  - 인증 초기화 5초 타임아웃(비복구) → 로그인 이동에서 서버 장애 차단으로. `AuthNotifier`가 서버 조회 실패를 안에서 삼키므로 여기 오는 타임아웃은 서버 무응답(connectTimeout 10초 × 2 > 5초)이다
  - `_returnToOffline` → `_returnToBlocked`: 재시도는 사전 체크를 건너뛰므로 실패 시점에 기기 연결을 다시 봐서 오프라인·서버 장애를 가른다. 연결 확인 자체가 예외를 내면 재시도 버튼이 있는 서버 장애 쪽으로
  - 차단 화면은 사유와 무관하게 연결 복구를 구독한다 — connectivity 보고값이 stale해 실제로는 오프라인인 경우 연결이 돌아오면 자동 재시도가 살아야 한다
  - 원시 `DioException`에만 걸려 실제로는 도달하지 않던 `_showNetworkErrorDialog` 삭제
- **이유**: PR #228에서 생긴 "비네트워크 에러 → 홈 fallback" 행이 5xx·서버 다운까지 덮고 있었다. 홈의 활성 게임 안전망도 같은 API를 부르므로 서버가 내려간 동안은 복구가 안 되고 게임 중이던 사용자가 홈에 갇힌다

#### 문구
- **파일**: `lib/l10n/app_ko.arb`, `app_en.arb`, `app_ja.arb` (+ 생성물 4종)
- **변경 내용**: `pageServerErrorTitle`·`pageServerErrorMessage` 추가 (기존 `pageMaintenance*` 옆). 재시도 스낵바는 기존 `errorServerUnreachable` 재사용

### 🔧 주요 변경사항 상세

#### 오진 가능성과 완화
사전 체크는 기기 링크만 보므로 캡티브 포털·DNS 실패도 "서버 장애"로 분류된다. 본문을 "서버 연결이 원활하지 않아요"로 중립화했고, 서버 장애 화면에서도 연결 복구를 구독해 네트워크가 돌아오면 자동 재시도된다.

#### 홈 fallback으로 남긴 것
`FailureKind.client`(4xx)와 `other`(파싱 등)는 재시도해도 같은 결과라 기존대로 홈으로 간다. 활성 게임 조회에서 4xx가 나올 경로는 현재 없다.

**특이사항**:
- ARB `dialogNetworkConnectionFailedTitle`·`dialogSplashOfflineMessage`는 삭제한 다이얼로그만 쓰던 키라 사용처가 0이 됐다. 키 삭제는 범위 밖이라 두었다
- 실기기 확인(서버 내린 상태 콜드 스타트 → 페이지 노출 → 서버 복구 후 재시도 성공) 미완
