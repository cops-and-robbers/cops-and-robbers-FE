## 📌 작업 개요

기존 중첩 라우트 기반의 4단계 세션 생성 플로우를 PageView 기반의 단일 페이지로 리팩토링하여 플로우 변경에 유연하게 대응할 수 있도록 개선. 802줄의 obsolete 코드 제거 및 아키텍처 단순화 달성.

**주요 성과**:

- 4개의 중첩 라우트 페이지 → 1개의 SessionCreationFlowPage로 통합
- 각 Step을 content widget으로 분리하여 재사용성 향상
- 변수명 통일 및 애니메이션 일관성 확보
- Clean Architecture 3계층 구조 준수

---

## 🔍 문제 분석

### 기존 문제점

1. **플로우 불확실성**: game_settings_page, invite_code_page의 화면 흐름이 확정되지 않아 추후 변경 비용 증가 우려
2. **로직 분리 부족**: 방 생성/초대 코드 생성 로직이 페이지에 종속되어 재사용/확장 어려움
3. **중첩 라우트 복잡도**: GoRouter의 nested routes로 인한 관리 복잡도 증가
4. **변수명 불일치**: locationRevealInterval vs locationShare 등 명명 규칙 불일치

### 설계 방향

- PageView 기반 단일 페이지로 4단계 플로우 통합
- UI와 비즈니스 로직 분리 (Presentation ↔ Domain ↔ Data)
- 각 Step을 독립적인 content widget으로 분리
- 상태 관리를 중앙 집중화하여 데이터 흐름 명확화
