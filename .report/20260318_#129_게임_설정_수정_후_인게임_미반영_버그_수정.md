### 📌 작업 개요

대기실에서 게임 설정(라운드 시간, 위치 공유 간격 등)을 수정한 후 게임을 시작하면, 수정된 설정이 아닌 방 생성 시점의 초기 설정값으로 게임이 진행되는 버그 수정

**보고서 파일**: `.report/20260318_#129_게임_설정_수정_후_인게임_미반영_버그_수정.md`

### 🔍 문제 분석

게임 설정이 **두 곳에 이중 저장**되어 있으나, 한 곳만 갱신되는 구조적 문제:

| 저장소 | 역할 | 설정 수정 시 갱신 여부 |
|--------|------|----------------------|
| `fetchGameSettingsProvider` (Riverpod 캐시) | 대기실 UI 표시용 | ✅ invalidate됨 |
| `gameParticipantNotifierProvider` (인메모리) | **인게임에서 읽는 값** | ❌ 갱신 안 됨 |

방장이 대기실에서 설정을 수정하면 STOMP `SETTINGS_UPDATED` 이벤트가 발생하고, `fetchGameSettingsProvider` 캐시는 무효화되어 대기실 UI에는 최신 값이 반영됨. 하지만 `gameParticipantNotifierProvider`에는 방 생성 시점의 값이 그대로 남아 있어, 게임 시작 후 인게임(`game_page.dart`)에서 이 stale 값을 읽게 됨.

### ✅ 구현 내용

#### GameParticipantNotifier에 설정 업데이트 메서드 추가
- **파일**: `lib/features/session/presentation/providers/game_participant_provider.dart`
- **변경 내용**: `updateSettings()` 메서드 추가. 게임 설정 4개 필드(`maxParticipants`, `locationRevealIntervalMinutes`, `policeWaitMinutes`, `roundTimeMinutes`)를 `copyWith`로 갱신
- **이유**: 기존에는 설정만 부분 업데이트하는 메서드가 없어서, STOMP 이벤트 수신 시 notifier를 갱신할 방법이 없었음

#### SETTINGS_UPDATED 이벤트 핸들러에서 notifier 동기화 추가
- **파일**: `lib/features/lobby/presentation/providers/lobby_provider.dart`
- **변경 내용**: `SETTINGS_UPDATED` 이벤트 수신 시 기존 캐시 무효화에 더해, 최신 설정을 서버에서 fetch한 후 `gameParticipantNotifierProvider.updateSettings()`를 호출하여 인메모리 상태도 동기화
- **이유**: 캐시 무효화만으로는 `gameParticipantNotifierProvider`가 갱신되지 않아, 인게임에서 stale 값을 읽는 문제 해결

### 🔧 주요 변경사항 상세

#### lobby_provider.dart — SETTINGS_UPDATED 핸들러

기존에 `ref.invalidate(fetchGameSettingsProvider(gameId))` 한 줄만 있던 핸들러에, invalidate 후 `.future`로 최신 설정을 다시 fetch하고 `updateSettings()`를 호출하는 로직 추가. `.then().catchError()` 패턴을 사용하여 `_handleLobbyEvent`의 `void` 시그니처를 유지.

**특이사항**:
- `invalidate` 후 바로 `.future`를 read하면 새 fetch가 트리거됨. invalidate는 대기실 UI watch 갱신용으로도 필요하므로 둘 다 유지
- fetch 실패 시 `catchError`에서 로그만 남기고 무시 (대기실 UI는 이미 캐시 무효화로 갱신됨)

#### game_participant_provider.dart — updateSettings()

기존 `initFromLobby()`와 동일한 `copyWith` 패턴으로 구현. `state == null` 가드 포함.

### 🧪 테스트 및 검증
- 방 생성 (라운드 30분, 위치 공유 5분) → 대기실에서 설정 변경 (60분, 10분) → 게임 시작 → 인게임에서 변경된 설정(60분, 10분)이 적용되는지 확인
- 비호스트 참가자 측에서도 설정 변경이 반영되는지 확인 (STOMP 브로드캐스트)

### 📌 참고사항
- 이 수정은 설정 변경의 실시간 동기화만 다룸. 구역(area) 변경은 인게임에서 별도 API(`gameAreaProvider`)로 fetch하므로 동일한 문제가 발생하지 않음
