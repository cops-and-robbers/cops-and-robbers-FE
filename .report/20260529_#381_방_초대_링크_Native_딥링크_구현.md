# #381 방 초대 링크 Native 딥링크 구현

### 📌 작업 개요

방 초대를 공유 링크(`https://copsnro66ers.site/join/{code}`)로 받아, 링크 클릭 시 OS가 앱을 자동 실행하고 곧바로 해당 방에 참여하는 **Native 딥링크(Android App Links / iOS Universal Links)** 플로우를 구현했다.

콜드스타트·웜스타트, 미로그인 진입(로그인 후 자동 재진입), 이미 다른 방 참가 중(409→활성 방 복귀) 등 진입 분기를 모두 처리했으며, 작업 도중 발견된 게임 종료 처리 결함(GAME_OVER 이벤트 유실)도 함께 보강했다.

---

### 🎯 구현 목표

- 초대 링크 공유 → 링크 클릭 → 앱 자동 실행 → 자동 방 참여
- 진입 시나리오별 분기: 미로그인 / 정상 참여 / 이미 참가 중 / 인원 초과 / 네트워크 오류
- 플랫폼 설정(Android App Links, iOS Universal Links) 구성
- 라우팅·토스트와 분리된 테스트 가능한 비즈니스 로직

---

### ✅ 구현 내용

#### 1. 딥링크 URI 수신 레이어 (`core/deeplink/`)

- **파일**: `lib/core/deeplink/deeplink_service.dart`, `deeplink_event.dart`
- **변경 내용**:
  - `app_links` 패키지를 래핑해 콜드스타트 1회 URI + 웜 URI 스트림을 단일 Broadcast Stream으로 노출 (`@Riverpod(keepAlive: true)`)
  - URI를 의미 있는 sealed 이벤트(`InviteJoinEvent` / `UnknownEvent`)로 정규화하는 `DeeplinkEvent.fromUri`
- **이유**: 콜드/웜 진입을 한 곳에서 통일 처리하고, host 화이트리스트(`copsnro66ers.site`) + `/join/{code}` 경로 형태만 통과시켜 그 외 경로는 안전하게 무시

#### 2. 딥링크 진입 화면 + 비즈니스 로직 분리

- **파일**: `lib/features/session/presentation/pages/deeplink_join_page.dart`, `providers/deeplink_join_notifier.dart`
- **변경 내용**:
  - `DeepLinkJoinNotifier`가 인증 확인 → join API 호출 → 에러 분류를 수행하고 `DeepLinkJoinOutcome`(loginRedirect / joinedRoom / alreadyInRoom / failure) 반환
  - `DeepLinkJoinPage`는 로딩 화면을 표시하며 Outcome에 따라 라우팅/토스트만 담당
- **이유**: Notifier가 `BuildContext`·`GoRouter`에 의존하지 않아 `ProviderContainer`만으로 단위 테스트 가능 (테스트 300줄 작성)

#### 3. 미로그인 진입 시 자동 재진입 (`PendingInvite`)

- **파일**: `lib/features/session/presentation/providers/pending_invite_provider.dart`, `lib/main.dart`
- **변경 내용**:
  - 미로그인 상태에서 받은 초대 코드를 `SharedPreferences`에 임시 저장
  - 로그인 + 진입 절차(약관 동의·닉네임 설정) 완료 시점에만 코드를 소비해 자동 join 흐름 재진입
- **이유**: 미로그인 → 로그인 후에도 초대 코드가 유실되지 않도록 보존. 신규 유저/약관 미동의 케이스에서 GoRouter redirect가 push를 무시하며 코드만 유실되던 문제를 "진입 절차 완료 후 소비"로 해결

#### 4. 활성 게임 복귀 라우트 공통화

- **파일**: `lib/router/active_game_route.dart`
- **변경 내용**: 참여 정보(`WAITING`/`IN_PROGRESS`)를 복귀 경로로 변환하는 `activeGameRoute()` 추출
- **이유**: "로그인 후 복귀", "딥링크 중복 참가 복귀" 등 동일 매핑을 쓰는 진입점이 여러 곳이라 한 함수로 통일 (알 수 없는 상태는 null → 호출자가 홈 폴백)

#### 5. join API 연동 (Clean Architecture 4계층)

- **파일**: `domain/usecases/join_game_by_invite_usecase.dart`, `domain/entities/game_join_result.dart`, `data/repositories/session_repository_impl.dart`, `presentation/providers/session_provider.dart`
- **변경 내용**: 초대 코드 → 백엔드 join → `GameJoinResult(gameId, participantId)` 반환하는 UseCase/Repository/Provider 추가
- **이유**: 딥링크·수동 입력 공통으로 쓰는 참여 경로를 표준 4계층 구조로 구성

#### 6. 플랫폼 설정 (Android / iOS)

- **파일**: `android/app/src/main/AndroidManifest.xml`, `ios/Runner/Info.plist`, `ios/Runner/Runner.entitlements`
- **변경 내용**:
  - Android: `autoVerify="true"` intent-filter (`https://copsnro66ers.site/join/*`)
  - iOS: `associated-domains`에 `applinks:copsnro66ers.site` 추가, `FlutterDeepLinkingEnabled=false`
- **이유**: OS가 도메인 소유권을 검증(`.well-known/assetlinks.json`, `apple-app-site-association`)한 뒤 링크를 앱으로 직접 전달하도록 설정. Flutter 기본 딥링킹은 끄고 `app_links`로 일원화

### 🔧 주요 변경사항 상세

#### 에러 분류 (`DeepLinkJoinNotifier._classifyError`)

백엔드 join 응답을 상황별 Outcome으로 분기한다.

- **409 Conflict** → "이미 다른 방 참가 중". 백엔드가 어느 방인지 알려주지 않으므로 활성 게임을 별도 조회(`getMyActiveGameUsecase`)해 복귀 경로를 채운다. 조회 실패 시 홈 폴백
- **400 + title `게임 인원 초과`** → 인원 초과 메시지, 그 외 400 → 초대 코드 유효하지 않음
- **NetworkException** → 네트워크 오류 안내

**특이사항**:
- `DioExceptionHandler`가 변환한 `AppException`의 `message`는 영문 고정값이고 백엔드 한국어 detail은 `code`(RFC 7807 title) 필드에 담긴다. 따라서 `messageKey`/`code`로 분기 (한국어 message 매칭 금지)
- 코드 주석에 백엔드 `errorCode` 필드 도입 시 title 매칭 → 코드 매칭으로 교체하라는 TODO 명시

#### GAME_OVER 이벤트 유실 fallback (`GameOverGuard`)

딥링크 작업 중 발견된 게임 종료 처리 결함을 함께 수정했다.

- **파일**: `lib/features/game/presentation/helpers/game_over_guard.dart`, `pages/game_page.dart`, `providers/game_result_provider.dart`
- **변경 내용**:
  - GAME_OVER 이벤트를 놓친 채 재연결 시, 서버 상태 동기화가 400(`게임 진행 중 아님`)을 받으면 승패 모달 대신 **중립 종료 다이얼로그** 표시
  - 게임 결과 조회를 **전용 Dio**로 격리 — 전역 `AuthInterceptor`를 거치지 않게 해 결과 조회 401이 앱 전체 강제 로그아웃으로 번지는 것을 차단
  - 종료 후 불필요한 퇴장 API 호출 제거 (이미 서버 게임이 종료됨)
  - 자동 라우팅/sync/콜백을 막는 가드 로직을 순수 함수로 분리해 단위 테스트(80줄)로 명세화

**특이사항**: 게임 결과 통계는 부가 정보이므로, 해당 조회 실패는 `AsyncValue.error`로만 제한하고 전역 인증 흐름에 영향을 주지 않는다.
