# 감옥 구역 이탈 안내 문구 핀 모드 대응 (#456)

### 📌 작업 개요

감옥 설정 화면에서 감옥이 플레이그라운드를 벗어나면 표시되는 안내 문구("감옥이 플레이그라운드 범위를 벗어났어요")가 **원형 모드에서만** 나오고 핀(폴리곤) 모드에서는 나오지 않던 문제를 수정. 핀 모드 사용자는 완료 버튼이 비활성인 이유를 알 수 없었다.

단순히 조건을 뒤집는 것으로는 부족했다. 핀 모드는 검증 실패 사유가 3가지로 갈려서, 그대로 문구를 띄우면 핀을 1개만 찍은 순간부터 "범위를 벗어났어요"가 떠 오히려 혼란을 준다.

**커밋**: `687ee2ab fix : 감옥 구역 이탈 안내 문구가 핀 모드에 표시되지 않던 문제 #456`

---

### 🔍 문제 분석

안내 문구 조건이 `!_isPinMode`로 명시적으로 막혀 있었다.

```dart
// 검증 실패 안내 문구 (원형 모드 전용)
if (!_isPinMode && _isMapReady && !_isJailInsidePlayground())
  Padding(
    child: Text(
      _playgroundCenter == null
          ? l10n.errorPlaygroundFirst
          : l10n.errorJailOutsidePlayground,
      ...
```

두 모드 모두 완료 버튼은 정상적으로 비활성되지만(`_canComplete`), 핀 모드는 **왜 비활성인지 설명이 없었다.**

#### 핀 모드는 실패 사유가 3가지

`_isJailPolygonInsidePlayground()`가 `false`를 반환하는 경로가 셋이다.

| 상태 | 사용자 관점 |
| --- | --- |
| 플레이그라운드가 없거나 꼭짓점 3개 미만 | 선행 단계가 안 끝났다 |
| 감옥 꼭짓점 3개 미만 | **아직 그리는 중 — 오류가 아니다** |
| 3개 이상인데 플레이그라운드 밖 | 실제 이탈 |

원형 모드에는 두 번째 상태가 없다(지도가 준비되면 원은 항상 존재). 그래서 기존 조건을 핀 모드에 그대로 적용하면 첫 핀을 찍는 순간부터 이탈 경고가 떠버린다.

### ✅ 구현 내용

#### 두 모드 공통 문구 해석기 도입

- **파일**: `lib/features/session/presentation/pages/setup_prison_page.dart`
- **변경 내용**: `_validationMessage(l10n)` 추가. `null`을 반환하면 문구를 표시하지 않는다. 위젯 조건은 `if (validationMessage != null)` 한 줄로 단순화.
- **이유**: 모드별 분기를 위젯 트리에서 걷어내고 한 곳에 모아, 사유별 문구 선택 규칙을 한눈에 읽히게 하려는 목적.

```dart
/// 검증 실패 안내 문구 — null이면 표시하지 않는다
///
/// 완료 버튼이 비활성인 이유를 사용자에게 알려준다. 단 핀 모드에서 감옥 꼭짓점이
/// 아직 3개 미만인 상태는 그리는 중인 정상 상태이므로 이탈 경고를 띄우지 않는다.
String? _validationMessage(AppLocalizations l10n) {
  if (_isPinMode) {
    final playground = _playgroundPinPoints;
    if (playground == null ||
        playground.length < GameConfig.minPolygonVertexCount) {
      return l10n.errorPlaygroundFirst;
    }
    if (_pinPoints.length < GameConfig.minPolygonVertexCount) return null;
    return _isJailPolygonInsidePlayground()
        ? null
        : l10n.errorJailOutsidePlayground;
  }

  // 원형 모드: 지도 초기화 전에는 판정 자체가 불가
  if (!_isMapReady || _isJailInsidePlayground()) return null;
  return _playgroundCenter == null
      ? l10n.errorPlaygroundFirst
      : l10n.errorJailOutsidePlayground;
}
```

#### 표시 규칙

| 모드 | 상태 | 표시 |
| --- | --- | --- |
| 핀 | 플레이그라운드 미설정 | `플레이그라운드를 먼저 설정해주세요` |
| 핀 | 감옥 꼭짓점 3개 미만 | 표시 안 함 |
| 핀 | 3개 이상 + 이탈 | `감옥이 플레이그라운드 범위를 벗어났어요` |
| 원형 | 지도 초기화 전 | 표시 안 함 |
| 원형 | 플레이그라운드 미설정 | `플레이그라운드를 먼저 설정해주세요` |
| 원형 | 이탈 | `감옥이 플레이그라운드 범위를 벗어났어요` |

**특이사항**:

- **원형 모드 동작은 그대로 보존.** 기존 조건(`_isMapReady && !_isJailInsidePlayground()` → `_playgroundCenter` 유무로 문구 선택)을 해석기 안에서 동일하게 재현했다. 이번 변경으로 원형 사용자가 보는 화면은 바뀌지 않는다.
- **신규 문자열 없음.** 기존 ARB 키 `errorPlaygroundFirst`·`errorJailOutsidePlayground`를 재사용해 `flutter gen-l10n` 재실행이 필요하지 않다.
- **레이아웃 안전.** 지도가 `Expanded`를 차지하는 구조라 문구 한 줄이 늘어도 지도가 줄어들 뿐 오버플로가 나지 않는다.

- `dart format .` — 540파일 중 변경 0건

**테스트를 추가하지 않은 이유**

`setup_prison_page`는 `GoogleMap` 플랫폼 뷰 + Riverpod + 로컬 스토리지 + l10n + ScreenUtil이 얽혀 있고, 이 계열 페이지의 위젯 테스트 선례가 저장소에 없다. 문구 선택 규칙 15줄을 검증하려고 첫 사례를 만들면 규칙보다 프레임워크 배선을 검증하게 되고, 프로젝트 테스트 정책(framework glue는 테스트 생략)과도 어긋난다.

규칙을 잠그려면 판정을 `enum`을 반환하는 순수 함수로 분리해 위젯 없이 테스트할 수 있으나, 테스트를 위해 프로덕션 구조를 바꾸는 선택이라 이번에는 하지 않았다.

**수동 확인 필요**

1. 핀 모드에서 플레이그라운드 밖에 감옥 꼭짓점 3개 이상 → 빨간 안내 문구 표시
2. 핀 1~2개만 찍은 상태 → 문구 표시되지 않고 완료 버튼만 비활성
3. 감옥을 플레이그라운드 안으로 이동 → 문구 사라지고 완료 버튼 활성화
4. 원형 모드 → 기존과 동일하게 동작
5. 다크 모드(도둑 테마)에서 문구 가독성

### 📌 참고사항

작업 중 확인한 별개 사안으로, 이번 변경에는 포함하지 않았다.

- **감옥 폴리곤의 자기교차 검증 없음**: 플레이그라운드 설정 화면은 `isValidPolygon`으로 자기교차를 거르지만, 감옥 설정 화면의 `_isJailPolygonInsidePlayground()`는 포함 관계만 본다. `isPolygonInsidePolygon`은 감옥 변과 플레이그라운드 변의 교차를 검사하므로, 플레이그라운드 안에 완전히 들어간 나비 모양(자기교차) 감옥은 통과한다. 서버 측 기하 검증 여부도 확인 대기 중이라 함께 판단이 필요하다.
