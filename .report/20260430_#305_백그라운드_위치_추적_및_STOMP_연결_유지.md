# 백그라운드 위치 추적 및 STOMP 연결 유지

> 이슈 [#305](https://github.com/cops-and-robbers/cops-and-robbers-FE/issues/305)
> PR [#306](https://github.com/cops-and-robbers/cops-and-robbers-FE/pull/306)

## 📌 작업 개요

게임 진행 중 사용자가 화면을 끄거나 다른 앱으로 전환해도 도둑 위치 송신과 STOMP 게임 이벤트 수신이 끊기지 않도록 백그라운드 인프라 도입. 게임이 IN_PROGRESS 상태일 때만 활성화되고 종료 시 자동 정리한다. 백엔드 변경 없이 클라이언트만 수정하며, 위치 권한 격상(`ACCESS_BACKGROUND_LOCATION`/`AlwaysAndWhenInUse`) 없이 "사용 중에만 허용"으로 동작하도록 구성한다.

## 🎯 구현 목표

- Android: Foreground Service(`foregroundServiceType="location"`) + 영구 알림으로 OS 프로세스 종료 차단
- iOS: `UIBackgroundModes`에 `location` 모드 추가 + geolocator 백그라운드 옵션 활성화
- 백그라운드 인프라 라이프사이클 트리거: `GAME_START` STOMP 이벤트로 시작, `GAME_OVER` 또는 게임 화면 이탈로 종료
- 콜드 재시작 / 비정상 진입 케이스를 위한 재진입 가드 추가
- STOMP heartbeat + 라이프사이클 인지 재연결 백오프
- 일부 OEM(샤오미·삼성·화웨이·오포)의 공격적 배터리 정책 대응 — 배터리 최적화 강제 체크
- App Store / Play Store 정책 준수

## ✅ 구현 내용

### iOS 네이티브 — 백그라운드 위치 모드 활성화
- **파일**: `ios/Runner/Info.plist`, `lib/core/services/location/device_location_service.dart`
- **변경**:
  - `UIBackgroundModes`에 `location` 추가 (기존 `fetch`, `remote-notification` 유지)
  - `NSLocationAlwaysAndWhenInUseUsageDescription` 키 제거 (사용 안 함)
  - `NSLocationWhenInUseUsageDescription` 문구를 백그라운드 사용 명시 버전으로 업데이트
  - `DeviceLocationService`의 `LocationSettings`를 `AppleSettings`로 분기:
    - `allowBackgroundLocationUpdates: true`
    - `pauseLocationUpdatesAutomatically: false`
    - `activityType: ActivityType.otherNavigation`
    - `showBackgroundLocationIndicator: true`
- **이유**: iOS는 위 셋업만으로 OS가 위치 콜백 발생 시 프로세스 keep-alive 처리. 같은 프로세스에서 도는 STOMP 클라이언트도 자동 유지된다.

### Android 네이티브 — Foreground Service 도입
- **파일**: `android/app/src/main/AndroidManifest.xml`, `GameSessionForegroundService.kt`, `MainActivity.kt`
- **변경**:
  - 권한 추가: `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`, `POST_NOTIFICATIONS`
  - `<service android:name=".GameSessionForegroundService" foregroundServiceType="location" exported="false" />` 등록
  - `GameSessionForegroundService` Kotlin 클래스 작성 (~70줄):
    - 영구 알림(`IMPORTANCE_LOW`, `setOngoing(true)`) + `START_NOT_STICKY`
    - 알림 탭 시 `MainActivity` 진입하는 `PendingIntent`
  - `MainActivity`에 `cops_and_robbers/background_service` MethodChannel 핸들러 추가:
    - `start`, `stop`, `openAppSettings`, `isIgnoringBatteryOptimizations`
    - `openAppSettings`는 `Settings.ACTION_APPLICATION_DETAILS_SETTINGS` deep link
- **이유**: Android는 OS 정책상 영구 알림을 표시하는 FGS만이 백그라운드에서 프로세스 keep-alive 가능. STOMP/위치 코드는 main isolate에서 그대로 작동한다.

### Flutter 공통 — BackgroundService 추상화
- **파일**: `lib/core/services/background/background_service.dart`, `_android.dart`, `_ios.dart`, `_provider.dart`

  - iOS: 사실상 no-op (geolocator AppleSettings에 위임)
  - Riverpod `@Riverpod(keepAlive: true)` Provider로 플랫폼 분기
- **이유**: 호출 측 코드가 플랫폼 분기를 의식하지 않도록 단일 진입점 제공.

### Flutter 공통 — 위치 / 라이프사이클
- **파일**: `lib/core/services/lifecycle/app_lifecycle_service.dart`
- **변경**:
  - `enableKeepAlive()` / `disableKeepAlive()` API 추가
  - `enableKeepAlive` 호출 시 `WidgetsBindingObserver` 자동 등록(activate)

### Flutter 공통 — STOMP / 게임 이벤트 통합
- **파일**: `lib/core/network/websocket/base_stomp_datasource.dart`
  - `StompConfig`에 `heartbeatIncoming`, `heartbeatOutgoing` 각 10초 설정
  - **이유**: Android의 idle TCP 회수(~20초) 회피. STOMP 양방향 heartbeat은 newline 1바이트라 트래픽 부담 미미.
- **파일**: `lib/features/game/presentation/providers/game_event_provider.dart`

  - `GAME_OVER` 수신 시 `_deactivateBackgroundInfrastructure()` 호출 → BackgroundService stop + keep-alive OFF
  - 명시적 disconnect 경로 2곳에서도 동일 정리
  - 재연결 백오프에 `AppLifecycleService.isInBackground` 분기:
    - 백그라운드: `[0, 1, 2, 5, 5]` (즉시 시도부터)
    - 포그라운드: `[1, 2, 4, 8, 10]`
  - **이유**: iOS 백그라운드 wake 시간이 짧아 첫 재연결을 즉시 시도해야 wake 윈도우 내 복구 가능.

## 🔧 주요 변경사항 상세

### 백그라운드 인프라 라이프사이클 흐름

```
사용자 → 방 만들기/참여하기 버튼 탭
   ↓
위치 권한 체크 → 통과
   ↓
배터리 최적화 체크 (Android만) → 통과
   ↓
세션 생성/참여 → 대기실
   ↓
방장 게임 시작 → STOMP GAME_START 브로드캐스트
   ↓
모든 참가자: _activateBackgroundInfrastructure
   ├─ BackgroundService.start (Android FGS or iOS no-op)
   └─ AppLifecycleService.enableKeepAlive
   ↓
[게임 진행 중 — 백그라운드/포그라운드 무관 STOMP/위치 유지]
   ↓
GAME_OVER 수신 또는 사용자 게임 이탈
   ↓
_deactivateBackgroundInfrastructure
   ├─ BackgroundService.stop
   └─ AppLifecycleService.disableKeepAlive
```

특이사항:
- 위치 권한과 배터리 최적화는 **HomePage 진입점에서만 강제 체크** (위치 권한 패턴과 일관)
- 게임 진행 중에는 추가 다이얼로그 없음 (다이얼로그 폭격 방지)

### 라이프사이클 트리거 전략 (왜 STOMP 이벤트 기반인가)
서비스 start/stop 트리거를 **Flutter Lifecycle이 아닌 STOMP 이벤트 + 게임 화면 위젯 라이프사이클**로 두는 결정이 핵심이다. 이렇게 하면 Flutter Lifecycle observer 없이도 핵심 기능이 동작한다. observer는 보조 역할만 한다 — iOS keep-alive 타이머 ON/OFF, STOMP 재연결 백오프 분기.

### 재진입 가드 폴백 체인
LobbyStomp가 `GAME_START` 이벤트를 먼저 수신하여 화면을 전환하면, 이후에 구독을 시작하는 GameEventStomp는 해당 이벤트를 받지 못한다. `GameEventNotifier.gameStartTime`이 영원히 null로 남는 race를 방어하기 위해 가드는 다음 순서로 게임 시작 시각을 확인한다:

1. `GameEventNotifier.gameStartTime` (정상 GAME_START 수신 시)
2. `participantInfo.gameStartTime` (lobby/API 응답에 포함된 ISO 문자열)

둘 중 하나라도 존재하면 IN_PROGRESS로 판정하여 백그라운드 인프라를 활성화한다.

### Android 14+ FGS 권한 분리
Android 14에서는 `FOREGROUND_SERVICE_LOCATION`이 별도 권한으로 분리되었다. 매니페스트에 이 권한을 명시하지 않으면 `startForegroundService` 호출 시 `SecurityException`으로 즉시 크래시한다. 본 PR에서 권한을 추가하여 14+ 단말 호환을 확보했다.

### ACCESS_BACKGROUND_LOCATION 미사용
FGS의 `foregroundServiceType="location"` 사용 시 `ACCESS_BACKGROUND_LOCATION` 권한은 불필요하다(Android 공식 문서 명시). 권한을 추가하면 Play Store 심사에서 background location justification 별도 제출이 필요해 거꾸로 비용이 발생한다. "사용 중에만 허용" 권한만으로 백그라운드 위치 동작을 확보한다.

### Optimistic Update 패턴
`BackgroundServiceAndroid.start/stop`은 `_isRunning` 상태를 await 이전에 선반영하고 실패 시 롤백한다. 게임 화면 진입 직후 즉시 뒤로가기 같은 빠른 라이프사이클 전환에서 start가 in-flight일 때 stop이 호출되어 멱등 가드가 잘못 빠져나가는 race를 차단한다.

### START_NOT_STICKY 채택
FGS는 메인 앱 프로세스에서 동작하므로 OS가 메모리 부족으로 FGS를 죽이는 시점에 앱 프로세스도 함께 사망한다. `START_STICKY`로 FGS만 부활시켜도 Flutter 측이 죽은 상태라 STOMP/위치 추적이 동작하지 않아 "게임 진행 중" 알림만 거짓으로 남는 문제가 발생한다. `START_NOT_STICKY`로 명시하여 이 케이스를 회피한다.

### iOS 백그라운드 알림 미발화 fix
- **파일**: `lib/core/services/lifecycle/app_lifecycle_service.dart`, `lib/features/game/presentation/pages/game_page.dart`
- `enableKeepAlive()`가 `_isActive`를 확인하여 `activate()` 자동 호출
- 재진입 가드를 `participantInfo.gameStartTime` 폴백 추가
- **이유**: `WidgetsBindingObserver` 미등록 시 `didChangeAppLifecycleState`가 발화 안 돼 `isInBackground`가 영원히 false → keep-alive 타이머 / STOMP 백그라운드 백오프 작동 안 함. LobbyStomp가 GAME_START을 먼저 가로채는 race condition도 함께 보강.

## 🧹 시도 후 제거된 변경

### iOS LocalNotification — 시도 후 제거
백그라운드에서 `Vibration.vibrate()`가 OS에 의해 silently 차단되는 이슈 확인 후 LocalNotification 도입 시도. 그러나 사용자 결정으로 향후 서버 푸시(FCM/APNs)로 대체하기로 하여 클라이언트 측 LocalNotification 코드는 revert. 백엔드 작업 시점에 다시 구현 예정.

### WAKE_LOCK + WIFI_LOCK — 시도 후 제거
Galaxy 화면 잠금 시 STOMP 끊김 발생 → DNS 실패 로그 확인 → WAKE_LOCK + WIFI_LOCK 추가로 해결 시도. 그러나 매뉴얼 테스트 결과 진짜 원인은 Samsung "배터리 최적화" 설정이었고, 사용자가 "제한 없음" 설정 후 lock 없이도 정상 작동 확인. lock 코드는 revert하고 강제 체크 다이얼로그(C2)로 사용자 안내 강화.

### 배터리 정보성 다이얼로그 — 강제 체크로 격상되며 제거
초기 PR에는 첫 게임 진입 시 1회 한정 정보성 다이얼로그(`GameStartNoticeFlow`: 배터리 최적화 안내 + 배터리 영향 안내)를 노출했지만, OEM 단말 안정성 확보를 위해 강제 체크 방식으로 격상하면서 제거. 관련 튜토리얼 키(`batteryOptNotice`, `batteryImpactNotice`)도 함께 제거.

- `UIBackgroundModes`에 `location`만 추가 (VoIP/Audio 등 부적절한 모드 사용 X)
- `NSLocationWhenInUseUsageDescription` 문구에 백그라운드 사용 명시 기재
- 자동 리다이렉트 X (사용자 명시적 [설정으로 이동] 탭에 의해서만 호출) — Guideline 5.1.1(iv) 준수

### 알려진 한계
- 사용자 강제 종료(swipe-away) 시 게임 한 판 망함 — 비목표
- 활성 게임 조회용 신규 백엔드 API 없음 (기존 STOMP 채널 그대로 사용)
- Samsung "절전 앱/심층 절전 앱" 추가 레이어는 표준 API로 감지 불가 (API true 반환해도 OEM 정책으로 잠들 수 있음)
- iOS "저전력 모드" 켜면 백그라운드 동작 일부 제한 가능
