### 📌 작업 개요
게임 생성 화면의 숫자 키패드에서, 마지막 줄(0 / 지우기) 아래로 홈 인디케이터 자리를 채우는 여백이 iOS에서 필요 이상으로 넓던 문제 수정

**보고서 파일**: `.report/20260904_게임생성_숫자키패드_하단여백_축소.md`

### 🔍 문제 분석
`NumberPad`는 하단 세이프 에어리어(홈 인디케이터)까지 자기 배경색으로 채우기 위해 `MediaQuery.viewPaddingOf(context).bottom`만큼 컨테이너 높이·하단 패딩을 늘린다(#539, LSN-0048 계약 — 화면 쪽 `SafeArea`는 `bottom: false`로 풀고 위젯이 인셋을 스스로 채운다). 이 인셋 값을 그대로 다 쓰다 보니, 마지막 줄 키 아래 남는 띠가 시각적으로 필요 이상으로 넓어 보였다.

같은 문제를 이미 겪은 `app_bottom_nav.dart`는 인셋에서 일정량(`AppSpacing.vertical18`)을 덜어내고 0 이하로는 내려가지 않게 clamp하는 방식으로 해결해 둔 전례가 있었다.

### ✅ 구현 내용

#### 플랫폼별 인셋 축소
- **파일**: `lib/core/widgets/inputs/number_pad.dart`
- **변경 내용**: iOS에서만 `(deviceBottomInset - AppSpacing.vertical18).clamp(0.0, double.infinity)`로 인셋을 줄여 사용. 안드로이드는 기존 인셋을 그대로 둠
- **이유**: 안드로이드는 제스처 인셋이 없거나 작은 기기가 많아 그대로 덜어내면 0으로 clamp되어 버튼이 시스템 내비게이션 바에 너무 붙을 수 있다 — `app_bottom_nav.dart`가 안드로이드에 `androidExtra`를 더해주는 것과 반대 방향의 같은 이유. iOS만 줄이는 쪽이 더 단순하고 안전해 이 화면에서는 안드로이드는 그대로 뒀다

### 🔧 주요 변경사항 상세

#### 인셋 계산
```dart
final deviceBottomInset = MediaQuery.viewPaddingOf(context).bottom;
final bottomInset = Theme.of(context).platform == TargetPlatform.iOS
    ? (deviceBottomInset - AppSpacing.vertical18).clamp(0.0, double.infinity)
    : deviceBottomInset;
```
키 그리드·컨테이너 높이 계산(`361.h + bottomInset`)은 그대로 두고, 이 값만 바꿔 배경이 채우는 인셋 폭만 줄인다.

**특이사항**:
- 인셋이 0인 기기(구형 홈버튼 기기 등)에서는 변화 없음 — `clamp(0.0, ...)`가 하한을 보장
- 사용처는 `basic_settings_form.dart`(게임 생성) · `game_settings_edit_page.dart`(설정 수정) 두 곳, 둘 다 이 위젯을 그대로 재사용하므로 별도 수정 불필요
