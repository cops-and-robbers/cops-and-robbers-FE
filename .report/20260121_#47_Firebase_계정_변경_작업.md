### 4. Firebase API 키 에러 처리 추가 (보안 강화)

#### 파일: `lib/features/auth/domain/utils/firebase_auth_error_handler.dart`
- **변경 내용**: Firebase API 키 설정 오류 감지 및 처리 로직 추가
- **추가된 기능**:
  1. **에러 감지 로직**:
     - `internal-error` 중 `API_KEY_INVALID` reason 자동 감지
     - 커스텀 에러 코드 `firebase-api-key-invalid` 할당

  2. **사용자 친화적 메시지**:
     - 일반 사용자: "Firebase 설정에 문제가 있습니다. 잠시 후 다시 시도해주세요."
     - 기술 용어 회피, 재시도 유도

  3. **개발자 디버깅 정보** (kDebugMode에서만):
     - Firebase Console 링크
     - 설정 파일 경로 안내 (android/app/google-services.json, ios/Runner/GoogleService-Info.plist)
     - 조치 방법 상세 가이드

**구현 세부사항**:
```dart
// API 키 에러 감지 로직
if (e.code == 'internal-error' && _isApiKeyError(e)) {
  errorCode = 'firebase-api-key-invalid';

  // 개발 모드에서만 상세 디버그 정보 출력
  if (kDebugMode) {
    debugPrint('🔥 Firebase API Key 에러 감지');
    debugPrint('  - Firebase Console 확인');
    debugPrint('  - google-services.json 재다운로드');
    debugPrint('  - GoogleService-Info.plist 재다운로드');
  }
}

// 헬퍼 함수
static bool _isApiKeyError(FirebaseAuthException e) {
  final message = e.message?.toLowerCase() ?? '';
  return message.contains('api key') || message.contains('api_key_invalid');
}
```

**보안 고려사항**:
- 프로덕션 환경에서는 민감한 정보 노출 방지 (`kDebugMode` 플래그)
- 사용자에게는 간단한 메시지만 표시
- 원본 Exception 정보는 `originalException` 필드에 보존 (에러 리포팅 가능)

## 🔧 주요 변경사항 상세

### Android Firebase 설정
- Firebase Console에서 새 프로젝트 생성 후 `google-services.json` 다운로드하여 교체
- SHA-1 인증서 지문 Firebase Console에 등록 (Google Sign-In 필수)
- OAuth 2.0 Client ID 3개 자동 생성:
  - Android 앱
  - 웹 앱 (Firebase Console용)
  - iOS 앱 (Cross-platform 지원)

### iOS Firebase 설정
- Firebase Console에서 iOS 앱 추가 후 `GoogleService-Info.plist` 다운로드하여 교체
- Bundle ID 일치 확인: `com.elipair.copsandrobbers`
- REVERSED_CLIENT_ID를 `Info.plist`의 URL Scheme에 동기화
- Apple Sign-In 설정 유지 (`Runner.entitlements`)

### API 키 에러 처리
- Clean Architecture 패턴 준수: Domain Layer에서 에러 처리
- Firebase Auth의 `internal-error` 중 API 키 관련 에러만 선별 감지
- 기존 에러 처리 흐름과 자연스럽게 통합 (AuthNotifier 세션 정리 로직 활용)

## 📌 참고사항 및 주의사항

### ⚠️ 중요 체크리스트

1. **Firebase Console 설정 확인**:
   - ✅ Android 앱 SHA-1 인증서 지문 등록됨
   - ✅ iOS 앱 Bundle ID 등록됨
   - ✅ Google Sign-In 제공업체 활성화됨
   - ✅ Apple Sign-In 제공업체 활성화됨 (iOS)

2. **환경 변수 재설정 불필요**:
   - `.env` 파일의 `API_BASE_URL`, `WS_URL` 등은 백엔드 설정으로 Firebase 계정 변경과 무관
   - Firebase 설정은 모두 네이티브 설정 파일(`google-services.json`, `GoogleService-Info.plist`)에 포함

3. **Git 보안 주의**:
   - ⚠️ `google-services.json`과 `GoogleService-Info.plist`에 API 키 포함
   - 현재 `.gitignore`에 포함되지 않아 Git에 추적됨
   - **Public 저장소인 경우 보안 위험** 존재
   - 권장 사항: Private 저장소 유지 또는 `.gitignore`에 추가 고려

4. **CI/CD 파이프라인**:
   - GitHub Actions 등 CI/CD 사용 시 Firebase 설정 파일을 Secrets로 관리해야 할 수 있음
   - 현재는 Git에 포함되어 있어 별도 Secrets 설정 불필요

5. **API 키 보안 강화**:
   - Firebase Console > 설정 > API 제한 설정 권장:
     - Android: SHA-1 인증서 제한
     - iOS: Bundle ID 제한
     - 웹: 도메인 제한 (해당 시)

### 🔄 앱 삭제 후 재설치 시 자동 로그인 관련

**현상**: 앱 삭제 후 재설치해도 로그인 상태 유지됨

**원인**:
- Firebase Auth가 iOS Keychain / Android Keystore에 세션 저장
- 이 저장소는 앱 삭제 후에도 데이터 유지 (OS 수준 보안 영역)
- 앱 재설치 시 Firebase Auth가 자동으로 세션 복원

**대응**:
- 이는 Firebase Auth의 **정상 동작**이며, 대부분의 앱(카카오톡, 네이버 등)도 동일하게 작동
- 사용자 경험 향상을 위해 현재 상태 유지 권장
- 완전 초기화가 필요한 경우 사용자가 명시적으로 로그아웃 후 삭제하도록 안내
