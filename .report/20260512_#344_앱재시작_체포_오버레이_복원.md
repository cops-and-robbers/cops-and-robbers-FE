### 📌 작업 개요

체포(JAILED) 상태에서 앱이 강제 종료된 뒤 다시 실행되면 `ArrestLockOverlay`가 나타나지 않아, 수감된 도둑이 지도/AppBar/우측 버튼을 그대로 조작할 수 있는 룰 위반 상황이 발생하던 버그를 수정한다. 원인은 STOMP `connected` 핸들러에서 서버 참가자 상태를 동기화하는 `_syncGameStateOnReconnect()` 호출이 `_hasGameEventConnectedOnce` 가드 안쪽에 묶여 있어, "최초 연결" 단 한 번에는 동기화가 실행되지 않았다는 점이다. 가드를 해당 호출 바깥으로 이동시켜 콜드 재시작 후 첫 connected 이벤트에서도 서버 JAILED 상태를 반영하도록 보정했다.

### 🔍 문제 분석

- `GameEventNotifier.arrestedParticipantIds`는 STOMP `ARREST` 이벤트 수신 시에만 채워지는 인메모리 상태로, 앱 프로세스가 종료되면 사라진다.
- 앱 재시작 후 게임 화면으로 복귀하면 GameEventStomp가 새로 연결되지만, 이미 발생한 ARREST 이벤트는 서버가 재전송하지 않는다. 따라서 `arrestedParticipantIds`는 빈 Set 상태로 시작한다.
- `game_page.dart`의 `isArrestedNow` 셀렉터는 `arrestedParticipantIds.contains(myId)` 기준이므로 위 상태에서는 `false`가 되어 `ArrestLockOverlay`가 렌더링되지 않는다.
- 원래 의도는 "재연결 시 서버 참가자 목록을 다시 가져와 보정"하는 `_syncGameStateOnReconnect()` 가 이 역할을 맡는 것이었으나, 해당 호출이 `if (_hasGameEventConnectedOnce)` 안쪽에 위치해 있었다. `_hasGameEventConnectedOnce`는 동일 핸들러의 뒷부분에서 비로소 `true`가 되기 때문에, 콜드 재시작 후 최초 `connected`에서는 sync가 한 번도 실행되지 않았다.
- 결과적으로 "끊김 → 재연결" 시나리오는 정상 보정되었지만, "강제 종료 → 재진입" 시나리오에서는 체포 상태가 영영 복원되지 않는 사각지대가 존재했다.

### ✅ 구현 내용

#### 게임 이벤트 STOMP `connected` 핸들러의 초기 연결 가드 제거

- **파일**: `lib/features/game/presentation/pages/game_page.dart`
- **변경 내용**: `ref.listen(gameEventNotifierProvider.select((s) => s.connectionState), ...)` 핸들러 내 `connected` 분기에서 `_syncGameStateOnReconnect()` 호출을 감싸던 `if (_hasGameEventConnectedOnce)` 조건을 제거. 이제 prev≠connected→next=connected 전이가 일어나는 모든 시점(재연결 + 콜드 재시작 후 첫 연결)에서 sync가 수행된다.
- **이유**: `_hasGameEventConnectedOnce`는 핸들러의 후반부에서 `next == StompConnectionState.connected` 조건으로 `true`가 되므로, sync 호출 시점에는 아직 `false`다. 따라서 최초 connected에서는 sync가 절대 일어나지 않아, JAILED 상태가 `arrestedParticipantIds`에 반영될 기회 자체가 없었다. 가드를 제거하면 서버 참가자 목록(`fetchGameParticipantsProvider`) 응답을 기반으로 `syncFromParticipants(arrestedIds, remainingThieves)`가 호출되고, 이 결과가 `isArrestedNow` 셀렉터에 즉시 반영되어 `ArrestLockOverlay`가 자동 노출된다.

#### `ArrestLockOverlay` 본문 텍스트 색상 톤 조정

- **파일**: `lib/features/game/presentation/widgets/arrest_lock_overlay.dart`
- **변경 내용**: 모달 본문 안내 문구("체포되어 있는 동안에는…")의 텍스트 색상을 `AppColors.black300` → `AppColors.black400`로 변경.
- **이유**: 검은 모달 카드 배경 위에서 본문 가독성이 약하다는 후속 디자인 검토에 따른 톤 보정. 본 이슈와 직접 인과관계는 없지만 동일 위젯을 만지는 커밋 한 곳으로 묶음.

### 🔧 주요 변경사항 상세

#### `connected` 핸들러 변경 전/후 비교

변경 전 — `_syncGameStateOnReconnect()`가 가드 안쪽:

```dart
if (next == StompConnectionState.connected &&
    prev != StompConnectionState.connected) {
  if (_hasGameEventConnectedOnce) {
    unawaited(_syncGameStateOnReconnect()); // 최초 connected에서는 false → 미실행
  }
  // …도둑 팀 위치 재전송…
}

if (next == StompConnectionState.connected) {
  _hasGameEventConnectedOnce = true; // 이 시점 이후에야 true
}
```

변경 후 — sync는 가드 바깥, 모달 표시 가드는 그대로 유지:

```dart
if (next == StompConnectionState.connected &&
    prev != StompConnectionState.connected) {
  // 끊김 구간 + 앱 재시작 후 첫 진입에서 누락된 체포·탈옥 상태를 서버 조회로 보정.
  // 최초 connected에서도 호출해, 재실행 시 JAILED 상태가 ArrestLockOverlay에 반영되도록 한다.
  unawaited(_syncGameStateOnReconnect()); // 모든 connected 전이에서 실행
  // …도둑 팀 위치 재전송…
}

if (next == StompConnectionState.connected) {
  _hasGameEventConnectedOnce = true;
}

if (!_hasGameEventConnectedOnce || widget.isDummy) return;
// 이하 disconnected/error 모달 표시 로직은 여전히 “2회차 이후”에만 작동
```

#### `_syncGameStateOnReconnect()` 흐름 (수정 없이 그대로 활용)

이미 존재하던 동기화 로직을 그대로 재사용하는 구조다. 핵심 동작은 다음과 같다.

1. sync 직전 `arrestedParticipantIds` / `escapedParticipantIds` 스냅샷 저장
2. `ref.refresh(fetchGameParticipantsProvider(_gameId).future)`로 서버 참가자 목록 강제 재조회 (autoDispose이므로 refresh 필수)
3. 서버 응답의 `JAILED` 참가자 집합을 base로 잡고, sync 요청~응답 사이에 STOMP가 추가로 반영한 신규 체포/탈옥 delta를 layer하여 최종 `finalArrested` 계산
4. 동일 원칙으로 `remainingThieves`를 `[0, 전체 도둑 수]` 범위로 clamp하여 산출
5. `gameEventNotifierProvider.notifier.syncFromParticipants(arrestedIds, remainingThieves)`로 일괄 반영

이 로직 자체는 변경하지 않았다. 단지 **호출 진입점만 한 단계 풀어주었을 뿐**이며, 앱 재시작 후 최초 connected에서도 동일한 보정 경로를 타게 된 것이 이번 수정의 본질이다.

#### `_hasGameEventConnectedOnce` 가드의 잔존 의미

`_hasGameEventConnectedOnce`는 이번 수정 후에도 핸들러 뒷부분에서 그대로 유지된다. 그 역할은 "초기 연결 자체가 실패해서 disconnected/error로 진입하는 경우 재연결 모달을 띄우지 않는다"는 UX 가드이며, sync 호출과는 책임이 다르다. 두 책임을 한 변수에 묶어두었던 것이 이번 버그의 직접 원인이었으므로, sync 책임만 가드 바깥으로 분리한 형태다.

**특이사항**:

- `_syncGameStateOnReconnect()`는 내부에 `try-catch`를 두고 실패 시 `debugPrint`만 남기고 무시한다. 따라서 가드를 제거해도 추가 에러 전파 위험은 없다.
- `widget.isDummy` 케이스는 메서드 첫 줄(`if (widget.isDummy || !mounted) return;`)에서 일찍 빠져나오므로, 더미 모드에서도 부작용이 없다.
- 가드를 풀면서 sync HTTP 요청이 게임 진입 직후 한 번 더 실행되지만, 동일 메서드를 통한 호출이라 추가 비용은 `fetchGameParticipantsProvider` 1회 refresh 수준이다. 도둑 팀 위치 재전송은 `await`하지 않으므로 위치 송신 지연도 없다.
