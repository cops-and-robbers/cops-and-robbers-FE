# 기능 구현 보고서 — 채팅방 고정 공지(고정 채팅 배너)

## 📌 작업 개요

- **이슈**: #534 채팅방 고정 공지(고정 채팅 배너) 등록/수정/삭제, 실시간 푸시 연동
- **범위**: 모임 채팅방에 방장이 공지 1건을 등록·수정·삭제하는 기능의 UI·실시간(STOMP)·에러 매핑 구현
- **선행 커밋**: API 명세 동기화, 다국어 문구 추가, 라우터 경로 추가가 이미 반영된 상태에서 이어지는 마무리 작업

## 🎯 구현 목표

- 채팅방 상세에서 고정 공지를 조회·작성·수정·삭제할 수 있는 화면 제공 (방장만 등록·수정·삭제 가능)
- 공지 변경을 실시간으로 감지하는 STOMP 채널 연동 (배너/대화 채널과 분리)
- 서버 에러 코드(`FORBIDDEN_NOT_CHAT_PIN_HOST`, `CHAT_PIN_NOT_FOUND` 등)의 사용자 노출 메시지 매핑

## 🔧 주요 변경사항 상세

- **채널 분리 구조**: 공지 배너는 `/subscribe/community/{postId}/chat/pin`, 대화는 `/subscribe/community/{postId}/chat`로 분리. 두 구독은 방 진입/퇴장 시 항상 함께 걸리고 함께 해제된다 (`subscribeRoom`/`unsubscribeRoom`).
- **payload 미해석 설계**: 공지 채널 프레임은 내용을 읽지 않고 "구독 중이던 방 번호"만 스트림(`onPinChanged`)으로 흘린다. 서버가 프레임 필드명을 바꿔도 깨지지 않도록 방어적으로 설계했고, 실제 내용은 소비자가 REST(`GET /{postId}/chat/pin`)로 재조회한다.
- **공지 없음은 예외가 아니라 값**: `CommunityChatPinResponseModel`은 공지가 없을 때도 200 응답을 받으며 전 필드가 null로 온다 — `data == null` 분기로 화면에서 처리.
- **등록/수정 단일 화면**: `CommunityChatNoticeEditPage`가 `initialContent`로 등록/수정을 분기해 화면 중복을 없앴다.
- **에러 코드 분리**: 채팅방 강퇴 권한(`FORBIDDEN_NOT_CHAT_HOST`)과 공지 권한(`FORBIDDEN_NOT_CHAT_PIN_HOST`)을 같은 문구로 묶지 않고 별도 매핑을 유지해 방장이 아닌 사용자가 잘못된 안내를 받지 않도록 함.

## 🧪 테스트 및 검증

- `test/features/community/data/datasources/community_chat_stomp_datasource_test.dart`에 공지 채널 관련 테스트 5건 확인:
  - 공지 채널 URL 형식 검증
  - 방 진입 시 공지 채널이 알림/방 채널과 함께 구독되는지
  - 재연결 시 공지 채널이 재구독되는지
  - 공지 프레임 수신 시 방 번호가 스트림으로 전달되는지
  - 방 퇴장 후에는 공지 채널 구독 해제 및 이벤트 미전달 확인
- 테스트는 실 소켓 대신 시스템 경계(`StompClient`)만 페이크로 대체하는 Classist 스타일을 따름 (`_FakeStompClient`, `_TestDatasource`)
- 본 세션에서 `flutter test`/`flutter analyze` 실행 로그는 별도로 확보하지 않음 — 필요 시 추가 검증 권장
