# 버그 수정 보고서 — 숫자 키패드 아래 세이프 에어리어 흰 띠

## 📌 작업 개요

- **이슈**: #539 숫자 키패드 아래 세이프 에어리어가 흰색으로 비어 보임
- **범위**: 공용 키패드 위젯 1개 + 키패드를 쓰는 화면 2개
- **수정 파일**: `number_pad.dart`, `session_creation_flow_page.dart`, `game_settings_edit_page.dart`

## 🐞 문제 상황

방 생성 **기본 정보를 설정해요** 화면에서 숫자 키패드 아래, 홈 인디케이터 주변에 키패드와 색이 다른 흰 띠가 보인다 (iOS 실기기 제보). 대기실 설정 수정 화면도 같은 구조라 다크 테마에서 톤이 끊긴다.

## 🔍 원인 분석

키패드 화면들은 `SafeArea`(bottom 기본 true) 안에 키패드를 두고 있다. SafeArea가 하단 인셋만큼 body를 위로 밀어올리면, 비워진 자리에는 **Scaffold의 배경색**이 노출된다.

- 방 생성 화면: Scaffold `white` vs 키패드 `background`(연회색) → 흰 띠가 도드라짐
- 설정 수정 화면(다크): Scaffold `black900` vs 키패드 `black800` → 덜 튀지만 동일한 끊김

## ✅ 수정 내용

커스텀 키패드를 쓰는 앱들의 관례대로, **키패드가 세이프 에어리어까지 자기 배경색으로 이어 채우게** 했다.

| 파일 | 변경 내용 | 이유 |
|---|---|---|
| `lib/core/widgets/inputs/number_pad.dart` | `MediaQuery.viewPaddingOf(context).bottom`만큼 높이와 하단 패딩을 늘려 배경색으로 채움 | 키 그리드 크기는 그대로 두고 배경만 인셋 영역까지 연장. `viewPaddingOf`는 SafeArea 내부에서도 기기 인셋을 그대로 돌려주므로 위젯이 스스로 채울 수 있다 |
| `lib/features/session/presentation/pages/session_creation_flow_page.dart` | `SafeArea`의 bottom을 기본 정보 단계에서만 해제 (`bottom: _phase != _CreationPhase.basic`) | 안 풀면 인셋이 이중 적용된다. 확인(confirm) 단계는 하단이 일반 버튼이라 SafeArea가 계속 필요해 단계별로 분기 |
| `lib/features/session/presentation/pages/game_settings_edit_page.dart` | `SafeArea(bottom: false)` | 이 화면은 하단이 항상 키패드라 전체 해제 |

## 🧪 테스트 및 검증

- 에뮬레이터(Android API 36.1, 제스처 내비게이션 = 하단 인셋 존재) 디버그 빌드로 방 생성 플로우를 구역 → 감옥 → 기본 정보까지 진행
- 기본 정보 화면에서 키패드 배경색이 화면 맨 아래(홈 인디케이터 뒤)까지 끊김 없이 이어지는 것 확인
- `dart format` 변경 없음, `flutter analyze` 수정 파일 3개 No issues

## 📌 참고사항

- 하단 인셋이 0인 기기(3버튼 내비게이션 일부, 구형 기기)에서는 수정 전후가 완전히 동일하다.
- `NumberPad` 사용처는 위 두 화면(방 생성의 `basic_settings_form.dart` 경유 포함)이 전부라 다른 화면 영향은 없다.
