### 📌 작업 개요
채팅 신고 기능의 백엔드 API 연동과 설정 페이지 UI를 디자인 시안에 맞게 카테고리 그룹화 적용

**보고서 파일**: `.report/20260409_#233_신고_API_연동_및_설정_페이지_UI_변경.md`

### 🎯 구현 목표
- 기존 클라이언트 전용 신고 UI를 실제 `POST /api/report/chat` API와 연동
- 설정 페이지를 계정, 앱 설정, 이용 안내, 기타 4개 카테고리로 그룹화

---

### ✅ 구현 내용

#### 1. 채팅 신고 API 연동 (Report Feature — Clean Architecture)

신고 기능을 독립 feature로 분리하여 Clean Architecture 3계층 구조로 구현

- **`report/data/models/report_request_model.dart`**: Freezed 기반 신고 요청 DTO (gameId, reportedParticipantId, messageContent, reportType, etcReason)
- **`report/data/datasources/report_remote_datasource.dart`**: Retrofit `POST /api/report/chat` 엔드포인트
- **`report/data/repositories/report_repository_impl.dart`**: DioExceptionHandler로 에러 처리 (중복 신고 409, 본인 신고 400 등 서버 에러 메시지 전달)
- **`report/domain/repositories/report_repository.dart`**: Repository 추상 인터페이스
- **`report/domain/constants/report_categories.dart`**: ReportCategory enum (chat feature에서 이동). `apiType` 필드 추가하여 enum → API reportType 매핑
- **`report/presentation/providers/report_provider.dart`**: Riverpod provider (DataSource → Repository 연결)

#### 2. ChatContextMenu 실제 API 호출 연결

- **`chat/presentation/widgets/chat_context_menu.dart`**: `onReport` 콜백 파라미터 추가. 기존 TODO 2곳(일반 카테고리 신고, 기타 직접 작성 신고)을 실제 API 호출로 교체. 성공 시 "신고가 접수되었어요" 스낵바, 실패 시 서버 에러 메시지 스낵바 표시
- **`chat/presentation/widgets/chat_overlay.dart`**: `onReport` 콜백에 `reportRepositoryProvider` 연결. gameId와 participantId를 전달하여 API 호출

#### 3. 설정 페이지 카테고리 그룹화

- **`settings/presentation/pages/settings_page.dart`**: 전면 리팩토링
  - 메뉴를 4개 카테고리로 그룹화: **계정** (닉네임 변경), **앱 설정** (알림, 위치 권한), **이용 안내** (앱 버전, 버그 제보, 이용약관, 개인정보 처리방침), **기타** (로그아웃, 회원 탈퇴)
  - 카테고리 헤더: `paragraph14Semibold` + `black600`
  - 카테고리 간 구분선: `h=4`, 화면 전체 너비, `black100`
  - 항목 간 구분선: `h=1`, 좌우 패딩 20px, `black100`
  - 디바이더-카테고리 헤더 간격: 24px
  - 닉네임 변경: 우측 `>` 화살표 (`icon_previous.svg` 180도 회전, `black300`, 20px)
  - 앱 버전: 이용 안내 섹션 내 Row 배치 (좌: "앱 버전", 우: "v1.x.x")
  - 인라인 람다 → 메서드 추출로 가독성 개선

#### 4. 기반 작업

- **`core/constants/api_endpoints.dart`**: `reportChat` 엔드포인트 상수 추가
- **`report_categories.dart`**: `apiType` 필드 추가 (bait→FISHING, abuse→VERBAL_ABUSE, impersonation→IMPERSONATION, spam→SPAM, exploit→CHEATING, teamSabotage→DEMORALIZATION, other→ETC)

### 🔧 주요 변경사항 상세

#### 에러 처리 흐름
API 호출 실패 시 `DioExceptionHandler.handle(e)`가 서버 응답의 RFC 7807 형식(title, detail)을 파싱하여 `AppException.message`로 변환. ChatContextMenu에서 이 메시지를 빨간색 스낵바로 표시

**특이사항**:
- 409 중복 신고: "해당 게임에서 이미 신고한 사용자입니다." 메시지 표시
- 400 본인 신고: "본인을 신고할 수 없습니다." 메시지 표시
- `callerContext.mounted` 체크로 위젯 해제 후 스낵바 표시 방지

#### ReportCategory cross-feature 의존성 정리
`ReportCategory` enum을 `chat/domain/constants/`에서 `report/domain/constants/`로 이동. chat feature에서 report의 도메인 상수를 참조하는 방향으로 의존성 정리 (코드 리뷰 반영)
