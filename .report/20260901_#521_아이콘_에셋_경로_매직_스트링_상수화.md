### 📌 작업 개요

`assets/icons/...` SVG 경로가 상수 없이 코드에 직접 박혀 있던 것을 `AppIcons` 상수 클래스와 경로 생성 함수로 일원화. 동작 변화 없는 순수 리팩토링이며, 상수화로 사용 여부 판정이 정확해지면서 미사용 아이콘 6개를 함께 정리했다.

**보고서 파일**: `.report/20260901_#521_아이콘_에셋_경로_매직_스트링_상수화.md`

### 🎯 구현 목표

- 경로 리터럴을 `lib/core/constants/app_icons.dart` 한 곳으로 모아 오타를 컴파일 타임에 잡는다
- 보간·문자열 연결로 만들던 경로를 생성 함수로 통일해, 완성된 파일명으로 검색되게 만든다
- 리터럴이 다시 흩어지지 않도록 회귀 방지 장치를 남긴다

### 🔍 문제 분석

착수 전 전수 측정 결과다.

| 항목 | 수치 |
|---|---|
| `assets/icons/` 참조 파일 | 57개 |
| 참조 줄 | 161줄 (코드 156 + DartDoc 5) |
| 정적 경로 종수 | 88종 |
| 보간·문자열 연결 지점 | 6곳 |

파생 문제 세 가지였다.

**1. 오타가 컴파일 타임에 안 잡힌다.** 빌드는 통과하고 그 화면을 열어야 아이콘이 사라진 걸 안다.

**2. 파일명이 이미 깨져 있는데 고치기 비싸다.** `icon_wrong mark.svg`·`icon_check mark.svg`(파일명에 공백), `icon_settiing_2.svg`(오타), `Loudspeaker.svg`·`Top_hat.svg`·`youtube.svg`(`icon_` 접두어 이탈·대소문자 혼재). 이름을 바꾸려면 57개 파일을 전수 검색해야 했다.

**3. 에셋 사용 여부를 정적으로 판정할 수 없다.** 핑 마커 경로 하나가 세 곳에서 서로 다른 방식으로 만들어졌다.

| 위치 | 만드는 방식 |
|---|---|
| `ping_marker_factory.dart:52` | 보간 |
| `test_widget_page.dart:635` | 보간 (변수명만 다름) |
| `in_game_tutorial_page.dart:409` | 문자열 3줄 연결 |

완성된 파일명(`icon_ping_found_marker_darkmode.svg`)으로 검색하면 세 곳 다 나오지 않았다. 그래서 `assets/icons/` 109개 중 21개가 단순 검색으로 미참조로 나왔지만 그중 10개는 실제 사용 중이었다.

### ✅ 구현 내용

#### AppIcons 상수 클래스 신설

- **파일**: `lib/core/constants/app_icons.dart` (신규)
- **변경 내용**: `abstract final class AppIcons`에 정적 경로 84종을 `static const String`으로 선언(알파벳순). 클래스 형태는 기존 `MapStyles`·`VibrationPatterns`를 따랐다
- **이유**: 다국어에서 문구를 `AppLocalizations` 키로 뽑아 쓰는 것과 같은 구조. 호출부가 상수를 참조하면 오타가 컴파일 에러가 된다

#### 조합 경로를 생성 함수로 통일

- **파일**: `lib/core/constants/app_icons.dart`
- **변경 내용**: `pingMarker` · `pingSelect` · `pingPin` · `role` 네 개의 정적 메서드 추가. 파일명의 테마 조각(`darkmode`/`lightmode`)은 private `_theme()`가 만든다
- **이유**: 조합 경로를 상수로 두면 조합 수만큼 늘어나고, 호출부가 문자열을 이어 붙이면 검색으로 사용 여부를 판정할 수 없게 된다. `character_assets.dart`가 이미 쓰는 방식을 그대로 따랐다

#### 호출부 교체

- **파일**: 57개 (`lib/` 전역)
- **변경 내용**: 경로 리터럴을 전부 `AppIcons` 참조로 교체. 데이터 클래스 안에 박혀 있던 경로(`sns_channels.dart`의 `svgAsset`, `credit_member.dart`의 `SocialType.svgAsset`)도 포함
- **이유**: 리터럴이 한 곳도 남지 않아야 "경로는 `AppIcons`만 만든다"가 불변식으로 성립한다

#### 미사용 아이콘 에셋 6개 삭제

- **파일**: `assets/icons/` 6개
- **변경 내용**: `icon_setting_1` · `icon_alert` · `Top_hat` · `plus` · `icon_loading` · `icon_date_setting` 삭제
- **이유**: 상수화 이후 모든 경로가 `AppIcons`를 거치므로 사용 여부 판정이 정확해졌다

### 🔧 주요 변경사항 상세

#### 역할 아이콘 — 이슈에 없던 네 번째 조합 패턴

착수 후 발견한 항목이다. 경찰·도둑 아이콘을 테마로 고르는 삼항이 세 곳에 복사돼 있었다.

- `chat_message_bubble.dart:54` (팀별 분기)
- `chat_message_bubble.dart:154` (정규식 그룹 기반 분기)
- `team_section.dart:124`

두 파일의 접두어가 서로 다르다(`icon_police_` / `mdi_robber_`). `AppIcons.role(isPolice:isDark:)`이 그 불일치를 흡수해 호출부는 접두어를 알 필요가 없어졌다.

```dart
// Before — team_section.dart
String get _iconPath {
  if (_isPolice) {
    return isDarkMode
        ? 'assets/icons/icon_police_darkmode.svg'
        : 'assets/icons/icon_police_lightmode.svg';
  }
  return isDarkMode
      ? 'assets/icons/mdi_robber_darkmode.svg'
      : 'assets/icons/mdi_robber_lightmode.svg';
}

// After
String get _iconPath => AppIcons.role(isPolice: _isPolice, isDark: isDarkMode);
```

#### 핑 종류 문자열은 enum 이름을 그대로 쓴다

`PingType`은 `{ found, suspect }`이고 파일명 조각이 정확히 그 이름이다. 별도 매핑 삼항이 필요 없다.

```dart
// Before — ping_marker_factory.dart
final typeName = type == PingType.found ? 'found' : 'suspect';

// After
final typeName = type.name;
```

`in_game_tutorial_page.dart`의 3줄 문자열 연결도 같은 함수 호출로 바뀌어, 핑 마커 에셋 10개가 이제 검색에 걸린다.

**특이사항**:

- `AppIcons`는 `core/constants`에 있고 `PingType`은 `features/game/domain`에 있다. 의존성이 역전되지 않도록 함수는 enum이 아니라 `String type`을 받고, 호출부가 `PingType.found.name`을 넘긴다. `character_assets.dart`가 `String team`을 받는 것과 같은 이유다
- 상수 **이름은 올바른 표기, 값은 실제 파일명 그대로**다. `AppIcons.wrongMark`의 값은 공백이 든 `'assets/icons/icon_wrong mark.svg'`, `AppIcons.setting2`의 값은 오타가 든 `'assets/icons/icon_settiing_2.svg'`. 에셋 파일명 교정은 별도 작업이며, 그때 고칠 곳은 이 파일의 값 한 줄뿐이다
- `pubspec.yaml`이 `assets/icons/`를 디렉터리 단위로 등록하므로 파일명 변경 시 `pubspec.yaml`은 손대지 않아도 된다
