# 폴리곤 게임 구역 지원 (#456) — 통합 보고서

### 📌 작업 개요

백엔드 v2.13.0에서 게임 구역에 폴리곤 타입이 추가됐다. 구역 요청/응답이 기존 평면 구조에서 `areaType` 판별자 + `circle`/`polygon` 중첩 구조로 바뀐 **breaking change**였고, 앱은 신규 응답을 파싱하지 못하는 상태였다.

이 작업에서 도메인 모델·핀 편집 UI·표시 문구·하위호환 배포 전략까지 대응했다. 브랜치 `20260722_#456_폴리곤_게임_구역_지원`, **총 28커밋**.

## 1단계 — 폴리곤 도메인·스키마 대응

### 🎯 구현 목표

원형/폴리곤을 공통으로 다루는 도메인 모델을 만들고, 이탈 판정·카메라·줌 계산이 도형 종류와 무관하게 동작하게 한다.

### ✅ 구현 내용

#### 핵심 설계 결정 — 분기를 도형 타입(union) 안에 은닉

- **파일**: `lib/features/game/domain/entities/area_shape.dart`
- **변경 내용**: `GeoPoint`, `AreaShape` freezed union(`CircleShape`/`PolygonShape`), `GameAreaEntity` 추가
- **이유**: 판정(`contains`)·카메라(`centroid`)·줌(`boundingRadiusInMeters`)을 union 메서드로 노출해, 소비처에서 원형/폴리곤 분기가 **0곳**이 되도록 하기 위함. 출력이 실제로 다른 렌더링만 `is CircleShape`/`is PolygonShape`로 명시 분기한다.

#### 순수 기하 함수 분리

- **파일**: `lib/features/game/domain/polygon_geometry.dart`
- **변경 내용**: `sortByAngleAroundCentroid`(무순서 핀 → 단순 다각형), `hasSelfIntersection`, `polygonAreaInSquareMeters`(shoelace), `isPolygonInsidePolygon`(감옥 ⊂ 플레이그라운드)
- **이유**: 핀 편집 검증 로직을 위젯에서 떼어내 단위 테스트 가능하게 함

#### 스키마 의존을 매퍼 1곳에 격리

- **파일**: `lib/features/game/data/models/game_area_model.dart`
- **변경 내용**: `GameAreaModel`(`areaType` + `circle?`/`polygon?`) → `toEntity()` 매퍼. `areaType`과 데이터 객체가 불일치하면 `ServerException`
- **이유**: 서버 와이어 문자열(`CIRCLE`/`POLYGON`)이 enum `@JsonValue`에만 존재하도록 하여 매직 스트링을 제거하고, 스키마 변경 시 수정 지점을 1곳으로 묶기 위함

**특이사항**: `gameAreaProvider`/`fetchGameAreaProvider`의 반환형이 `GameAreaModel` → `GameAreaEntity`로 바뀌었다. 소비처는 `area.playground.contains(...)` 형태로 도형을 직접 다룬다.

## 3단계 — 지도 레이아웃 통일 및 버그 정리

### 📌 작업 개요

방 만들기 구역 설정에서 원형 모드와 폴리곤 모드의 **지도 세로 크기가 다르게** 보이던 문제를 해결. 폴리곤 편집 위젯을 원형과 동일한 3단 구조로 통일하고, "전체 해제"를 지도 위 오버레이에서 하단 컨트롤 영역으로 이동.

**커밋**: `36975467 feat : 구역 핀 설정 지도 레이아웃 원형과 통일 #456`

### 🔍 문제 분석

원형과 폴리곤 편집 위젯의 **내부 레이아웃 구조가 달라** 지도 크기가 어긋났다.

| | 원형 `ZoneSettingWidget` | 폴리곤 `PinZoneSettingWidget` |
| --- | --- | --- |
| `build` 구조 | `Column[지도 360.h, 간격, 반경 슬라이더]` | `SizedBox(mapHeight) → 지도만` |
| setup 페이지가 넘긴 값 | 미전달 → **360.h 고정** | `mapHeight: double.infinity` → **Expanded 전체** |
| 하단 컨트롤 | 반경 슬라이더 (지도 밖) | 없음 (전체해제는 지도 위 오버레이) |

폴리곤은 반경 개념이 없어 슬라이더가 없고, 남는 공간을 지도로 채우려 `double.infinity`를 준 것이 크기 불일치의 직접 원인이었다.

### ✅ 구현 내용

#### 폴리곤 편집 위젯을 3단 구조로 전환

- **파일**: `lib/core/widgets/map/pin_zone_setting_widget.dart`
- **변경 내용**: `build()` 반환을 단일 `SizedBox(지도)` → `Column[지도 360.h, 간격, 전체해제 버튼]`
- **이유**: 지도 영역을 `360.h`로 고정하고 하단 컨트롤 자리를 확보해 원형과 지도 크기를 일치시키기 위함

```dart
return Column(
  children: [
    map,                                        // 지도 360.h + 오버레이(내위치·면적칩)
    SizedBox(height: AppSpacing.vertical20),
    Padding(
      padding: AppPadding.horizontal20,
      child: Align(
        alignment: Alignment.centerRight,
        child: custom_chip.ActionChip(
          text: AppLocalizations.of(context).zoneClearAllPins,
          onTap: _points.isEmpty ? null : _clearAll,   // 핀 0개 → 비활성
          backgroundColor: widget.pinColor,
        ),
      ),
    ),
  ],
);
```

#### 전체 해제 버튼을 하단으로 이동

- **변경 내용**: 지도 우상단 오버레이 칩을 제거하고 하단 컨트롤 영역에 `ActionChip`으로 재배치(우측 정렬). 핀이 없으면 자동 비활성
- **이유**: 오버레이가 지도를 가리는 문제 해소 + 원형의 상시 노출 슬라이더와 대칭. 버튼 등장/사라짐에 따른 지도 들썩임도 방지(자리 유지 + 비활성)

#### setup 페이지의 mapHeight 강제 제거

- **파일**: `setup_playground_page.dart`, `setup_prison_page.dart`
- **변경 내용**: `mapHeight: double.infinity` 인자 삭제 → 기본값 `360.h` 적용

#### 내 위치 포커스 판정 개선

- **변경 내용**: 단순 플래그 토글 대신 카메라 중심과 현재 위치의 거리(`_locationFocusToleranceInMeters = 5m`)를 비교하는 `_isCameraFocusedOnLocation`/`_updateLocationFocus` 도입. `onCameraIdle`에서도 갱신하고 프로그래밍적 카메라 이동은 판정에서 제외
- **이유**: 사용자가 지도를 움직여 현재 위치에서 벗어났는지를 정확히 반영

**특이사항**:

- 내 위치 버튼(좌하단)·면적 칩(우하단)은 그대로 지도 위 오버레이로 유지 — 원형의 반경 칩 오버레이와 대칭
- 전체 해제 텍스트는 기존 `zoneClearAllPins` 키를 재사용 → 신규 문자열 없음

### 📌 참고사항

- **공용 레이아웃 셸은 추출하지 않음(YAGNI)**: 3단 구조를 쓰는 곳은 setup 2개 페이지뿐이다(게임 세팅 변경은 setup 재진입, 구역 보기는 읽기전용 `ZonePreview`, 인게임은 `GoogleMapView`로 구조가 다름). 3~4줄 뼈대를 위젯으로 빼면 배관만 늘어난다. 세 번째 사용처가 생기면 그때 추출.

## 4단계 — 구역 크기 표시 도형별 대응

### 📌 작업 개요

폴리곤을 지원하게 됐지만 **구역 크기를 보여주는 UI는 원형 전제로 남아 있었다.** 폴리곤인데도 "반경 523m"로 표시되고, 폴리곤 설정을 마쳐도 버튼이 미설정 색상으로 보였다. 원형은 반경, 폴리곤은 면적으로 표시하도록 바꾸고 3곳에 중복됐던 반경 포맷 로직을 공용 포맷터로 통합했다.

작업 중 `AppSlider.valueFormatter`가 **선언만 되고 본문에서 쓰이지 않는** 것을 발견해, 반경 슬라이더가 최대값에서 "1000km"로 1000배 오표기되던 버그도 함께 수정했다.

### 🔍 문제 분석

#### 문제 1 — 폴리곤을 반경으로 표시

`ZoneInfo.radiusMeters`(int)와 `ZoneSettingButton.radiusMeters`(double?)가 **반경만 받는 타입**이라 프레젠테이션에 도달하기 전에 도형 정보가 소실됐다. 호출부는 폴리곤의 외접 반경을 억지로 뽑아 넘기고 있었다(`_polygonDisplayRadius`).

| 위치 | 폴리곤일 때 |
| --- | --- |
| 게임 설정 페이지 / 생성 Step3 요약 | 외접 반경을 "반경 523m"로 → 다각형인데 원형처럼 읽힘 |
| 생성 Step0 버튼 | `radiusMeters: null` 전달 → 부가정보 없음 + **설정 완료인데 미설정 색상** |
| 핀 편집 화면 면적 칩 | "면적 0.42km²" — 유일하게 올바르나 포맷 로직이 위젯 private에 갇혀 있었음 |

Step0 버튼의 색상 판정이 `radiusMeters != null`이어서, 폴리곤 모드에서는 값이 항상 null → 완료해도 흐린 색으로 남았다.

#### 문제 2 — 반경 포맷 3중복

동일한 반경 표시 로직이 세 곳에 복제돼 있었다(`zone_list_card`, `zone_setting_button`, `zone_setting_widget` 인라인). ARB에도 문구가 완전히 동일한 중복 키가 있었다 — `zoneRadiusMeter`와 `zoneRadiusMeters`.

#### 문제 3 — AppSlider의 valueFormatter 미배선

`AppSlider.valueFormatter`는 필드 선언과 생성자 파라미터만 있고 **본문 참조가 0건**이었다. 값 텍스트는 `'${value.toInt()}$unit'`을 쓰는데 반경 슬라이더의 `unit`은 `_currentRadius >= 1000 ? 'km' : 'm'`로 동적이었다.

| 반경 | 값 텍스트 | min 라벨 | max 라벨 |
| --- | --- | --- | --- |
| 500m | `500m` ✅ | `100m` ✅ | `1000m` ✅ |
| **1000m** | **`1000km`** ❌ | `100km` ❌ | `1000km` ❌ |

플레이그라운드 반경은 최대 1000m(10m 스텝 90칸)이므로 **슬라이더를 끝까지 끌면 도달하는 상태**였다. 값이 1000배로 오독된다.

### ✅ 구현 내용

#### 공용 포맷터 추가

- **파일**: `lib/core/utils/zone_metric_formatter.dart` (신규)
- **변경 내용**: `formatRadiusValue`, `formatAreaValue`, `AreaShape.metricText(l10n)` 확장
- **이유**: 반경/면적 포맷을 한 곳으로 모으고, 원형/폴리곤 분기를 도형 union 안에 은닉

```dart
extension ZoneMetricDisplay on AreaShape {
  String metricText(AppLocalizations l10n) => when(
    circle: (_, r) => l10n.zoneRadiusValue(formatRadiusValue(r)),
    polygon: (points) => l10n.zoneAreaValue(
      formatAreaValue(
        polygonAreaInSquareMeters(sortByAngleAroundCentroid(points)),
      ),
    ),
  );
}
```

표시 규칙:

| 도형 | 표시 | 예 |
| --- | --- | --- |
| 원형 | 반경 | `반경 523m` / `반경 1.50km` |
| 폴리곤 | 면적 | `면적 31,416m²` / `면적 0.79km²` |

- 반경: 1,000m 이상 km(소수 2자리), 미만 정수 m
- 면적: 1,000,000m²(=1km²) 이상 km²(소수 2자리), 미만 정수 m² + 천단위 콤마
- 정수 구간은 `round()`로 통일 (기존에 `toInt()` 버림과 섞여 있었음)

#### 면적 단위 기준을 1ha에서 1km²로 조정

- **이유**: 1ha 기준에서는 감옥(반경 100m 상당 ≈ 31,416m²)이 **"0.03km²"로 뭉개져** 크기 구분이 불가능했다. 1km² 기준이면 `31,416m²`로 실수치가 남고, m² 구간 최대가 999,999라 콤마가 가독성을 확보한다.

#### 위젯이 AreaShape를 직접 받도록 변경

- **파일**: `zone_list_card.dart`, `zone_setting_button.dart`
- **변경 내용**
  - `ZoneListCard({required List<ZoneInfo> zones})` → `({required GameAreaEntity area})`
  - `ZoneSettingButton.radiusMeters`(double?) → `.shape`(AreaShape?)
  - 색상 완료 판정을 `radiusMeters != null` → `shape != null`로 교체
- **이유**: 도형 정보를 소실하지 않고 전달. 색상 판정 교체로 **폴리곤 완료 시 미설정 색상 버그가 함께 해소**된다.

#### AppSlider valueFormatter 배선

- **파일**: `app_slider.dart`, `zone_setting_widget.dart`
- **변경 내용**: `_formatValue` 도입 후 값 텍스트(2곳)와 min/max 라벨(2곳)이 모두 같은 경로를 타게 함. 반경 슬라이더는 `valueFormatter: formatRadiusValue`로 전환하고 매직 상수 `1000` 3개 제거
- **이유**: 값에 따라 단위가 바뀌는 경우(500m ↔ 1.00km)에도 세 표시가 어긋나지 않게 함

```dart
/// valueFormatter가 있으면 단위까지 그 함수가 책임진다
String _formatValue(double v) => valueFormatter?.call(v) ?? '${v.toInt()}$unit';
```

#### ZoneInfo 제거 + 중복 ARB 키 정리

- **변경 내용**: `zone_info.dart`(+`.freezed.dart`) 삭제. ARB에 `zoneRadiusValue`·`zoneAreaValue` 추가, `zoneRadiusKm`·`zoneRadiusMeter`·`zoneRadiusMeters` 3개 삭제
- **이유**: `ZoneInfo`의 `id`는 아무도 읽지 않는 죽은 필드였고, `name`은 l10n 상수 2개뿐이었다. `displayDistance` 게터는 `'반경 ${km}km'`를 하드코딩한 i18n 규칙 위반 상태의 죽은 코드였다.

**단위는 Dart 한 곳, 어순은 ARB.** `m²`/`km²`는 로케일 무관 SI 기호이므로 포맷 함수가 단일 소스로 갖고, "반경 …"/"면적 …" 어순은 ARB 문장 키가 갖는다. 로케일별 어순 변경(`{value} 면적`)이 ARB 수정만으로 가능하다.

#### 감옥 포함 판정 허용 오차 통일

- **변경 내용**: `GameConfig.zoneContainmentToleranceInMeters` 추가 후 `session_creation_flow_page`(리터럴 `1.0`)와 `setup_prison_page`(로컬 `_epsilonMeters`) 양쪽이 참조

### 5.1 API 하위호환 배포 전략

#### 🔍 문제 분석

#### ✅ 해결 — 서버 하위호환 + 앱 코드 변경 0건

백엔드에 두 가지를 요청해 반영됐다.

#### 회귀 테스트

- **파일**: `test/features/game/data/game_area_mapper_test.dart`
- **변경 내용**: 중첩 `circle`과 평면 필드가 **일부러 다른 값**으로 함께 온 응답을 파싱해 앱이 중첩만 읽는지 검증

## 🧩 부록 A — 폴리곤 구역 이탈 판정 알고리즘

### 원형 vs 폴리곤 판정 차이

두 도형 모두 진입점은 `AreaShape.contains(내 위치)` 하나 — `true`면 구역 안, `false`면 밖. 판정 "방법"만 다르다.

| | 판정 방식 | 쓰는 값 |
| --- | --- | --- |
| **원형** (`CircleShape`) | 중심~내 위치 직선 거리 ≤ 반지름 → 안 (거리 계산 1번) | 중심점, 반지름 |
| **폴리곤** (`PolygonShape`) | ray casting — 변 교차 횟수 홀/짝 | 꼭짓점 목록 |

폴리곤이 반지름을 못 쓰는 이유: 다각형은 방향마다 경계까지 거리가 달라 단일 거리로 안/밖을 가릴 수 없다.

### ray casting 핵심 (`area_shape.dart`)

- 광선은 **1개**, 오른쪽(경도 증가 = 동쪽) 한 방향. 앞뒤·여러 개 아님.
- **실제로 선을 긋지 않는다** — 각 변마다 두 부등식만 계산:
  - 조건 A: 변이 내 위도(수평선)를 위아래로 가로지르나 `(a.lat > p.lat) != (b.lat > p.lat)`
  - 조건 B: 그 교차점 경도가 내 경도보다 큰가(= 내 오른쪽/동쪽) `p.lng < 교차경도`
  - 둘 다 참이면 `inside` 토글. 초기 `false`(밖)에서 홀수번 토글되면 `true`(안).
- "얼마나 멀리 쏘나"에 해당하는 **거리 값은 코드에 없다**(무한 반직선과 대수적으로 동치).
- 경계선 위(변 밟기)는 `_isPointOnSegment`가 먼저 잡아 "안"으로 처리(경계 포함).
- 위경도를 평면(x=경도, y=위도)으로 근사 — 홀짝 위상 판정이라 축 스케일 왜곡에 영향 없음. 게임 스케일(수 km)에서 정확, 날짜변경선·극지 미지원(한국 서비스 전제).

### 분기 위치 — `areaType`이 아니라 union 타입

- 서버 `areaType("CIRCLE"|"POLYGON")` 문자열은 **파싱 매퍼 1곳**에서만 읽혀 `CircleShape`/`PolygonShape` 객체로 변환된다.
- 이후 소비처(인게임 이탈 판정·렌더링, 미리보기)는 `areaType` enum이 아니라 **도형 union 타입**(`when` / `is CircleShape` / `is PolygonShape`)으로 분기한다.
- 이탈 판정 진입점: `game_page.dart` `area.playground.contains(...)` (분기는 `AreaShape` 내부 은닉).

### 인게임 폴리곤 렌더링

- 경계선: `_buildAreaBorderPolygons` — `PolygonShape`면 경계 `Polygon`(playground=`blue800`, jail=`red500`).
- 구역 밖 딤: `_buildOutsideOverlay` — `playground.when(circle:, polygon:)`로 hole을 도형별 분기.
- 최소 줌: `boundingRadiusInMeters`(폴리곤=centroid~꼭짓점 최대거리)로 환산.
- 인게임 폴리곤 경계·외부 딤·줌 모두 코드 경로상 지원. 단 **실기기 런타임 검증 권장**(ray casting은 꼭짓점 각도 정렬에 의존).

### 확인된 동작 범위

- **생성·수정 모두 원형↔핀 전환 가능**: `AreaTypeToggle`이 생성 플로우와 대기방 설정 수정에 모두 노출된다. 편집 시 플레이그라운드 타입을 바꾸면 감옥을 반드시 다시 설정하도록 강제해(타입이 다르면 기존 감옥을 버림) 서버의 "타입 혼합 불가" 제약을 구조적으로 만족한다.
- **감옥은 독립 토글 없음**: 플레이그라운드 타입을 따른다(서버 제약).
- **다른 참가자 동기화**: `AREA_UPDATED` 이벤트는 payload를 파싱하지 않고 캐시만 무효화하며, 재조회 응답을 `GameAreaModel.toEntity()`가 `areaType`별로 분기하므로 타입과 무관하게 동작한다.
- **줌 계산**: 원형·폴리곤 모두 `boundingRadiusInMeters`로 환산해 기존 파이프라인을 재사용한다.
