## 🔧 주요 변경사항 상세

### 커서 페이지네이션 (v2.15.0 오프셋 → v2.17.0 커서)

이슈 참고 항목에서 예상한 대로 백엔드가 커서 방식으로 전환. `PageInfoModel` → `CursorInfoModel`, 쿼리 파라미터 `page` → `cursor`로 교체.

**특이사항**:
- `nextCursor`는 서버 내부 형식이라 파싱하지 않고 다음 요청에 그대로 실음
- 커서는 "몇 번째"가 아니라 "어디까지 봤는지"를 들고 다니므로 스크롤 중 새 글이 올라와도 경계가 밀리지 않음 → **이슈에 적힌 id 기준 중복 제거가 불필요해짐**
- 총 개수(`totalElements`)는 커서 방식이라 서버가 주지 않음

### 모집 상태 파싱 — 폴백 없음

DTO는 `status`를 `String`으로 받고 Repository 경계에서 도메인 enum으로 변환. 알 수 없는 값이면 `FormatException`을 던지고 Repository가 `ServerException`으로 감쌈.

**특이사항**: 폴백을 두지 않은 이유는 마감된 글이 모집중으로 보이면 사용자가 끝난 모임에 참여를 시도하기 때문. 조용히 넘기는 대신 파싱 단계에서 끊음.

### 백엔드 미지원 값 우회

서버가 아직 400을 주는 값이 둘 있어 화면에서 막아둠:

| 파라미터 | 상태 | 처리 |
|---|---|---|
| `scope=NEARBY`, `MINE` | 400 (`UNSUPPORTED_LIST_SCOPE`) | Notifier가 호출 자체를 건너뛰고 빈 목록 반환 → 화면은 "준비 중" 안내 |
| `sort` (LATEST 외) | 400 | 정렬 시트에서 선택 시 "준비 중" 스낵바, 상태 반영 안 함 |

**특이사항**: 정렬은 선택을 반영하면 라벨만 "인기순"으로 바뀌고 목록은 최신순 그대로라 **에러 없이 틀린 화면**이 됨. 서버가 열리면 두 곳 모두 분기만 지우면 됨.

### loadMore 경합 처리

`await` 도중 범위 토글이 바뀌면 `build()`가 재실행되며 state가 교체됨. 응답이 돌아왔을 때 `identical(state.valueOrNull, pending)`으로 자기 요청인지 확인한 뒤에만 반영해, 낡은 응답이 새 스코프의 목록을 덮어쓰지 않게 함.

스크롤 리스너는 프레임마다 `loadMore()`를 부르지만 `isLoadingMore` 대입이 첫 `await` 이전이라 동기적으로 끝나 중복 요청이 걸러짐.

### 위치 표기 (주소 3종)

서버가 좌표를 한 번 역지오코딩해 건물명·도로명·지번을 저장. Repository가 `buildingName ?? roadAddress ?? address` 순으로 가장 구체적인 것을 골라 `locationLabel` 한 줄로 접음. 셋 다 null(역지오코딩 실패)이면 카드가 위치 행 자체를 숨김 — 좌표는 사용자에게 무의미하므로.

### 시각 정규화

백엔드가 timezone suffix(+09:00)를 포함해 직렬화하므로 파싱 결과가 UTC `DateTime`. 엔티티 경계에서 `toLocal()`로 정규화.

### 목록 스크롤이 상단 토글을 덮던 문제 (수정)

카드 그림자(`AppShadows.ver2`, blur 10)가 잘리지 않게 `ListView`에 `clipBehavior: Clip.none`을 줬는데, 클립이 없으면 위로 밀린 카드가 뷰포트 밖까지 그려져 범위 토글과 정렬 라벨을 덮음. 클립을 되살리고 정렬 라벨 아래 12px 여백은 스크롤 영역 밖에 유지.

**특이사항**: 시안상 그 간격이 12여야 해서 목록 상단 padding은 0. 대신 첫 카드 위쪽 그림자가 뷰포트 경계에서 잘리는 것을 받아들임 (7% 알파라 육안 확인 필요).

### 카드 더보기(⋮) 메뉴 — 신고하기

`PopupMenuButton`으로 앵커 위치·바깥 탭 닫기만 프레임워크에 맡기고, 표면(204×52, radius 12, border black100, `AppShadows.ver2`)은 직접 그림.

**특이사항**:
- Material elevation 그림자로는 `ver2`를 재현할 수 없어 프레임워크 쪽 표면을 투명으로 비움
- `icon:` 대신 `child:` 사용 — `icon:`은 `IconButton`으로 감싸져 최소 48×48이 붙고 그만큼 제목 행 높이가 늘어남
- `_PopupMenu`의 `IntrinsicWidth(stepWidth: 56)`가 폭을 56 배수로 올림하므로 `constraints`로 204를 못 박음
- 문구는 기존 ARB `buttonReport` 재사용 (신규 키 없음)
- 커뮤니티 글 신고 API가 없어 탭 시 "준비 중이에요" 스낵바

### 진동 피드백 기준

⋮ 탭(메뉴 열기)과 신고하기 항목 탭에 `buttonTap()` 적용. 카드 본문 탭(상세 화면 이동)에는 넣지 않기로 결정 — 이 코드베이스는 버튼·토글·시트를 여는 컨트롤만 울리고, 눌러서 화면이 바뀌는 행/카드(마이페이지 설정 행, SNS 채널 행)는 울리지 않음. 무한 스크롤 목록이라 스크롤 중 오터치가 잦은 점도 고려.

## 📌 참고사항

### ⚠️ 머지 전 반드시 처리

**`community_page.dart`의 `_useMockPosts = true`를 `false`로 되돌려야 함.** UI·무한 스크롤 확인용 임시 하드코딩이며, 켜져 있는 동안 화면이 실제 API를 타지 않고 목데이터 40개를 그림. 지울 대상은 플래그, `_mockTemplates`/`_mockPosts` 목록, `_mock*` 필드, `_loadMore()`·`_refresh()`·`_buildBody()` 맨 위 분기 3곳.

### 미구현 항목과 사유

| 항목 | 사유 |
|---|---|
| 게시글 상세 화면 | 별도 작업. 카드 `onTap`이 연결 지점 |
| 작성 등록 API | 장소를 좌표로 받아야 하는데 지도 선택 방식이 미정. 현재는 텍스트 입력, 완료 시 안내만 표시 (`_submit`이 연결 지점) |
| 수정·삭제 메뉴 | "내 글인지" 판단할 로그인 사용자 id가 카드에 없음 |
| 모집 상태 변경 | 상세 화면과 함께 작업 |
| `우리 동네`·`내 모임` | 백엔드 400. 서버 지원 시 Notifier·화면의 분기 제거만 필요 |
| 정렬 (인기·거리·마감임박) | 백엔드 400. 서버 지원 시 `SelectedCommunitySort`를 `build()`에서 watch |
| 좋아요·스크랩 토글 | API에 "내가 눌렀는지" 필드가 없어 off 아이콘 고정, 표시 전용 |

- `writerNickname`은 탈퇴한 작성자면 null
