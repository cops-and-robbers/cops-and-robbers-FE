### 📌 작업 개요

게임 종료 직후 결과 모달(GameOverResultDialog)에서 버튼 클릭 시 `Cannot use "ref" after the widget was disposed` StateError로 크래시되는 #346 이슈를 해결. 같은 흐름에서 파생된 두 가지 후속 케이스(강퇴된 사용자가 "한 번 더" 클릭 시 대기방 무한 로딩 + STOMP 재연결 루프, 사용자 액션 버튼 누를 때 404 누락)도 동일 PR로 묶어 안전망을 보강.

PR: #347 (main 머지 완료, d63c3fb)
관련 커밋: 2cc8d9a, 8c11b0f

### 🔍 문제 분석

#### 1) 결과 모달 ref 폭발 (메인 케이스)

- 게임 진행 중 앱이 백그라운드에 있는 동안 게임이 종료되면 GAME_OVER 이벤트가 발행됨
- 사용자가 앱을 다시 포그라운드로 가져오면 `_checkGameStatusOnResume`이 호출돼 게임 상태를 재조회 → 게임이 끝난 게임이면 자동 라우팅 발생
- 그런데 이때 이미 GamePage에서는 GameOverResultDialog를 띄우려고 흐름이 진행 중
- 사용자가 자동 라우팅으로 GamePage에서 빠져나간 직후(GamePage dispose됨) 다이얼로그 콜백이 ref를 호출 → StateError 폭발

#### 2) 강퇴된 사용자의 "한 번 더" 시 대기방 무한 로딩

- 게임 종료 다이얼로그가 떠있는 동안 방장이 본인을 강퇴(KICKED 이벤트)
- 사용자는 GamePage에 있어서 lobby STOMP 구독이 없으므로 KICKED 이벤트를 받지 못함
- 사용자가 "한 번 더" 클릭 → `context.go('/waiting-room/{gameId}')`
- WaitingRoomPage 진입 → 두 API(`GET /api/games/{id}/lobby`, `GET /api/games/{id}`)가 모두 RFC 7807 형식의 404를 응답:
  ```json
  {"title":"참가자를 찾을 수 없음","status":404,"detail":"해당 게임에 참가하지 않은 사용자입니다.","instance":"/api/games/214/lobby"}
  ```
- 기존 catch는 `debugPrint`만 하고 함수가 early return → UI 무한 로딩
- 동시에 LobbyNotifier가 STOMP ERROR("권한 없음")를 일반 끊김으로 인식해 지수 백오프 재연결 루프 진입

#### 3) 안내 다이얼로그 후 홈에서 재연결 로직이 계속 실행되며 ref 폭발

- `_handleNotParticipating`이 `disconnectLobby()`를 호출해 STOMP 재연결을 차단
- 그런데 `disconnectLobby`가 내부에서 `state = const LobbyState()`로 상태를 초기 disconnected 로 되돌리는 순간 WaitingRoomPage의 `ref.listenManual` 콜백이 한 번 더 fire
- 그 콜백이 마이크로태스크 큐에 남아있다가 사용자가 홈으로 이동한 직후 실행되며 dead path 진입

#### 4) 사용자 액션(team/ready/start) 시 동일한 404 미처리

- 방에 더 이상 참가자가 아닌 상태인데 UI에는 그대로 남아있는 케이스
- 사용자가 준비 버튼/팀 변경/시작 버튼을 누르면 동일한 404 RFC 7807이 내려옴
- 기존 catch는 일반 스낵바만 띄움 → 사용자가 같은 화면에 갇힘

### 🔧 주요 변경사항 상세

#### `_handleNotParticipating` — 3중 방어 락

```text
1) _isHandlingNotParticipating = true      // 재진입 가드
2) _lobbyEventSub?.close()                 // listener 자체 차단 (방금 추가된 안전망)
3) LobbyNotifier.disconnectLobby()         // STOMP 재연결 차단
4) Navigator.of(rootNavigator: true).pop() // 이미 떠있는 ReconnectModal 정리
5) AppDialog.show → context.go(home)
```

**특이사항**:
- `Navigator.of(context, rootNavigator: true)` 사용. ReconnectModal은 `showGeneralDialog` 기본값(`useRootNavigator: true`)으로 root에 push되므로 동일하게 root navigator로 pop해야 닫힘
- `AppDialog.show`에 `isDarkMode: ref.read(roleThemeProvider)` 명시 — 도둑팀(다크 화면)에 라이트 다이얼로그가 뜨는 시각 충돌 방지
- 안내 타이틀은 "강퇴" 단어를 쓰지 않음. 클라이언트가 KICKED 이벤트를 직접 받지 않으므로 강퇴/게임 삭제/세션 만료를 한 톤으로 묶어 "방에 참여할 수 없어요"로 부드럽게 처리

#### `_handleApiErrorOrNotParticipating` — 사용자 액션 catch 통일

```dart
Future<void> _handleApiErrorOrNotParticipating(
  DioException e, {
  required String fallbackMessage,
}) async {
  if (_isDisposed) return;
  if (e.response?.statusCode == 404 && mounted) {
    final apiError = ApiErrorResponse.tryParse(e.response?.data);
    await _handleNotParticipating(apiError?.detail);
    return;
  }
  if (mounted && !_isDisposed) {
    final apiError = ApiErrorResponse.tryParse(e.response?.data);
    AppSnackbar.show(
      context,
      message: apiError?.detail ?? fallbackMessage,
      backgroundColor: AppColors.red,
    );
  }
}
```

**특이사항**: 호출자가 반환값에 따라 분기할 필요가 없도록 `Future<void>` 시그니처. 404 분기는 내부에서 다이얼로그 → 홈 라우팅까지 완료한다.

#### GameOverGuard

```dart
class GameOverGuard {
  GameOverGuard._();
  static bool shouldSkipResume({required bool gameOverDialogShown})
      => gameOverDialogShown;
  static bool shouldSkipSync({required bool gameOverDialogShown})
      => gameOverDialogShown;
  static bool shouldSkipDialogCallback({required bool isMounted})
      => !isMounted;
}
```

**특이사항**: 의도적으로 단순한 함수 모음. 핵심은 가드 호출 지점을 명시화해 향후 새 진입점이 추가될 때도 동일 패턴을 빠르게 적용할 수 있게 한 것.
