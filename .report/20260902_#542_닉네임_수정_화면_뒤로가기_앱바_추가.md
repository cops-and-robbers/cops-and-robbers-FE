# 기능 개선 보고서 — 닉네임 수정 화면 뒤로가기 앱바

## 📌 작업 개요

- **이슈**: #542 닉네임 수정 화면에 뒤로가기 앱바 추가
- **범위**: 닉네임 화면 1개
- **수정 파일**: `lib/features/auth/presentation/pages/nickname_setup_page.dart`

## 🐞 문제 상황

닉네임 화면은 첫 로그인 온보딩과 마이페이지의 닉네임 수정이 같은 화면을 공유한다. 온보딩은 되돌아갈 곳이 없어 앱바 없이 설계됐는데, 그 구조가 수정 진입에도 그대로 적용돼 **수정으로 들어와도 화면 안에 나가는 길이 없다**. iOS 엣지 스와이프나 Android 시스템 백만 가능했다.

## ✅ 수정 내용

| 파일 | 변경 내용 | 이유 |
|---|---|---|
| `nickname_setup_page.dart` | `context.canPop()`이 true일 때(설정에서 push 진입)만 `AppTopBar(title: 닉네임 변경, onBack: pop)`을 붙임 | 온보딩(redirect 진입, canPop false)은 기존처럼 앱바 없이 유지 - `_navigateAfterComplete`가 이미 쓰는 기준과 동일한 분기. 타이틀은 마이페이지에서 진입하는 다른 화면들(언어 설정·약관 설정·버그 제보 - 모두 앱바 타이틀+뒤로가기 형식)과 통일했고, 문구는 마이페이지 메뉴명과 같은 `settingsAccountChangeNickname`을 재사용 |
| 〃 | 앱바가 있을 때 상단 여백을 50 → 8로 조정 | 페이지 패딩 20과 합쳐 28 - 방 생성 등 다른 화면들의 "상단 바에서 제목까지 28" 시안 관례에 맞춤 |

## 🧪 테스트 및 검증

에뮬레이터(Android API 36.1) 디버그 빌드로 실제 계정 로그인 후 확인했다.

- 마이페이지 → 닉네임 변경 진입 - 상단에 뒤로가기 앱바 표시, 제목까지의 여백 자연스러움
- 뒤로가기 탭 - 마이페이지로 정상 복귀
- 닉네임 실제 변경(중복 확인 → 확인) - 저장 후 마이페이지 복귀, 대기실 등 다른 화면에 새 닉네임 반영 (기존 저장 플로우의 `_navigateAfterComplete` pop과 앱바 추가가 충돌하지 않음)
- `dart format` 변경 없음, `flutter analyze` No issues

첫 로그인(redirect) 케이스는 신규 계정이 필요해 기기 재현은 못 했다. 다만 이 경로는 `canPop == false` → `appBar: null`로 기존 코드와 완전히 같은 렌더라서 회귀 여지가 없다.

## 📌 참고사항

- 팀 나눔 없이 이 화면 하나만 바뀌므로 다른 화면 영향 없음.
- 앱바 유무 분기 기준을 `_navigateAfterComplete`(완료 후 pop/go 분기)와 같은 `context.canPop()`으로 맞춰, 진입 경로 판단이 화면 안에서 한 가지 기준으로 통일된다.
