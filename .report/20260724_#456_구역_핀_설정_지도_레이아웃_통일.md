# 구역 핀 설정 지도 레이아웃 원형과 통일 (#456)

### 📌 작업 개요

방 만들기 구역 설정에서 원형(CIRCLE) 모드와 폴리곤(POLYGON) 모드의 **지도 세로 크기가 다르게** 보이던 문제를 해결. 폴리곤 편집 위젯을 원형과 동일한 `[지도 + 하단 컨트롤]` 3단 구조로 통일하고, "전체 해제"를 지도 위 오버레이에서 하단 컨트롤 영역으로 이동. 더불어 내 위치 버튼의 포커스 판정을 카메라 위치 기반으로 정확히 개선.

**커밋**: `36975467 feat : 구역 핀 설정 지도 레이아웃 원형과 통일 #456`

---

### 🔍 문제 분석

원형과 폴리곤 편집 위젯의 **내부 레이아웃 구조가 달라** 지도 크기가 어긋났다.

| | 원형 `ZoneSettingWidget` | 폴리곤 `PinZoneSettingWidget` |
|---|---|---|
| `build` 구조 | `Column[지도 360.h, 간격, 반경 슬라이더]` | `SizedBox(mapHeight) → 지도만` |
| setup 페이지가 넘긴 값 | 미전달 → **360.h 고정** | `mapHeight: double.infinity` → **Expanded 전체** |
| 하단 컨트롤 | 반경 슬라이더 (지도 밖) | 없음 (전체해제는 지도 위 오버레이) |

폴리곤은 반경 개념이 없어 슬라이더가 없고, 남는 공간을 지도로 채우려 `double.infinity`를 준 것이 크기 불일치의 직접 원인이었다.

---

### ✅ 구현 내용

#### 1. 폴리곤 편집 위젯을 3단 구조로 전환
- **파일**: `lib/core/widgets/map/pin_zone_setting_widget.dart`
- **변경 내용**: `build()` 반환을 단일 `SizedBox(지도)` → `Column[지도 360.h, 간격, 전체해제 버튼]`으로 변경. 원형 위젯과 동형 구조가 되도록 맞춤.
- **이유**: 지도 영역을 `360.h`로 고정하고 하단 컨트롤 자리를 확보해, 원형과 지도 크기를 일치시키기 위함.

#### 2. 전체 해제 버튼을 하단으로 이동
- **파일**: `lib/core/widgets/map/pin_zone_setting_widget.dart`
- **변경 내용**: 지도 우상단 오버레이 칩(`if (_points.isNotEmpty) Positioned(...)`)을 제거하고, 하단 컨트롤 영역에 `ActionChip`으로 재배치(우측 정렬). `onTap: _points.isEmpty ? null : _clearAll`로 핀이 없으면 자동 비활성.
- **이유**: 오버레이가 지도를 가리는 문제 해소 + 원형의 상시 노출 슬라이더와 대칭. 버튼 등장/사라짐에 따른 지도 들썩임도 방지(자리 유지 + 비활성).

#### 3. setup 페이지의 mapHeight 강제 제거
- **파일**: `lib/features/session/presentation/pages/setup_playground_page.dart`, `lib/features/session/presentation/pages/setup_prison_page.dart`
- **변경 내용**: `PinZoneSettingWidget(... mapHeight: double.infinity ...)`에서 `mapHeight` 인자 삭제 → 기본값 `360.h` 적용.
- **이유**: 위젯이 원형과 동일한 고정 높이를 쓰도록 하여 크기 통일을 완성.

#### 4. 내 위치 포커스 판정 개선
- **파일**: `lib/core/widgets/map/pin_zone_setting_widget.dart`
- **변경 내용**: 단순 플래그 토글 대신, 카메라 중심과 현재 위치의 거리(`_locationFocusToleranceInMeters = 5m`)를 비교하는 `_isCameraFocusedOnLocation` / `_updateLocationFocus` 도입. `onCameraIdle`에서도 포커스 상태를 갱신하고, 프로그래밍적 카메라 이동(`_isProgrammaticMove`)은 판정에서 제외.
- **이유**: 사용자가 지도를 움직여 현재 위치에서 벗어났는지를 정확히 반영해 내 위치 버튼의 활성/비활성 표시를 신뢰성 있게 만듦.

### 🔧 주요 변경사항 상세

#### pin_zone_setting_widget.dart

`build()`에서 지도 `Stack`을 `map` 지역 변수로 뽑고, 이를 포함한 `Column`을 반환하도록 재구성:

```dart
return Column(
  children: [
    map,                                        // 지도 360.h + 오버레이(내위치·면적칩)
    SizedBox(height: AppSpacing.vertical20),
    Padding(
      padding: AppPadding.horizontal20,
      child: Align(
        alignment: Alignment.centerRight,
        child: custom_chip.ActionChip(
          text: AppLocalizations.of(context).zoneClearAllPins,
          onTap: _points.isEmpty ? null : _clearAll,   // 핀 0개 → 비활성
          backgroundColor: widget.pinColor,
        ),
      ),
    ),
  ],
);
```

**특이사항**:
- 내 위치 버튼(좌하단)·면적 칩(우하단)은 그대로 지도 위 오버레이로 유지 — 원형의 반경 칩 오버레이와 대칭 유지.
- 전체 해제 텍스트는 기존 `zoneClearAllPins` 키를 재사용 → 신규 문자열 추가 없음.

- 방 만들기 → 플레이그라운드/감옥에서 원형↔폴리곤 토글 시 지도 세로 크기 동일 확인

### 📌 참고사항

- **공용 레이아웃 셸은 추출하지 않음(YAGNI)**: 원형/폴리곤 편집 3단 구조를 쓰는 곳은 `setup` 2개 페이지뿐이며(게임 세팅 변경은 setup 재진입, 게임 영역 보기·세팅 미리보기는 읽기전용 `ZonePreview`, 인게임은 `GoogleMapView`로 구조가 다름), 3~4줄 뼈대를 위젯으로 빼면 배관만 늘어 실이득이 없음. 세 번째 사용처가 생기면 그때 추출.
- **범위 밖(미변경)**: 원형 `ZoneSettingWidget`, 읽기전용 `ZonePreviewPage`, 지도 헬퍼 중복(`_calculateZoom` 등), `setup_prison`(삼항 분기) vs `setup_playground`(IndexedStack) 구조 불일치는 별개 사안으로 이번 작업에서 제외.

## 🧩 참고 — 폴리곤 구역 이탈 판정 알고리즘 (이번 커밋 아님)

> ⚠️ 아래는 이번 레이아웃 통일 커밋(`36975467`)의 변경이 **아니다.** 앞선 #456 폴리곤 도메인 작업(`area_shape.dart` 등)에서 이미 구현된 판정 로직을, 레이아웃 작업 검토 중 함께 확인한 결과로 기록한다.

### 원형 vs 폴리곤 이탈 판정 차이

두 도형 모두 진입점은 `AreaShape.contains(내 위치)` 하나 — `true`면 구역 안, `false`면 밖. 판정 "방법"만 다르다.

| | 판정 방식 | 쓰는 값 |
|---|---|---|
| **원형** (`CircleShape`) | 중심~내 위치 직선 거리 ≤ 반지름 → 안 (거리 계산 1번) | 중심점, 반지름 |
| **폴리곤** (`PolygonShape`) | ray casting — 변 교차 횟수 홀/짝 | 꼭짓점 목록 |

폴리곤이 반지름을 못 쓰는 이유: 다각형은 방향마다 경계까지 거리가 달라 단일 거리로 안/밖을 가릴 수 없다.

### ray casting 핵심 (`area_shape.dart:92`)

- 광선은 **1개**, 오른쪽(경도 증가 = 동쪽) 한 방향. 앞뒤·여러 개 아님.
- **실제로 선을 긋지 않는다** — 각 변마다 두 부등식만 계산:
  - 조건 A: 변이 내 위도(수평선)를 위아래로 가로지르나 `(a.lat > p.lat) != (b.lat > p.lat)`
  - 조건 B: 그 교차점 경도가 내 경도보다 큰가(= 내 오른쪽/동쪽) `p.lng < 교차경도`
  - 둘 다 참이면 `inside` 토글. 초기 `false`(밖)에서 홀수번 토글되면 `true`(안).
- "얼마나 멀리 쏘나"에 해당하는 **거리 값은 코드에 없음**(무한 반직선과 대수적으로 동치).
- 경계선 위(변 밟기)는 `_isPointOnSegment`가 먼저 잡아 "안"으로 처리(경계 포함).
- 위경도를 평면(x=경도, y=위도)으로 근사 — 홀짝 위상 판정이라 축 스케일 왜곡에 영향 없음. 게임 스케일(수 km)에서 정확, 날짜변경선·극지 미지원(한국 서비스 전제).

### 분기 위치 — `areaType`이 아니라 union 타입

- 서버 `areaType("CIRCLE"|"POLYGON")` 문자열은 **파싱 매퍼 1곳**에서만 읽혀 `CircleShape`/`PolygonShape` 객체로 변환된다.
- 이후 소비처(인게임 이탈 판정·렌더링, 미리보기)는 `areaType` enum이 아니라 **도형 union 타입**(`when` / `is CircleShape` / `is PolygonShape`)으로 분기한다.
- 이탈 판정 진입점: `game_page.dart:805` `area.playground.contains(...)` (분기는 `AreaShape` 내부 은닉).

### 인게임 폴리곤 렌더링 (코드 경로 확인됨)

- 경계선: `_buildAreaBorderPolygons` (`game_page.dart:1065`) — `PolygonShape`면 경계 `Polygon`(playground=`blue800`, jail=`red500`).
- 구역 밖 딤: `_buildOutsideOverlay` (`:1122`) — `playground.when(circle:, polygon:)`로 hole을 도형별 분기.
- 최소 줌: `boundingRadiusInMeters`(폴리곤=centroid~꼭짓점 최대거리)로 환산 (`:1868`).
- 결론: 인게임 폴리곤 경계·외부 딤·줌 모두 코드 경로상 지원. 단, **실기기 런타임 검증 권장**(ray casting은 꼭짓점 각도 정렬에 의존).
