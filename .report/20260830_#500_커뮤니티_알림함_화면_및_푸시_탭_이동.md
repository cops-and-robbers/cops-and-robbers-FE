# 커뮤니티 알림함 화면 신설, 미읽음 배지 연동, 푸시 알림 탭 이동

### 📌 작업 개요
커뮤니티 상단 종 아이콘이 아무 동작도 없는 자리표였다. 백엔드 #182(Swagger v2.26.0)로 알림함 API
3종이 열려 있어, 알림함 화면을 새로 만들고 종 아이콘 배지·읽음 처리까지 서버와 연결했다. 작업 중
댓글·답글 FCM 푸시가 이미 발송되고 있으나 탭해도 앱만 열리는 것을 확인해, 푸시 탭 → 게시글 상세
이동을 같은 이슈에 포함했다(서버 변경 없음).

**보고서 파일**: `.report/20260830_#500_커뮤니티_알림함_화면_및_푸시_탭_이동.md`

### 🎯 구현 목표
- 알림함 화면 — 내 글의 댓글(`COMMENT`)·답글(`REPLY`) 목록, 최신순 커서 페이징, 무한 스크롤, 당겨서 새로고침
- 종 아이콘 안읽음 배지 — 커뮤니티 탭 복귀·앱 복귀 시 재조회
- 읽음 처리 — 화면 이탈 시 1회, 배지 즉시 갱신
- 푸시 알림 탭 — 앱 종료(콜드 스타트)·백그라운드 양쪽에서 게시글 상세로 이동

### ✅ 구현 내용

#### 데이터·도메인 계층
- **파일**: `community_notification_model.dart`(신규), `community_notification_entity.dart`(신규),
  `community_wire.dart`, `community_remote_datasource.dart`, `community_repository.dart`,
  `community_repository_impl.dart`
- **변경 내용**: `GET /notifications`(cursor·size) · `GET /notifications/unread-count` ·
  `POST /notifications/read` 3종 연동. DTO는 `type`을 문자열로 받고 Repository 경계에서
  `CommunityNotificationType`으로 바꾼다. 봉투는 스크랩 목록과 같은 평평한 정수 커서다.
- **이유**: 모르는 `type`(서버가 나중에 추가할 종류)은 예외 대신 `comment`로 접는다 — 던지면 그 알림
  하나 때문에 목록 한 장이 통째로 에러 화면이 된다(`ENDED` 추가 때 실제로 그랬던 패턴과 같은 이유).

#### 알림함 화면
- **파일**: `community_notification_page.dart`(신규), `community_notification_card.dart`(신규),
  `community_notification_provider.dart`(신규), `community_notification_time_format.dart`(신규)
- **변경 내용**: `community_scrap_page.dart` 골격(무한 스크롤 리스너 + 로딩·에러·빈 상태)을 따르고
  `AppRefreshControl`로 당겨서 새로고침을 붙였다. 빈 상태·에러 상태도 당길 수 있다. 카드는 시안대로
  좌우 24·상하 20 패딩, radius 12, 카드 간 14, 앱바~첫 카드 32. 안읽음은 옅은 파랑 배경.
- **이유**: 알림함은 소켓이 없어 당김이 새 알림을 확인할 유일한 수단이다. 새로고침 실패는 스낵바로
  알린다 — 조용히 삼키면 "당겼는데 아무 일도 없다"가 된다.

#### 읽음 처리
- **파일**: `community_notification_page.dart`
- **변경 내용**: `PopScope.onPopInvokedWithResult`에서 `didPop`일 때 한 번 `POST /read` → 성공 시
  안읽음 개수 provider 무효화. `ref`가 아니라 `ProviderScope.containerOf(context)`를 `await` 전에
  잡아 둔다.
- **이유**: 서버 읽음 상태가 유저당 커서 하나라 개별 알림 읽음 처리가 불가능하다(DEC-0038). 클릭
  시점에 불러도 결과가 같으므로 이탈 시 1회가 가장 단순하다. `ref`를 `await` 너머에서 쓰면 pop 직후
  위젯이 disposed돼 `Cannot use "ref" after the widget was disposed`로 죽는다(안드로이드 실기기에서
  재현) — `ProviderContainer`는 위젯 생명주기와 무관해 안전하다.

#### 종 아이콘 배지
- **파일**: `community_page.dart`, `assets/icons/icon_noti.svg`(rename), `assets/icons/icon_bell.svg`(rename)
- **변경 내용**: `icon_noti_on.svg`로 아이콘을 통째로 바꾸는 대신 `icon_noti.svg` 하나 위에 6×6 빨간
  배지(우상단 -3)를 직접 그린다. `icon_noti_on.svg`·`icon_bell_on.svg`는 삭제, `_off`는 기본 이름으로
  rename. 배지는 커뮤니티 탭 복귀·앱 포그라운드 복귀 시 재조회한다.
- **이유**: 두 svg의 내부 정렬이 달라(on은 배지 자리만큼 여백을 두고 종을 그림) 전환할 때 종 모양이
  미세하게 움직여 보였다. 크기·오프셋 보정으로는 픽셀 단위로 맞지 않아 단일 아이콘 + 오버레이로
  바꿨다.

#### 푸시 알림 탭 → 게시글 상세
- **파일**: `push_navigation_event.dart`(신규), `push_navigation_service.dart`(신규),
  `firebase_messaging_service.dart`, `splash_page.dart`, `main.dart`, `route_paths.dart`
- **변경 내용**: 백엔드 `CommunityFcmNotifier`가 이미 `data{type: COMMENT|REPLY, postId}`를 보내므로
  앱만 고쳤다. 딥링크(`coldStartDeeplink`·`deeplinkEvents`) 패턴을 그대로 따른다.
  - 콜드 스타트: `init()`이 `getInitialMessage()`를 소비하며 목적지를 보관 →
    `coldStartPushNavigationProvider` → SplashPage가 인증·활성 게임 확인을 마친 "홈으로 갈 자리"에서
    홈 대신 `go('/community/{postId}')`
  - 백그라운드: `onMessageOpenedApp` → `pushNavigationEventsProvider` → `_LocalizedApp`이
    `rootNavigatorKey`로 상세 push
- **이유**: 딥링크는 스플래시가 "양보"만 하고 `DeepLinkJoinPage`가 최종 `go`를 맡지만, 알림 탭에는
  그런 중간 페이지가 없다. 스플래시가 양보만 하면 상세 아래 스플래시가 남아 뒤로가기에 갇히고,
  `go(home)`과 경합하면 목적지가 유실된다 — 그래서 스플래시가 직접 `go`한다. 진행 중인 게임이 있으면
  게임 복구가 우선이다.

### 🔧 주요 변경사항 상세

#### 콜드 스타트 dedup을 두지 않은 이유
딥링크는 recents 재실행 때 OS가 launch intent를 다시 주므로 SharedPreferences로 직전 처리 URI를
기억한다. FCM은 다르다 — `firebase_messaging` 플러그인이 `getInitialMessage()`를 한 번 소비하면
저장소에서 지워(`consumedInitialMessages`·`removeFirebaseMessage`) 같은 메시지가 다시 오지 않는다.
플러그인 소스(16.x)로 확인하고 앱 쪽 dedup은 넣지 않았다.

#### 서버 FCM payload (BE 코드 실측)
- 댓글·답글: `notification{title=게시글 제목, body=댓글 내용}` + `data{type: COMMENT|REPLY, postId}`
- 발송 대상은 `allowCommunityPush`가 켜진 기기, 댓글 작성자 본인 제외
- Android `HIGH` priority, iOS `sound: default` — 앱이 종료돼 있어도 OS가 알림을 띄운다
- 채팅 푸시(`data.type: TEXT|GAME_INVITE`)는 이번 범위 밖 — 탭하면 앱만 열린다

**특이사항**:
- 알림 종류는 서버 스펙대로 `COMMENT`·`REPLY` 둘뿐이다. 시안의 "추천 게시글"은 스펙에 없어 만들지
  않았고, 그 아이콘(`icon_post.svg`)도 쓰지 않는다.
- 목록·배지 모두 최근 60일만 내려온다(DEC-0047). 그 이전 알림이 안 보이는 것은 버그가 아니다.
- 비로그인·약관 미동의 상태의 푸시 탭은 라우터 redirect가 처리하고 목적지는 버린다 — 푸시는
  로그인 사용자에게만 오므로 실질 영향이 없다.

### 📌 참고사항
- 배지 갱신은 폴링이다(탭 복귀·앱 복귀·알림함 이탈). 커뮤니티 탭을 보는 중에 달린 댓글은 그 자리에서
  반영되지 않는다 — 알림용 소켓 채널이 없다.
- 남은 후속: 채팅 푸시 탭 라우팅(`communityChat(postId)` case 하나면 된다), 알림 수신 설정 3단
  연동(별도 이슈 문서 있음), 강퇴 errorCode 3종 매핑(#493 잔여)
- 이슈 문서에 결정 사항(시안 스펙·읽음 시점·배지 방식·푸시 탭 범위)을 반영해 두었다
