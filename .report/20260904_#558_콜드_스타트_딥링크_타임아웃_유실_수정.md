### 📌 작업 개요
콜드 스타트에서 딥링크 프로브가 스플래시의 2초 타임아웃을 넘기면 목적지(모집글 상세·초대 참여)가 홈으로 유실되던 문제 수정. 설치 직후 첫 실행(초기화가 느린 환경)에서 잘 재현되며, dedup(last-handled) 특성상 한 번 버려진 링크는 재클릭해도 되살아나지 않는 영구 유실이었다

**보고서 파일**: `.report/20260904_#558_콜드_스타트_딥링크_타임아웃_유실_수정.md`

### 🔍 문제 분석
스플래시는 `coldStartDeeplinkProvider`(getInitialLink + dedup)를 `.timeout(2초)`로 기다리고, 타임아웃이면 "링크 없음"으로 간주하고 홈으로 갔다. 설치 직후 첫 콜드 스타트는 플러그인 채널 초기화·prefs 첫 로드가 겹쳐 프로브가 2초를 넘길 수 있다 — 실측(에뮬레이터 API 36.1, deploy 기준 빌드)에서 같은 링크가 첫 콜드에서는 홈으로 유실되고 재시도에서는 성공하는 것으로 레이스를 확정했다(#558 이슈의 실측 표).

이슈에 적었던 수정 방향 중 **"프로브 조기 시작"은 구현하지 않았다** — 코드를 따라가 보니 `deeplinkEvents`가 앱 첫 프레임(main.dart `_LocalizedApp.build`의 `ref.listen`)에 활성화되면서 `emitColdStart()`가 같은 프로바이더를 즉시 read하므로, 프로브는 이미 스플래시보다 훨씬 이른 시점에 시작되고 있었다. 남는 문제는 "그런데도 늦게 끝나는 프로브를 스플래시가 버린다"는 것뿐이라, 수정은 아래 두 가지로 좁혔다.

### ✅ 구현 내용

#### 1. 프로브 타임아웃 완화 (2→4초)
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart`
- **변경 내용**: `.timeout(const Duration(seconds: 2))` → 4초
- **이유**: 링크 없는 일반 실행은 `getInitialLink()`가 즉시 null을 반환해 대기가 발생하지 않는다. 대기가 실제로 생기는 건 딥링크 실행에서 프로브가 밀린 경우뿐이고, 그때는 홈으로 잘못 가느니 기다리는 것이 맞다

#### 2. 늦게 완료된 프로브 회수 + 최후 안전망
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart`
- **변경 내용**: 타임아웃 발생을 기억해 두고(`deeplinkProbeTimedOut`), auth 대기(최대 5초)가 끝난 시점에 프로브를 동기적으로 한 번 더 확인(`ref.read(...).valueOrNull`)
  - 완료돼 있으면 그 결과를 이번 실행에서 그대로 사용 — 모집글이면 기존 분기대로 상세를 목적지로, 초대면 기존 규칙대로 네비게이션 양보
  - 그때도 미완이면(극단 케이스) `then` 콜백을 걸어 완료되는 대로 모집글 id를 `pendingCommunityPostProvider`에 보존 — 진입 절차가 남은 사용자는 절차 완료 시점에, 이미 로그인된 사용자는 늦어도 다음 실행에서 소비된다(유실 대신 지연). splash가 dispose된 뒤 완료될 수 있어 `ref` 대신 앱 수명의 `ProviderScope.containerOf(context)`로 저장한다
- **이유**: 스플래시의 양보/경합 설계(초대 콜드는 `deeplinkEvents` emit과 동일 dedup 공유)는 건드리지 않고, "버려지는 지점"만 막는 최소 변경. 늦은 초대는 `deeplinkEvents`가 프로브 완료 시점에 emit해 리스너가 join 페이지를 띄우므로, 재확인에서 초대가 나오면 home 이동으로 그 페이지를 덮지 않도록 양보한다

#### 3. 회귀 테스트 (신규)
- **파일**: `test/features/auth/presentation/pages/splash_cold_deeplink_timeout_test.dart` (신규)
- **변경 내용**: 프로브 완료 시점을 직접 제어해 세 경로를 고정 — ①타임아웃 후 auth 대기 중 완료된 모집글 → 상세 이동 ②늦게 완료된 초대 → 홈으로 덮지 않고 양보 ③재확인 시점에도 미완 → 홈 진행 후 완료 시 pending 보존
- **이유**: 실기기·에뮬레이터에서는 프로브 지연이 설치 직후 첫 실행에서만 간헐 재현되므로, 타임아웃 경로는 위젯 테스트로만 결정론적으로 고정할 수 있다

### 🔧 주요 변경사항 상세

**변경하지 않은 것**: `deeplink_service.dart`(dedup·emit 구조)와 `main.dart`(리스너·pending 소비)는 무변경. dedup 마킹 시점(평가 시)도 그대로 뒀다 — 회수·안전망이 생기면서 "마킹됐지만 아무도 소비 못 한" 상태 자체가 사라지므로 마킹 시점을 옮길 필요가 없어졌다. 타임아웃 없는 이벤트 드리븐 단일 경로로의 구조 개선은 이슈에 적은 대로 행사 이후 과제

**특이사항**:
- 안전망 경로(재확인 시점에도 프로브 미완)에서 이미 로그인된 사용자는 pending 소비 트리거(auth 상태 변화)가 이번 실행에 다시 발화하지 않아 **다음 실행에서** 상세가 열린다. 로컬 플러그인 호출이 auth 대기까지 끝난 뒤(실행 후 ~9초+)에도 미완인 극단 케이스라 실제로는 거의 도달하지 않고, 도달해도 유실이 아닌 지연으로 강등된다
- 위젯 테스트의 최소 스플래시 딜레이(`_waitRemaining`)는 실제 시계(`DateTime.now`) 기준이라 FakeAsync 가상 시간과 무관하게 최대 2초가 남는다 — pump를 넉넉히 흘리는 이유를 테스트 주석에 남겼다
