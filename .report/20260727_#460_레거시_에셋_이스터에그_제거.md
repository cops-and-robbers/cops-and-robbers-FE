# 미사용 레거시 에셋 및 클래식 스킨 이스터에그 제거

### 📌 작업 개요

홈 화면 캐릭터를 5번 탭하면 구 버전 캐릭터(`classic` 스킨)로 바뀌던 이스터에그를 제거하고, 그에 딸린 전역 스킨 상태·페이드 트랜지션·전용 문구·SVG 자산을 전 계층에서 걷어냈다. 참조가 끊긴 `assets/` 루트 레거시 PNG 3개도 함께 정리했다.

커밋 5개, 42개 파일 변경(41 추가 / 1060 삭제).

### 🎯 구현 목표

- 이스터에그 트리거와 `classic` 스킨을 코드·문구·자산에서 완전히 제거
- 스킨이 하나만 남으므로 에셋 경로 헬퍼의 죽은 `skinId` 인자 제거
- 레거시 PNG 3개(`splash.png`, `app_icon.png`, `app_icon_1024.png`) 삭제
- 사용자 관점 변화는 "홈 캐릭터를 여러 번 탭해도 아무 일이 없다" 하나로 한정

### ✅ 구현 내용

#### 1. 홈 화면 이스터에그 트리거 제거 (`c74a43c0`)

- **파일**: `lib/features/session/presentation/widgets/home_character_stack.dart`, `lib/features/session/presentation/pages/home_page.dart`, `lib/l10n/app_{ko,en,ja}.arb`
- **변경 내용**: 탭 카운터(`_tapCount`/`_lastTap`)와 `GestureDetector` 두 개, 페이드 트랜지션 호출 제거. `HomeCharacterStack`을 `ConsumerStatefulWidget` → `StatelessWidget`으로 강등. 말풍선의 스킨 분기를 없애고 `homePageWelcomeMessageClassic` 키를 3개 로케일에서 삭제 후 `flutter gen-l10n` 재생성
- **이유**: 이스터에그의 입구를 먼저 막아, 이후 단계에서 내부를 걷어내는 동안에도 사용자가 클래식 스킨에 도달할 수 없게 함

#### 2. 전역 스킨 상태·페이드 트랜지션 제거 (`db3d61c8`)

- **파일**: `lib/core/theme/character_skin_provider.dart`(+`.g.dart`), `lib/core/widgets/fade_skin_transition.dart` 삭제. `participant_card.dart`, `arrest_lock_overlay.dart`, `game_over_result_dialog.dart`, `my_record_dialog.dart` 수정
- **변경 내용**: 스킨을 구독하던 6곳에서 `ref.watch(characterSkinProvider)` 제거. `ParticipantCard`만 `StatelessWidget`으로 강등
- **이유**: 스킨 상태가 사라지면 이를 구독하던 위젯의 `ref` 사용처도 함께 정리해야 함

#### 3. 에셋 경로 헬퍼에서 `skinId` 인자 제거 (`17a49f92`)

- **파일**: `lib/core/constants/character_assets.dart`
- **변경 내용**: `characterAssetPath`, `resultCharacterAssetPath` 시그니처에서 `skinId` 제거하고 경로에 `default` 고정
- **이유**: 스킨이 하나뿐이 되어 쓰이지 않는 확장점이 됨

#### 4. classic 캐릭터 자산 삭제 (`7aa4d294`)

- **파일**: `assets/characters/{police,robber}/classic/`, `assets/characters/{police,robber}/result/classic/` (SVG 19개), `pubspec.yaml`
- **변경 내용**: classic 디렉토리 4곳 삭제 및 `flutter.assets:` 등록 4줄 제거
- **이유**: 코드에서 참조가 끊긴 뒤 자산을 지워 번들 용량 회수

#### 5. 레거시 PNG 3종·런처 아이콘 설정 정리 (`f038a710`)

- **파일**: `assets/{splash,app_icon,app_icon_1024}.png` 삭제. `lib/test_widget_page.dart`, `pubspec.yaml`, `docs/INFORMATION_ARCHITECTURE.md` 수정
- **변경 내용**: 개발용 위젯 카탈로그의 아바타를 실제 게임(`game_action_modal.dart`)과 동일한 회색 플레이스홀더로 교체. `flutter_launcher_icons`의 `image_path`를 실사용 중인 `assets/app_icons/app_icon_en.png`로 교체하고 `adaptive_icon_*` 2줄 제거
- **이유**: 세 파일 중 둘은 참조가 남아 있어, 참조를 먼저 정리하지 않고 파일만 지우면 아이콘 생성기와 개발용 화면이 깨짐

### 🔧 주요 변경사항 상세

#### "레거시"가 아니었던 파일 2개

작업 착수 시점에 세 PNG 모두 미사용으로 알려졌으나, 실제 참조는 아래와 같았다.

| 파일 | 실제 참조 |
| --- | --- |
| `assets/splash.png` | 없음 |
| `assets/app_icon.png` | `lib/test_widget_page.dart` 아바타 다이얼로그 |
| `assets/app_icon_1024.png` | `pubspec.yaml`의 `image_path`, `adaptive_icon_foreground` |

`macos/Runner/Assets.xcassets/AppIcon.appiconset/app_icon_1024.png`는 이름만 같은 macOS 아이콘셋 소속 별개 파일이라 손대지 않았다.

#### ConsumerWidget 강등 판단

스킨 구독을 제거하면 `ref`를 안 쓰게 되는 위젯만 `StatelessWidget`으로 강등했다. 실제 강등 대상은 `HomeCharacterStack`과 `ParticipantCard` 둘뿐이다.

- `ArrestLockOverlay` — 탈옥 확인 콜백에서 `gameEventNotifierProvider` 사용
- `GameOverResultDialog` — `gameResultProvider` 사용
- `MyRecordCard` — `playerGameRecordNotifierProvider` 사용

**특이사항**: `arrest_lock_overlay.dart`의 해당 줄은 `onConfirm: () => ref` 로 줄바꿈되어 있어 `ref.` 패턴 검색에 잡히지 않는다. 검색 결과만 믿고 강등했다면 컴파일이 깨졌을 지점이다.

#### 에셋 디렉토리 규칙 보존

`skinId` 인자는 코드에서 제거했지만 **자산 폴더 구조 `assets/characters/{team}/{skinId}/{state}.svg`는 그대로 유지**했다. SVG 파일을 옮기지 않았고, `character_assets.dart` DartDoc에 확장 방법을 남겼다.

> 스킨을 추가할 때는 `assets/characters/{team}/{skinId}/` 폴더를 만들어 `pubspec.yaml`에 등록하고, 이 함수에 `skinId` 인자를 되살린다.

**이유**: 향후 옷장 시스템을 붙일 때 실제로 재사용되는 부분은 폴더 규칙이다. 반면 지금의 `skinId` 인자는 재사용되지 않는다. 현재 구조는 전역 단일 스킨(토글하면 화면의 모든 참가자가 함께 변경)이지만, 옷장은 참가자별 스킨이 서버에서 내려오는 구조라 데이터 흐름이 다르기 때문이다. 어느 쪽이든 그 시점에 캐릭터를 그리는 화면들은 전부 수정 대상이 된다.

**실기기 수동 확인 필요** — 아래는 자동 검증으로 덮이지 않아 별도 확인이 필요하다.

1. 홈 화면 캐릭터를 빠르게 5회 이상 탭해도 화면이 어두워지거나 캐릭터가 바뀌지 않음

**남은 개선 여지 2건** (이번 범위에서 처리하지 않음)

- `pubspec.yaml`의 `- assets/` 등록이 죽은 설정이 됐다. 이 줄이 등록하던 루트 직속 파일이 이번에 지운 PNG 3개뿐이었기 때문이다(디렉토리 등록은 비재귀라 하위 폴더는 각자 등록되어 있다). 현재 이 줄의 유일한 효과는 `assets/.DS_Store`를 앱 번들에 포함시키는 것이다. 기존부터 있던 동작이라 회귀는 아니다
- `character_assets_bundle_test.dart`가 `ready`/`not_ready`/`jailed` 5건만 로드한다. 이번에 바뀐 `state: 'home'` 2건과 `resultCharacterAssetPath` 12건은 어떤 테스트도 번들 로드로 검증하지 않는다. 경로 문자열 오타가 나면 정적 분석과 테스트가 모두 통과한 채 런타임에만 깨진다. 해당 14개 경로가 실재하고 등록되어 있음은 수동 대조로 확인했다
