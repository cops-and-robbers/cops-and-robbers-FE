# 구역 크기 표시 도형별 대응 (#456)

### 📌 작업 개요

#456으로 폴리곤 구역을 지원하게 됐지만 **구역 크기를 보여주는 UI는 원형 전제로 남아 있었다.** 폴리곤인데도 "반경 523m"로 표시되고, 폴리곤 설정을 마쳐도 버튼이 미설정 색상으로 보였다. 원형은 반경, 폴리곤은 면적으로 표시하도록 바꾸고 3곳에 중복됐던 반경 포맷 로직을 공용 포맷터로 통합했다.

작업 중 `AppSlider.valueFormatter`가 **선언만 되고 본문에서 쓰이지 않는** 것을 발견해, 반경 슬라이더가 최대값에서 "1000km"로 1000배 오표기되던 버그도 함께 수정했다.

### 🔍 문제 분석

#### 문제 1 — 폴리곤을 반경으로 표시

`ZoneInfo.radiusMeters`(int)와 `ZoneSettingButton.radiusMeters`(double?)가 **반경만 받는 타입**이라, 프레젠테이션에 도달하기 전에 도형 정보가 소실됐다. 호출부는 폴리곤의 외접 반경을 억지로 뽑아 넘기고 있었다(`_polygonDisplayRadius`).

| 위치 | 폴리곤일 때 |
| --- | --- |
| 게임 설정 페이지 / 생성 Step3 요약 | 외접 반경을 "반경 523m"로 → 다각형인데 원형처럼 읽힘 |
| 생성 Step0 버튼 | `radiusMeters: null` 전달 → 부가정보 없음 + **설정 완료인데 미설정 색상** |
| 핀 편집 화면 면적 칩 | "면적 0.42km²" — 유일하게 올바르나 포맷 로직이 위젯 private에 갇혀 있었음 |

Step0 버튼의 색상 판정이 `radiusMeters != null`이어서, 폴리곤 모드에서는 값이 항상 null → 완료해도 흐린 색으로 남았다.

#### 문제 2 — 반경 포맷 3중복

동일한 반경 표시 로직이 세 곳에 복제돼 있었다.

- `zone_list_card.dart` `_ZoneItem._displayDistance`
- `zone_setting_button.dart` `_subtitleOf`
- `zone_setting_widget.dart` `_buildRadiusIndicator` (인라인)

ARB에도 문구가 완전히 동일한 중복 키가 있었다 — `zoneRadiusMeter`("반경 {radiusMeters}m")와 `zoneRadiusMeters`("반경 {meters}m").

#### 문제 3 — AppSlider의 valueFormatter 미배선 (작업 중 발견)

`AppSlider.valueFormatter`는 필드 선언과 생성자 파라미터만 있고 **본문 참조가 0건**이었다. 값 텍스트는 `'${value.toInt()}$unit'`을 쓰는데 반경 슬라이더의 `unit`은 `_currentRadius >= 1000 ? 'km' : 'm'`로 동적이었다.

| 반경 | 값 텍스트 | min 라벨 | max 라벨 |
| --- | --- | --- | --- |
| 500m | `500m` ✅ | `100m` ✅ | `1000m` ✅ |
| **1000m** | **`1000km`** ❌ | `100km` ❌ | `1000km` ❌ |

플레이그라운드 반경은 최대 1000m(10m 스텝 90칸)이므로 **슬라이더를 끝까지 끌면 도달하는 상태**였다. 값이 1000배로 오독된다.

### ✅ 구현 내용

#### 1. 공용 포맷터 추가

- **파일**: `lib/core/utils/zone_metric_formatter.dart` (신규)
- **변경 내용**: `formatRadiusValue`, `formatAreaValue`, `AreaShape.metricText(l10n)` 확장 추가
- **이유**: 반경/면적 포맷을 한 곳으로 모으고, 원형/폴리곤 분기를 도형 union 안에 은닉하기 위함

```dart
extension ZoneMetricDisplay on AreaShape {
  String metricText(AppLocalizations l10n) => when(
    circle: (_, r) => l10n.zoneRadiusValue(formatRadiusValue(r)),
    polygon: (points) => l10n.zoneAreaValue(
      formatAreaValue(
        polygonAreaInSquareMeters(sortByAngleAroundCentroid(points)),
      ),
    ),
  );
}
```

표시 규칙:

| 도형 | 표시 | 예 |
| --- | --- | --- |
| 원형 | 반경 | `반경 523m` / `반경 1.50km` |
| 폴리곤 | 면적 | `면적 31,416m²` / `면적 0.79km²` |

- 반경: 1,000m 이상 km(소수 2자리), 미만 정수 m
- 면적: 1,000,000m²(=1km²) 이상 km²(소수 2자리), 미만 정수 m² + 천단위 콤마
- 정수 구간은 `round()`로 통일 (기존에 `toInt()` 버림과 섞여 있었음)

#### 2. 면적 단위 기준을 1ha에서 1km²로 조정

- **파일**: `lib/core/utils/zone_metric_formatter.dart`, `lib/core/widgets/map/pin_zone_setting_widget.dart`
- **변경 내용**: 기존 `_formatArea`(1ha=10,000m² 기준)를 제거하고 공용 `formatAreaValue`(1km² 기준) 사용
- **이유**: 1ha 기준에서는 감옥(반경 100m 상당 ≈ 31,416m²)이 **"0.03km²"로 뭉개져** 크기 구분이 불가능했다. 1km² 기준이면 `31,416m²`로 실수치가 남고, m² 구간 최대가 999,999라 콤마가 가독성을 확보한다.

#### 3. 위젯이 AreaShape를 직접 받도록 변경

- **파일**: `lib/features/session/presentation/widgets/zone_list_card.dart`, `lib/core/widgets/buttons/zone_setting_button.dart`
- **변경 내용**
  - `ZoneListCard({required List<ZoneInfo> zones})` → `({required GameAreaEntity area})`
  - `ZoneSettingButton.radiusMeters`(double?) → `.shape`(AreaShape?)
  - 색상 완료 판정을 `radiusMeters != null` → `shape != null`로 교체
- **이유**: 도형 정보를 소실하지 않고 프레젠테이션까지 전달. 색상 판정 교체로 **폴리곤 완료 시 미설정 색상 버그가 함께 해소**된다.

#### 4. AppSlider valueFormatter 배선

- **파일**: `lib/core/widgets/inputs/app_slider.dart`, `lib/core/widgets/map/zone_setting_widget.dart`
- **변경 내용**: `_formatValue` 도입 후 값 텍스트(2곳)와 min/max 라벨(2곳)이 모두 같은 경로를 타게 함. 반경 슬라이더는 `valueFormatter: formatRadiusValue`로 전환하고 매직 상수 `1000` 3개 제거
- **이유**: 값에 따라 단위가 바뀌는 경우(500m ↔ 1.00km)에도 세 표시가 어긋나지 않게 하기 위함

```dart
/// valueFormatter가 있으면 단위까지 그 함수가 책임진다
String _formatValue(double v) => valueFormatter?.call(v) ?? '${v.toInt()}$unit';
```

#### 5. ZoneInfo 제거 + 중복 ARB 키 정리

- **파일**: `lib/features/session/domain/entities/zone_info.dart`(+`.freezed.dart`) 삭제, ARB 3개
- **변경 내용**
  - `ZoneInfo` 제거 — `id`는 아무도 읽지 않는 죽은 필드였고, `name`은 l10n 상수 2개뿐이었다. `displayDistance` 게터는 `'반경 ${km}km'`를 하드코딩한 i18n 규칙 위반 상태의 죽은 코드였다.
  - ARB: `zoneRadiusValue`("반경 {value}")·`zoneAreaValue`("면적 {value}") 추가, `zoneRadiusKm`·`zoneRadiusMeter`·`zoneRadiusMeters` 3개 삭제(사용처 0)
- **이유**: 호출부 보일러플레이트(~25줄)와 중복 키 제거

**단위는 Dart 한 곳, 어순은 ARB.** `m²`/`km²`는 로케일 무관 SI 기호이므로 포맷 함수가 단일 소스로 갖고, "반경 …"/"면적 …" 어순은 ARB 문장 키가 갖는다. 로케일별 어순 변경(`{value} 면적`)이 ARB 수정만으로 가능하다.

#### 6. 감옥 포함 판정 허용 오차 통일

- **파일**: `lib/core/constants/game_config.dart`, `session_creation_flow_page.dart`, `setup_prison_page.dart`
- **변경 내용**: `GameConfig.zoneContainmentToleranceInMeters` 추가 후 양쪽이 참조
- **이유**: 같은 1m 규칙이 `setup_prison_page`(로컬 명명 상수)와 방 생성 플로우(리터럴 `1.0`)로 갈려 있었다

### 🔧 주요 변경사항 상세

#### session_creation_flow_page.dart — 도형 게터로 분기 흡수

원형/폴리곤 삼항 분기가 5곳에 흩어져 있던 것을 게터 2개로 모았다.

```dart
/// 플레이그라운드 도형 — 현재 모드 입력이 유효할 때만 non-null
AreaShape? get _playgroundShape => ...;
AreaShape? get _prisonShape => ...;
```

이 게터로 정리된 것:

- `_isPlaygroundSet`·`_isPrisonSet` → `_xxxShape != null`로 흡수(게터 2개 제거)
- `_polygonDisplayRadius` 삭제 — 카드 표시용 억지 변환이었음
- Step0 전달부의 `_areaType == circle ? … : null` 삼항 2개 제거
- Step3 전달부의 `ZoneInfo` 2개 + 삼항 2개 제거
- `_buildAreaEntity`가 게터를 재사용 → **감옥 ⊂ 플레이그라운드 포함 검증만** 담당

**특이사항**: 게터는 접근할 때마다 검증(폴리곤이면 자기교차 O(n²))과 객체 할당을 수행한다. 꼭짓점이 최대 10개라 실측이 무의미한 규모이고 리팩토링 전에도 `_isPlaygroundSet`가 같은 검증을 했으므로 회귀는 아니다.

#### zone_metric_formatter.dart — 정렬 후 면적 계산

```dart
polygon: (points) => l10n.zoneAreaValue(
  formatAreaValue(
    polygonAreaInSquareMeters(sortByAngleAroundCentroid(points)),
  ),
),
```

저장·응답의 꼭짓점 순서를 신뢰하지 않고 정렬한 뒤 계산한다. shoelace 공식은 자기교차 다각형에서 잘못된 값을 내는데, 표시 시점에는 `isValidPolygon` 검증을 거칠 수 없다. n ≤ 10이라 정렬 비용은 무의미하다.

**특이사항**: 천단위 콤마는 `NumberFormat('#,##0')` 고정 패턴을 쓴다. 지원 3로케일(ko/en/ja)이 모두 콤마이고, 앱이 시스템 로케일이 아닌 `appLocaleProvider`로 언어를 관리해 `Intl.defaultLocale` 기반 자동 선택은 불일치할 수 있다. `'#,##0'`은 값이 0일 때도 최소 한 자리를 보장한다.

#### app_slider.dart — editable과 동시 사용 금지

편집 모드는 TextField에 원시 숫자를 넣으므로 포맷이 무시된다. 미래의 함정을 막기 위해 assert를 추가했다(기존 `displayValue` assert와 같은 방식).

```dart
assert(
  !(editable && valueFormatter != null),
  'AppSlider: editable과 valueFormatter는 함께 사용할 수 없다 '
  '(편집 모드는 TextField에 원시 숫자를 넣으므로 포맷이 무시됨)',
);
```

**특이사항**: `valueFormatter`를 넘기는 호출부가 반경 슬라이더 하나뿐이라, 인원(2~50명)·라운드(10~180분)·위치공유·경찰출동 슬라이더는 폴백 경로(`?? '${v.toInt()}$unit'`)로 출력이 완전히 동일하다.

### 📌 참고사항

**범위에서 제외한 항목**

- **편집 모드 원형→핀 전환 시 지도 카메라**: `PinZoneSettingWidget`은 `initialPoints`가 비면 현재 GPS를 카메라로 쓴다. 원형→핀 전환 시 항상 빈 목록이라, 기존 구역과 먼 곳에서 핀을 찍기 시작할 수 있다. 별도 작업으로 남김(`initialCameraTarget` 파라미터 추가 + 편집 모드에서 기존 도형 `centroid` 전달로 해결 가능).
- **줌 레벨 테이블 매직 상수**: `zone_setting_widget.dart`의 `<= 1000 => 12.0`, `if (radiusMeters <= 1000) return 14`는 표시 포맷과 무관한 카메라 도메인이라 통합 대상이 아니다.
- **`AppSlider`의 동적 단위 API**: 반경 슬라이더는 값에 따라 단위가 바뀌는데 `unit`은 슬라이더 전체에 하나뿐인 고정 문자열이다. 이번엔 `valueFormatter`가 단위까지 책임지게 해서 우회했다. 근본적으로는 `unit` 대신 `labelFormatter`를 받는 API 변경이 맞지만, 소비처 5곳에 파급되므로 필요해질 때 진행.

**설계 문서**: `docs/superpowers/specs/2026-07-25-zone-metric-display-design.md`, `docs/superpowers/plans/2026-07-25-zone-metric-display.md` (`.gitignore`에 있어 Git 추적 안 됨)

리뷰 과정에서 "`AppSlider` 포맷은 손대지 않는다"는 초기 결정이 뒤집혔다. `valueFormatter` 미배선을 발견하면서 제외 근거가 성립하지 않게 됐고, 배선 후에는 별도 헬퍼 분리 없이 해결됐다. 문서에 뒤집힌 근거를 함께 기록해 뒀다.

### 확인된 동작 범위

- **생성·수정 모두 원형↔핀 전환 가능**: `AreaTypeToggle`이 생성 플로우와 대기방 설정 수정에 모두 노출된다. 편집 시 플레이그라운드 타입을 바꾸면 감옥을 반드시 다시 설정하도록 강제해(타입이 다르면 기존 감옥을 버림) 서버의 "타입 혼합 불가" 제약을 구조적으로 만족한다.
- **감옥은 독립 토글 없음**: 플레이그라운드 타입을 따른다(서버 제약).
- **다른 참가자 동기화**: `AREA_UPDATED` 이벤트는 payload를 파싱하지 않고 캐시만 무효화하며, 재조회 응답을 `GameAreaModel.toEntity()`가 `areaType`별로 분기하므로 타입과 무관하게 동작한다.
- **줌 계산**: 원형·폴리곤 모두 `boundingRadiusInMeters`(폴리곤은 centroid~꼭짓점 최대거리)로 환산해 기존 파이프라인을 재사용한다.
