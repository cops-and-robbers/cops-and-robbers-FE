# 번역이 없어 대체된 공지에 안내 표시 (language·requestedLanguage 매핑)

### 📌 작업 개요
BE #185(Swagger v2.29.0)가 공지 응답에 `language`(실제 내려간 본문의 언어)와
`requestedLanguage`(요청한 언어)를 추가해 **"요청한 언어의 번역이 아직 없다"는 사실 자체를
계약에 노출**했다. 그런데 `NoticeResponseModel`은 두 필드를 받지 않아 앱이 그냥 버리고
있었다 — freezed가 모르는 키를 조용히 무시하므로 `analyze`도 테스트도 울지 않는다.

공지가 현재 앱 언어로 나오는 것 자체는 #506이 이미 했다. 이 작업은 그 나머지 절반,
**서버가 대체했을 때 그 사실을 사용자에게 알리는 것**이다.

**보고서 파일**: `.report/20260831_#511_번역이_없어_대체된_공지에_안내_표시.md`

| 상황 | 서버 응답 | 개선 전 | 개선 후 |
|---|---|---|---|
| 일본어 번역이 있다 | `language: ja`, `requestedLanguage: ja` | 일본어 본문 | 일본어 본문 |
| 일본어 번역이 없다 | `language: ko`, `requestedLanguage: ja` | 한국어 본문 (설명 없음) | 한국어 본문 + 안내 |

### 🎯 구현 목표
- 응답의 두 언어 필드를 앱 모델까지 실제로 들여온다
- 대체 여부 판정을 순수 함수로 빼고 테스트로 고정한다
- 대체된 공지에만 안내를 띄우고, 본문은 그대로 보여준다
- 문구는 ko/en/ja 세 언어로

### ✅ 구현 내용

#### 1. DTO — 언어 쌍 매핑 + 대체 판정 getter
`NoticeResponseModel`에 `String? language` · `String? requestedLanguage`를 더하고,
`isTranslationFallback`를 순수 getter로 뒀다(freezed `const NoticeResponseModel._();` 패턴,
선례: `AgreementStatusEntity.hasAllRequired`).

#### 2. Entity — 판정 결과 하나만
`NoticeEntity`는 `@Default(false) bool isTranslationFallback` 하나만 받는다. 이 클래스의
기존 doc이 "UI가 직접 보는 형태, DTO에서 사용하지 않는 필드는 제외"라고 선언하고 있어
그 계약을 따랐다 — 언어 코드 두 개를 도메인까지 끌면 UI가 문자열을 비교하게 된다.

#### 3. 안내 UI — 펼친 본문 위
`notice_card.dart`의 `isExpanded` 블록 안, 본문 바로 앞에 한 줄. 스타일은 날짜와 같은
`AppTextStyles.tag_12` + `AppColors.black600`으로 새 토큰 없이 붙였다.

#### 4. 문구 3로케일
`noticeTranslationFallback` 1키. 톤 린터 통과.

| 로케일 | 문구 |
|---|---|
| ko | 아직 번역 준비 중이라 원문 그대로 보여드려요 |
| en | Translation is on the way — showing the original for now |
| ja | 翻訳を準備中のため、原文のまま表示しています |

### 🔧 주요 변경사항 상세

#### 이슈에 적힌 미매핑 2개가 실제로는 3개였다
착수 전 `docs/api-docs.json` v2.30.0의 `NoticeResponse`를 통째로 펴 보니 **9필드**인데 앱
모델은 **6필드**였다. 미매핑은 `language`·`requestedLanguage`에 더해 **`category`까지 3개**다.
`category`는 카테고리 칩이 쿼리 파라미터로만 동작해 응답을 읽을 필요가 없으므로 이 PR
범위 밖으로 두되, 사실을 기록으로 남긴다. 티켓의 개수는 스냅샷이라 정본이 자라면 낡는다.

#### 대소문자가 어긋났으면 안내가 항상 떴을 것이다
api-docs의 응답 예시는 `"ja"` 소문자인데, 같은 PR의 마이그레이션은 기존 공지를 `'KO'`
대문자로 넣었다(`INSERT ... SELECT id, 'KO', title, content FROM notices`). 실제로 어느
쪽이 내려오는지는 **api-docs로 판정할 수 없다.**

대문자로 내려온다면 `language != requestedLanguage`가 항상 참이 되어, 일본어 번역이 멀쩡히
있는 공지에도 "번역 준비 중" 안내가 붙는다. 서버 코드를 열어 배제했다:

- `NoticeLanguage.code()` = `name().toLowerCase(Locale.ROOT)` → **응답은 양쪽 다 소문자**
- DB 저장은 enum 이름(`KO`)이지만 응답 직전에 소문자화된다

같은 김에 하나 더 확인했다. `NoticeController.toLanguage()`는 지원하지 않는 코드를 400이
아니라 `KO`로 폴백하므로, 그때는 `requestedLanguage`도 보낸 값이 아니라 `ko`로 내려온다.
앱에서는 `appLocaleProvider`가 ko/en/ja만 내보내므로 발생하지 않는다.

#### 두 필드를 nullable로 받은 이유
현재 서버는 record 생성자에서 두 값을 무조건 채우지만, api-docs의 `NoticeResponse`에는
`required` 배열 자체가 없다. 한쪽이라도 없으면 대체 여부를 **알 수 없으므로**, 안내를
띄우지 않는 쪽(false)으로 떨어뜨린다. 계약이 좁아지는 방향으로는 화면이 조용해진다.

#### 안내를 카드 헤더가 아니라 펼친 본문 위에 둔 이유
어드민 번역 편집 화면이 아직 없어(`dongsim-web#72`, 미착수) **ja/en 번역이 0건**이다.
지금 헤더(항상 보임)에 두면 일본어·영어 사용자의 공지 목록이 통째로 안내로 덮인다.
안내는 "지금 읽고 있는 이 본문이 원문이다"라는 말이므로, 본문을 펼쳤을 때 그 바로 앞에서만
띄운다. 문구도 부정형("번역이 없어요") 대신 준비 중으로 잡아 톤을 낮췄다.

#### `requestedLanguage`도 받는 이유 — 현재 로캘과 비교하면 안 된다
앱이 자기가 보낸 언어를 알고 있으니 `language` 하나만으로도 비교는 된다. 그런데
`NoticesNotifier.build()`가 `appLocaleProvider`를 watch 해서 언어가 바뀌면 0페이지부터
재조회한다(#506). 그 사이 화면에 남아 있는 **이전 언어의 목록**을 "현재 로캘 vs language"로
비교하면 재조회 중인 stale 데이터를 전부 대체됨으로 오판한다. `requestedLanguage`는 그
응답이 어떤 요청에 대한 것인지가 데이터에 붙어 오므로 그 창이 없다.

### 📦 의존성 변경
없음. 서버 변경도 없다(BE #185에서 이미 완료).

|---|---|---|
| `notice_response_model_test.dart` | 6건 | 두 필드가 실제로 파싱된다 / 키가 없어도 안 깨지고 false / 한쪽만 있어도 false / 같으면 false·다르면 true |
| `notice_repository_impl_test.dart` | +1건 | 판정 결과가 DTO에서 Entity로 옮겨진다 (대체 1건 + 정상 1건 한 응답에서) |
| `notice_card_test.dart` | 3건 | 펼침+대체=보임 / 펼침+동일=없음 / 접힘=없음 |

테스트가 실제로 가드하는지 **변이 4종으로 확인**했다. 전부 RED가 됐다:

| 변이 | 잡은 테스트 |
|---|---|
| 판정을 `!=` → `==`로 뒤집기 | 모델·리포지토리·위젯 |
| null 가드 제거(한쪽만 있어도 판정) | `is_not_fallback_when_only_one_side_is_present` |
| 카드에서 조건 제거(항상 표시) | `hides_fallback_hint_when_requested_language_was_served` |
| 안내를 `isExpanded` 밖으로(헤더 위치) | `hides_fallback_hint_when_card_is_collapsed` |

위젯 테스트는 문구를 하드코딩하지 않고 `lookupAppLocalizations(const Locale('ko'))`에서
읽는다 — 카피가 바뀌어도 테스트가 깨지지 않고, 키가 사라지면 컴파일에서 잡힌다.

### 📌 참고사항
- **`category` 응답 미매핑은 남는다.** 칩 필터는 쿼리 파라미터로만 동작하므로 현재 동작에
  영향이 없다. 별건으로 다룬다.
- **번역 데이터가 채워지기 전까지 ja/en 사용자는 사실상 모든 공지에서 이 안내를 본다.**
  의도된 동작이며(실제로 원문을 읽고 있는 게 맞다) 문구를 은은하게 잡은 이유다.
  `dongsim-web#72`(어드민 공지 번역 편집 화면)가 닫히면 자연히 줄어든다.
- 앱에는 공지 상세 화면이 없다. `GET /api/notices` 목록만 부르고
  `GET /api/notices/{noticeId}`는 호출하지 않으며, 공지는 `notice_card.dart`의 `isExpanded`
  펼침 카드다. 그래서 손댄 곳이 모델·엔티티 + 카드 한 곳뿐이다.
