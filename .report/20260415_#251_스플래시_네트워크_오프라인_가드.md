### 📌 작업 개요
스플래시 단계에서 네트워크 연결 상태를 먼저 점검하고, 오프라인이면 이후 플로우(Remote Config, Auth, 게임 상태 조회) 진입을 차단하는 오프라인 가드 추가. 연결 복구 시 자동/수동으로 원래 흐름에 복귀한다.

### 🎯 구현 목표
- 콜드 스타트 직후 네트워크 미연결 상태에서 API 호출이 무분별하게 실패하는 문제 차단
- 오프라인 전용 인라인 UI + 수동 재시도 버튼 제공
- `connectivity_plus` 스트림 구독으로 연결 복구 시 자동 재진입
- 복구 경로(recovery) 중 네트워크성 실패가 다시 발생하면 오프라인 화면으로 되돌리는 루프 복구 구조

### 🔧 주요 변경사항 상세

#### 복구 루프 구조 (핵심)
```
[앱 시작] → isConnected() 체크
   │
   ├─ 연결됨 → Remote Config → Auth → 게임 상태 조회 → 목적 화면
   │                │              │             │
   │                └─ 네트워크 실패(recovery=true) → _returnToOffline()
   │
   └─ 연결 안 됨 → _isOffline=true → 오프라인 UI + 스트림 구독
                                           │
                                           ├─ 자동: onConnectivityChanged → _navigateToNextScreen(isRecovery: true)
                                           └─ 수동: 재시도 버튼 → isConnected() 재확인 → 재진입
```

복구 경로에서 다시 네트워크 실패가 발생하면 홈 fallback으로 빠지지 않고 오프라인 화면으로 **되돌린다**. 비복구(최초) 경로에서는 기존 동작(홈 fallback, 재시도 다이얼로그)을 유지하여 회귀 최소화.

#### captive portal 등 "링크만 있고 통신 안 됨" 케이스
`ConnectivityService._hasConnectivity`는 `ConnectivityResult.none` 외의 값이 있으면 연결로 간주한다. 실제 HTTP 통신 실패는 후속 API 호출에서 `NetworkException`/`DioException`으로 감지 → `isNetworkFailure`로 판정 → 복구 루프가 오프라인 UI로 되돌리는 구조로 상위에서 흡수한다.

## 🩹 추가 보강 (커밋 `2f4b488` — fix : 스플래시 수동 재시도 오프라인 피드백 복구)

초기 구현을 시뮬레이터 기내 모드에서 테스트한 결과, **"다시 시도" 버튼을 눌러도 아무 피드백이 없는 현상**이 재현되었다. 에러 자체는 `session_repository_impl.dart:99`까지 도달했지만 스낵바가 뜨지 않았고, 대신 zone error handler가 `🔥 Async Error: NetworkException [connection-error]` 로그를 남겼다. 원인 분석 및 수정 내역은 아래와 같다.

### 🔍 근본 원인: unhandled async error 누수

기존 게임 상태 조회 블록의 패턴:

```dart
final statusFuture = _fetchActiveGameWithRetry(); // (1) 호출 즉시 실행 시작
await _waitRemaining(startTime, minDelay);        // (2) 2초 대기
final status = await statusFuture;                // (3) 뒤늦게 await
```

(1)에서 생성된 `statusFuture`는 호출 직후 리포지토리 에러로 빠르게 reject되는데, 그 시점에는 아직 아무도 `.then` / `.catchError` / `await`를 걸고 있지 않다. Dart는 이 상태의 에러를 **"unhandled async error"** 로 분류하여 `Zone.onUncaughtError` 로 먼저 내보내버리고, 이후의 `await statusFuture`가 뒤늦게 만나더라도 외부의 `on NetworkException` catch까지 정상적으로 흘러오지 않는다. 결과적으로:

- `_returnToOffline()` 호출 안 됨 → `_isOffline`은 false 상태 유지
- `_onManualRetry`의 `if (_isOffline) → 스낵바` 조건이 false → 스낵바 미표시
- 사용자는 "버튼이 먹통"처럼 인식

### ✅ 수정 내용

#### 1) `Future.wait`로 에러 전파 경로 통일
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart`
- **변경**: 게임 상태 조회와 최소 딜레이를 `Future.wait`로 묶어 단일 await로 처리
- **이유**: `Future.wait`는 첫 에러 발생 시 즉시 호출자(대기 중인 await)로 에러를 전파하여 핸들러 공백 구간이 생기지 않는다. 병렬성도 유지

```dart
final results = await Future.wait<Object?>([
  _fetchActiveGameWithRetry(maxRetries: isRecovery ? 0 : 2),
  _waitRemaining(startTime, minDelay),
]);
final status = results[0] as UserGameStatusEntity;
```

#### 2) `_fetchActiveGameWithRetry` 재시도 판정 로직 수정
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart`
- **변경**: `on DioException` → `catch (e)` + `isNetworkFailure(e)` 체크
- **이유**: Repository는 `DioExceptionHandler.handle()`로 `DioException`을 `NetworkException` 등 `AppException`으로 변환해 던지기 때문에 `on DioException`만으로는 매칭되지 않아 재시도가 전혀 동작하지 않았다. 네트워크성 실패만 재시도하고 5xx/파싱 에러 등은 즉시 전파

#### 3) 복구 경로에서 재시도 생략
- **변경**: `_fetchActiveGameWithRetry(maxRetries: isRecovery ? 0 : 2)`
- **이유**: 수동 재시도/자동 복구는 이미 앱이 warm 상태이므로 콜드 스타트 네트워크 스택 지연을 대비한 재시도가 불필요. 사용자 피드백까지 걸리는 시간을 단축 (최초 콜드 스타트 경로에선 기존처럼 2회 재시도 유지)

#### 4) `_onManualRetry` 예외 안전성 보강
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart`
- **변경**: `_navigateToNextScreen` 호출을 try-catch로 감싸고, 예외가 네트워크성 실패이면 직접 `_returnToOffline()` 호출. 최종적으로 `_isOffline`이 true이면 스낵바 표시
- **이유**: 어떤 예기치 못한 경로로든 예외가 새어나오는 경우에도 사용자가 "버튼이 먹통"이라고 느끼지 않도록 최후의 피드백 보장

```dart
Future<void> _onManualRetry() async {
  if (_isNavigating) return;
  try {
    await _navigateToNextScreen(isRecovery: true, skipConnectivityCheck: true);
  } catch (e) {
    debugPrint('⚠️ SplashPage: 수동 재시도 중 예외 - $e');
    if (isNetworkFailure(e) && mounted && !_isOffline) {
      await _returnToOffline();
    }
  }
  if (mounted && _isOffline) {
    AppSnackbar.show(
      context,
      message: '아직 네트워크에 연결되지 않았어요',
      backgroundColor: AppColors.red,
    );
  }
}
```

#### 5) 수동 재시도 경로 사전 체크 우회
- **변경**: `_navigateToNextScreen`에 `skipConnectivityCheck` 파라미터 추가. 수동 재시도 시 `connectivity_plus.isConnected()` 사전 체크를 건너뛰고 실제 API 호출로 연결 여부를 판정
- **이유**: `connectivity_plus`의 보고값이 stale하거나 captive portal인 경우 사전 체크에서 false가 나와 버튼이 먹통처럼 보이는 문제가 있었다. 자동 복구 경로(스트림 리스너)는 기존대로 동작

#### 6) 오프라인 UI 버튼 레이아웃 정리
- **파일**: `lib/features/auth/presentation/pages/splash_page.dart` (`_buildOfflineView`)
- **변경**: 기존 `Center` 고정 레이아웃 → `SafeArea + Padding(AppPadding.all20) + Column(Expanded(Center) + AppButton)` 구조
- **이유**: `session_creation_flow_page.dart`의 하단 버튼 패턴과 일치시켜 앱 전반의 CTA 위치 일관성 확보. 재시도 버튼은 화면 하단에 고정되고 아이콘/텍스트는 남은 영역 중앙에 배치

### 🔧 수정 후 플로우

```
[다시 시도 탭]
   ↓
_onManualRetry (try-catch)
   ↓
_navigateToNextScreen(isRecovery: true, skipConnectivityCheck: true)
   ↓
Connectivity 사전 체크 스킵 → _isOffline = false 리셋 (UI 깜박임)
   ↓
Remote Config (캐시로 통과 가능) → Auth (로컬 상태) → Future.wait([게임상태, 최소딜레이])
   ↓
Repository line 99 → NetworkException
   ↓
Future.wait가 즉시 에러 전파 → on NetworkException catch
   ↓
_returnToOffline() (1s delay) → _isOffline = true + 스트림 재구독
   ↓
_navigateToNextScreen 반환 → _onManualRetry 복귀
   ↓
_isOffline == true → AppSnackbar.show("아직 네트워크에 연결되지 않았어요")
```

### 📌 교훈
- **Dart의 async 에러 처리**: Future 핸들을 보관만 하고 즉시 await/catch를 걸지 않으면, 그 사이에 reject된 에러가 zone으로 새어나갈 수 있다. 병렬 실행이 필요하면 `Future.wait`로 묶거나 생성 직후 `.catchError`를 연결해야 한다
- **Repository 변환 경계**: Repository가 예외를 `DioException → AppException`으로 변환하면, 호출자의 `on DioException` catch는 더 이상 매칭되지 않는다. 변환 경계를 넘는 쪽에서는 반드시 변환된 타입으로 catch하거나, `isNetworkFailure` 같은 판정 함수를 쓰는 것이 안전하다
