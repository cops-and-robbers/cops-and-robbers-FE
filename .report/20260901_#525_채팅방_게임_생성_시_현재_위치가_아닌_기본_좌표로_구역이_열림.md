### 📌 작업 개요

채팅방에서 게임을 생성하면 구역 설정 지도가 현재 위치가 아니라 늘 같은 기본 좌표(어린이대공원역)에서 열리던 버그 수정. 원인은 채팅방 진입점이 홈이 하던 진입 전 처리 두 가지를 빠뜨린 것이다. 진입점마다 붙이는 대신 진입 함수 하나로 모았고, 그 과정에서 드러난 폴백 좌표 중복도 함께 정리했다.

**보고서 파일**: `.report/20260901_#525_채팅방_게임_생성_시_현재_위치가_아닌_기본_좌표로_구역이_열림.md`

### 🔍 문제 분석

두 진입점이 하는 일이 달랐다.

| | 홈 (`home_page.dart:300`) | 채팅방 (`community_chat_room_page.dart:240`) |
|---|---|---|
| 위치 권한 게이트 | `gameEntryGateProvider.ensure()` | 없음 |
| 이전 초안 정리 | `SessionDraftStorageService().clearDraft()` | **없음** |
| 라우팅 | `context.go(...)` | `context.push(..., extra: postId)` |

증상을 만든 것은 **초안 정리 누락**이다.

```
clearDraft() 안 함
  → _loadDraftData() 가 이전 초안의 playgroundCenter 복원
  → setup_playground_page:389 이 initialCenter 로 전달
  → zone_setting_widget:163  initialCenter ?? 현재위치 ?? fallback
                             ^^^^^^^^^^^^^ 첫 항에서 끝나 현재 위치 조회를 안 함
```

한 번 폴백 좌표로 저장된 초안이 계속 복원되는 구조라 권한 상태와 무관하게 항상 같은 좌표가 나온다. 홈은 진입 전에 초안을 지우므로 매번 현재 위치를 새로 잡는다.

**게이트 누락은 이번 증상의 원인이 아니다.** 조사 초기에 원인으로 지목했으나 틀렸다 — `GameEntryGate.ensure()`는 권한을 요청하지 않고 `canAccessLocation()`으로 **확인만** 하고, 권한은 `main.dart:61`이 앱 시작 시 이미 확보한다. 따라서 게이트를 건너뛰어도 위치 조회는 성공한다. 다만 게이트 누락은 **별개의 실재 결함**이다 — 권한이 회수된 기기에서는 채팅방 진입만 안내 다이얼로그 없이 조용히 폴백으로 들어간다.

**재발이다.** #432에서 딥링크 진입이 같은 게이트를 우회하던 버그를 고치며 `GameEntryGate`를 공용 헬퍼로 추출했지만, **호출 책임은 각 화면에 남겨** 두었다. #516이 채팅방 진입점을 추가하면서 그 목록에 자기를 넣지 않았다. 헬퍼는 부를 수 있게 할 뿐 부르게 만들지 않는다.

### ✅ 구현 내용

#### 게임 생성 진입 함수 신설

- **파일**: `lib/features/session/presentation/game_creation_entry.dart` (신규)
- **변경 내용**: `startGameCreation({context, ref, communityPostId, replace})` — 게이트·초안 정리·라우팅을 한 함수에 묶었다
- **이유**: 진입점마다 두 줄을 각각 붙이면 네 번째 진입점이 또 빠뜨린다. 부를 자리를 하나로 만들면 새 진입점이 이 함수를 부르지 않은 것이 리뷰에서 드러난다

#### 두 진입점을 그 함수로 위임

- **파일**: `lib/features/session/presentation/pages/home_page.dart`, `lib/features/community/presentation/pages/community_chat_room_page.dart`
- **변경 내용**: 홈은 기존 17줄을 1줄 호출로 대체(동작 동일), 채팅방은 같은 함수를 호출
- **이유**: 홈의 기존 동작이 정답이었으므로 그것을 공용화하고 채팅방을 맞췄다

#### 현재 위치 폴백 결정 일원화

- **파일**: `lib/core/services/location/device_location_service.dart` 외 5개
- **변경 내용**: `fallbackLocation` 상수 하나로 통합, `getCurrentLatLng()` 추가, `getCurrentPosition()`이 권한·서비스 예외도 흡수
- **이유**: 이번 버그가 하필 늘 같은 좌표로 보인 이유가 이 구조다. 권한 문제가 "그냥 좀 이상한 위치"로만 드러났다

### 🔧 주요 변경사항 상세

#### game_creation_entry.dart

`replace` 플래그로 `go`/`push` 차이를 보존한다. 홈은 현재 화면을 대체하고, 채팅방은 위에 쌓아 뒤로가기로 방에 돌아온다 — 의도된 차이라 통일하지 않았다.

**특이사항**:

- **대기방의 게임 설정 수정 흐름(`gameSettingsWithId`)은 합치지 않았다.** 그쪽은 이미 만들어진 게임의 구역을 고치는 흐름이라 초안을 지우면 안 되고, `initialCenter`가 기존 구역으로 채워지는 것이 정상 동작이다. 합쳤다면 "설정 열었더니 구역이 초기화됨"이라는 반대 방향 버그가 난다
- 홈의 방 **참여**(`_showJoinRoomDialog`)는 생성과 다른 흐름이라 자체 게이트 호출을 그대로 뒀다
- 함수 DartDoc에 #432·#525 재발 이력을 적었다. 근거가 없으면 다음 사람이 "이 래퍼 굳이 필요한가"라며 도로 풀어놓는다

#### DeviceLocationService

폴백 좌표가 5개 파일에 복붙돼 있었다.

| 파일 | 옛 상수명 |
|---|---|
| `zone_setting_widget.dart:139` | `_fallbackLocation` |
| `pin_zone_setting_widget.dart:92` | `_fallbackLocation` |
| `record_route_map.dart:80` | `_fallbackCenter` |
| `google_map_view.dart:42` | `_fallback` |
| `community_location_picker_page.dart:56` | `_fallbackTarget` |

`getCurrentPosition()`은 `TimeoutException`만 잡아 권한 거부(`PermissionDeniedException`)·위치 서비스 꺼짐(`LocationServiceDisabledException`)이 호출부의 제각각인 `catch (e)`로 흘러갔다. 이제 서비스가 흡수해 `null` 하나로 수렴하고, 마지막으로 알던 위치가 있으면 그것을 쓴다.

지도용 `getCurrentLatLng()`를 더해 두 위젯이 각자 갖고 있던 `Position` → `LatLng` 변환 헬퍼 2개를 지웠다.

**특이사항**:

- **폴백을 주면 안 되는 곳은 `null` 계약을 유지했다.** `game_page:695`·`930`(서버로 위치 전송)과 `community_provider:121`(주변 검색)은 가짜 좌표가 나가면 게임 판정과 검색 결과가 틀어진다. "내 위치로 이동" 버튼 2곳도 위치를 못 얻으면 이동하지 않는 편이 맞다. 이 구분을 `fallbackLocation` DartDoc에 적었다
- **폴백을 썼다는 사실을 호출부에 알리는 것은 만들지 않았다.** 아직 그것을 필요로 하는 곳이 없다. 필요해지면 `getCurrentLatLng`이 결과 타입을 돌려주면 된다
- `app_lifecycle_service.dart:119`의 직접 `Geolocator` 호출은 위치를 쓰려는 게 아니라 OS suspend 방지가 목적이라 범위에서 제외했다

### 📌 참고사항

- 커밋을 롤백 단위로 분리했다. 폴백 정리를 되돌려도 버그 수정은 남고, 버그 수정을 되돌려도 정리는 유효하다
  - `87a38ee0` fix : 게임 생성 진입을 한 함수로 모아 채팅방 진입이 이전 초안을 남기지 않게 한다
  - `98ea65b3` refactor : 현재 위치 폴백 결정을 DeviceLocationService 한 곳으로 모은다
- 폴백 정리는 처음 별도 이슈로 분리했다가 같은 도메인이라는 판단으로 이 브랜치에 합쳤다
- **`_loadDraftData()`의 세션 간 이어하기는 원래도 홈 경로에서 도달 불가였다** — 홈이 진입 전에 항상 초안을 지우기 때문이다. 이번 수정으로 채팅방도 같아진다. 초안 이어하기를 기능으로 살릴지 아예 걷어낼지는 별개 판단이라 손대지 않았다
- **폴백 좌표를 계속 어린이대공원역으로 둘지는 미결이다.** 개발 편의로 정해진 값으로 보이는데, 위치를 못 얻은 사용자에게 서울 특정 지점을 보여주는 게 맞는지는 따로 정할 문제다
