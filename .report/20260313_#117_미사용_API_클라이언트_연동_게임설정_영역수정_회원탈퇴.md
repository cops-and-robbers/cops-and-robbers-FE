### 📌 작업 개요

백엔드에서 제공하지만 Flutter 클라이언트에서 미연동 상태였던 3개 API를 연동하고, 관련 UI/UX를 구현.

- `PUT /api/games/{gameId}/settings` — 게임 설정 수정 (방장 전용)
- `PUT /api/games/{gameId}/area` — 게임 영역(플레이그라운드·감옥) 수정
- `DELETE /api/user/me` — 회원 탈퇴

추가로 대기실 안정성 개선, 코드래빗 리뷰 반영, UX 개선 작업 포함.

---

### 🎯 구현 목표

1. 대기실에서 방장이 게임 설정(라운드 시간, 위치 공개 주기, 경찰 대기 시간, 최대 인원)을 수정 가능하도록 구현
2. 대기실에서 게임 영역(플레이그라운드, 감옥)을 지도 기반으로 재설정 가능하도록 구현
3. 설정 화면에서 확인 다이얼로그를 통한 회원 탈퇴 기능 제공
4. STOMP 이벤트(`SETTINGS_UPDATED`, `AREA_UPDATED`) 수신 시 실시간 캐시 무효화

---

### ✅ 구현 내용

#### 1. 회원 탈퇴 기능 (DELETE /api/user/me)

**Data 레이어**
- **파일**: `lib/features/user/data/datasources/user_remote_datasource.dart`
- Retrofit `@DELETE` 메서드 추가, 응답 모델 `DeleteAccountResponseModel` 신규 생성
- `UserRepositoryImpl`에 `deleteAccount()` 구현

**Domain 레이어**
- **파일**: `lib/features/user/domain/usecases/delete_account_usecase.dart`
- UseCase 패턴으로 백엔드 계정 삭제만 담당, 로컬 정리는 Presentation에서 수행

**Presentation 레이어**
- **파일**: `lib/features/settings/presentation/pages/settings_page.dart`
- 2단계 확인 다이얼로그(1차 확인 → 2차 최종 확인) 후 탈퇴 실행
- 로딩 팝업으로 터치 차단, 에러 시 SnackBar 표시
- 탈퇴 성공 시 `context.go(login?accountDeleted=true)` → `forceLogout()` 순서로 state 초기화

**Auth 정리**
- **파일**: `lib/features/auth/presentation/providers/auth_provider.dart`
- `cleanupAfterAccountDeletion()`: `try { signOut } finally { clearTokens }` 구조로 signOut 실패 시에도 토큰 삭제 보장
- state 초기화는 호출부(`settings_page.dart`)에서 `context.go()` 후 `forceLogout()` 호출로 수행 — GoRouter 리다이렉트보다 탈퇴 완료 메시지 전달이 먼저 실행되도록 순서 보장
- 로그인 페이지에서 `accountDeleted=true` 쿼리 파라미터 수신 시 탈퇴 완료 SnackBar 표시

#### 2. 게임 설정/영역 수정 API 연동

**Data 레이어**
- **파일**: `lib/features/session/data/datasources/session_remote_datasource.dart`

**Provider 레이어**

**API 엔드포인트**
- **파일**: `lib/core/constants/api_endpoints.dart`
- `gameSettings(gameId)`, `gameArea(gameId)`, `deleteMe` 헬퍼 메서드 추가

**구역 수정 (편집 모드)**

- 영역 수정은 플레이그라운드 → 감옥 순서로 진행 후 `PUT /area` 단일 호출

### 🔧 버그 수정 및 안정성 개선

#### 대기실 무한 재시도 방지
- **파일**: `waiting_room_page.dart`
- `_onGameStartEvent`에서 participantInfo 미준비 시 무한 재귀 호출 → 최대 10회(3초) 제한
- `_toggleReady`에 `finally` 블록 추가하여 `_isUpdatingReady` 상태 복구 보장

#### 코드래빗 리뷰 반영
- `cleanupAfterAccountDeletion()`: state 초기화를 호출부로 이동하여 탈퇴 완료 메시지 유실 방지, signOut 실패 시에도 `clearTokens` 실행 보장 (`try-finally`)
- `lobby_provider.dart`: `_gameId` 대신 `event.gameId` 사용하여 방 전환 타이밍 이슈 방지
- `game_settings_page/edit_page`: `int.tryParse ?? 0` 제거, null 시 early return/pop 처리

#### 게임 설정 UX 개선
- 구역 수정 시 기존 감옥 좌표를 초기값으로 전달 (GPS 위치가 아닌 원래 감옥 위치에서 시작)
- async gap에서 `GoRouter.of(context)` 캡처하여 context 안전성 확보

### 📌 참고사항

- `PUT /area`는 플레이그라운드와 감옥을 동시에 전송하는 단일 API. 플레이그라운드만 수정해도 감옥 재설정이 필요한 이유는 감옥이 새 플레이그라운드 밖에 위치할 수 있기 때문
- 게임 설정 수정은 `WAITING` 상태에서만 가능 (서버 측 검증)
- 회원 탈퇴 시 409 에러는 "진행 중인 게임이 있어 탈퇴 불가" 케이스
- STOMP 이벤트 캐시 무효화는 `event.gameId` 기반으로 동작하여 방 전환 시 잘못된 캐시 무효화 방지
