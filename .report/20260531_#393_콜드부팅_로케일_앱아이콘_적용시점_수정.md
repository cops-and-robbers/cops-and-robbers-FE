# 콜드 부팅 시 로케일 앱 아이콘 적용 시점 수정 (#393)

### 📌 작업 개요

시스템 언어가 한국어인 상태에서 앱을 처음 설치하면 런처 앱 아이콘이 영어(Primary)로 표시되는 버그를 수정. 단일 원인(콜드 부팅 직후의 위험한 아이콘 적용 호출)이 두 플랫폼에서 다르게 발현되던 것을, lifecycle 옵저버 일원화로 해결.

### 🔍 문제 분석

`main.dart`가 `runApp()` 직후 `unawaited(applyStartupLocaleIcon())`를 "가장 이른 시점"에 플랫폼 가드 없이 호출한 것이 직접 원인.

- iOS: 앱이 foreground-active 되기 전에 `setAlternateIconName`이 호출되어 iOS가 "작업이 취소되었습니다"로 거부. 실측 로그 `PlatformException(SET_ICON_FAILED, 작업이 취소되었습니다.)`. 이 예외를 서비스가 흡수하고, iOS에는 재시도할 lifecycle 경로가 없어(`LocaleAppIconObserver`가 Android 전용이었음) 영어 아이콘으로 고정됨. iOS는 alternate 아이콘 선택을 OS 레벨에 영구 저장하므로, 설정에서 한 번 수동 적용되면 이후엔 정상 유지 → "첫 설치 때만" 재현.
- Android: activity-alias를 포그라운드에서 토글 → 런처가 앱 태스크를 재시작/강퇴("자동 뒤로") → 재시작 후 한글로 바뀜. 설정 화면 코드는 이 위험을 알고 Android 즉시 적용을 피했지만(`if (Platform.isIOS)` 가드), `main.dart`의 콜드 부팅 호출만 이 안전 규칙을 우회.

### ✅ 구현 내용

#### main.dart — 위험한 eager 호출 제거
- 파일: `lib/main.dart`
- 변경 내용: `runApp()` 직후의 `unawaited(applyStartupLocaleIcon())` 제거. 그 호출로만 쓰이던 `dart:async`, `startup_app_icon.dart` import도 함께 정리. 옵저버 등록(`startLocaleAppIconObserver()`)만 유지.
- 이유: 이 호출이 iOS cancelled / Android 강퇴의 직접 원인. 아이콘 적용은 옵저버가 안전한 시점에 담당.

#### LocaleAppIconObserver — 플랫폼별 안전 시점으로 일원화
- 파일: `lib/core/services/app_icon/locale_app_icon_observer.dart`
- 변경 내용: Android 전용 등록을 iOS·Android 양쪽 등록으로 확장. 순수 함수 `iconReconcileTriggers(TargetPlatform)`로 플랫폼별 적용 시점을 결정(iOS=`resumed`, Android=`paused/hidden/detached`, 그 외=`null`=미등록). 등록 시점에 이미 trigger 상태면 `addPostFrameCallback`으로 1프레임 뒤 1회 catch-up.
- 이유: "언제 적용이 안전한가"를 한 곳에서 결정. iOS는 active 상태에서만 `setAlternateIconName`이 성공하고, Android는 백그라운드에서만 alias 토글이 안전.

#### 초기 catch-up 콜백 실행 시점 lifecycle 재확인 (리뷰 반영)
- 파일: `lib/core/services/app_icon/locale_app_icon_observer.dart`
- 변경 내용: 예약된 post-frame 콜백 본문을 `maybeRunInitialReconcile()`(`@visibleForTesting`)로 추출하고, 콜백 실행 시점에 `needsInitialReconcile()`로 상태를 한 번 더 확인해 **아직 trigger 상태일 때만** 적용하도록 가드 추가.
- 이유: 등록 시점엔 trigger(iOS=`resumed`)였더라도 첫 프레임 전에 앱이 inactive/백그라운드로 바뀌면, not-active 상태에서 호출돼 다시 iOS cancelled 케이스를 밟을 수 있음. 벗어난 경우는 이후 `didChangeAppLifecycleState`가 다음 trigger 전이에서 catch-up(self-healing).

#### 옵저버 단위 테스트 재작성
- 파일: `test/core/services/app_icon/locale_app_icon_observer_test.dart`
- 변경 내용: 기존 6개(Android 하드코딩) → 11개로 재작성. (1) `iconReconcileTriggers` 플랫폼 결정, (2) lifecycle 트리거 포함/미포함, (3) 초기 catch-up 판단(`needsInitialReconcile`), (4) 콜백 시점 재확인 가드(`maybeRunInitialReconcile`: trigger 유지 시 적용 / 프레임 전 trigger 이탈 시 미적용).
- 이유: 등록 경로와 트리거 분기를 단위 테스트로 보호. 그 외 플랫폼이 no-op인지까지 검증해 "Android 전용 가드 잔존" 회귀를 잡음. 콜백 시점 상태 이탈 케이스까지 명시 검증.

### 🔧 주요 변경사항 상세

#### iconReconcileTriggers (순수 함수)
플랫폼별 적용 시점 집합을 반환. `switch`가 모든 `TargetPlatform`을 exhaustive하게 처리해, 미래 플랫폼 추가 시 컴파일 타임에 드러남. 이 함수가 null을 반환하면 옵저버를 등록하지 않으므로 "등록 여부"와 "적용 시점"을 동시에 결정.

#### LocaleAppIconObserver
`triggers` 집합으로 동작하며 `onReconcile`(아이콘 적용 콜백)·`currentState`(현재 lifecycle 조회)를 주입 가능. 덕분에 `WidgetsBinding` 없이 순수 단위 테스트로 검증된다. `didChangeAppLifecycleState`는 `triggers.contains(state)`일 때만 적용.

특이사항:
- 초기 catch-up은 동기 즉시 호출이 아니라 `addPostFrameCallback` 경유. 동기 호출은 `runApp()` 직후 타이밍과 겹쳐 iOS cancelled를 재현할 수 있어, 1프레임 뒤로 미뤄 앱이 확실히 그려진 뒤 적용한다.
- 콜백은 실행 직전 `needsInitialReconcile()`로 상태를 재확인하므로, 등록~첫 프레임 사이에 lifecycle이 trigger를 벗어나면 호출하지 않는다(계약: "안전한 상태에서만 적용"). 단, 사용자 체감 결과는 기존과 동일 — 기존에도 실패는 swallow되고 이후 `resumed` 복귀 시 재적용되므로, 이 가드는 실패할 게 뻔한 호출을 생략하는 정합성 보강.
- `needsInitialReconcile()`·`maybeRunInitialReconcile()`은 `@visibleForTesting`으로 표시(외부 공개 API 아님).

#### main.dart
아이콘 적용 시점이 "콜드 부팅 즉시" → "iOS 첫 active / Android 첫 백그라운드"로 늦춰진다. 이는 의도된 설계 변경(버그 수정의 핵심). 설정 화면의 명시적 즉시 적용 경로는 그대로 유지.

### 🧪 테스트 및 검증

- 옵저버 단위 테스트 11개 전부 통과.
- 변경 파일 `flutter analyze`: 이슈 없음.
- 전체 테스트 회귀: 본 변경으로 신규 실패 0건. 기준선 비교(변경 제외 `+293 -4` vs 변경 포함 `+296 -4`) — 통과 테스트만 +3, 실패 4건은 모두 사전 존재(`login_page_test` 로고/레이아웃 등, 본 변경과 무관 파일).

### 📌 참고사항

- 실기기 검증 필요(자동 테스트 불가 영역):
  - iOS: 시스템=한국어로 재설치 → 설정 진입 없이 active 직후 아이콘이 한국어로 전환되는지 + `SET_ICON_FAILED` 로그 소멸 확인.
  - Android: 재설치 → 실행(영어) → 백그라운드 전환 시 한국어로 전환 + 앱 강퇴 없음 확인.
  - iOS에서 여전히 cancelled가 관측되면 짧은 지연 또는 네이티브 `applicationDidBecomeActive` 신호로 트리거 승격(동일 파일 국소 변경, 설계 골격 유지). 콜백 시점 재확인 가드로 "등록 후 첫 프레임 전 비active 전환" 한정 케이스는 이미 차단됨.
- 사전 존재 관찰(본 변경 범위 밖, 손대지 않음): `stop()` 메서드가 호출처 없음 + `startLocaleAppIconObserver()`가 nullable 반환. 원래 코드부터의 설계로, 정리하려면 별도 작업 권장.
