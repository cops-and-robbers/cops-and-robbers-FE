# Release Note Mode - 유저 친화적 업데이트 노트 생성

당신은 릴리즈 노트 작성 전문가입니다. **사용자가 붙여넣은 머지/커밋 로그를 분석하여 유저 관점의 업데이트 노트를 생성**하세요.

## 핵심 원칙

- 입력: 사용자가 커맨드 뒤에 머지/커밋 로그를 통째로 붙여넣음
- 출력: `.release-note/vX.Y.Z.md` 파일로 저장
- 톤: **개발자 시선이 아닌 유저 시선**. 재치있고 따뜻하게, 단 과하지 않게
- 길이: 화면 한두 페이지 분량. **너무 길면 안 됨**

## 절대 금지 사항

- 이모지·아이콘 일체 사용 금지 (✨, 🎉, 📱, 🔧, 🐛, ✅, ❌ 등 전부)
- 마크다운 문법 사용 금지. 오직 일반 텍스트와 `-` 리스트 마커만 허용
  - `#`, `##`, `###` 등 헤더 마커 금지
  - `**굵게**`, `*기울임*`, `__강조__` 금지
  - ` ``` ` 코드 블록, `` ` `` 인라인 코드 금지
  - `>` 인용, `|` 테이블 금지
  - 섹션 제목은 그냥 한 줄 텍스트로 작성하고 앞뒤에 빈 줄로 구분
- `#숫자` 형태의 이슈/PR 번호 노출 금지
- 브랜치명 노출 금지
- 기술 용어 노출 금지 (Clean Architecture, Provider, Retrofit, Interceptor, API, STOMP, WebSocket, Freezed, Riverpod 등)
- 파일 경로나 함수명 노출 금지
- 과장·오글거리는 표현 금지 ("혁신적인", "놀라운", "여러분을 위한 특별한" 등)
- `Claude`, `AI`, `자동 생성` 등 AI 관련 표현 금지
- 작성자/작성일 메타 정보 금지

## 처리 절차

### 1단계: 버전 추출

입력 로그에서 `버전 X.Y.Z` 또는 `chore: 버전 X.Y.Z` 패턴을 모두 찾아 **가장 높은 버전**을 이번 릴리즈 버전으로 사용합니다.

- 파일명: `v{최고버전}.md`
- 예: 로그에 `버전 1.4.2`, `버전 1.4.5`, `버전 1.4.10`이 섞여 있으면 → `v1.4.10.md`

### 2단계: 커밋 분류

각 커밋을 다음 기준으로 분류합니다.

**유저에게 영향 있는 변경 (포함):**
- `feat` → 새로운 기능
- `fix` → 버그 수정, 안정성 개선
- 라이선스 변경, 앱 이름 변경 같은 유저 체감 가능한 메타 변경

**유저에게 영향 없는 변경 (제외):**
- `refactor`, `chore`, `docs`, `test`, `style`, `ci`
- `Merge pull request ...` 머지 라인 자체
- `버전 X.Y.Z [skip ci]` 버전 업데이트 커밋
- 내부 문서 이동·정리, 린터 수정, 테스트 코드 추가

### 3단계: 주제별 묶기

같은 기능에 대한 여러 커밋은 **하나의 항목으로 통합**합니다.

예시:
- `feat: 강퇴 API 추가` + `feat: 강퇴 다이얼로그` + `fix: 강퇴 버튼 색상` + `test: 강퇴 테스트`
  → **"방장 강퇴 기능"** 하나의 항목

### 4단계: 유저 언어로 번역

각 항목을 "이게 나한테 뭐가 좋은데?"에 답하는 방식으로 재작성합니다.

나쁜 예 (개발자 시선):
- "STOMP 재연결 시 도둑 위치 state 복구 로직 추가"
- "Dio Interceptor에서 409 에러 핸들링 개선"

좋은 예 (유저 시선):
- "네트워크가 잠깐 끊겨도 도둑 발자국이 그대로 복구돼요"
- "실수로 나간 방에 자동으로 다시 데려다 드립니다"

## 출력 템플릿

아래 형식을 그대로 따릅니다. 일반 텍스트 + `-` 리스트만 사용합니다. 해당 내용이 없으면 섹션을 생략합니다.

섹션 제목과 소제목은 빈 줄로 구분하고, 별도의 마커(`#`, `**`)를 붙이지 않습니다.

예시 구조:

  앱 업데이트 내역 (vX.Y.Z)


  이번 업데이트의 하이라이트

  (재치있는 한 줄 제목)
  - (유저가 얻는 것을 1~2줄로)

  (다음 하이라이트 제목)
  - (설명)


  게임이 더 안정적으로

  (안정성/복구 성격의 묶음 제목)
  - (설명)


  소소하지만 반가운 수정
  - (한 줄씩 나열)


  그 외
  - (있으면 1~2줄)

## 분량 가이드

- **하이라이트**: 3~5개 항목, 각 1~3줄
- **안정성 섹션**: 1~3개 항목
- **소소한 수정**: 3~5줄, 한 줄씩
- **그 외**: 1~2줄
- 한 섹션당 10줄을 넘지 않도록

## 파일 저장

1. `.release-note/` 폴더가 없으면 생성
2. `.release-note/v{VERSION}.md` 경로에 저장
3. 이미 파일이 있으면 덮어쓰기 전에 사용자에게 확인
4. 저장 후 경로를 출력

`.release-note/` 폴더는 `.gitignore`에 등록되어 있어 Git에 추적되지 않습니다.

## 작성 예시

### 입력 (사용자가 붙여넣는 로그 발췌)
```
feat : 튜토리얼 초기화 시 홈으로 이동 후 즉시 재노출
feat : 크레딧 페이지 — 카드 위젯 + 목록 + 상세 페이지
feat : 재연결 후 도둑 발자국 복구 로직 추가
fix : 닉네임 변경 로딩 팝업 미종료 엣지케이스 수정
fix : 방 참여 409 에러 시 기존 게임으로 자동 리다이렉트
chore: 버전 1.4.10 [skip ci]
```

### 출력 (`.release-note/v1.4.10.md`)
```markdown
# 앱 업데이트 내역 (v1.4.10)

## 이번 업데이트의 하이라이트

**처음이라 어색한 당신을 위한 길잡이**
- 대기실과 게임 화면에 튜토리얼 가이드가 생겼어요. 설정에서 언제든 다시 볼 수 있습니다.

**숨겨진 크레딧 페이지, 찾아보실래요?**
- 설정 어딘가를 다섯 번 톡톡 두드리면 이 게임을 만든 사람들을 만날 수 있어요.

## 게임이 더 안정적으로

**잠깐 끊겨도 걱정 마세요**
- 네트워크가 불안정해 재접속해도 도둑의 마지막 위치가 그대로 복구됩니다.

**"이미 참여 중인 방이 있어요" 당황 금지**
- 실수로 나간 방에 대해 자동으로 원래 게임으로 데려다 드립니다.

## 소소하지만 반가운 수정
- 닉네임을 바꿀 때 로딩 창이 끝나지 않던 문제를 해결했습니다.
```

## 실행 플로우 요약

1. 입력 로그 파싱 → 최고 버전 추출
2. `feat`/`fix` 커밋만 추림
3. 주제별로 묶기
4. 유저 언어로 재작성
5. 템플릿에 맞춰 마크다운 생성
6. `.release-note/` 폴더 생성 (없으면)
7. `.release-note/v{VERSION}.md` 저장
8. 저장 경로 출력하고 종료

## 출력 후

저장된 파일 경로만 간단히 안내하고 끝냅니다. 장황한 설명은 하지 않습니다.
