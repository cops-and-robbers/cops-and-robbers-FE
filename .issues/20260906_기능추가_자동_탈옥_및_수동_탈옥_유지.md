# ⚙️ [기능추가][게임] 감옥 이탈 시 자동 탈옥 및 수동 탈옥 유지

## 📝 현재 문제점

수감된 도둑이 실제로 감옥을 벗어나도 탈옥 버튼과 확인 모달을 조작해야 한다. 감옥 진입 후 이탈을 감지해 기존 탈옥 API를 자동 호출하고, GPS 감지 실패와 통신 오류에 대비해 수동 탈옥 버튼도 항상 유지한다.

<br>

## 🛠️ 해결 방안 / 제안 기능

| 항목 | 요구 동작 |
| --- | --- |
| 대상 | 진행 중 일반 게임의 수감된 본인 도둑. 이벤트 게임 제외 |
| 감옥 밖에서 체포 | 이번 체포 이후 내부 위치를 확인하기 전에는 자동 탈옥하지 않음 |
| 감옥 안에서 체포 | 체포 이후 유효한 내부 위치를 확인하면 이번 주기의 진입으로 인정 |
| 원형·폴리건 | AreaShape.contains를 재사용하고 실제 도형 경계까지의 거리로 이탈 여유 구간 판정. 폴리건을 외접 원으로 대체하지 않음 |
| GPS | 오래되거나 정확도가 나쁜 표본으로 전이하지 않음. 경계 여유 거리와 연속 표본 확인 기준을 명시하고 현장에서 보정 |
| 수동 탈옥 | 기존 버튼과 확인 모달을 항상 유지. 자동 감지에 사용하는 GPS 조건으로 수동 경로를 막지 않음 |
| 요청 중복 | 자동·수동이 같은 요청 가드를 사용. 진행 중 추가 호출 차단 |
| 재체포 | 이전 주기의 진입·이탈 및 요청 결과가 새 수감 상태를 변경하지 못하도록 격리 |
| 실패·연결 복구 | 실패 시 수감 유지. 밖에 머물러도 복구 후 재시도할 수 있도록 설계하고 GPS tick마다 무한 요청하지 않음 |
| 재시작 | 서버 수감 상태를 먼저 복원. 과거 진입 기록을 새 체포에 잘못 적용하지 않음. 주기를 식별할 수 없으면 자동 감지는 보수적으로 재시작하고 수동 경로 제공 |
| UI | 기존 지도 차단 모달 구조 유지. 자동 처리 안내와 수동 버튼의 관계만 ko/en/ja 문구에 반영 |

> [!IMPORTANT]
> 지도 차단 해제·하단 카드 전환·감옥 카메라 안내는 회의에서 별도 결정한다. 이번 작업에 포함하지 않는다.

## ❓ 확인 필요

서버에서 아직 JAILED인 도둑은 재체포 요청이 거절된다. 현실에서 탈옥하다 다시 잡혔으나 최초 탈옥이 서버에 확정되지 않은 상황을 FE 위치만으로 판별할 수는 없다. 기존 서버 규칙을 유지하며, 서버 상태 확인 없이 재체포를 추정하거나 이전 탈옥을 강제로 확정하지 않는다. 별도 규칙/서버 계약 변경이 필요하면 후속 논의로 분리한다.
