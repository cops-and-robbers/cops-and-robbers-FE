## 본문

## 📝 현재 문제점

- 모바일 앱(Flutter)에서 방 초대 링크 딥링크 기능은 구현 완료되었으나, 실제 OS가 링크를 가로채 앱을 자동 실행하려면 도메인 측에서 검증 파일을 호스팅해야 함
- 현재 copsnro66ers.site 에는 다음 두 가지가 없음
  - `/.well-known/assetlinks.json` (Android App Links 검증)
  - `/.well-known/apple-app-site-association` (iOS Universal Links 검증)
- 앱 미설치 사용자가 카톡 등으로 받은 링크를 클릭했을 때 보여줄 `/join/{code}` 폴백 페이지도 없음
- 위 작업이 끝나야 모바일 앱의 딥링크 기능이 운영에서 정상 작동함

## 🛠️ 해결 방안 / 제안 기능

- 모바일 측에서 핸드오프 패키지를 준비해두었음 (`docs/deeplink-handoff/` 디렉토리)
- 해당 패키지를 통째로 받아 Next.js + Vercel 프로젝트에 그대로 적용
- 자세한 배치 위치, vercel.json 설정, App Router / Pages Router 컴포넌트 레퍼런스 코드, 검증 절차는 `docs/deeplink-handoff/README.md` 에 모두 정리되어 있음

## ⚙️ 작업 내용

1. `assetlinks.json` 을 `public/.well-known/assetlinks.json` 에 정적 파일로 배치
2. `apple-app-site-association` 을 `public/.well-known/apple-app-site-association` 에 정적 파일로 배치 (확장자 없음 주의)
3. `vercel.json` 의 `headers` 항목 적용해 두 파일의 Content-Type 을 application/json 으로 강제 (기존 vercel.json 이 있으면 headers 항목만 병합)
4. `/join/[code]` 폴백 페이지 구현 (Next.js 사용 중인 App Router 또는 Pages Router 한 가지로 선택, README 에 양쪽 레퍼런스 코드 포함)
5. 배포 후 검증
   - curl 로 두 파일이 HTTP 200 + `Content-Type: application/json` 응답하는지 확인
   - Branch AASA Validator (https://branch.io/resources/aasa-validator/) 로 iOS 검증 통과 확인
   - PC 브라우저로 `https://copsnro66ers.site/join/TEST123` 접속해 폴백 페이지 노출 확인
6. 위 검증이 모두 통과되면 모바일 측에 통보 (실제 카톡 / 단말 e2e 테스트 진행 예정)
