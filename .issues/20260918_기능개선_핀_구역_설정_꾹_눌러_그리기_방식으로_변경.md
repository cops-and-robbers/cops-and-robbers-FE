| 항목 | 내용 |

## 📝 현재 문제점

`lib/core/widgets/map/pin_zone_setting_widget.dart`의 폴리곤 구역 편집은 **꼭짓점 하나마다 지도를 탭**해야 한다.

| 불편 | 위치 |
|---|---|
| 실수로 지도를 탭하면 핀이 하나 더 생긴다 | `_onMapTap` (`:208`) |
| 핀 간 10m 미만이면 탭마다 빨간 스낵바가 뜬다 | `_onMapTap` (`:220`) |
| 핀을 찍은 순서를 무시하고 중심 각도로 재정렬해 오목한 모양이 의도와 다르게 이어진다 | `sortedPoints` (`:203`) |
| 삭제가 핀 탭이라 지도 이동과 헷갈리고, 삭제 때 카메라가 잠깐 튄다 | `_removePin` (`:250`) |
| 최대 10개 상한 — 서버(`PolygonAreaData`)에는 꼭짓점 수 제약이 없다 | `GameConfig.maxPolygonVertexCount` |

<br>

## 🛠️ 해결 방안 / 제안 기능

GoogleMap 위에 `GestureDetector(onLongPressStart / MoveUpdate / End)` + `CustomPaint`를 겹친다. 롱프레스가 제스처 아레나에서 이기면 지도 팬은 탈락하므로 **같은 움직임을 롱프레스와 팬이 동시에 받지 않는다** (#66에서 원형 위젯이 겪은 충돌은 좌표를 매 프레임 변환하며 두 제스처가 공존하던 구조였다).

- 그리는 동안은 **픽셀 좌표만** 쓰고(`CustomPaint`), 지도 좌표 변환은 손을 뗄 때 단순화된 꼭짓점만 `getLatLng`로 한 번 한다.
- 각도 정렬을 없애고 **그린 순서 = 경계 순서**. `sortByAngleAroundCentroid`는 소비처가 0이 되어 삭제.
- `zone_metric_formatter.dart:47`의 면적 계산도 각도 정렬을 빼고 링 순서를 그대로 쓴다 — 오목한 구역을 각도로 재정렬하면 면적이 틀린다.
- `polygon_pin_marker_factory.dart` 삭제 (소비처가 핀 위젯뿐). 에셋 `polygon_pin.svg`는 남긴다.
- 취소는 기존 **전체 해제 칩** 그대로. 다시 그리면 교체되므로 되돌리기는 두지 않는다.

> [!IMPORTANT]
> `getLatLng`는 `getScreenCoordinate`와 같이 **Android는 물리 픽셀** 기준이다 (#405 DPR 이슈의 역방향). Android에서만 `devicePixelRatio`를 곱해 넘긴다.

> [!IMPORTANT]
> 롱프레스 vs 팬 아레나 동작과 DPR 보정은 시뮬레이터로 판정이 안 된다. **Android·iOS 실기기 확인**이 필요하다.
