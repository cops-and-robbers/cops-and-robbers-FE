## 제목

⚙️ [기능추가][백그라운드] 게임 진행 중 백그라운드 위치 추적 및 STOMP 연결 유지

## 본문

## 📝 현재 문제점

- 게임 진행 중 사용자가 화면을 끄거나 다른 앱으로 잠깐 전환하면 도둑의 위치 전송이 중단됨
- 그 결과 LOCATION_REVEAL 시점에 경찰이 보는 도둑 위치가 옛날 데이터이거나 비어있는 상태로 표시됨
- STOMP 웹소켓 연결도 백그라운드 진입 시 끊겨서 ARREST, ESCAPE, 채팅 등 게임 이벤트를 실시간으로 받지 못함
- 폰을 다시 깨워야만 그동안 발생한 이벤트가 보이는 문제로 게임이 원활하지 않음

## 🛠️ 해결 방안 / 제안 기능

게임이 IN_PROGRESS 상태인 동안에만 백그라운드 위치 추적과 STOMP 연결 유지를 활성화한다.

플랫폼별 접근

- Android는 Foreground Service(foregroundServiceType="location") + 영구 알림으로 OS가 프로세스를 죽이지 않도록 keep-alive
- iOS는 UIBackgroundModes에 location 추가 + geolocator의 allowBackgroundLocationUpdates 활성화

핵심 원칙

- 위치 권한 격상 없이 "사용 중에만 허용"으로 충분 (네이버 지도 내비게이션과 동일 방식)
- 백엔드 변경 없이 기존 STOMP `/publish/game/{gameId}/location` 채널 그대로 사용
- STOMP 클라이언트와 위치 추적 코드는 main isolate에서 그대로 실행, 별도 isolate 사용 안 함
- 백그라운드 인프라는 단순히 OS에게 프로세스 keep-alive 신호만 보내는 역할
- Flutter Lifecycle(WidgetsBindingObserver)은 보조 역할로만 사용 (iOS keep-alive 타이머 ON/OFF, STOMP 재연결 백오프 분기). 핵심 기능(Android FGS, iOS Background Location, STOMP 연결 유지)은 Flutter Lifecycle 없이도 동작함

라이프사이클 트리거

- GAME_START STOMP 이벤트 수신 시 service 시작
- GAME_OVER STOMP 이벤트 수신 시 service 종료
- 게임 화면 진입 시점에 IN_PROGRESS 상태면 service 강제 시작 (재진입 가드)
- 사용자가 게임에서 명시적으로 이탈 시 service 즉시 종료

추가 보강책

- iOS stationary 케이스: 백그라운드 진입 후 30초마다 getCurrentPosition 강제 호출하여 OS suspend 방지
- STOMP 재연결 백오프를 라이프사이클 인지 정책으로 변경 (백그라운드 시 0s → 1s → 2s → 5s)
- Android 14+ 대응: FOREGROUND_SERVICE_LOCATION 권한 추가
- Android 13+ 대응: POST_NOTIFICATIONS 권한 요청
- 일부 제조사(샤오미, 삼성, 화웨이, 오포)의 공격적 배터리 정책 대응: 첫 게임 시작 시 배터리 최적화 제외 안내 1회 노출
- 첫 게임 시작 시 배터리 영향 안내 1회 노출

명시적 비목표

- 사용자가 앱을 강제 종료(swipe-away)한 경우의 자동 복구는 다루지 않음
- 활성 게임 조회용 신규 백엔드 API는 만들지 않음
- 대기실, 메인화면 등 게임 외 화면에서의 백그라운드 동작은 하지 않음
- VoIP, Audio 등 부적절한 백그라운드 모드는 사용하지 않음 (App Store 리젝 리스크)
- Flutter Lifecycle을 service start/stop의 트리거로 사용하지 않음 (트리거는 STOMP 이벤트 + 게임 화면 위젯 라이프사이클)

## ⚙️ 작업 내용

iOS 네이티브

- Info.plist UIBackgroundModes에 location 항목 추가 (기존 fetch, remote-notification 유지)
- NSLocationAlwaysAndWhenInUseUsageDescription 키 제거 (사용 안 함)
- NSLocationWhenInUseUsageDescription 문구를 백그라운드 사용 명시한 내용으로 업데이트

Android 네이티브

- AndroidManifest에 권한 3개 추가 (FOREGROUND_SERVICE, FOREGROUND_SERVICE_LOCATION, POST_NOTIFICATIONS)
- AndroidManifest에 GameSessionForegroundService 등록 (foregroundServiceType="location")
- GameSessionForegroundService Kotlin 작성 (영구 알림, START_STICKY, ~70줄 규모)
- MainActivity에 background_service MethodChannel 핸들러 추가

Flutter 공통

- BackgroundService 추상화 인터페이스 및 플랫폼별 구현체 작성 (lib/core/services/background/)
- DeviceLocationService의 iOS LocationSettings에 백그라운드 옵션 적용 (pauseLocationUpdatesAutomatically=false, activityType=otherNavigation, allowBackgroundLocationUpdates=true)
- AppLifecycleService에 paused 진입 시 keep-alive 타이머 추가, resumed 시 종료
- GameEventNotifier에 GAME_START/GAME_OVER 라이프사이클 트리거 통합
- GamePage initState에 IN_PROGRESS 재진입 가드 추가
- GameEventNotifier 재연결 백오프 정책에 라이프사이클 분기 추가
- 게임 시작 권한 플로우 작성 (위치 권한 → Android 13+ 알림 권한 → Android 배터리 최적화 안내 → 배터리 영향 안내)

테스트 시나리오

- 게임 시작 후 화면 잠금 5분, 위치 송신과 STOMP 연결 정상 유지 확인
- 게임 시작 후 다른 앱(카톡 등) 전환 후 복귀, 게임 상태 정상 확인
- iOS 도둑이 한 자리에 10분 정지한 상태에서 STOMP 살아있는지 확인
- 백그라운드에서 비행기 모드 ON/OFF 시 자동 재연결 확인
- GAME_OVER 수신 후 30초 이내 Android 알림 사라짐 및 iOS 위치 인디케이터 멈춤 확인
- Android 14 단말에서 service 정상 시작 확인
- Android 13+ 단말에서 알림 권한 거부 시 service 동작 확인
- 샤오미, 삼성 등 공격적 배터리 정책 단말에서 배터리 최적화 제외 후 정상 동작 확인
