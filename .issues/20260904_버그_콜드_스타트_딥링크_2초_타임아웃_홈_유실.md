# ❗ [버그][Flutter][딥링크] 콜드 스타트에서 2초 타임아웃에 걸리면 딥링크가 홈으로 유실됨

## 🗒️ 설명

콜드 스타트(앱이 꺼진 상태)에서 딥링크로 앱을 실행하면, 목적지(모집글 상세·초대 참여) 대신 홈으로 가는 경우가 있다. 특히 **링크를 받고 앱을 처음 설치한 사용자의 첫 실행**에서 잘 재현된다.

**원인**

스플래시가 콜드 스타트 딥링크 프로브(`coldStartDeeplinkProvider`)를 `.timeout(2초)`로만 기다린다. 설치 직후 첫 실행처럼 초기화가 느린 상황에서는 `getInitialLink()` 플랫폼 채널 응답이 2초를 넘겨, 스플래시가 "링크 없음"으로 판단하고 홈으로 이동한다.

한 번 버려진 링크는 되살아나지 않는다. 딥링크 서비스의 중복 방지(dedup)가 초기 링크의 스트림 재전달을 스킵하기 때문에("initial link 스트림 재전달 스킵" 로그), 타임아웃으로 아무도 소비하지 못한 링크가 영구 유실된다.

**실측 (deploy 기준 빌드, 에뮬레이터 API 36.1)**

| 시나리오 | 설치 직후 첫 콜드 | 콜드 재시도 |
|---|---|---|
| https /g/10 | 홈으로 유실 | 상세 도달 |
| https /join/{code} | 홈으로 유실 | join 시도 |
| 스킴 open/community/10 | - | 상세 도달 |
| 웜 + https /g/10 | - | 상세 도달 |

같은 링크가 타이밍에 따라 성공/실패가 갈리는 것으로 2초 타임아웃 레이스를 확정했다.

<br>

## 🔄 재현 방법

1. 앱을 삭제 후 재설치 (또는 force-stop 후 저사양 환경)
2. `adb shell am start -a android.intent.action.VIEW -d "https://copsandrobbers.app/g/10" com.elipair.copsandrobbers`
3. 첫 실행에서 스플래시 후 모집글 상세가 아닌 홈에 도착

<br>

## ✅ 예상 동작

콜드 스타트 딥링크는 초기화가 느려도 유실되지 않아야 한다.

**수정 방향 (3개 조합)**

1. **프로브 조기 시작** - 스플래시 진입 즉시 `coldStartDeeplinkProvider`를 read해 두어, Remote Config 등 다른 초기화와 병렬로 진행 (2초 안에 끝날 확률을 높임)
2. **타임아웃 완화 (2→4초 수준)** - 링크 없이 켠 일반 실행은 "없음" 응답이 즉시 오므로 시작 속도에 영향 없음
3. **늦은 도착 안전망** - 타임아웃으로 홈에 갔더라도, 뒤늦게 완료된 프로브 결과를 pending으로 저장해 홈 도착 후 소비 (`pendingCommunityPostProvider`의 기존 메커니즘 재활용). 이것으로 유실 0을 보장

스플래시의 네비게이션 양보/경합 로직 자체는 건드리지 않는다 (행사 전 회귀 위험 최소화). 타임아웃 없는 이벤트 드리븐 단일 경로로의 구조 개선은 행사 이후 별도 과제로 남긴다.

<br>
